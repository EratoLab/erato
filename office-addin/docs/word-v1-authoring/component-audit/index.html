This needs a component cleanup before more Word UI is added.

The main primitives already exist in the frontend library. We should reuse them and remove the competing Word CSS. We do not need another design direction or a Word-specific component kit.

Some Word colors already use shared tokens, so light/dark surfaces do change. The gaps are control geometry, density, focus styling, diff colors, and duplicated control behavior. The implementation introduced these inconsistencies; updating the kit alone cannot resolve them.

Three ownership decisions

Shared primitives own appearance and interaction conventions. Word owns what an edit means and how it reaches the document.

Reuse existing frontend

Most of the visible controls

  • Button: apply, copy, Revert, details
  • TabRail: both sets of review views
  • Card: review frame and receipt surface
  • Row + DisclosureChevron: expandable edit rows
  • ActionConfirmationCard: permission decision
  • DocumentIcon: document inclusion control

Verified in source, deliberate shared exports, and the actual built library exports.

Add to frontend

Two justified new primitives

  • TextComparison / InlineDiff: exact original, proposed and changed text
  • Native Select: a themed, labeled native filter control

Add dedicated added/removed theme tokens. If needed, extend the shared permission card for compact embedding and Alert for appropriate announcement behavior.

These are recommendations. No such new components were created in this audit.

Keep in Word / add-in core

The document workflow

  • Original and proposed structure
  • Source references and coverage meaning
  • Full draft and source mapping
  • Applied / skipped / failed outcomes
  • Locate, apply and guarded Revert
  • Review state, stale-source checks and Office calls

Shared Office policy/settings orchestration belongs in add-in core, already composed from frontend controls.

Chat shell, input and settings
Already shared 		Shared ThemeProvider, MessageList, ChatInput, ModalBase, TabRail, settings panes, EntityRow and RadioCard. Keep this composition. The Office theme adapter correctly forwards system theme choice to the shared provider.
Apply / copy / Revert / details
Reuse Button 		Raw buttons, copied ACTION_BUTTON_CLASS recipes, and Word CSS geometry. Use library Button with appropriate variants and busy/disabled states. Remove the copied recipes and descendant overrides, or they will still win.
Review view switches
Reuse TabRail 		Paragraph comparison duplicates tab behavior. Structural views use a group of pressed buttons. Use controlled TabRail for both. Preserve panel IDs and selection. The paragraph tabs already support arrow keys; structural views would gain the common tab behavior.
Frame and expandable rows
Reuse Card / Row 		Custom frame, fixed corners, bespoke row toggle and chevron. Structural sections use native details. Use Card surfaces and Row disclosures with DisclosureChevron. Keep Word content/layout local. Native details may remain; no need to replace sound HTML purely to add a component.
Permission decision
Keep shared card 		ActionConfirmationCard is reused, but the Word feature adds overrides for its typography, spacing and focus. Remove the Word overrides and preserve focus when Word replaces the confirmation with a result. Reuse the existing shared component; its pre-existing geometry is outside this refactor.
Document inclusion chip
Reuse Button + icon 		Raw toggle with token-based colors and a platform-dependent document emoji. Use shared Button with aria-pressed and DocumentIcon. The full-width placement, inclusion state, capture and labels stay in Word.
Exact text comparison
New shared primitive 		Comparison renderer lives inside WordReviewPanel; wordTextDiff is already independent of Office. Extract pure TextComparison and diff utility; add semantic diff tokens. Preserve whitespace, Unicode, original-unavailable and large-diff fallback. No Office refs or write calls in frontend.
Paragraph / status / source filters
New native Select 		Three native select sites, styled separately. No general native select was found in the public frontend UI. Add a small themed native Select using the existing field/label contract. A model selector or action menu is not an equivalent substitute.
Errors, warnings and passive notices
Small API gap 		Local notice paragraphs with largely the same visual treatment. Use Alert for actual alerts. It currently hardcodes role="alert"; passive explanations and polite status updates need suitable semantics, not automatic assertive announcements.
Completed receipt
Compose locally first 		Paragraph receipt is a component; structural receipt duplicates its markup and state interpretation. Consolidate presentation inside Word, using Card/Button. Consider a generic ActionResult only when another host needs the same contract. Permission granted must not mean edit succeeded.
Coverage and status labels
Local meaning 		Native progress and spans; some success/error colors already follow tokens. Keep document counts and outcomes local. Tokenize progress accent. CountBadge is suitable only for numeric counts, not paragraph IDs or applied/skipped labels.
Structure, draft and source mapping
Word composition 		Outline columns, grouped draft, source references, retained view/filter state and bounded scroll regions. Keep in Word and compose shared controls around the content. Heading/list previews and source identity encode document semantics.
Host actions and policy integration
Word + add-in core 		HostCardCodeBlock registration, captures, Office calls, write gate, stored consent and result states. Keep the Word adapter and safeguards in Word; common Office client-action/settings orchestration stays in add-in core. No Word workflow needs to move into the kit.
Preparing / invalid / technical detail
Existing primitives 		Some states render outside the review root; invalid paragraph data falls back to a custom raw fence. Use self-contained shared surfaces/status treatment. SyntaxHighlightedCode and CollapsibleCodeBlock are already exported. Distinguish incomplete streaming from a completed invalid proposal.
Insertion and Revert variants
Preserve contracts 		Insertion is the third v1 action. Paragraph Revert has an inline overwrite warning; structural Revert checks whether the document changed. Standardize controls, keeping each action's scope and protection. Do not add batch-Revert promises to insertion or change an inline warning to a modal solely to reuse a component.

Reuse must preserve the behavior we designed

Collapsing a completed card must retain state and remove hidden controls from navigation.

Word currently keeps the full review mounted with hidden, retaining its filter and view. Shared Card's default animated Collapse only clips content; its own documentation notes that descendants remain in keyboard and accessibility navigation. unmountOnCollapse solves hiding but discards local state.

Use a shared surface with a retained hidden body, or explicitly extend the shared disclosure contract to meet both requirements. A direct switch to animated Collapse is not equivalent.

Card.tsx:95 · WordHostCardRenderer.tsx:441 · WordDocumentPlanCard.tsx:326

Tabs need TabRail, not a row of standard Buttons.

The library deliberately renders its tabs without Button's geometry hook, so customer pill styling does not turn every tab into an action button. Use TabRail's controlled value, panel relationships and keyboard behavior. Keep Word's panels and long-document scrolling outside it.

frontend/src/components/ui/Controls/TabRail.tsx:143

A permission receipt and an execution result are different states.

ActionConfirmationCard owns allow once / always allow / deny. Word owns whether the permitted operation was applied, skipped, blocked, failed or reverted. Its compact decision row must not falsely report successful editing. A generic result surface can accept outcome text and actions later; the Word state machine stays local.

Comparison needs exact content and bounded work.

Keep the current whitespace and Unicode fidelity, paragraph-break markers, original-unavailable state and complete Original/Proposed views. Preserve the existing 80,000-character and 250,000-cell comparison bounds when extracting the algorithm. Add added/removed colors to the full theme contract with light/dark defaults; document changes are not automatically errors or successes.

office-addin/src/word/utils/wordTextDiff.ts:7 · WordReviewPanel.tsx:74

Not every notice should interrupt a screen reader.

Shared Alert now supports role="status" for polite notices. Word uses it for routine explanations and retains role="alert" for failures. This resolves the fixed-role limitation recorded in the original audit.

frontend/src/components/ui/Feedback/Alert.tsx:93

Also fix action-specific settings copy.The current Always allow helper promises that changed paragraphs are skipped and a single Revert undoes the batch. Full-document rewriting instead stops the whole plan if its source changed, and guarded Revert refuses subsequent edits. Supply the correct explanation per Word action through the add-in settings API.

Recommended implementation sequence

  1. Replace the duplicated primitives.Buttons, tabs, frames, row disclosures and the document icon. Remove competing Word geometry/focus/consent selectors at the same time.
  2. Fill the actual shared gaps.Extract TextComparison and its diff tokens; add a native Select. Make small permission-card/Alert API extensions only where composition cannot satisfy the existing contract.
  3. Consolidate Word composition.Unify the two receipts locally. Retain structure/source mapping, all action safeguards and the review state. Correct the action-specific settings explanation.
  4. Validate theme propagation and behavior together.Use actual shared components with representative long documents, consent states, completed receipts, keyboard navigation and changed theme tokens.

What “done” should mean

  • Default and custom theme; light and dark; larger text; 320px and 400px panes.
  • Both paragraph batches and full-document rewrites with many changes.
  • Theme radius, spacing and focus changes reach every applicable control.
  • Pending, applying, partial/complete, blocked, denied, collapsed, expanded and reverted states remain understandable.
  • Hidden controls leave keyboard/accessibility navigation; filters and view selection survive reopening.
  • Filters do not change the apply scope. Source checks and guarded Revert remain unchanged.
