## Reviewed but not a reason to change our design

[Anthropic’s text editor tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/text-editor-tool) requires application-side execution and exact unique search matches for replacement. Our captured identity plus exact verification already addresses duplicate-text ambiguity more directly. Keep that stronger property. Its text-file interface does not supply Word structure, rich-content fidelity or a better review model.

[Tiptap’s public demo repository](https://github.com/ueberdosis/ai-toolkit-demos) corroborates available schema/review examples; the review here covered its overview and the linked official documentation, not a full source or security audit. [Its edit workflow](https://tiptap.dev/docs/ai/ai-toolkit/client/workflows/tiptap-edit) is a useful example of tying operations to a prior read. Do not adopt streaming mutations into the live document: our read → plan → review → consent → write boundary must remain intact.

Microsoft’s [resource/performance guidance](https://learn.microsoft.com/en-us/office/dev/add-ins/concepts/resource-limits-and-performance-optimization) supports measuring responsiveness and avoiding long blocking work. It does not justify inventing a universal Word payload limit. Earlier planning’s 256 KB / 100-paragraph batch suggestions were proposals, not measured API caps.

No evidence found here warrants replacing our host/client-action infrastructure with a broad editor-agent framework, adding dozens of granular mutation tools, or introducing a second model by default. The useful changes are the representation, complete reading, validation and evaluation discipline.

## What remains unproven

Native fidelity for moving rich content; the selected structural compiler on every supported host; concurrency/recovery behavior; exact deployment model budgets; and first-pass model quality for the proposed schema. The recommendation is sufficiently concrete to implement and evaluate, but these are genuine release gates. Browser screenshots and JSON validation cannot replace them.
