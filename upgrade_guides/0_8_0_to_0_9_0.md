# 0.8.0 to 0.9.0 upgrade guide

Covers the defaults that changed between 0.8.0 and 0.9.0 and the new optional
configuration worth deliberately adopting. Features marked **alpha** may change
or be removed without a deprecation period; features marked **stable** follow
the normal deprecation policy. See `CHANGELOG.md`'s "Deprecations and upgrade
notes" section for the short version.

<a id="audio-back-default"></a>

## Audio-back is on by default where a speech provider is configured

Added by [#1540](https://github.com/EratoLab/erato/pull/1540). Default behavior change.

### What changed

In 0.8.0 spoken replies ("Audio-back") needed a speech provider *and* each
user switching them on. In 0.9.0 the frontend treats the stored preference as
on unless the user has explicitly turned it off, so every user of a deployment
that has `audio_conversational.speech_provider` set now hears replies in
conversational voice mode. The choice is stored in the browser.

### Before (0.8.0 default)

```toml
[audio_conversational]
speech_provider = "assistant_voice"   # Audio-back off until each user enabled it
```

### After (0.9.0 default)

```toml
[audio_conversational]
speech_provider = "assistant_voice"   # Audio-back on until a user switches it off
```

### Action required

Deployments that configured a speech provider but did not want Audio-back to
start enabled for everyone should tell users how to switch it off, or leave
`audio_conversational.speech_provider` unset until they are ready.

<a id="reply-audio-storage"></a>

## Conversational voice replies are no longer stored by default

Added by [#1648](https://github.com/EratoLab/erato/pull/1648). Default behavior change, overridable.

### What changed

A conversational reply's voice is no longer saved as a WAV file attached to the
assistant message unless `audio_conversational.keep_reply_audio` is set, and
the "Spoken: …" line and replay player in the chat are hidden unless
`audio_conversational.reply_speech.show_in_chat` is set. Recordings stored by
0.8.0 stay in file storage and remain fetchable by chat members; there is no
cleanup path. Migration `0075` is additive.

### Before (0.8.0 default)

```toml
# Every reply's voice was stored and could be replayed after a reload;
# the "Spoken" line was shown.
```

### After (0.9.0 default — or restore explicitly)

```toml
[audio_conversational]
keep_reply_audio = true                 # store each reply's voice so it can be played again

[audio_conversational.reply_speech]
show_in_chat = true                     # show what the voice said, with a replay player
```

### Action required

If users rely on replaying a spoken reply after a reload, set both keys above
before upgrading. Otherwise nothing is required, and less personal audio is
retained.

<a id="icon-only-chips"></a>

## Composer tool chips are icon-only in mobile and add-in layouts

Added by [#1541](https://github.com/EratoLab/erato/pull/1541). Default behavior change, overridable.

### What changed

The unified tool-chips menu in the mobile and Office add-in layouts now honors
icon-only facet display. The facet name next to its icon is shown only if the
facet's `show_indicator_with_display_name` is `true` or, when that is unset,
the global `show_facet_indicator_with_display_name` (default `false`) is
`true`. Previously those layouts always showed the name.

### Before (0.8.0 behavior)

```toml
# Mobile and add-in chips always showed "<icon> Facet name".
```

### After (0.9.0 — restore the names)

```toml
[facets]
show_facet_indicator_with_display_name = true   # global: show names everywhere

# or per facet:
[facets.facets.extended_thinking]
show_indicator_with_display_name = true
```

### Action required

If your facets rely on their name being visible in the mobile or add-in chips
(for example because their icons are not self-explanatory), set one of the keys
above.

<a id="subscription-package"></a>

## Update the subscription configuration package

Relates to [#1569](https://github.com/EratoLab/erato/pull/1569),
[#1570](https://github.com/EratoLab/erato/pull/1570),
[#1571](https://github.com/EratoLab/erato/pull/1571),
[#1630](https://github.com/EratoLab/erato/pull/1630),
[#1631](https://github.com/EratoLab/erato/pull/1631),
[#1635](https://github.com/EratoLab/erato/pull/1635),
[#1568](https://github.com/EratoLab/erato/pull/1568) and
[#1573](https://github.com/EratoLab/erato/pull/1573). Not an Erato configuration key change: the
changes live in the subscription configuration package
(`erato-subscription-content`), which deployments apply on top of Erato.

### What changed

The Word and PowerPoint behavior added in 0.9.0 is partly implemented by that
package, so it should be updated together with the release:

- **Word plan schema.** The per-change block cap is lifted and block ids become
  optional (`$defs.block.required = ["type"]`), so long single-change inserts
  and plans without ids are accepted. Until the package is updated the backend
  keeps rejecting more than 16 blocks per change and blocks without ids.
- **Word prompts and tools.** The prompts that make the model prefer a sparse
  change after a complete read, and write large changes section by section
  (a section plan, one part per rewritten section and a finish), together with
  the `submission` part tools (`client_tools.tools.<key>.submission.part_tools`,
  `part_key`, `max_row_tries`, `max_part_calls`) they use. Until updated, the
  in-parts flow is never selected and large changes are still sent as one plan.
- **Word reads in long chats.** The tool descriptions and replay settings that
  go with the new receipts for earlier tool calls.
- **PowerPoint.** The `powerpoint_presentation` action facet and the
  `powerpoint_*` client tools (read presentation, slide and selection, view slide
  picture). Until applied the PowerPoint pane is a plain chat.

### Before (0.8.0)

```toml
# erato-subscription-content: Word plan schema with a block cap and required block
# ids; prompts that resend full plans; no part tools; no PowerPoint facet.
```

### After

```toml
# erato-subscription-content (updated for 0.9.0):
# - Word plan schema without the block cap and with optional block ids
# - prompts for sparse changes and section-by-section writing
# - client_tools.tools.<key>.submission part tool entries
# - powerpoint_presentation facet and powerpoint_* client tools
```

### Action required

Update the subscription configuration package to the version released with
0.9.0. Deployments that maintain their own Word or PowerPoint facet
configuration instead of the package need to carry the same changes. Nothing
breaks if you do not: the new behavior is then simply not used.

<a id="assistant-hub-controls"></a>

## Adopting Assistant Hub and sharing controls (stable)

Added by [#1641](https://github.com/EratoLab/erato/pull/1641),
[#1643](https://github.com/EratoLab/erato/pull/1643) and
[#1647](https://github.com/EratoLab/erato/pull/1647). Defaults keep today's behavior.

### What it does

- `assistants.enable_direct_organization_sharing = false` hides the
  whole-organization target from the Groups picker in the direct assistant
  Share dialog; users can still share with individual users and groups. It only
  changes the UI: the API still accepts organization-wide grants, and existing
  organization grants stay effective until an owner removes them.
- `assistant_hub.action_permissions` sets, per action, who may Publish,
  Unpublish and Make current for hub assistants. A caller needs any one listed
  role: `editors` (the source assistant's owner and users with effective edit
  access) or `reviewers` (users matching `assistant_hub.reviewers.rules`). `[]`
  disables an action. Unknown roles are rejected at startup.
- `assistant_hub.force_whole_organization_audience = true` makes the whole
  organization the fixed audience of every new Assistant Hub submission and
  version: the audience field is hidden and the grant overrides
  `assistant_hub.default_share_with_whole_organization` and any previous
  version's audience.

### Before (0.8.0 — no equivalent switches)

```toml
# The Share dialog always offered the organization target, both editors and
# reviewers could publish, and the audience was chosen per submission.
```

### After

```toml
[assistants]
enable_direct_organization_sharing = false   # default true

[assistant_hub]
force_whole_organization_audience = true     # default false

[assistant_hub.action_permissions]           # each defaults to ["editors", "reviewers"]
publish = ["reviewers"]
unpublish = ["reviewers"]
make_current = ["editors", "reviewers"]
```

### Notes

- Review-queue access and accepting or declining a submission still use the
  reviewer rules.
- Direct sharing follows `assistants.enable_direct_organization_sharing`
  separately from the Assistant Hub audience setting.

<a id="powerpoint-addin"></a>

## Adopting the PowerPoint add-in manifest settings (stable)

Added by [#1580](https://github.com/EratoLab/erato/pull/1580), with the panes
from [#1559](https://github.com/EratoLab/erato/pull/1559) and
[#1568](https://github.com/EratoLab/erato/pull/1568). The Excel and PowerPoint
panes themselves are a **preview**.

### What it does

Erato serves a deployable PowerPoint add-in manifest at
`/office-addin/manifest-presentation.xml` (add `?distribution=sharepoint` for
SharePoint app catalogs) and lists PowerPoint next to Word on the add-in setup
page. It is a separate add-in with its own id, requires no API set, so Office
LTSC 2024 still shows it. Excel can only be sideloaded from a local manifest
for now.

### Before (0.8.0 — no PowerPoint add-in)

```toml
# No [integrations.ms_office.addin.presentation] table.
```

### After — optional overrides

```toml
[integrations.ms_office.addin.presentation]
addin_id = "f13aa6d0-f017-46e3-8b17-a72159d689ea"   # a GUID; must differ from the Outlook, Word and Teams ids

[integrations.ms_office.addin.presentation.manifest]
display_name = "Erato for PowerPoint"                # max 125 characters (default shown)
description = "Erato AI assistant for PowerPoint presentations"   # max 250 characters
```

### Notes

- Without any of these keys the built-in id and texts are used.
- Reading the presentation, the selection, slide pictures, notes and chart data
  needs the `powerpoint_presentation` action facet and the `powerpoint_*` client
  tools from the content package; until they are applied the pane is a plain
  chat.
- The panes are only partly verified on real hosts (Microsoft 365 for Windows
  first); on Office LTSC 2024 sign-in falls back to the oauth2-proxy popup.
- Migration `0070` widens a `chats_created_via` constraint for the new
  platforms; it is quick and runs on deploy.

<a id="facet-chip-labels"></a>

## Adopting per-facet chip labels

Added by [#1533](https://github.com/EratoLab/erato/pull/1533) and
[#1541](https://github.com/EratoLab/erato/pull/1541).

### What it does

`facets.facets.<id>.show_indicator_with_display_name` overrides, per facet,
whether its name is shown next to its icon in the composer indicator and the
mobile/add-in tool chips; when unset the global
`facets.show_facet_indicator_with_display_name` applies.

### Before (0.8.0 — global only)

```toml
[facets]
show_facet_indicator_with_display_name = false
```

### After

```toml
[facets.facets.extended_thinking]
display_name = "Extended thinking"
show_indicator_with_display_name = true    # unset: follow the global key
```

### Notes

- The `experimental_facets` section name remains accepted as a deprecated alias
  for `facets`, including for this key; use `facets.facets.<id>`.
- See also [icon-only chips](#icon-only-chips) for the default this controls.

<a id="mcp-display-name"></a>

## Adopting MCP server display names

Added by [#1490](https://github.com/EratoLab/erato/pull/1490), with stricter validation from
[#1491](https://github.com/EratoLab/erato/pull/1491).

### What it does

`mcp_servers.<id>.display_name` is the name users see for a server on approval
cards (their own calls, delegated tasks and Teams), trace rows and the
Servers & Tools tab. Without it the server id is tidied up
(`web_access` becomes "Web access"). Messages saved before keep showing the id,
and live trace rows pick the name up once the message completes.

### Before (0.8.0)

```toml
[mcp_servers.file_provider]
transport_type = "sse"
url = "http://127.0.0.1:63490/sse"
# cards and traces show "file_provider"
```

### After

```toml
[mcp_servers.file_provider]
display_name = "File Provider"
transport_type = "sse"
url = "http://127.0.0.1:63490/sse"
```

### Notes

- The name must not be blank, at most 128 bytes, and contain no control, bidi or
  invisible formatting characters; a configuration with such a name fails to
  load.

<a id="message-text-actions"></a>

## Adopting Quote and Explain on marked text

Added by [#1566](https://github.com/EratoLab/erato/pull/1566). Both actions are off by default.

### What it does

Marking text in a finished chat message shows a small toolbar. **Quote**
appends the text to the composer as a markdown quote. **Explain** (assistant
messages only) opens a small chat at the passage, streamed from a stateless
endpoint and never saved; it is disabled above 4,000 marked characters, and
reading a message you cannot access returns 404.

### Before (0.8.0)

```toml
# No [message_text_actions] table; marking text shows no toolbar.
```

### After

```toml
[message_text_actions]
quote_enabled = true

[message_text_actions.explain]
enabled = true
chat_provider_id = "my-provider"   # required when enabled
# prompt can be a string or an object, as for the prompt optimizer:
# prompt = "Explain the marked passage briefly."
# prompt = { source = "langfuse", prompt_name = "message-explain", label = "production", fallback = "..." }
```

### Notes

- The provider named by `explain.chat_provider_id` receives the marked text and
  the message it comes from (security relevance: medium), so pick one that is
  approved for that content.
- A built-in instruction applies when `prompt` is omitted.
- Component kits get the toolbar without a rebuild.

<a id="tool-labels"></a>

## Adopting model-assisted tool-call labels (alpha)

Added by [#1498](https://github.com/EratoLab/erato/pull/1498) and
[#1499](https://github.com/EratoLab/erato/pull/1499). **Alpha**: may change or be
removed without a deprecation period. Off by default.

### What it does

Generic rules label every MCP call on approval cards and trace rows. Where the
rules are unsure what a call does, a configured chat provider can pick the verb
and object kind from a skeleton of the call. The label replaces the rules label
on the running row or the parked approval card; the card never waits for it
(10 s timeout, no retry), and a per-user cache avoids repeat requests.

### Before (0.8.0)

```toml
# No [tool_labels] table.
```

### After

```toml
[tool_labels]
enabled = true
chat_provider_id = "my-provider"   # required when enabled
allow_other_provider = false       # default: only label turns that already run on this provider
```

### Notes

- The skeleton of the call (member names, text lengths and the verb fields and
  values the tool's schema lists, not free text) goes to this provider, only for
  users whose model permissions allow it. `allow_other_provider = true` also
  labels turns running on another provider and has high security relevance.
- The label requests are traced like compaction and not counted against user
  budgets.

<a id="read-aloud"></a>

## Adopting Read aloud (alpha)

Added by [#1564](https://github.com/EratoLab/erato/pull/1564). **Alpha**: may change or be
removed without a deprecation period. Off by default.

### What it does

Finished assistant messages get a speaker button; one click reads the answer
aloud with the configured voice and the button stops playback. It is
independent of the conversational audio modes and stores nothing. The endpoint
returns 404 while the feature is off and 409 while the message is still
generating.

### Before (0.8.0)

```toml
# No [audio_read_aloud] table; speech providers were used only by conversational audio.
```

### After

```toml
[audio_read_aloud]
enabled = true
speech_provider = "assistant_voice"   # an ID from speech_providers.provider; required when enabled
```

### Notes

- Reuses the `speech_providers.provider` registry introduced in 0.8.0; see the
  [0.7.0 to 0.8.0 guide](0_7_0_to_0_8_0.md#speech-providers).
- Component kits that draw the host's message controls get the button without
  a rebuild.
