<a id="outlook-session-mode"></a>

## Outlook add-in default session mode changed

Added by [#1402](https://github.com/EratoLab/erato/pull/1402). Default behavior change, overridable.

### What changed

Users without a saved Outlook add-in session preference now default to **Ask
on conversation change** instead of **Resume last chat** when switching
between emails. Any user's own saved choice, and any deployment that already
sets this key explicitly, are unaffected — only the out-of-the-box default
changes. Replies/forwards continue to stay in the current chat regardless of
this setting.

### Before (0.7.0 default)

```toml
[integrations.ms_office.addin.default_settings]
mode = "resume"
```

### After (0.8.0 default — or pin back explicitly)

```toml
[integrations.ms_office.addin.default_settings]
mode = "ask"   # set to "resume" explicitly to keep the old default
```

### Action required

If your deployment relies on the implicit old default, set `mode = "resume"`
explicitly before upgrading — otherwise every user without a saved preference
silently gets different behavior.

<a id="exchange-se-manifest"></a>

## Update the Outlook add-in manifest for Exchange SE

### What changed

The Exchange SE Outlook add-in manifest now includes a nested `VersionOverridesV1_1`
block with `SupportsPinning`, `SupportsSharedFolders`, and
`SupportsNoItemContext` declarations. The Exchange Server variant uses Mailbox
1.5 requirements at all three manifest levels. Existing installations need
the updated manifest to receive these declarations; upgrading Erato alone
does not update the manifest installed in Exchange.

### Action required

After upgrading to 0.8.0, download the newly generated manifest from
`/office-addin/manifest-exchange-server.xml` on your Erato deployment, or select
**Exchange Server SE / Exchange Server 2016** in the Office add-in setup page.
Update the installed add-in manifest through the Exchange admin center or
Exchange Management Shell. Use the Exchange Server variant for this deployment.

Verify installation, task-pane pinning, and switching between emails on your
target Exchange SE/Outlook combination, since client support for these
declarations varies.

<a id="interrupted-parts-index"></a>

## Interrupted-parts cleanup index (one-time blocking migration)

Added by [#1397](https://github.com/EratoLab/erato/pull/1397). Not a
configuration change — an operational note about this release's database
migration.

### What changed

The periodic sweep that cancels interrupted/stale in-progress tool-call
message parts (for example, after a crash or restart mid-generation)
previously scanned the `messages` table's JSON content with a query the
planner could not reliably use an index for at scale. This release adds a new
partial index, `idx_messages_interrupted_parts`, so the sweep can use it
instead of scanning full message history.

### Action required

The new index is built by a **non-concurrent** `CREATE INDEX`
(`backend/sqitch/deploy/0059_add_interrupted_parts_index.sql`), which scans the
whole `messages` table once and **blocks writes to it while building**. On a
large installation, this can be a noticeable pause. Schedule the deployment
that includes this migration in a maintenance window, the same way you would
for any other blocking schema change.

## Adopting text-to-speech ("Audio-back") responses

Added by [#1431](https://github.com/EratoLab/erato/pull/1431),
[#1437](https://github.com/EratoLab/erato/pull/1437),
[#1438](https://github.com/EratoLab/erato/pull/1438),
[#1440](https://github.com/EratoLab/erato/pull/1440),
[#1442](https://github.com/EratoLab/erato/pull/1442),
[#1444](https://github.com/EratoLab/erato/pull/1444). Disabled by default.

### What it does

In conversational audio mode, the assistant's reply can now also be spoken
aloud, streamed sentence-by-sentence as it's generated instead of waiting for
the full reply. Speech output is configured independently of chat/
transcription via a named provider registry. The spoken audio is saved as a
WAV file attached to the assistant message, so replaying it after a reload
does not call the provider again. Code blocks and image descriptions are
omitted from spoken output; a synthesis failure leaves the text response
available.

### Before (0.7.0 default — feature inert)

```toml
# No [speech_providers] table: conversational mode is text/transcription only,
# no spoken reply is generated.
```

### After — enable Audio-back with an OpenAI TTS voice

```toml
[speech_providers.provider.assistant_voice]
provider_kind = "openai"              # also: openai_realtime, gemini, gemini_live
model_name = "gpt-4o-mini-tts"
voice = "alloy"
api_key = "your-api-key"

[audio_conversational]
# ... existing conversational-mode keys (enabled, chat_provider_id, etc.) unchanged
speech_provider = "assistant_voice"   # new sibling key
```

### After — a self-hosted TTS server (`audio_cpp`)

```toml
[speech_providers.provider.local_voice]
provider_kind = "audio_cpp"
model_name = "<model-name>"
voice = "<voice-id>"
base_url = "http://localhost:8080/v1"  # required for audio_cpp
sample_rate = 24000                    # native PCM rate; default 24000
```

### After — Gemini Live, over the regional WebSocket transport

```toml
[speech_providers.provider.live_voice]
provider_kind = "gemini_live"
model_name = "gemini-3.8-live"
voice = "Kore"
api_key = "your-api-key"   # or access_token for OAuth; exactly one of the two
project_id = "your-project" # required unless using an Express-mode api_key
location = "eu"              # routes to the EU multi-region endpoint
```

### Notes

- `provider_kind` must be `openai`, `openai_realtime`, `gemini`, or
  `gemini_live`; `sample_rate` must be 8000–192000; `audio_cpp` requires
  `base_url`; `gemini`/`gemini_live` require `api_key` or `access_token` (not
  both), and `project_id` unless using an Express-mode `api_key`.
- `audio_conversational.speech_provider` only applies to conversational mode;
  other audio input modes don't generate speech.
- Realtime and Live models are instructed to read the supplied text verbatim,
  but being generative, their spoken output may still deviate from the input
  text.
- Streamed output is 16-bit little-endian mono PCM; speech input is capped at
  1 MiB per assistant message — exceeding it stops synthesis for that message
  and discards the incomplete replay, while the text response is preserved.
- New database column: `file_uploads.audio_synthesis` (JSONB, nullable;
  sqitch migration `0060_add_audio_synthesis`).

<a id="provider-replacement"></a>

## Adopting provider archiving and replacement

Added by [#1438](https://github.com/EratoLab/erato/pull/1438). Disabled by
default (no existing provider is archived).

### What it does

Lets you retire a chat or speech provider ID while keeping old references —
existing chat history, assistants, permission rules, and historical cost
reporting — working. An archived entry keeps its metadata (for example,
historical token prices and display name) without being selectable for new
use or requiring live inference credentials. File storage providers are
explicitly excluded from this mechanism.

### Before (0.7.0 default — no archiving)

```toml
[chat_providers.providers.old]
provider_kind = "openai"
model_name = "old-model"
```

### After — archive a retired provider and redirect to its successor

```toml
[chat_providers]
priority_order = ["new"]
replacement_providers = [{ old = "old", new = "new" }]

[chat_providers.providers.old]
archived = true
model_name = "old-model"
[chat_providers.providers.old.model_capabilities]
cost_input_tokens_per_1m = 1.0
cost_output_tokens_per_1m = 2.0

[chat_providers.providers.new]
provider_kind = "openai"
model_name = "new-model"
```

The same shape applies under `[speech_providers]` /
`speech_providers.provider.<id>`.

### Notes

- Validation panics at startup on an invalid/duplicate replacement source, a
  non-archived old entry still listed as a replacement source, or a chain
  that doesn't resolve to an active (non-archived) provider.
- Chat-model permission rules granted for the old ID also grant access to the
  replacement.

## Adopting SharePoint cross-drive filename search

Added by [#1432](https://github.com/EratoLab/erato/pull/1432),
[#1445](https://github.com/EratoLab/erato/pull/1445). **Enabled by default**
if `[integrations.sharepoint]` is already enabled — review the permission
requirement below before upgrading.

### What it does

The upload picker's cloud-file search can search filenames (and drive/site
names) across every configured, delegated-access SharePoint/OneDrive source
in one request, instead of only browsing one drive at a time. Results cap at
100 files across up to 10 pages per drive, within a 20-second overall Graph
budget; a degraded/partial result is flagged rather than claimed complete.

### Before (0.7.0 — drive/site-name browsing only)

```toml
[integrations.sharepoint]
enabled = true
```

### After (0.8.0 default — cross-drive filename search enabled)

```toml
[integrations.sharepoint]
enabled = true
file_search_enabled = true   # default; set false to restore 0.7.0 behavior
```

### Action required for narrower Graph grants

Cross-drive filename search needs the `Files.Read.All` or `Sites.Read.All`
Microsoft Graph permission. If your deployment's forwarded Graph token only
grants `Files.Read`, set `file_search_enabled = false` — otherwise cross-drive
search will fail or degrade for your users. Drive/site-name search
(`all_drives_sources`) is unaffected either way.

## Adopting desktop sidecar Intune distribution and multi-environment installs

Added by [#1422](https://github.com/EratoLab/erato/pull/1422). Intune packages
are available when desktop-sidecar distribution is enabled and includes a
Windows MSI. Multi-environment overrides are optional.

### What it does

Adds Microsoft Intune (`.intunewin`) packaging for the desktop sidecar's
Windows distribution, and lets multiple sidecar environments (for example,
staging and production) be installed side-by-side on one machine without
colliding, each with its own launch URI scheme and its own MSI product/
upgrade codes.

### Adopting Intune packages for sidecar deployment

Enable desktop-sidecar distribution if it is not already enabled, and ensure
the distribution directory contains its `manifest.json` and the Windows MSI
referenced by that manifest:

```toml
[desktop_sidecar.distribution]
enabled = true
directory = "/app/desktop-sidecar-artifacts"
```

1. After upgrading Erato, open the desktop-sidecar download page and download
   the **Microsoft Intune package** (`.intunewin`) for the target Windows
   architecture. Erato generates it from the MSI with your deployment's
   organization bootstrap, including origins, installation identity, and TLS
   settings. No separate packaging step or extra distribution artifact is needed.
2. Upload the package to Microsoft Intune as a **Windows app (Win32)**. Review
   the install/uninstall commands and MSI product-code detection using the
   metadata from the uploaded package.
3. Assign the app to the intended deployment group. Verify installation and
   connection to your Erato deployment on a pilot device before rolling it out
   broadly.

For a packaged MSI named `erato-desktop-sidecar-windows-x86_64.msi`, use this
silent install command (adjust the filename to match your package):

```powershell
msiexec /i "erato-desktop-sidecar-windows-x86_64.msi" /qn
```

For uninstall, use `msiexec /x "{ProductCode}" /qn` with the product code from
the uploaded package. When deploying a new release, refresh the package and
review its detection metadata rather than reusing an older release's product
code. Intune packaging does not require setting `launch_suffix`, `product_code`,
or `upgrade_code`; the overrides below are for separate environments.

### Before (0.7.0 default — single environment only)

```toml
[desktop_sidecar]
# launch_suffix, product_code, upgrade_code all unset: one environment only,
# codes derived from the template plus directory_suffix.
```

### After — a second, side-by-side environment

```toml
[desktop_sidecar]
launch_suffix = "-staging"             # appended to the Windows launch URI scheme
product_code = "11111111-1111-1111-1111-111111111111"  # keep stable across downloads of this environment
upgrade_code = "22222222-2222-2222-2222-222222222222"   # keep stable across releases of this environment
```

### Notes

- `launch_suffix` accepts up to 64 ASCII letters/digits/`-./+`.
- Keep `product_code` stable across repeated downloads of the *same*
  environment, and `upgrade_code` stable across releases *within* one
  environment, to get correct upgrade-vs-side-by-side MSI behavior.

<a id="sidecar-autopin"></a>

## Adopting desktop sidecar Outlook add-in auto-pinning

Added by [#1430](https://github.com/EratoLab/erato/pull/1430). Disabled by
default.

### What it does

Lets a deployment opt in to having the desktop sidecar automatically pin the
Erato Outlook add-in (and optionally its task panes, on classic Outlook for
Windows), instead of requiring each sidecar to be configured individually or
leaving pinning to users.

### Before (0.7.0 default — no auto-pinning)

```toml
[desktop_sidecar.organization_configuration]
# outlook_addin_autopin, outlook_addin_autopin_panes, outlook_addin_id all unset.
```

### After — auto-pin the add-in and its task panes

```toml
[desktop_sidecar.organization_configuration]
outlook_addin_autopin = true
outlook_addin_autopin_panes = true   # classic Outlook for Windows only
# outlook_addin_id left unset: filled automatically from
# integrations.ms_office.addin.addin_id when the Office add-in is enabled.
```

### Notes

- Removing `outlook_addin_autopin` or setting it `false` stops further
  pinning; existing pins are left in place (not un-pinned).

<a id="delegated-task-model"></a>

## Adopting per-facet delegated-task model selection

Added by [#1407](https://github.com/EratoLab/erato/pull/1407). Default-unset;
no behavior change until configured.

### What it does

A delegated task now resolves and reports an explicit model at launch — the
task facet's configured model, else the parent turn's model — instead of
silently inheriting whatever the origin assistant's default happened to be.
Configuring this just makes an existing implicit choice explicit and visible
on the task's result card; it does not change behavior if left unset.

### Before (0.7.0 default — implicit inheritance)

```toml
[facets.facets.research_task]
# child_chat_provider / child_chat_providers unset: inherits the parent's model
```

### After — pin a task facet to a specific model, with fallbacks

```toml
[facets.facets.research_task]
child_chat_provider = "gpt-5-mini"          # single preferred model
child_chat_providers = ["gpt-5-mini", "gpt-5"]  # or a priority list of fallbacks
```

### Notes

- Both keys are validated at load time against the task-usable chat-provider
  list; an unknown or non-chat provider id panics at startup.
- Also available on action-facet delegation-override blocks.
