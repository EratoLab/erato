# PR #889: Add MCP server allow/exclude tool filtering

- PR: https://github.com/EratoLab/erato/pull/889
- Status: pending
- Category: Features and enhancements
- Theme: MCP controls

## Summary

Adds per-MCP-server tool filtering via two new config keys on
`McpServerConfig` (`backend/erato/src/config.rs`):
`allow_tools` (optional list of wildcard patterns; when omitted, all tools
are allowed — equivalent to `["*"]`; an explicitly empty list allows no
tools) and `exclude_tools` (list of wildcard patterns removed from the
allowed set after `allow_tools` is applied, defaulting to `[]`). Matching
is implemented in `backend/erato/src/services/mcp_session_manager.rs`
(`wildcard_matches`, `is_tool_allowed_by_server_config`,
`filter_tools_by_server_config`): `*` matches any sequence of characters
against the unqualified MCP tool name, patterns match the full tool name
(not a substring), and the allowlist is applied before the exclude-list,
both before existing request-level assistant/facet/permission filtering
(per `site/content/docs/configuration.mdx`). Backed by unit tests covering
wildcard matching, the omitted-vs-wildcard-vs-empty allowlist semantics,
and allow-then-exclude ordering.

## Compatibility and configuration

New optional per-server keys:
```toml
[mcp_servers.<server-id>]
allow_tools = ["get_page", "list_*"]   # default: omitted (all tools allowed)
exclude_tools = ["get_secret_*"]        # default: []
```
Both default to preserving existing behavior (all tools from a configured
MCP server remain exposed) unless explicitly set. No migration. This
narrows what a deployment can expose from a given MCP server without
needing changes to the MCP server itself or to existing
assistant/facet/permission-level tool filtering, which continues to apply
on top of this.
