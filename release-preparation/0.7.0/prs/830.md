# PR #830: Upgrade from kreuzberg to xberg

- PR: https://github.com/EratoLab/erato/pull/830
- Status: pending (diff reviewed)
- Category: Dependency changes
- Theme: None

## Summary

Replaces the `kreuzberg` Rust crate (`5.0.0-rc.18`) with its successor
`xberg` (`1.0.0-rc.29`) as the document text-extraction backend
(`backend/erato/Cargo.toml`), and renames the internal
`KreuzbergProcessor` struct to `XbergProcessor`
(`backend/erato/src/services/file_processor/mod.rs`) along with doc
comments in `backend/erato/src/models/file_capability.rs` (e.g. "supported
by Kreuzberg" → "supported by Xberg"). The `file_processor.processor`
config value itself remains named `"kreuzberg"` (per
`backend/erato.template.toml`'s example — only the underlying crate
changed, not the user-facing config string, and that config value's
default was already `"kreuzberg"` from an earlier release since
`parser-core` had already been deprecated before this PR). The
`html-to-markdown-rs` dependency (used alongside for HTML-to-Markdown
conversion) is bumped from `3.6.11` to `3.8.3`, and the private
`[patch.crates-io]` override for `html-to-markdown-rs` pointing at a fork
is removed from `backend/Cargo.toml` (implying the needed fix has landed
upstream). `backend/deny.toml`'s `Elastic-2.0`/`kreuzberg` license
exception is removed (the `# TODO: Update to xberg, which is MIT` from
#797 is now resolved). Several extraction snapshot tests changed output
(`file_processor_snapshots__*.snap`), consistent with the new
library producing slightly different extracted text/formatting for PDFs
and EML threads; not independently verified whether any of these represent
extraction quality regressions or improvements.

## Compatibility and configuration

No configuration keys renamed or removed; `file_processor.processor =
"kreuzberg"` continues to work and remains the default, now backed by the
`xberg` crate. No migration. Because `xberg` is MIT-licensed (vs.
`kreuzberg`'s `Elastic-2.0`), this also simplifies license compliance.
Extracted text/markdown output for PDFs, Office documents, and emails may
differ slightly from the previous library version (per the changed
snapshot tests), which could be user-visible in file-preview/summary
content derived from extracted text, though no specific regression was
identified in this diff.
