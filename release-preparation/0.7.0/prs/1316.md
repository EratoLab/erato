# PR #1316: Add indexed range and search coverage to the sidecar protocol

- PR: https://github.com/EratoLab/erato/pull/1316
- Status: pending
- Category: Features and enhancements
- Theme: Desktop Sidecar

## Summary

Adds a precisely-specified "indexed range" concept to the desktop
sidecar protocol, replacing the older depth-based
(`fullyIndexedSince`/`processedSince`) reporting with a from/through
range that states which period of a source's documents search can
actually be relied on for — the protocol part of ERDSCAR-28/25, with the
sidecar's own implementation tracked separately (ERDSCAR-29, linked
upstream repo PRs). Confirmed from the full `SPEC.md` diff (90 lines,
read in full):

- Each `discovery[]` entry on `indexing.status.v1` (and the start/stop
  results) gains an optional `indexedRange` with `from`/`through`
  (exclusive/inclusive per precise rules spelled out in the spec),
  `pendingNewer`/`olderPending` counts of unprocessed documents, an
  `unsearchable` count of terminal-but-in-range documents, an `undated`
  count, and an `unavailableReason` (e.g. `not_enumerated`,
  `no_searchable_documents`, `source_disabled`,
  `index_not_initialized`) for when no claim can be made yet — `from` is
  null exactly when `unavailableReason` is set.
- A document's date basis is explicit per source type
  (`emailReceivedAtThenSentAt` for Outlook, `teamsMessageTimestamp` for
  Teams), and `inventory` distinguishes a complete local-store
  enumeration (`localStore`, Outlook) from an inherently partial
  cache-observation view (`cacheObservations`, Teams) — the spec warns
  clients that under `cacheObservations`, older documents "may never
  have reached the device."
- `search.query.v1` results gain an optional `coverage` object (sources'
  identity + the same range values, as of `coverage.sampledAt`) and a
  `limitReached` boolean; `coverage.basis` distinguishes an `index`-based
  text search (only searchable documents) from a `catalog`-based
  empty-text listing (reads the full discovered inventory, so can return
  documents outside the stated range). Empty-text listing order also
  changes here: explicitly newest-first by date (undated last,
  `documentId` tie-break), up from an unspecified/unordered listing.
- `indexing.status.v1`/benchmark results also gain an optional
  `missingFromLocalCacheDocuments` count (explicitly "not failed
  documents") for content known to exist but not present in the local
  cache.
- All of this is additive and optional: "older sidecars omit it" is
  stated repeatedly, and the diff only ever adds fields/fixtures, never
  tightens a schema's `required` list (not independently re-verified
  against every one of the 4 touched `.schema.json` files' JSON content,
  given their size).

## Compatibility and configuration

Additive protocol extension; older sidecars that omit `indexedRange`/
`coverage` continue to work exactly as before (the spec explicitly
instructs clients not to present the old depth fields from a server that
lacks `indexedRange`, implying client-side feature detection, but that
consuming logic itself ships in the dependent PRs #1320/#1322/#1324, not
here). No backend config keys in this PR. No migration.
