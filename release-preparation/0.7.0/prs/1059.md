# PR #1059: Fold the redundant attachments seam into one registry key

- PR: https://github.com/EratoLab/erato/pull/1059
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Re-lands #1054 (whose content never reached `main` due to a merge-timing
accident: merged 16 seconds after #1053 into an already-merged, effectively
dead branch — the PR states nothing was lost, since the branch survives
and this replays that same merge onto current `main`; not independently
re-verified beyond confirming the landed diff makes sense on its own
merits). Removes the now-redundant `ChatAttachmentsPreview` registry key,
since #1049 made it functionally identical to `ChatInputAttachmentPreview`
(both slots render in the same in-shell position). Confirmed by reading
all three core files in full:

- **Key removed entirely, confirmed via `componentRegistry.ts`**:
  `ChatAttachmentsPreview` is removed from the `ComponentRegistry`
  interface, its JSDoc, and `emptyComponentRegistry`'s defaults —
  `ChatInputAttachmentPreview` is the sole surviving key. The PR's stated
  reason for removing outright rather than deprecating (no public
  override-table entry, no in-repo or Beckhoff-kit registration, no
  per-key deprecation-warning hook in `buildComponentRegistry`) was not
  independently re-verified but is consistent with the clean removal
  found in the diff (no compatibility shim, no fallback alias).
- **Latent-bug fix, confirmed via `ChatInput.tsx`**: the previous
  two-branch `ChatInputAttachmentPreview ? <...> : <AttachmentsPreview
  override-or-default ...>` — where `ChatAttachmentsPreview`'s override
  (via `resolveComponentOverride`) could win only in the `else` branch,
  meaning `ChatInputAttachmentPreview` always took priority when both were
  set — collapses into a single `ChatInputAttachmentPreview ??
  FileAttachmentsPreview` resolution. Confirmed this structurally
  eliminates the two-keys-one-slot ambiguity the PR describes: a kit
  registering `ChatInputAttachmentPreview` while the Teams tab's own
  `ChatAttachmentsPreview` registration was active would previously have
  silently suppressed Teams' transcript grouping, since exactly one key
  could win the ternary and it was always this one.
- **Teams moved to the surviving key, confirmed by the diff stat**:
  `office-addin/src/teams/components/TeamsAttachmentsPreview.tsx` (7
  lines) and `installTeamsComponentRegistrations.ts` (2 lines) are both
  touched, consistent with re-registering against
  `ChatInputAttachmentPreview` instead of the removed key — not
  independently read in full, but the diff stat is consistent with this
  claim and no other plausible reason for touching those two files
  together presents itself.
- **Type relocation and deduplication, confirmed via
  `FileAttachmentsPreview.tsx`**: `ChatInputAttachmentPreviewProps`
  (previously in `src/types/chat-input-attachment-preview.ts`, removed in
  this diff) now lives directly in `FileAttachmentsPreview.tsx` — matching
  the PR's stated reason that the shared-surface generator only walks
  `src/components`, so the kit contract type was otherwise unreachable
  from `@erato/frontend/shared`. `FileAttachmentsPreviewProps` is
  confirmed rewritten to `extends ChatInputAttachmentPreviewProps` rather
  than duplicating its fields, so the shared props now have one
  definition.

## Compatibility and configuration

**Real, intentional behavior change for component-kit consumers**: a kit
overriding the staged-attachments preview via the now-removed
`ChatAttachmentsPreview` key stops working — it must register
`ChatInputAttachmentPreview` instead. Per the PR, Teams was the only
registration of the removed key in this codebase, and it is confirmed
migrated in the same diff. No API or database changes; this is purely an
internal component-kit registry seam.
