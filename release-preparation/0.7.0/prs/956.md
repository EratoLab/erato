# PR #956: Cite Teams transcript messages by ordinal

- PR: https://github.com/EratoLab/erato/pull/956
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Substantial token-efficiency rework of the Teams transcript format
(#939/#940/#948/#949/#950). Confirmed by reading `buildTeamsTranscriptFile.ts`
in full: message headings switch from
`**Sarah Neumann** — 09:14 (edited) · <permalink or raw id>` to a compact
`[3] Sarah Neumann (09:14, edited):` form, where the bracketed ordinal is
now the message's entire citation address — permalinks, raw Teams message
ids, and the previously-emitted "Message links: ..." explanatory template
line (needed to let a model reconstruct a link from a bare id) are all
removed from the transcript body entirely, since nothing downstream reads
them anymore (per the header comment, "everything that needs them reads
the parsed sections instead"). Confirmed the ordinal counter is global
across the whole transcript (not reset per section), which matters
because a single attached selection can span several different
conversations and a citation must unambiguously name exactly one message
across all of them.

Also confirmed, via the `teamsTranscriptAssets.ts` diff, a related
token-waste fix: an attached file's in-text marker previously named the
file **twice** — `[attachment: {original Teams name} — attached as
{uploaded name}]` — even though the uploaded filename already ends with a
slugified version of the original name; it's now stamped just once as
`[attachment: {uploaded name}]` (and similarly `[image: {uploaded name}]`
rather than `[image: attached as {uploaded name}]`). The original
Teams-side name is still retained separately for the "too large to
attach" disclosure case, where there is no uploaded name to fall back on.
A new `uploadedAssetNames()` helper extracts the uploaded filenames from
rendered marker text via a regex anchored on the `teams-img-`/`teams-file-`
prefixes those uploads always carry — confirmed this specifically avoids
misreading a *bare*, never-fetched marker (which still carries its
original Teams-side name, not an uploaded one) as if it referenced an
upload.

The PR's own token-count measurements (not independently reproduced,
since they require an actual tokenizer run): a 200-message whole-chat
transcript drops from 5,964 to 4,282 tokens (-28%), and a 25-message
hand-picked selection from 2,467 to 592 tokens (-76%).

## Compatibility and configuration

None. Pure frontend format change; no configuration or API changes.
Behavior change: an attached Teams transcript now cites messages by a
compact numeric ordinal instead of embedding raw Teams message ids or
permalinks, and files/images are named once instead of twice in their
markers — this changes the exact text the model receives for a Teams
transcript attachment, though the underlying information (who said what,
when, with what attachments) is preserved.
