# PR #886: Integrate assistants hub and existing assistants pages

- PR: https://github.com/EratoLab/erato/pull/886
- Status: pending
- Category: Features and enhancements
- Theme: Assistant Hub and assistant sharing

## Summary

Continues the page merge started in #884 (which split
`AssistantHubPage`/`AssistantsListPage` into a single view-parameterized
`AssistantsPage`), substantially reworking `frontend/src/pages/AssistantsPage.tsx`
(net +788/-… lines) and `frontend/src/pages/assistantHubUtils.tsx` (+344
lines) to actually share logic/UI between the "My Assistants" and
"Assistant Hub" views rather than just routing to the same component
shell. Several backend changes support this:
- `GET /assistants` gains a new `include_archived` query parameter
  (default `false`) on `ListAssistantsQuery`
  (`backend/erato/src/server/api/v1beta/assistants.rs`), plumbed through
  `get_user_assistants` (`backend/erato/src/models/assistant.rs`), which
  can now optionally include archived assistants in both the
  owned-by-user and shared-with-user queries (previously archived
  assistants were always excluded).
- A new `backend/erato/src/services/ms_graph.rs` (`MsGraphService`) calls
  the Microsoft Graph API to resolve a user's display name from their
  identity subject (falling back to email). It is wired into
  `backend/erato/src/server/api/v1beta/share_links.rs`'s
  `resolve_share_link`: when `integrations.experimental_entra_id.enabled`
  is true and a forwarded access token is available, a shared chat's
  owner is now shown by display name (resolved via Graph) instead of just
  their email address; without a forwarded token or with Entra ID
  integration disabled, it falls back to the previous email-based
  behavior.
- `backend/erato/src/server/api/v1beta/assistant_hub.rs` shrank by ~120
  net lines, consistent with logic being consolidated/shared rather than
  duplicated between the hub and regular assistants endpoints (not
  independently verified line-by-line).

## Compatibility and configuration

No new top-level configuration keys; `include_archived` is a new
API-request parameter, not a server config flag, defaulting to `false` (no
behavior change for existing API callers that don't pass it). The MS Graph
display-name lookup only activates under the pre-existing
`integrations.experimental_entra_id.enabled` flag and requires a forwarded
user access token; when unavailable it degrades gracefully to the
pre-existing email-based owner display. No migration.
