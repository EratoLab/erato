# PR #1361: ERMAIN-854: Reserve validated submission attempts beyond tool budgets (#1361)

- PR: https://github.com/EratoLab/erato/pull/1361
- Status: pending
- Category: Stability improvements
- Theme: Word add-in / Client tool submissions

## Summary

A rejected validated client-tool submission (schema/parser failure, mixed
batch, or a prose reply with no progress) could previously end silently
after a prose reply, or consume the model's ordinary tool-call budget for
the turn, leaving less room for legitimate retries. This reserves a
separate, configurable allowance specifically for a server-owned editing
step's submission attempts, independent of the generation's normal tool
budgets, and charges it *before* the ordinary budget and task-approval
gates run.

Confirmed via the `config.rs` diff: `ClientToolSubmissionConfig.max_attempts`
(1–10, default 3, unchanged default) now covers the initial submission plus
schema/client failures and no-progress replies, explicitly documented as
"independent of ordinary tool budgets." Two new fields are added:
`recovery_read_tools` (a list of already-authorized, already-configured
non-submission client tool qualified names — validated at startup to
actually exist and not themselves be submission tools) lets a correction
step re-read current state via those tools without granting new tool
access, and `max_recovery_reads` (0–128, default 32) caps how many such
recovery reads (including pagination) one editing step may make. Per the
PR description (not independently re-verified beyond the config surface):
duplicate results, reconnects, and approval continuations all preserve
these counts rather than resetting them; "Generate answer now" and "Stop"
record a typed unresolved outcome instead of ending silently; and a
shared answer-area alert now persists these outcomes through completion
and page reload, clearing only on acceptance.

Per the PR body: Word's own private (not-yet-public) configuration moves
its own `max_attempts` override from 3 to 5 as a consequence of this PR
landing (initial submission plus four corrections) — this is a downstream
config change in Word-specific deployment config, not a change to this
PR's own defaults.

## Compatibility and configuration

Existing key's semantics clarified, two new optional keys added, defaults
unchanged for existing deployments:

```toml
[client_tools.tools.<id>.submission]
max_attempts = 3                       # unchanged default; now independent of ordinary tool budgets
recovery_read_tools = ["my_read_tool"] # optional; must name existing non-submission client tools
max_recovery_reads = 32                 # 0-128, default 32
```

No migration. `recovery_read_tools` entries are validated at startup to
reference a configured, non-submission client tool by its qualified name;
an unknown or submission-type name panics at startup.

Proposed category: Stability improvements, grouped with the Word add-in /
client-tool-submission theme (#1352-#1354, #1362-#1366). Worth a mention if
