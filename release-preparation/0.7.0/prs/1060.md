# PR #1060: Fail CI when the kit shared surface drifts

- PR: https://github.com/EratoLab/erato/pull/1060
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

CI tooling fix, companion to #1055. `component-registry.generated.ts`
(the `@erato/frontend/shared` surface) drifted three times in one day per
the PR (`Tooltip` leaving when #1046 dropped an import; the new diagonal
icons and `ExpandMediaButton` from #1057 never arriving) because it's
only regenerated as a side effect of `build:app`/`build:lib`, not checked
independently. Confirmed by reading the complete generator script diff:

- **New `--check` mode, confirmed exactly**: mirrors the existing
  `generate-served-routes.mjs --check` pattern already run one CI step
  above this one. When the freshly generated source differs from the
  committed file, `checkMode` prints `✖ <path> is out of date.`, a drift
  report, and `Run \`pnpm generate:component-registry-shared\` to
  update.` to stderr, then exits with code 1; when up to date, it prints
  `✓ <path> is up-to-date` and exits 0.
- **Removals-first diagnostic, confirmed exactly**: `reportDrift` diffs
  the exported-name sets of the current vs. next generated source
  (matching `export {...}`/`export type {...}` statement names via
  regex), and orders its output `removed:` before `added:` — matching the
  PR's stated design that a removal is the one that silently breaks a kit
  at load time, so it should be the first thing the reader sees. A
  no-name-change drift (only ordering/paths moved) gets its own message
  rather than an empty diff.
- **CI wiring, confirmed exactly**: `docker-build.yml` gains a new
  `"Component-kit shared surface is up-to-date"` step running `pnpm run
  check:component-registry-shared`, placed immediately after the existing
  `generate-served-routes.mjs --check` step and sharing its `if: success()
  || failure()` non-fail-fast condition — confirmed the new `package.json`
  script is `node scripts/generate-component-registry-shared-exports.mjs
  --check`, exactly matching the existing `check:served-routes` script's
  naming/invocation pattern.

## Compatibility and configuration

None for runtime behavior. Pure CI/tooling addition: a new required CI
check that fails the build if `component-registry.generated.ts` is
committed out of date relative to the current import graph. No effect on
a deployed build, since both `build:app`/`build:lib` already regenerate
the file unconditionally before use — per the PR, the risk this closes is
a stale committed file silently disagreeing with local type-checking and
a removed export never showing up as a visible diff line.
