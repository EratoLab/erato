## Summary

Re-lands the "Add support for stateless MCP" feature that shipped as
#1369, was reverted as #1373, and is re-introduced here — on the same
source branch — together with "Fix compatibility issues with older MCP
protocol specs" (the PR's own title). **This is the PR that actually
ships stateless MCP in the final 0.7.0 state**; #1369 and #1373 cancel
out and need no separate mention. Confirmed via the full diff against
docs and config:

- **New per-server `protocol_mode` config key, confirmed exactly**:
  `mcp_servers.<id>.protocol_mode` (`McpProtocolMode` enum: `auto`
  (default), `legacy`, `stateless`). `auto` probes for the stateless MCP
  `2026-07-28` protocol and falls back to legacy initialization for older
  servers; authentication failures, rate limits, and modern-protocol
  errors do **not** trigger a downgrade (per the new docs section,
  `site/content/docs/features/mcp_servers.mdx`, "Protocol selection and
  caching"). Startup validation rejects `protocol_mode = "stateless"`
  combined with `transport_type = "sse"` (confirmed in `config.rs`:
  stateless requires `streamable_http`).
- **Caching/session-lifecycle differences, per the new docs, not
  independently re-verified against the 344-line `mcp_session_manager.rs`
  diff**: legacy servers keep per-chat/per-auth-context cached sessions as
  before; stateless servers keep HTTP connection pools and tool metadata
  with no idle sessions or notification streams, honor the server's own
  tool-list `ttlMs` (capped at 24h, default 30s if omitted, 0 disables
  reuse), and share explicitly-public tool lists across auth contexts
  while keeping private lists credential-specific. User permissions, tool
  decisions and chat restrictions are stated to be applied independently
  of this cache.
- Substantial new test coverage: `mcp_stateless.rs` (637 lines) and
  `mcp_stateless_tests.rs` (830 lines), plus a new `erato_config/tests/
  mcp_protocol.rs` (29 lines) and new routes on the development
  mock-MCP-server (`/mcp/legacy/file`, `/mcp/stateless/file`,
  `/mcp/dual/file` and auth/progress/file-output/deep-research
  equivalents) specifically to exercise both protocol paths.
- Per the PR (not independently re-verified): the detailed caching
  behavior claims in the new docs section beyond what's summarized above
  (e.g. the exact drain-before-first-result progress-notification
  handling, cancellation semantics, and per-credential backoff bounds).

## Compatibility and configuration

**Additive, non-breaking, on by default for new `streamable_http` servers
via `protocol_mode = "auto"`** — existing `sse` servers and existing
`streamable_http` servers with no `protocol_mode` set are unaffected
(auto-probing can only add capability, and failures merely fall back to
the prior legacy behavior, per the docs). The only hard restriction is
that `protocol_mode = "stateless"` cannot be combined with
`transport_type = "sse"`, which fails startup validation. No database
migration.
