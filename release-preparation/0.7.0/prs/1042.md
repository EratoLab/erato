# PR #1042: Route local admin panel through auth proxies

- PR: https://github.com/EratoLab/erato/pull/1042
- Status: pending (diff reviewed)
- Category: Other
- Theme: None

## Summary

Local-development-only infrastructure change: wires a new admin-panel
backend (running on `localhost:3131`) into the local auth proxy setups
used for developing against Keycloak/Entra ID/generic OAuth2 locally.
Confirmed by reading the two most load-bearing files in full:

- **`main.js` refactor, confirmed exactly**: the previously duplicated
  `/api/`-vs-`/frontend` upstream-selection logic (inlined twice) is
  extracted into a single `targetLocationForUri(uri)` helper, now also
  checking `uri === "/admin" || uri.startsWith("/admin/")` first (routing
  to `@admin`) before falling through to the existing `/api/` → `@backend`
  check and the `@frontend` default.
- **`nginx.conf`, confirmed exactly**: a new `admin_backend` upstream
  pointing at `host.docker.internal:3131` and a new `@admin` internal
  location proxying to it with the same header set (Host, X-Real-IP,
  X-Forwarded-For/Proto, and the JWT `Authorization` header) as the
  existing `@backend`/`@frontend` locations.
- Per the PR (not independently re-verified given the local-dev-only
  scope): the three OAuth2 Proxy config files
  (`oauth2-proxy.cfg`/`-keycloak.cfg`/`-entra-id.template.cfg`) add the
  admin routes to their `upstreams` lists, add `/admin/api/.*` to Entra
  ID's `api_routes`, and extend `whitelist_domains` in all three to
  include `.localhost:3131` so cookies/auth work against the admin
  backend's port.

## Compatibility and configuration

None for production deployments — this touches only
`frontend/local-auth/`, the local-development proxy configuration used to
simulate the production auth-proxy setup on a developer machine. No
production nginx, oauth2-proxy, or Helm/Kubernetes configuration is
affected.
