# PR #943: Add optional pinned chats

## Summary

This PR bundles two unrelated changes.

**Feature (ERMAIN-568)**: adds an optional "pinned chats" capability.
Confirmed by reading the code:
- New migration `0035_add_pinned_chats`: a `chats.is_pinned` boolean
  (default `false`) plus a composite index on `(owner_user_id, is_pinned)`.
- New config flags, both with sensible defaults so this is opt-in:
  `frontend.enable_pinned_chats` (default `false`) and
  `frontend.pinned_chats_limit` (default `5`, capping how many pinned
  chats the sidebar shows).
- Backend API: `RecentChat`/`UpdateChatRequest`/`UpdateChatResponse` all
  gain `is_pinned`; `GET /me/chats` (recent chats) gains a new `pinned`
  query parameter to filter by pin state; `PUT /me/chats/{chat_id}` now
  supports updating pin state independently of (or together with) the
  title — confirmed via the diff that a pin-only request correctly
  preserves the existing title, and a combined request applies both
  updates.
- Frontend: `useChatHistory.ts` (107-line diff, not read in full),
  `ChatHistoryList.tsx`/`ChatHistorySidebar.tsx` (29 and 77-line diffs,
  not read in full) presumably render a separate pinned-chats section and
  a pin/unpin affordance — consistent with the API surface confirmed
  above but not independently traced through the UI layer. New locale
  strings across de/es/fr/pl for the pin UI.

**Separate, unrelated CI change**: confirmed via the `docker-build.yml`
diff — all four Kubescape Helm-chart security-scan steps
(DevOpsBest/MITRE/NSA/SOC2 frameworks against `infrastructure/charts/erato`)
are disabled (`if: false`), citing two specific upstream Kubescape bug
reports (kubescape/kubescape#3056, kubescape/github-action#78) as the
reason the action's own version-override mechanism isn't reliable right
now. The action reference is bumped to a newer commit with an explicit
`version: v4.0.11` pin, presumably so re-enabling later is a one-line
flip once upstream is fixed, rather than requiring the version/commit
research to be redone. **Worth flagging clearly**: this means Helm chart
security-benchmark scanning is not running in CI for the duration this
disablement is in effect — a temporary, upstream-caused gap tracked under
ERMAIN-573, not a deliberate policy relaxation, but worth the maintainer
confirming it gets re-enabled promptly rather than being forgotten.

## Compatibility and configuration

New, optional, default-`false` config flag:
```toml
[frontend]
enable_pinned_chats = false  # default
pinned_chats_limit = 5       # default
```
No behavior change for any deployment that doesn't enable it. New
database migration (`0035`, additive column + index, includes a revert
script) — requires a migration run on upgrade regardless of whether the
feature is enabled. Separately: Helm chart security scanning
(Kubescape) is currently disabled in CI due to an upstream tooling bug,
unrelated to this feature and not gated by any config.
