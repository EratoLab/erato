# PR #1329: Make favicon path configurable

- PR: https://github.com/EratoLab/erato/pull/1329
- Status: pending
- Category: Features and enhancements
- Theme: Customer themes and component kits

## Summary

Adds a new `frontend.favicon_path` config key (default `/favicon.svg`)
so a themed deployment can serve its own favicon instead of the bundled
default. The backend injects the configured path into the frontend
environment and, when it differs from the default `/favicon.svg`,
rewrites the HTML's `<link rel="icon">` tags at serve time (dropping
their `type`/`sizes` attributes, since a custom image can be a different
format/size than the bundled SVG+ICO pair) via
`inject_environment_script_tag`'s new `element!("link[rel~=\"icon\"]", ...)`
handler. On the frontend, the same configured path is read through
`env().faviconPath` (with a `VITE_FAVICON_PATH` override for local dev)
and consumed by both the tab-activity favicon badge
(`composeBadgedIcon`/`TabChatIndicator`, which now fetches the configured
image as its base icon and reconfigures the existing `<link>` elements to
point at it) and presumably by the static HTML's own icon links.

## Compatibility and configuration

New optional config key, defaulting to the existing behavior:
```toml
[frontend]
favicon_path = "/favicon.svg"  # default; unchanged behavior
```
Setting it to a different deployment-root-relative path (e.g. a
theme-specific icon) changes the served favicon and the chat-activity
badge's base image. No breaking change for deployments that don't set
it. No migration.
