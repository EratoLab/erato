# PR #836: Dropdown menus: soft active highlight + arrow-key roving navigation

- PR: https://github.com/EratoLab/erato/pull/836
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Reworks focus handling across all shared dropdown menus to follow the
WAI-ARIA menu-button pattern, fixing a visual bug where opening a menu
with a mouse click made the first item look pre-selected (a heavy 2px
focus ring) even though nothing had actually been chosen. Confirmed by
reading the code:

- `AnchoredPopover` now tracks how the popover was opened via a new
  `openViaKeyboardRef`, set by inspecting `event.detail === 0` on the
  trigger's click handler (a real pointer click has `detail >= 1`; a
  synthetic click dispatched by Enter/Space has `detail === 0`) — a small
  but precise technique confirmed directly in the diff. A new
  `onKeyDown` handler additionally opens the menu on ArrowDown/ArrowUp
  when closed, per the WAI-ARIA pattern. On open, focus goes either to the
  first matching item (keyboard-open, via `initialFocusSelector`) or to
  the panel container itself (pointer-open — the panel gained
  `tabIndex={-1}` and `focus:outline-none` specifically so it can hold
  focus invisibly).
- New shared hook `useRovingMenuFocus` (111 lines, read in full):
  ArrowUp/Down move focus among navigable items (matching a caller-supplied
  `itemSelector`, expected to exclude disabled items) with wraparound;
  Home/End jump to the first/last item. This is confirmed to be an
  **extraction** of roving-focus logic that already existed in
  `ChatInputAddMenu` (which loses 85 lines in this diff, consistent with
  being refactored onto the shared hook) — now also consumed by
  `DropdownMenu`, replacing its previous Tab-only cycling.
- `DropdownMenu`'s keyboard-active row styling changes from a heavy focus
  ring to a "soft rounded background + faint 1px inset border" (new
  Tailwind config entries support this), explicitly kept visually distinct
  from both the hover state and `bg-theme-bg-selected` (reserved for an
  actually-selected item); the danger/destructive item variant keeps its
  existing error-colored background.
- Escape-to-close and focus-return-to-trigger continue to live centrally
  in `AnchoredPopover`, unchanged by this PR.
- Per the PR, this affects every `DropdownMenu` consumer (chat-history
  kebab, ModelSelector, FacetSelector, FileSourceSelector,
  AudioInputTabContent, AssistantsListPage, SearchPage) plus the chat "+"
  menu — not independently enumerated/verified against each call site,
  but plausible given the shared-component nature of the change.

## Compatibility and configuration

None. Pure frontend interaction/accessibility fix; no configuration or API
changes. Visual change: the previously-heavy default-item focus ring on
menu open is replaced by a softer highlight, and only appears at all when
the menu was opened via keyboard or after an arrow-key press — a
mouse-opened menu now shows no item highlighted until the user presses an
arrow key.
