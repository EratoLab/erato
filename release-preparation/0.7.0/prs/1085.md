# PR #1085: Improve robustness of generation when dropping client connection

- PR: https://github.com/EratoLab/erato/pull/1085
- Status: pending (diff reviewed)
- Category: Stability improvements
- Theme: Streaming/generation stability

## Summary

Fixes a reliability bug in `send_generation_event`
(`backend/erato/src/server/api/v1beta/message_streaming.rs`), the helper
used throughout the generation loop (`send_generation_event(&message,
tx.clone()).await?` — used, e.g., by the tool-call error handling added in
#995 and the approval-flow events from #915) to forward an event to the
client's per-request SSE channel. Previously, if that channel's receiver
had been dropped — which happens whenever a client navigates away,
refreshes, or reconnects mid-generation — sending failed and the error was
propagated with `?`, which aborted the entire generation for what was
really just a disconnected *viewer*, not a failure of generation itself.
Per the new code comment: "Generation is also delivered through
StreamingTask's broadcast/history path. The request-scoped SSE receiver
can disappear when a client navigates away or reconnects; that must not
cancel the generation or turn a successfully persisted tool call into a
generation failure." Now, a failed send to the closed channel is logged at
`debug` level and `send_generation_event` always returns `Ok(())` — the
generation loop continues undisturbed, relying on the separate
`StreamingTask` broadcast/history mechanism (persisted state, consistent
with the cross-replica generation-state work in #898) for any client that
reconnects to pick up where it left off. A new unit test,
`closed_sse_channel_does_not_abort_generation_event_delivery`, verifies
sending to an already-dropped channel no longer errors.

## Compatibility and configuration

No configuration keys or migrations. Pure reliability fix: a client
disconnecting, navigating away, or reconnecting mid-generation no longer
risks aborting that generation turn server-side. This complements #995
(recoverable MCP tool errors) and the broader "Long running or
disconnected turns recover more cleanly" theme this cycle.
