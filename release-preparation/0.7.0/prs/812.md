# PR #812: Ensure stable translation ids for assistant/assistant-hub pages

- PR: https://github.com/EratoLab/erato/pull/812
- Status: pending
- Category: Chores & Developer experience
- Theme: None

## Summary

Converts Lingui `t\`...\`` macro calls (whose message IDs are auto-derived
by hashing the English source text) to explicit
`t({ id: "some.stable.id", message: "English text" })` calls throughout
`frontend/src/pages/AssistantChatSpacePage.tsx`,
`AssistantCreatePage.tsx`, `AssistantEditPage.tsx`,
`AssistantHubDetailPage.tsx`, `AssistantHubMyPage.tsx`,
`AssistantHubReviewPage.tsx`, `AssistantsListPage.tsx`, and
`assistantHubUtils.tsx`. Spot-checked samples confirm this is a purely
mechanical ID-stabilization change (e.g. `t\`Assistants\`` →
`t({ id: "assistants.title", message: "Assistants" })`), with no wording,
logic, or behavior changes — the English source text is preserved
verbatim at each call site. The bulk of the diff (~1180 of 1347 added
lines) is in the five `frontend/src/locales/*/messages.po` files, which
gain/rename message-ID entries to match. With hash-derived IDs, any future
edit to the English source text would silently mint a new message ID and
orphan existing non-English translations of the old text; stable,
hand-assigned IDs decouple the translation key from the exact source
wording.

## Compatibility and configuration

No configuration keys or migrations. No end-user-visible text changes.
Deployments that maintain external translation overrides keyed by the old
auto-generated (hash-based) message IDs for these specific strings would
need to update those keys to the new stable IDs — relevant given the
config-mirroring work for `.po` files elsewhere this cycle (#897, #914,
#989, #991).
