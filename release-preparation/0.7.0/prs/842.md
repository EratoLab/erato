## Summary

Two small presentation fixes to the "queued next message" chip introduced
in #840, both confirmed by reading the diff:

1. The chip's border/background switch from `--theme-border-chat-input`
   on `bg-theme-bg-secondary` to `--theme-border-attachment` on
   `bg-theme-bg-primary`, matching the sibling attachment-preview
   component's surface tokens instead of the composer input's own. A
   no-op in the stock theme (which aliases both border tokens to the same
   value), but visible in a customer theme that splits them.
2. Layout: the label span previously had `shrink-0` while the message text
   button used `flex-1`, so in the Outlook add-in's narrow (~320px)
   taskpane the message text collapsed to nothing first while the fixed
   label held its width. Fixed by letting the label truncate
   (`min-w-0 truncate`, no longer `shrink-0`) and switching the message to
   `flex-auto` (a non-zero flex-basis, unlike `flex-1`'s zero basis) so it
   keeps visible space; the cancel button explicitly gets `shrink-0` to
   stay a fixed size.

No behavior change, per the PR — purely visual/layout.
