# PR #781: Switch from native-tls to rustls

- PR: https://github.com/EratoLab/erato/pull/781
- Status: pending
- Category: Dependency changes
- Theme: Backend image slimming/hardening

## Summary

Switches the backend's TLS implementation from `native-tls` (OpenSSL-backed)
to `rustls` across all crates that make outbound HTTPS/TLS connections, by
changing feature flags in `backend/erato/Cargo.toml` and
`backend/rmcp-sse/Cargo.toml`:
- `sea-orm`: now `default-features = false` with an explicit feature list
  including `runtime-tokio-rustls` (was `runtime-tokio-native-tls`).
- `sqlx`: now `default-features = false` with `tls-rustls` (was
  `tls-native-tls`), plus explicit `json`, `macros`, `migrate`, `chrono`,
  `uuid` features.
- `reqwest` (both `erato` and `rmcp-sse` crates): now
  `default-features = false` with an explicit `rustls` feature (was pulling
  in the default TLS backend).
- `opentelemetry-otlp`: adds `reqwest-rustls` feature.
- `graph-rs-sdk`: now `default-features = false` with `rustls-tls`.
- `sentry`: features changed from `["...", "native-tls"]` to
  `["...", "rustls"]`.

`backend/Cargo.lock` shrank by ~100 lines, consistent with dropping the
OpenSSL/native-tls dependency chain.

## Compatibility and configuration

No configuration keys, migrations, or user-facing behavior change. This is
a build-time TLS backend swap; functionally, HTTPS/TLS connections (database,
outbound HTTP, OTLP export, MS Graph API, Sentry) should behave the same,
though rustls's certificate/cipher-suite support can differ subtly from
OpenSSL's in edge cases (e.g. systems relying on a legacy cert store or
cipher suite not supported by rustls) — this PR's diff does not show any
compensating code changes, so no such incompatibility was evident in the
Cargo.toml/Cargo.lock diff alone. Likely motivated by removing the OpenSSL
system dependency from the build/runtime image, complementing the parallel
`backend/Dockerfile` changes in this release cycle (e.g. #782 chainguard
base image).
