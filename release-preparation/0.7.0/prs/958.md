# PR #958: Render the Teams composer preview from the transcript's index block

- PR: https://github.com/EratoLab/erato/pull/958
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Reworks the Teams composer's grouped conversation preview (#953) to parse
the structured index block (#957) directly out of the attached transcript
file, instead of reading the in-memory `sections` the picker held —
"dogfooding" the index block's own serialization format on the same path
that consumes it, per the PR. Confirmed via `TeamsAttachmentsPreview.tsx`:
a new `useTeamsTranscriptIndex(attachedTranscript)` hook reads and parses
the file; while parsing is in flight the region renders nothing rather
than the fallback flat chips, specifically to avoid a one-frame flash of
flat chips being immediately replaced by the grouped view once parsing
completes. When there's no attached transcript, or its index block can't
be read, the component correctly falls through to the ordinary flat
`FileAttachmentsPreview` — matching the PR's stated fallback behavior.

**A real, previously-undisclosed bug fix is also included, not mentioned
in the PR's title or description at all**: confirmed by reading the
`file_processor/mod.rs` diff, #957's `strip_transcript_index` had an edge
case where a message's own *prose* merely mentioning the marker string
`"erato:teams-transcript"` (e.g. a message discussing the transcript
format itself) would be misidentified as the start of the real serialized
index block. Since the old logic searched for a closing delimiter across
the *entire remaining file* rather than bounding it to one line, this
could silently swallow everything from that innocent mention through the
real index block's terminator at the very end of the file — deleting
legitimate conversation content between them. The fix adds
`starts_index_block()`, which additionally requires the marker to be
immediately followed by the serializer's own `v<n>` version token before
treating it as a real block, and bounds the search strictly to the single
line the marker appears on (the serializer always writes the block as one
line with JSON-escaped payload, so a legitimate block can never span
two). A new test,
`strip_transcript_index_keeps_prose_that_only_names_the_marker`, confirms
a message naming the marker followed by a real trailing index block
correctly keeps all conversation content and strips only the real block.

## Compatibility and configuration

None. Pure bug fix and internal refactor; no configuration or API
changes. The backend fix corrects a real (if narrow) data-loss bug that
could have affected any Teams transcript whose conversation happened to
discuss or mention the literal string "erato:teams-transcript" in a
message.
