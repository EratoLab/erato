# PR #1323: Add deployment controls for reduced customer chat interfaces

- PR: https://github.com/EratoLab/erato/pull/1323
- Status: pending
- Category: Features and enhancements
- Theme: None

## Summary

Adds three new `[frontend]` presentation flags —
`enable_message_editing`, `enable_message_regeneration`, and
`enable_chat_history_filters` — all defaulting to `true`, letting an
embedded customer-chat deployment hide message editing, message
regeneration, and the chat-history filter UI when updating to a newer
Erato version that added those controls, without losing the ability to
upgrade. Per the PR's own description, confirmed by the file list:
turning off `enable_chat_history_filters` restores the ungrouped
"Recent" chat list and ignores saved browser filters from the very first
request (including optimistic chat-list reconciliation), while leaving
copying, feedback, and existing chat-sharing permissions untouched —
these are explicitly UI-presentation controls, not API authorization
changes (so the underlying API endpoints for editing/regenerating/
filtering remain reachable; only the triggering UI is hidden). Saved
filter preferences are preserved and become available again if the flag
is re-enabled later.

## Compatibility and configuration

New optional keys, all defaulting to `true` (no behavior change for
existing deployments that don't set them):
```toml
[frontend]
enable_message_editing = true
enable_message_regeneration = true
enable_chat_history_filters = true
```
No migration. Explicitly presentation-only: the PR states API
authorization and permissions are unaffected by these flags, so a
determined client could still call the underlying endpoints directly —
this is a UI-reduction knob, not an access-control mechanism.
