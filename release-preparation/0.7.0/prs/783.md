# PR #783: Mobile model selector placement and alignment

- PR: https://github.com/EratoLab/erato/pull/783
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Fixes the chat model selector's placement on the mobile/Office-add-in
"unified" composer layout (`useUnifiedMobileMenu`, where composer controls
collapse into a single "+" menu). Previously, the model selector always
rendered in the right-hand control group (next to Send) regardless of
layout mode; on the unified-mobile layout this put it awkwardly far from
the "+" menu it conceptually belongs with. Now, when
`useUnifiedMobileMenu` is active, the selector renders in the left control
group instead (next to "+"), and a new `ModelSelector` `align` prop
(`"left" | "right"`, default `"right"`) makes its dropdown open flush-left
in that position instead of using the default right-aligned menu (which
would otherwise clip against the left edge of the screen). On the
non-unified (desktop) layout, the selector's position and right-alignment
are unchanged. The visibility condition itself
(`showModelSelector = !hasTopLeftAccessoryOverride && !(isAudioMode &&
!showModelSelectorInAudioMode)`) was extracted into a named variable but
is otherwise identical to the prior inline condition — no change to
*when* the selector shows, only *where* and how its menu aligns.

## Compatibility and configuration

None. Purely a frontend layout/UX fix confined to
`frontend/src/components/ui/Chat/ChatInput.tsx` and
`ModelSelector.tsx`; no configuration keys, API changes, or migrations.
