# PR #879: Withhold owner feedback from share-link viewers

- PR: https://github.com/EratoLab/erato/pull/879
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Fixes a privacy leak (ERMAIN-489) in the shared-chat active-thread route
introduced by #866: `assemble_chat_messages_response` (shared by both the
owner's and the share-link's messages routes) fetched message feedback
unconditionally, so a share-link viewer's response embedded the chat
owner's own private 👍/👎 and free-text feedback comments, even though a
viewer has no write access to feedback at all. Confirmed by reading the
diff: `assemble_chat_messages_response` gains a new `include_feedback:
bool` parameter — the owner route (`chat_messages`) passes `true`
(unchanged behavior), while the share-link route (`share_link_messages`)
passes `false`, in which case the feedback lookup is skipped entirely and
an empty map is used, guaranteeing a share-link viewer's response never
contains the owner's feedback for any message.

A new integration test (extending the existing
`test_chat_share_link_enable_disable_flow`) is confirmed to check: the
owner leaves feedback and sees it in their own response (a positive
control, so the negative assertion below isn't vacuous); the share-link
view returns `feedback: null` for that same message; the viewer's `PUT
.../feedback` is denied with 403; and the viewer's `DELETE .../feedback`
(from #865/ERMAIN-488) is also denied with 403.

**Context worth flagging**: this PR is described as stacked on, and
dependent on the policy change from, `#878` (ERMAIN-486, "removes the
share-link `Chat::Read` grant") — the same PR referenced in #866's
description as the follow-up expected to fully separate `shared_read`
from the owner-level `read` action. However, **PR #878 does not appear in
this release's manifest** (`release-preparation/0.7.0/manifest.json` has
no entry for it), meaning either it isn't part of this release's included
PR set, was merged under a different mechanism, or is tracked elsewhere —
worth the maintainer confirming #878 (or its equivalent) actually shipped
in 0.7.0 alongside this PR and #866, since this PR's write-denial claims
(403 on PUT/DELETE feedback) depend on that policy change having landed.
This PR's own read-scope fix (withholding feedback data) is independent of
that policy question and correct regardless.

## Compatibility and configuration

None. Pure bug fix; no configuration or API shape changes (the
`feedback` field simply returns `null` for share-link viewers instead of
the owner's actual feedback).
