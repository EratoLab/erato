# PR #1211: Fix sidecar mailbox IDs and keep indexing status in settings

- PR: https://github.com/EratoLab/erato/pull/1211
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Two independent fixes bundled together: a mailbox-ID format mismatch
that broke automatic sidecar configuration, and removal of a duplicate
indexing-status surface. Confirmed both directly:

- **Compact-vs-hyphenated UUID mismatch fixed via a new normalization
  helper, confirmed exactly**: the new `indexingMailboxId(mailboxId)`
  function lowercases the input and, via a regex matching exactly 32 hex
  characters in `8-4-4-4-12` groups, inserts hyphens to produce a
  standard UUID — directly addressing "Outlook discovery returns compact
  mailbox IDs, while indexing configuration requires hyphenated UUIDs."
  Confirmed applied consistently at every ID comparison/storage site
  touched by this diff: `initializeMailboxConfiguration` now stores
  `mailbox_id: indexingMailboxId(mailbox.id)` (previously the raw compact
  ID); `orderedMailboxes`'s override lookup map is now keyed by
  `indexingMailboxId(entry.mailbox_id)` on the stored side and looked up
  via `indexingMailboxId(mailbox.id)` on the discovery side (previously
  both sides only `.toLowerCase()`d, which normalizes case but not
  compact-vs-hyphenated format, so a discovery ID and a stored ID
  referring to the same mailbox in different formats would silently
  fail to match); and `mailboxCoverage` now normalizes both the queried
  `mailboxId` and each segment's `segment.mailboxId` before comparing,
  with an added explicit `segment.mailboxId !== null` null-guard ahead of
  the normalization call (a defensive fix, since passing `null` through
  `indexingMailboxId` would have been a type error / runtime crash on a
  non-string value — this guard is new in this diff and a direct
  correctness improvement over the prior `?.toLowerCase()` null-safe
  chain).
- **Duplicate-override prevention follows directly from the same fix,
  confirmed structurally**: since `orderedMailboxes`'s override map is
  now keyed by the same normalized identity on both the stored-override
  side and the discovered-mailbox side, a settings edit can no longer
  write a second override entry for a mailbox already present under a
  differently-formatted id for the same mailbox — directly substantiating
  "This also prevents settings edits from adding duplicate overrides for
  the same mailbox" as a consequence of the normalization fix rather than
  a separately implemented mechanism.
- **Mailbox indexing card removed from the chat history sidebar,
  confirmed exactly**: `ChatHistorySidebar.tsx`'s import of
  `SidecarIndexingCard` and its render call
  (`{!collapsed && <SidecarIndexingCard />}`) are both deleted — matching
  "Remove the mailbox indexing card from the chat history sidebar.
  Indexing status and controls remain in Settings" (the component itself
  is not deleted, only this one call site, consistent with it remaining
  available in the Settings surface).
- Per the PR (not independently re-verified given remaining scope): the
  disclosed test results (31 targeted tests passing, 8 regression cases
  disclosed as failing before the fix "including the reported UUID error
  through the real protocol client validator" — a credible, specific
  claim given this is the same protocol package touched in #1210,
  reviewed just above); the regression coverage for mixed-case UUIDs,
  priorities, enablement, progress counts, and preservation of
  disconnected-mailbox overrides and extra fields (in the 107-line
  `SidecarIndexingCard.test.tsx` additions and 43-line
  `indexingConfiguration.test.ts` additions, not read in full); and the
  disclosed validation (strict ESLint/Prettier, `git diff --check`,
  frontend typecheck, shared library build/package, and the Office
  add-in typecheck against the rebuilt library).

## Compatibility and configuration

None breaking. Pure frontend bug fix shared between the web frontend and
Office add-in (confirmed the changed files live under the shared
`frontend/src/lib/desktopSidecar/` and `frontend/src/components/ui/`
trees, matching "The shared frontend code supplies both the web frontend
and the Office add-in"). No wire or config changes; the fix changes only
how mailbox IDs are normalized before comparison/storage on the client
side.

## Release note disposition

Proposed category: Bug fixes. Worth a mention: automatic sidecar
configuration for Outlook mailboxes no longer fails with a UUID-format
validation error, and editing mailbox indexing settings no longer risks
creating duplicate per-mailbox overrides. Also: the standalone mailbox
