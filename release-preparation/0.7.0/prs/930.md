## Summary

Local dev-tooling only (ERMAIN-552); confirmed via full diff read. The
local dev `manifests/manifest.json` (Teams unified manifest) is promoted
from the `devPreview` schema to the GA Microsoft 365 schema (`v1.29`),
adds a Teams `personalTab` static tab (`staticTabs`, `webApplicationInfo`
with nested-app-auth info, `Mailbox.ReadWrite.User` resource-specific
permission), and renames itself "(Local)" to distinguish it from any
production manifest. `office-addin/scripts/dev.py` gains a new
`write_funnel_app_package()` function that renders this unified manifest
with `localhost` substituted for the current Tailscale funnel host,
validates the result is well-formed JSON with no leftover unresolved
placeholders, and zips it (manifest + icons) into
`manifest-funnel.zip` — a sideloadable local dev package for testing the
add-in as a Teams personal tab over the funnel URL. Confirmed the failure
handling is deliberately isolated: the function clears any stale previous
package first (so a failed render can never leave a stale-funnel-URL
package around to be sideloaded by mistake) and its caller wraps it in a
best-effort try/except so a packaging failure logs a warning rather than
taking down the rest of the dev session (matching the pattern already
used for the existing on-prem XML manifest variant).
