# PR #989: Skip check for sibling .json files before mirroring .po files

- PR: https://github.com/EratoLab/erato/pull/989
- Status: pending
- Category: Bug fixes
- Theme: None

## Summary

Removes a check in `collect_translation_po_sources`
(`backend/erato/src/distribution/translations.rs`, the `.po`
discovery/mirroring logic from #897/#914, since relocated by #988) that
previously skipped a `.po` translation catalog from mirroring unless a
compiled `messages.json` sibling file already existed alongside it. Per
the updated test (`translations.sources().len()` goes from 5 to 6, and a
previously-excluded "not-served" catalog is now asserted present), `.po`
files are now always mirrored regardless of whether a compiled JSON
sibling exists — e.g. in precompiled translation mode where no
per-locale compiled JSON sibling is produced at all in that location, or
before the JIT compiler has run for a given locale.

## Compatibility and configuration

No configuration keys or migrations; only affects deployments with
`runtime_configuration.enabled = true` (the mirroring feature from #897).
More `.po` files will now be mirrored into the `runtime_configuration`
table than before — specifically, ones that were previously silently
excluded because their compiled JSON sibling wasn't found at discovery
time. This closes a gap where such translation sources were invisible to
whatever consumes the mirrored configuration (e.g. an admin panel).
