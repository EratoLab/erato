# PR #871: Add configuration method for desktop sidecar

- PR: https://github.com/EratoLab/erato/pull/871
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Desktop Sidecar for local sources

## Summary

Adds the first end-to-end (protocol + backend + frontend) piece of desktop
sidecar functionality: a way for the organization/deployment to push
configuration to a user's locally-running sidecar. Adds
`sidecar.configure.v1` to the protocol
(`desktop-sidecar-protocol/schemas/methods/sidecar-configure-v1-params.schema.json`),
accepting `user_configuration` and `organization_configuration` objects
(a `sidecar-configuration.schema.json` shape, currently just
`show_tray_icon: boolean | null`).

On the backend, a new authenticated endpoint
`GET /me/desktop-sidecar/organization-configuration`
(`backend/erato/src/server/api/v1beta/desktop_sidecar.rs`) returns
`app_state.config.desktop_sidecar.organization_configuration`, gated by a
new policy resource `DesktopSidecarConfigurationSingleton`
(`backend/policy/backend/backend.rego`,
`backend/erato/src/policy/types.rs`). On the frontend, a new
`DesktopSidecarConfigurationSync` component
(`frontend/src/providers/DesktopSidecarProvider.tsx`) fetches this
organization configuration and, once the sidecar client is `"ready"` and
supports `sidecar.configure.v1`, invokes it with
`{user_configuration: {show_tray_icon: null}, organization_configuration:
<fetched config>}` — i.e. this PR wires the organization-level
configuration through but does not yet implement a per-user override UI
(`user_configuration.show_tray_icon` is hardcoded to `null` here).

## Compatibility and configuration

New backend configuration key:
`desktop_sidecar.organization_configuration.show_tray_icon` — defaults to
`None`/unset (type `boolean | None`), meaning "no organization-level
override" (per `site/content/docs/configuration.mdx`, a user-specific
sidecar setting may take precedence when the organization value is unset;
if neither layer sets it, the sidecar defaults to showing the tray icon).
No migration. This only takes effect for deployments that both configure
this key and have a compatible desktop sidecar installed and connected
(via the still-in-progress sidecar distribution work, e.g. #860, #872);
without a connected sidecar this has no observable effect. No breaking
change.
