# PR #785: Add assistant hub reviews

- PR: https://github.com/EratoLab/erato/pull/785
- Status: pending
- Category: Features and enhancements
- Theme: Assistant Hub and assistant sharing

## Summary

Adds a review/rating system for published Assistant Hub assistants. Any user
who can view the published current version of a hub assistant may submit a
1–10 integer score with an optional text comment
(`backend/erato/src/models/assistant_hub.rs`: `submit_review`,
`HubReviewInput`, validated 1–10 in `validate_review_input`). A user has at
most one review per assistant (unique constraint
`assistant_hub_reviews_assistant_reviewer_key` on
`(assistant_hub_assistant_id, reviewer_user_id)`); resubmitting updates the
existing review (score/comment/associated version) rather than creating a
new row. New backend endpoints: `GET
/assistant-hub/assistants/{hub_assistant_id}/reviews` (list) and `POST
/assistant-hub/assistants/{hub_assistant_id}/review` (submit), in
`backend/erato/src/server/api/v1beta/assistant_hub.rs`.

Visibility of individual reviews is asymmetric: the assistant's owner/creator
sees all reviews left on their assistant; any other viewer sees only their
own review (`list_visible_reviews`). An aggregate — average score and review
count — is computed per assistant
(`review_summaries_for_hub_assistant_ids`) and shown to everyone as a star
rating (`ScoreStars` component) plus a text label
(`getAssistantHubRatingLabel`) on `frontend/src/pages/AssistantHubDetailPage.tsx`,
which also gained a "Reviews" section with a score picker (1–10) and comment
field, and a list of visible review comments.

## Compatibility and configuration

New database migration `backend/sqitch/deploy/0029_add_assistant_hub_reviews.sql`
creates table `public.assistant_hub_reviews` (id, assistant_hub_assistant_id,
assistant_hub_assistant_version_id, reviewer_user_id, score
1–10 CHECK constraint, optional comment, created_at/updated_at) with foreign
keys to `assistant_hub_assistants`, `assistant_hub_assistant_versions`
(both `ON DELETE CASCADE`), and `users` (`ON DELETE CASCADE`), and a unique
constraint on `(assistant_hub_assistant_id, reviewer_user_id)`. This
migration must be applied (via the standard Sqitch deploy, e.g. through the
sqitch-migrator init container from #780) before deploying this backend
version. No new configuration keys are introduced; the feature is gated only
by the existing `AssistantHubConfig.enabled` flag and existing hub
view/creator permissions — no separate feature flag for reviews specifically.
