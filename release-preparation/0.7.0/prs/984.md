# PR #984: Composer assistant mentions: @-picker, add-menu and Tools sections (ERMAIN-618)

- PR: https://github.com/EratoLab/erato/pull/984
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Delegation

## Summary

First of a 3-part delegation *frontend* stack, on top of the backend
stack (#978–#982). Closes the loop: without a client that can produce
`mentioned_assistant_ids`, the backend's `delegate_to_assistant` tool from
#981 is never offered at all. Given the 2641-line scale, review targeted
the two most correctness-critical pieces.

- **"Text is the source of truth" matching, confirmed via full read of
  `assistantMentions.ts`**: `mentioned_assistant_ids` sent with a message
  are derived by re-scanning the composed text for each tracked
  `@{Name}` token at send time — not from a persisted selection list —
  so deleting the `@Name` text drops the mention automatically, with no
  separate "remove mention" UI needed. Confirmed the two specific edge
  cases the PR calls out are handled exactly as described: `isAtWordEnd`
  requires a non-letter/digit character (or end-of-string) after the
  token, so `@Bobby` does **not** match a tracked assistant named "Bob"
  (a further letter continues the word); and `isMentionPresent` builds a
  `shadowingTokens` list of every other tracked name that is a strict
  prefix-extension of the current one (e.g. "Data Analyst" shadows
  "Data") and skips a match that's actually the start of one of those
  longer names, so `@Data Analyst` resolves only to the longer name, never
  double-counting the shorter one it starts with. The leading-boundary
  check is intentionally asymmetric with the trailing one (whitespace-or-
  start only, not "any non-word character") — confirmed via comment, to
  stop something like `me@Data` (an email-shaped string) from being
  read as a mention.
- **A genuinely disclosed, confirmed real bug fix** in the add-in send
  path: `AddinChatCore.tsx`'s `NeutralAddinChatHost` previously passed
  `renderInput={(props) => <AddinChatInputCore {...props} />}` — a bare
  prop spread. Confirmed via the diff that `AddinChatInputCore`'s
  `onSendMessage` signature has 5 positional parameters ending in the new
  `mentionedAssistantIds`, while the wider `props.onSendMessage` this
  spread ultimately forwards to has 7 parameters, with `actionFacet` and
  `hostContextIdentity` sitting in positions 5–6 *before* the real
  `mentionedAssistantIds` slot at position 7 — TypeScript's structural
  typing accepts passing a narrower function where a wider one is
  expected (extra parameters are simply never supplied), so this bare
  spread would have silently placed the add-in's `mentionedAssistantIds`
  argument into the parent's `actionFacet` slot, corrupting both. Fixed by
  replacing the spread with an explicit adapter function that maps each
  named argument to its correct positional slot, passing `undefined`
  explicitly for the two slots the add-in doesn't populate. This is a
  real bug the PR found and fixed while widening the send path, not a
  hypothetical.
- Per the PR (not independently re-verified given remaining scope): the
  `@`-autocomplete popover anchors to the composer shell rather than the
  text caret (stated to degrade better in the add-in's narrow 320–450px
  pane); a shared "Assistants" menu section is contributed once and
  rendered in both `ChatInputAddMenu` (mobile/add-in) and the desktop
  `FacetSelector` Tools dropdown via a common extracted `AddMenuActionRow`;
  a "Browse assistants…" modal offers client-side filter-as-you-type over
  the full accessible list (no server-side assistant search exists); the
  send-path threading follows the established `selectedFacetIds`
  precedent through `Chat` → `useChatActions` → `useChatMessaging`, with
  the #841/#846 message-queue drain resolving mentions from the *queued
  draft's own text* rather than live composer state (mentions belong to
  the text they were typed into, unlike the model/facet selection which
  are read live at drain time per #840); `ComposeDraftState` gains
  `mentionedAssistants` so a queued/restored draft keeps its mentions
  intact; and the whole feature is gated on
  `ASSISTANTS_DELEGATION_ENABLED` plus a non-empty accessible-assistants
  list, with no assistant list fetched at all when the gate is off.
  Several shared primitives (`AnchoredPopover`, `DropdownMenu`,
  `useFuzzySearch`) gain new backward-compatible options for this feature
  (focus-management opt-out for a caret-driven typeahead, labelled
  `role="group"` section headers, an immediate-close option for dialog-
  opening rows, a minimum fuzzy-match character length), all defaulting to
  prior behavior.

## Compatibility and configuration

None new beyond the existing `ASSISTANTS_DELEGATION_ENABLED` frontend gate
(from #978's backend config, threaded through per #978's own PR). No
behavior change for any deployment with delegation disabled — confirmed
the mention picker and its supporting assistant-list fetch are both gated
off entirely in that case.

## Release note disposition

Proposed category: Features and enhancements, "Delegation" — the
user-facing entry point for the backend delegation stack (#978–#982).
