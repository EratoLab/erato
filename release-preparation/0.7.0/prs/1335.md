# PR #1335: Document preview-marked exports and pass export warnings to chat (ERDSCAR-42)

- PR: https://github.com/EratoLab/erato/pull/1335
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Sidecar source capabilities (new Outlook for Mac/Windows parity, foundation)

## Summary

Per the PR description: protocol side of ERDSCAR-42 (new Outlook for Mac
reads and exports), bumping the sidecar protocol to 0.1.37. Confirmed
directly in the `SPEC.md` and `chatTools.ts` diffs: `sources.get_document.v1`
results may now carry a `warnings` array (`code`, optional `message`,
`documentId`, `sourceError`). A new-Outlook-for-Mac (`macOsHxAccount`) email
of which only a preview is locally cached now exports that preview as its
body — prefixed with a bracketed note and the header `X-Erato-Body: preview`
— instead of failing outright with `missing_from_local_cache` as every other
source still does for an incomplete body. A thread export now omits an
unreadable non-subject member rather than failing the whole export,
listing it in a leading text part and as a `message_omitted` warning with
its `documentId`/`sourceError`; only a failure of the subject itself still
fails the export. On the frontend, `chatTools.ts` threads these warnings
through to the model: `read_sidecar_conversation` tags a preview-only
message with `bodyPreviewOnly: true` (matched by `internetMessageId`
against a new `body_preview_only` conversation warning) and
`get_sidecar_document` forwards the new `warnings` array, both with updated
`contentNotice` instructions explicitly telling the model to disclose when
it is relying on a preview or an incomplete thread.

## Compatibility and configuration

Additive protocol change (0.1.36 → 0.1.37); no config keys. Per `SPEC.md`,
a sidecar older than 0.1.37 still fails a new-Outlook-for-Mac preview-only
export with `missing_from_local_cache` exactly as before — this PR only
adds a better-than-failure path for sidecars that implement the new
version, it doesn't change behavior against old ones. No database
migration.
