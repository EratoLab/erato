# PR #1348: Keep bold, italic, underline and strikethrough through a Word selection rewrite (ERMAIN-943)

- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Word selection editing

## Summary

Per the PR description: previously, a Word Replace rewrite (built up over
this batch) collapsed any word-level bold/italic/underline/strikethrough
emphasis down to the surrounding paragraph's plain formatting; this PR
preserves it. Runs whose emphasis differs from their paragraph are sent to
the model as format spans using the same `⟦n⟧…⟦/n⟧` marker syntax as kept
items (#1342), listed in the `kept_items` argument as e.g. "formatting:
bold". Confirmed directly in `wordSelectionFormatSpans.ts`: a new
`WORD_FORMAT_SPANS_MAX` constant caps this at 6 spans per paragraph —
beyond that, or when the server doesn't advertise `kept_items` at all, the
rewrite flattens emphasis as before (with the card saying so), i.e. this
is a bounded best-effort enhancement, not a hard guarantee. Per the PR
(not independently verified beyond the constant above): the model is
treated leniently — it may move, reorder, or drop a span, with a dropped
span's text taking on the surrounding formatting and the card naming it —
but an invented, duplicated, nested, or malformed span pairing is refused
outright, while kept-item markers (the non-formatting kind from #1342)
remain strictly validated. The plain write path chains
`insertText(..., "Replace")` then `insertText(..., "After")` per
formatted part with `setFont`, all within one write sync; the kept-item
write path instead copies each span's old run's toggles onto the new
text. The final pre-write check re-marks the live paragraph, so emphasis
that changed since Send refuses with a new `TARGET_TEXT_MISMATCH` code.
The card and the web-app history renderer (from #1347, same batch) label
spans as `[bold]…[/bold]`-style text; Copy omits the markers.

## Compatibility and configuration

Per the PR: gated the same way as #1342's kept-items feature — only
active when the server advertises `kept_items`; without it, or beyond the
6-spans-per-paragraph cap, the existing flatten-to-paragraph-formatting
behavior applies unchanged. No config keys in this repo (the capability
flag is server-side, external to this repo, same caveat as #1342). No
database migration.
