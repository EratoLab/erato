# PR #1078: Extend Helm chart to allow for automatic building of upstreams

- PR: https://github.com/EratoLab/erato/pull/1078
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Extends the Helm chart's oauth2-proxy setup to automatically compute the
`OAUTH2_PROXY_UPSTREAMS` environment variable from new structured values,
instead of it only being auto-set for the intermediate-load-balancer case
(#901) or otherwise left to the operator to configure manually. New
`oauth2Proxy.upstreams` values block: `enabled` (default `true`) turns on
this auto-computation; `backendUrl` (optional override, otherwise derived
from the load-balancer setting from #901/#911 or the default backend
Service) sets the base URL for non-admin routes; `adminPanelUrl`
(optional) is new — when set, oauth2-proxy is configured to route both
`/admin` and `/admin/` (including nested assets/API routes) to that
separate admin-panel service, falling back to the normal backend for
everything else. This is implemented via two new Helm template helpers,
`erato.oauth2ProxyBackendUrl` and `erato.oauth2ProxyUpstreams` (the latter
composing a path-aware, comma-separated upstream list:
`"<admin>/admin#/admin,<admin>/admin/#/admin/,<backend>/#/"` when an admin
panel is configured, or just `"<backend>/#/"` otherwise). This appears to
be the deployment-side counterpart to the admin-panel integration work
from #897/#913/#991 this cycle (translation overrides authored via an
external admin panel), giving that panel a routable path behind the same
authenticating proxy.

## Compatibility and configuration

New `oauth2Proxy.upstreams.*` values:
```yaml
oauth2Proxy:
  upstreams:
    enabled: true       # default; set false to manage OAUTH2_PROXY_UPSTREAMS manually via oauth2Proxy.config
    backendUrl: ""       # optional override
    adminPanelUrl: ""    # optional; routes /admin and /admin/ to this service
```
Behavior change on upgrade for deployments with `oauth2Proxy.enabled =
true`: `OAUTH2_PROXY_UPSTREAMS` is now auto-populated by default
(`upstreams.enabled` defaults to `true`), which could override a
previously hand-configured value set via `oauth2Proxy.config` or
`extraEnvVars` if both are now present — operators who already manually
manage `OAUTH2_PROXY_UPSTREAMS` should set `oauth2Proxy.upstreams.enabled:
false` to preserve their existing configuration on upgrade. No migration.
