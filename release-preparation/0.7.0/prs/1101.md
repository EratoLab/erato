# PR #1101: Move menu and sidebar rows onto one Row primitive

- PR: https://github.com/EratoLab/erato/pull/1101
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Fourth of nine styling-primitives-consolidation topics (after #1092,
#1096, #1100). Consolidates five byte-identical copies of a menu-row
class string and three inline mirrors of the sidebar-row geometry onto
one `Controls/Row.tsx` primitive (`menu`/`sidebar`/`list` variants). Given
the very large scope (2479 lines), review focused on the one disclosed
real correctness bug the PR found and fixed during the migration.
Confirmed by reading the complete new `Row.tsx` in full:

- **The keyboard-navigation bug and its fix, confirmed exactly**: the
  roving-focus marker `data-row-item` is emitted as
  `data-row-item={interactive && variant === "menu" ? "" : undefined}` —
  gated on both `interactive` and being the `menu` variant together. A
  code comment states the bug precisely: before this gating existed (per
  the PR's narrative, during migration), the marker was emitted
  unconditionally, so a non-interactive status-line `<div>` (e.g. "loading
  attachments", a thread-load error) rendered inside the Outlook "+" menu
  joined the menu's roving-focus set — since such a div has no `role` and
  `.focus()` on it is a no-op, arrow-key navigation into it left
  `document.activeElement` unchanged and targeted the same non-focusable
  element again on the next key press, freezing keyboard navigation of
  the menu. Confirmed the family-default `data-ui` hook
  (`FAMILY_DATA_UI[variant]`) is gated identically
  (`dataUi ?? (interactive ? FAMILY_DATA_UI[variant] : undefined)`), so a
  non-interactive row now carries neither hook — matching the PR's stated
  fix of restoring such rows to "carrying no hook at all," their
  pre-migration state.
- **The general lesson the PR draws from this, confirmed as a design
  principle actually reflected in the code**: `ROW_ITEM_SELECTOR` is
  scoped as `"[data-row-item]:not([disabled])"`, and the doc comment
  above it states explicitly that a disabled-mode-aria row stays in the
  roving set (reachable, to say why it's unavailable) while a natively
  `disabled` row drops out via the `:not([disabled])` clause — confirmed
  this distinction is implemented via the `disabled` attribute being set
  only when `disabledMode === "native"` (native rows use the real
  `disabled` attribute and drop from both the tab order and the
  selector; aria rows use `aria-disabled` and stay reachable).
- Per the PR (not independently re-verified given the very large
  remaining scope): the stylesheet-text-diff zero-delta verification
  methodology (same approach as #1100, checking the compiled Tailwind
  output before/after to catch an unintended visual change like #1096's
  disclosed Alert radius delta) claims exactly two intended rule-family
  changes plus additive unused-tone utility rules; two deliberate visible
  changes are disclosed and detailed with measured before/after values —
  the session-ask toast's keyboard focus ring moving from outset to inset
  (justified by that row sitting flush against a container's clipped
  edge), and the `AssistantBrowserModal`'s option rows gaining rounded
  corners and a themeable hover/focus fill via the new `list` variant,
  where they previously had no geometry class and no theme hook at all
  (measured via a Storybook+Playwright probe: `0px` → `8px` border-radius,
  `data-ui` none → `list-row`); `Button variant="list-item"` is retired as
  dead code (its only consumer was its own Storybook story), which lets
  `.dropdown-item-geometry`'s radius read drop the guard fallback #1100
  had to add, now a bare `var(--dropdown-item-radius)` — stated as safe
  because all six remaining consumers of that class render inside
  `.anchored-popover-skin` (not independently re-verified); and both
  customer component kits deliberately keep their own inline row styles
  until a later "kit phase," since a kit importing a name the deployed
  host predates would fail module linking and take the kit offline.

## Compatibility and configuration

None functionally breaking for the default (non-override) path. Two
disclosed, deliberate visible changes (see above): the recent-chats
session-ask toast's focus ring moves from outset to inset, and the
`AssistantBrowserModal`'s mention-browser rows gain rounded, theme-reachable
hover/focus styling they previously lacked entirely. Everything else is
claimed measured zero-delta via the stylesheet-diffing methodology
described above (not independently reproduced in this review).

## Release note disposition

Proposed category: Bug fixes. Worth two mentions: a keyboard-navigation
freeze in the Outlook add-in's "+" attachment menu (arrowing into a
non-interactive status line like "loading attachments" and getting
stuck) is fixed, and the assistant-mention browser's option rows now
