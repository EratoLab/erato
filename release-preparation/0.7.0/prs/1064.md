# PR #1064: Make the info tooltip reachable by keyboard

- PR: https://github.com/EratoLab/erato/pull/1064
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Fixes a real accessibility gap: `Tooltip` previously only responded to
`onMouseEnter`/`onMouseLeave`, with no focus handling, no `role="tooltip"`,
no `id`, and no dismissal mechanism — meaning `InfoTooltip`'s
customer-configurable help text (the component's entire purpose) was
unreachable via keyboard and invisible to a screen reader even with a
pointer. Confirmed by reading the complete `Tooltip.tsx` diff:

- **Focus support, confirmed exactly**: `onFocus={showTooltip}` and
  `onBlur={hideTooltip}` are added alongside the existing mouse handlers
  on the same wrapper div (renamed from `handleMouseEnter`/`handleMouseLeave`
  to the neutral `showTooltip`/`hideTooltip`, now shared by both trigger
  types) — a code comment notes React focus events bubble, so the wrapper
  sees them from whatever the child renders without per-child wiring.
- **Screen-reader wiring, confirmed exactly**: the portal's tooltip div
  gains `id={tooltipId}` (from `useId()`) and `role="tooltip"`; the
  existing `React.cloneElement(children)` (previously a no-op clone) now
  passes `{ "aria-describedby": isVisible ? tooltipId : undefined }` to
  the child, so the trigger element is only described by the tooltip
  while it's actually shown.
- **Escape-to-dismiss, confirmed exactly matching the PR's WCAG 1.4.13
  rationale**: a `useEffect` gated on `isVisible` registers a
  `document.addEventListener("keydown", handleEscape, true)` (capture
  phase) only while the tooltip is visible, calling
  `event.stopPropagation()` before `setIsVisible(false)` — confirmed this
  is not an `onKeyDown` on the wrapper (which the PR correctly notes would
  never fire for a hover-shown tooltip, since focus is elsewhere), and the
  `stopPropagation()` prevents the same Escape keystroke from also
  reaching `ModalBase`'s own document-level listener and closing a
  surrounding dialog. The effect's cleanup removes the listener, so
  Escape is completely untouched by this component while no tooltip is
  showing.
- **Timer cleanup, confirmed exactly**: a new unmount-only `useEffect`
  clears `timeoutRef.current` if a show-timer is still pending — per the
  PR's own explicit framing, this is disclosed as hygiene rather than a
  functional leak fix (the PR states it measured the surviving timer as a
  no-op today, since React nulls `triggerRef.current` before it fires and
  an existing guard swallows the callback).
- Per the PR (not independently re-verified): showing the tooltip on
  focus is a deliberate, disclosed behavior trade — on browsers that
  focus a button on click, mouseenter→focus→click leaves the tooltip
  visible past the click, and a later mouseleave hides it while focus
  remains on the trigger; gating on `:focus-visible` was considered and
  rejected because `jsdom` returns `false` for `matches(":focus-visible")`
  on a focused button, which would silently disable the tooltip in every
  jsdom-based test exercising it; `Tooltip` is part of the explicit
  kit-facing shared surface (per #1055) and `cloneElement`'s existing
  caveats (silent no-op for prop-swallowing components/Fragments,
  clobbering any pre-existing `aria-describedby` on the child) are noted
  as pre-existing, not introduced by this PR; no
  `ERATO_SHARED_SURFACE_VERSION` bump since no exported type changed; and
  a separately-scoped, disclosed-but-unfixed layout issue remains where
  the `fixed` positioning combined with `bottom-full`/`right-full` classes
  is over-constrained for `"top"`/`"left"` placements (stated as
  unverifiable by unit test since jsdom performs no layout).

## Compatibility and configuration

None breaking for the shared `Tooltip` export's type signature (no
exported type changed, matching the PR's no-version-bump claim). Real,
disclosed behavior change: a tooltip now also shows on keyboard/programmatic
focus of its trigger, not just mouse hover, and can be dismissed with
Escape while visible.
