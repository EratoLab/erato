## Summary

Part 2 of the durable-client-operations work that started with #1363
("Part 1", attached SSE continuation for Outlook). This extends durable
parking to Word document reads specifically: a parked `read_document_blocks`
call can now resume in its original pane and complete, including a live
validated submission afterward, in one continuation — only
`read_document_blocks` opts into durability, per the PR body. Confirmed
via `config.rs`: a new `ClientToolHostContext::WordDocument` variant
(serialized as `"word_document"`) is added alongside the existing
`OutlookMailbox` variant, extending the host-context binding introduced for
Outlook durability to Word documents.

Per the PR description (not independently re-verified beyond the config
surface and file scope): a `word_document` binding hashes document identity
together with a pane-lifetime ID; capture ownership is re-checked after any
asynchronous work, and a lost capture is rejected rather than silently
recaptured. A live-only validated submission fails immediately with
`context_unavailable` if no owner exists at dispatch time (preserving
earlier validation refusal behavior), but once dispatched tolerates up to
15 seconds of observed owner absence so a brief SSE reconnect doesn't
discard an in-flight result; resume observers retry acquisition every
second and owned leases renew every 5 seconds. Ordinary (non-durable)
client calls are unaffected, and the durable+submission combination
remains banned (tracked separately under ERMAIN-944, consistent with the
restriction already confirmed in #1358's review). Recovery-read
rejections, correction-state updates, the 5-attempt limit, and result
fencing from #1361 are stated to be preserved transactionally through this
new resume path.

## Compatibility and configuration

No new user-facing config key beyond the one enum variant shown above
(an internal classification, not a toggle). The feature only activates for
calls already opted into durability via the existing
`client_tools.durable_operations_enabled` foundation (#1249) and a tool's
own `durable` config (#1358) — both off by default. No migration.
