# PR #859: Fix sidebar dropping an unrelated chat when archiving

- PR: https://github.com/EratoLab/erato/pull/859
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Fixes a bug (ERMAIN-474) where archiving one chat could make a completely
different, unrelated chat vanish from the history sidebar until a hard
page reload. Root cause, confirmed by reading `useChatHistory.ts`:
`archiveChat` invalidated the infinite recent-chats query, causing React
Query to refetch every loaded page from its stored offset
(`current_offset + returned_count`). Since archiving shrinks the server's
underlying result set by exactly one row, every page boundary *after* the
archived row's position shifts by one — so an offset-based refetch of a
later page silently skipped whichever chat now straddled that shifted
boundary, without any error.

Fix, confirmed in the diff: instead of invalidating and refetching,
`archiveChat` now optimistically edits the React Query cache in place —
`queryClient.setQueryData` filters the archived chat's id out of every
loaded page's `chats` array and adjusts that page's `returned_count`/
`total_count` stats accordingly, so exactly one row disappears and no
page boundary shifts at all. Two additional correctness details
confirmed: the mutation now snapshots both the previous cache state and
the "pending chat" placeholder (a chat that hasn't landed in a cache page
yet) *before* mutating, and rolls both back on a failed mutation
(`queryClient.setQueryData(infiniteChatsQueryKey, previousData)` plus
restoring the placeholder) — a real improvement over the prior code,
which had no rollback path on failure at all (confirmed via the removed
comment "If using optimistic updates, would need to revert changes here,"
i.e. this exact rollback logic hadn't existed before). As a side effect
of removing the round-trip invalidation, the archived row now disappears
from the sidebar immediately rather than after the mutation completes.
