# PR #1115: Move the attachment chip family onto one tile primitive and themable corner and tint channels

- PR: https://github.com/EratoLab/erato/pull/1115
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Sixth of nine styling-primitives-consolidation topics (after #1092,
#1096, #1100, #1101, #1105). Consolidates four separate hand-rolled
file-chip implementations onto the existing `AttachmentTile` primitive,
plus a new `AttachmentNotice` for status/loading rows. Given the very
large scope (1485 insertions), review focused on the one item most
important to verify directly: a disclosed **live regression on `main`**
found during this PR's manual review pass and fixed as part of it.
Confirmed by reading the complete `Card.tsx` diff:

- **The live "Card" regression and its fix, confirmed exactly**: #1105's
  `Card` primitive moved `flex` from the frame element onto the body,
  which works for `as="div"`/`as="button"` (block-level by default) but
  not `as="label"` or `as="a"` (inline by default) — since neither
  `.card-geometry` nor `.card-skin` sets `display`, a card rendered as a
  label (the share dialog's toggle row is the PR's cited real-world
  instance) stayed `display: inline`, so the browser split the inline box
  around its block-level body, painting the card's border only on the two
  empty zero-content fragments either side — no visible frame at all. The
  fix, confirmed directly in `Card.tsx`: a new `inlineByDefault = as ===
  "a" || as === "label"` check adds a `block` class to the frame in that
  case, with a code comment explaining Tailwind's compiled stylesheet
  order lets an explicit display utility a caller passes still win over
  this default. Confirmed the PR's framing is accurate: this is a genuine
  fix to an already-shipped defect (from #1105, earlier in this same
  styling-primitives series), not merely a chip-topic side effect.
- **The chip family's own core geometry contract, confirmed by direct
  code-comment inspection in the same diff pass**: the PR states
  `.attachment-tile-geometry` deliberately *reads*
  `--attachment-tile-radius` but never *declares* it, so only a
  surrounding frame (the thread card) can set the corner value — a
  pattern directly consistent with this same session's confirmed reading
  of #1100's analogous `--dropdown-item-radius` declare-on-family/read-
  on-member design and #1105's card-radius derivation, both from this
  same consolidation series.
- Per the PR (not independently re-verified given the very large
  remaining scope): the core `AttachmentTile.tsx` rewrite (359 lines)
  gaining `variant`/`selection`/`validation`/`icon`/`hideIcon`/
  `metaLabel`/`showType`/`showSize` props and absorbing two previously
  hand-duplicated behaviors (the label-vs-div click-forwarding footgun,
  and derived filename-extension rendering); the new `AttachmentNotice.tsx`
  (92 lines) consolidating status/loading rows under one `[data-tone]`
  rule; `FilePreviewBase.tsx` becoming a thin shim over the tile (138
  lines, claimed to keep its module/name/twelve-helpers-unchanged public
  shape); five disclosed visible deltas (a border-alpha change isolated
  in its own final commit for easy revert; a meta-separator glyph
  convergence; chips gaining a max-width they previously lacked; a
  read-only thread attachment no longer incorrectly dimming; and
  `FilePreviewLoading` gaining a named `role="status"` live region at six
  call sites); and five additional disclosed review-follow-up fixes
  found during a manual pass and fixed in separate commits within this
  same PR — a list-row radius fix in the assistant-mention picker, an
  `.eml` preview corner-radius/focus-ring fix, an MCP-server row now
  toggling its checkbox from the whole row rather than half of it, status
  filter chips migrated onto `Button` with new min-height/padding, and
  removal of several `@tailwindcss/forms`-dependent classes verified
  inert (the plugin isn't installed) in favor of `accent-color`, the one
  recipe that actually does anything for a native checkbox in this
  codebase.
- **The PR's own stated verification methodology**: a
  Storybook+Playwright harness (`e2e-tests/storybook-chip-retune/`)
  against the real shipped `open-webui-like` theme pack, asserting both
  directions of the radius-inheritance contract (a chip inside a thread
  card takes the card's 9999px pill corner; the same chip outside a card
  stays on the 12px base corner) — stated as verified to actually catch
  the regression class this PR guards against (deliberately re-introducing
  a default on the chip class was confirmed to fail exactly the
  inside-a-card case, not the outside case). Not independently reproduced
  in this review.

## Compatibility and configuration

None functionally breaking for the default (non-override) path. **The
Card `display` fix is a genuine bug fix** correcting a shipped-but-broken
visual defect (the share dialog toggle row rendering with no visible
frame) — a real, positive visible change for any deployment currently on
a version including #1105 but not this PR. Several other small disclosed
visible deltas listed above are individually minor and consistent with
this series' established consolidation-driven-delta pattern.

## Release note disposition

Proposed category: Bug fixes. Worth a mention as a genuine, positive fix:
the share dialog's sharing-toggle row (and any other card rendered as a
label or link) now correctly shows its frame/border and hover/selected
fill, which was silently broken since #1105 shipped earlier in 0.7.0.
Several MCP-server row and assistant-mention-picker click-target/radius
polish items also ride along; the broader chip/attachment-tile
consolidation itself is internal styling infrastructure with minimal
default-visible effect.
