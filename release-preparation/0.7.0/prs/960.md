# PR #960: Show target audience on assistant hub review page

- PR: https://github.com/EratoLab/erato/pull/960
- Status: pending
- Category: Features and enhancements
- Theme: Assistant Hub and assistant sharing

## Summary

Adds an `audience_grants: Vec<ShareGrant>` field to the Assistant Hub
version response
(`backend/erato/src/server/api/v1beta/assistant_hub.rs`), listing the
share grants (viewer/editor grants on the underlying assistant, per #937,
#903) targeting the submission's audience. A new `include_audience_grants`
parameter on the internal `records_to_response` function gates whether
this field is populated (it queries `ShareGrants` filtered by
`resource_type = "assistant"` and the relevant assistant IDs, logging and
degrading to an empty map on a query failure rather than failing the
request). Of the ~10 call sites in this file, only the reviewer queue
listing endpoint (`list_review_versions`, i.e. the reviewer's "review
queue" page) passes `include_audience_grants = true`; all other endpoints
(single version, my-submissions, audience-facing listings) pass `false`
and never include this field. `frontend/src/pages/AssistantHubReviewPage.tsx`
(21-line diff) presumably renders this list so reviewers can see, before
approving, which users/groups (or the whole organization, per #903/#961)
an assistant is shared with.

## Compatibility and configuration

None. Purely an additive API response field and reviewer-page UI change;
no configuration keys or migrations. No breaking change to existing API
consumers (new optional field, only populated for one specific endpoint).
