# PR #822: Export message-rendering surface for component kits + stable i18n ids

- PR: https://github.com/EratoLab/erato/pull/822
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Phase 1 of a component-kit de-duplication effort: expands
`frontend/src/library/index.ts`'s exported surface so downstream
"component kit" consumers (e.g. the Beckhoff white-label kit, which
per the PR currently carries ~2000 lines of frozen forked copies) can
consume the base `Trace`/`MessageContent` rendering tree directly instead
of maintaining their own copy — motivated by a stated regression (a
missing status indicator) and staleness (the kit missing the #800
clipboard fix) caused by that forking. Confirmed by reading the code:

- `library/index.ts` newly exports the `Trace` subsystem
  (`Trace`, `groupIntoTraceClusters`, `isTraceablePart`,
  `durationFromTracePartsOrLegacyMessageTimestamps`, and the
  `TraceCluster`/`TraceablePart` types), `ImageContentDisplay`, the
  registry-aware `EratoEmailSuggestion` component (previously only its
  `DefaultEratoEmailCodeBlock` default was exported), `useTraceFeature` +
  `TraceFeatureConfig`, and a new `UiImagePart` type.
- `componentKitReactRuntime.ts` now also assigns
  `window.ERATO_FEATURES = { useTraceFeature }`, giving a kit's own bundle
  runtime access to the trace-feature hook without bundling React context
  plumbing itself; a version-negotiation handshake for this runtime
  surface is explicitly deferred to a later "governance phase," per the
  PR.
- Twenty previously auto-hashed `t` macro strings across
  Trace/ToolCall/MessageContent/EratoEmailSuggestion are converted to
  explicit, stable ids (`trace.*`, `toolcall.*`, `chat.message.*`) —
  confirmed in `TraceClusterHeader.tsx`'s diff, matching the existing
  `trace.reasoning.masked` naming convention already in use. The PR
  explicitly flags that this changes compiled catalog keys, which would
  detach any theme override keyed by the old auto-generated hash id, and
  states this was checked against all three known themes
  (beckhoff/trilux/novoferm) with none affected — not independently
  verifiable from this repository (those theme definitions live outside
  it), so this claim is taken on trust from the PR author rather than
  re-derived.

## Compatibility and configuration

No backend/config changes. Frontend-library-surface change only: new
named exports from `@erato/frontend/library` (additive, no existing
export removed or changed in shape) and new `window.ERATO_FEATURES` global
assignment. The i18n id changes are a compiled-catalog-key breaking change
for any external theme that overrides one of the 20 affected strings by
its old auto-generated hash id rather than by an explicit id — per the
PR, no currently-known theme does this, but this is worth flagging
explicitly in release notes for any theme maintainer relying on
string-hash overrides.

## Evidence and review

Verified via this PR's squash-merge commit against its parent (both
present locally). Read in full: the complete `library/index.ts` diff and
`componentKitReactRuntime.ts` diff (confirming every new export and the
`window.ERATO_FEATURES` assignment exactly as described), and the
`TraceClusterHeader.tsx` diff (confirming the stable-id conversion
pattern). Not read in full: the remaining 7 component files with i18n id
changes (`ToolCallInput.tsx`, `ToolCallOutput.tsx`, `TraceDoneMarker.tsx`,
`TraceThinkingPlaceholder.tsx`, `useThinkingDuration.ts`,
`ReasoningStep.tsx`, `ToolUseStep.tsx`) or the five `.po` locale catalog
diffs (174 lines each, described as translation relocation under the new
stable ids — mechanical, following the source id changes). PR description
is precise and matches the shipped code exactly for everything checked.

## Release note disposition

Proposed category: Features and enhancements (internal/library-consumer
facing, not end-user visible in the base product). Worth noting for
anyone maintaining a custom component-kit theme: string translation keys
for 20 trace/tool-call/message strings changed from auto-generated hashes
to stable explicit ids — a theme overriding these by hash id needs to
migrate to the new ids.
