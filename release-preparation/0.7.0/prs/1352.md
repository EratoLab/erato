# PR #1352: Include the open Word document by default and keep one chat per document (ERMAIN-945) (#1352)

- PR: https://github.com/EratoLab/erato/pull/1352
- Status: pending
- Category: Features and enhancements
- Theme: Word add-in

## Summary

Changes how the Word add-in pane relates to the open document, to match how
the Outlook add-in already treats the current item:

- **Included by default.** A new chip reads "<name> is included" with a ✕ to
  remove it for that chat; a user-made selection, when present, is sent
  instead of the whole document. Confirmed in `config.rs`: a new
  `MsOfficeAddinDefaultSettings.word_include_document` field (default `true`)
  controls the admin-level default, with a user-facing override surfaced in a
  new Word settings tab.
- **One chat per document.** The open chat now lives in pane state keyed by a
  hashed document URL, so reopening a saved document resumes its own chat;
  an unsaved document always starts a new chat, and a chat that 404s is
  forgotten. This replaces a single shared `erato.addin.word.currentChat.v1`
  storage key that previously meant every open document shared one chat.
- **No stall on send.** The document capture is taken ahead of time and
  reused until Word reports a change, so sending a message doesn't block
  waiting on a fresh read. The composer stays usable while the capture is in
  flight, Stop/✕ end the wait immediately, "Send without document" appears
  after 8 seconds, and a 30-second deadline falls back to an earlier capture.
  A failed full-package capture (including documents over 4 MB) falls back
  to read-only text review instead of silently dropping the document
  entirely.

## Compatibility and configuration

New optional config key, defaulting to today's effective behavior:

```toml
[integrations.ms_office.addin.default_settings]
word_include_document = true  # default
```

Confirmed via the `config.rs` diff: the field is added to
`MsOfficeAddinDefaultSettings` with `default_ms_office_addin_word_include_document()
-> true`, and surfaced in `backend/generated/config_reference.json`. No
migration; existing deployments get the new "include by default" behavior
unless they explicitly set this to `false`. The replaced
`erato.addin.word.currentChat.v1` browser-storage key is a client-side
implementation detail with no server-side migration needed.
