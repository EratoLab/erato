# PR #848: Take button radii from theme tokens (frontend + add-in)

- PR: https://github.com/EratoLab/erato/pull/848
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Continues the #843–#847 theming-consistency sweep, this time targeting
raw `<button>`/card elements that hardcoded a Tailwind radius value
instead of a `--theme-radius-*` token, plus a real Tailwind build-config
bug affecting the Outlook add-in. Confirmed by reading the code:

- **Tailwind content-glob fix (the substantive part of this PR).** The
  add-in ships no Tailwind build of its own — it renders against
  `@erato/frontend/library.css` (the frontend's compiled stylesheet) — but
  the frontend's `tailwind.config.ts` `content` glob only scanned
  `frontend/src`, not the add-in's own source. Confirmed in the diff: a
  class used only in `office-addin/src` and never in `frontend/src` was
  silently dropped from the compiled CSS and never took effect at all.
  The PR's concrete example, `border-t-theme-fg-primary` (the add-in's
  loading spinner's top-border color in `AddinChatInput.tsx`), is a real,
  previously-broken visual bug this fix surfaces and resolves — not
  independently re-verified by building the CSS myself, but the code
  change (`content: [..., "../office-addin/src/**/*.{js,ts,jsx,tsx}"]`) is
  exactly what's needed to fix it, and a missing directory matching
  nothing means a standalone frontend-only build is unaffected. Per the
  PR, this glob addition also causes 12 other previously-dropped
  utilities to newly take effect in the add-in (`py-5`, `pr-1`, `-mx-1`,
  `shadow`, `max-w-*`, `max-h-[600px]`, `space-y-0.5`, `overscroll-none`,
  `isolate`, `invert`, `focus-visible:bg-*`), several of which are
  described as layout-visible and intentional side effects of the fix
  rather than unrelated scope creep.
- **Radius tokenization**, mapped to different tokens by affordance rather
  than a blanket sweep: `--theme-radius-control` (dropdown row, prefs tab,
  email copy button, add-menu rows, `FrequentAssistantsList`; add-in
  client-action buttons/settings tabs/injected add-menu rows/three dismiss
  buttons), `--theme-radius-shell` (`CloudDriveList` card/wrapper/skeleton,
  `AssistantHubPage` tile), `--theme-radius-message` (`EmlPreview`
  attachment chip; add-in composer status chips and email/appointment
  cards).
- Confirmed two genuinely coupled cases handled with real care, not just
  find-replace: `CloudDriveList`'s drive-row button now rounds only its
  **top** corners when a footer (`drive.web_url`) is present, so its hover
  fill meets the footer border squarely rather than curving away from it
  — with an explained reason the wrapper can't simply clip instead
  (`focus-ring` is an offset/outset ring that `overflow-hidden` would cut
  off). `SegmentedControl`'s track and its selected-segment chip are
  concentric (`calc(var(--theme-radius-control) - 0.125rem)` for the
  inner segment), reproducing the exact previous 0.5rem/0.375rem
  relationship at the default theme so nothing visually shifts there,
  while both move together under a themed radius so the selected chip's
  corners can never bulge past the track's.
- Confirmed explicitly-scoped exclusions: `rounded-full` circular elements
  (assistant avatar, modal close, tooltip, trace pill) are deliberately
  left untokenized, since an existing legacy compatibility shim
  (`withBorderRadiusCompatibility`, locked in by an existing test) maps a
  tenant's top-level `borderRadius` override onto every radius token
  including `pill` — tokenizing these circular elements would turn an
  80px circular avatar into a rounded square for tenants using that
  legacy override.
- The PR explicitly scopes itself as a **partial** sweep, citing ~166
  remaining hardcoded `rounded-*` instances repo-wide (naming several
  specific untouched components) and one remaining `rounded-full` add-in
  spinner.

## Compatibility and configuration

None new. Visual-only changes under the default theme (a detailed
before/after radius table is given in the PR body, not independently
re-verified value-by-value beyond the two coupled cases read directly).
The Tailwind content-glob fix is a real, previously-silent add-in styling
bug fix — the add-in's compiled CSS bundle grows slightly (the PR states
+1,007 bytes minified) as previously-dropped utility classes start being
emitted.

## Evidence and review

Verified via this PR's squash-merge commit against its parent (both
present locally). Read in full: the `tailwind.config.ts` diff (content
glob fix), the `CloudDriveList.tsx` diff (top-corner-only conditional
rounding), and the `SegmentedControl.tsx` diff (concentric radius
calculation) — all matching the PR description precisely, including the
documented rationale in code comments. Not independently re-verified:
the remaining ~13 single-line radius-token swaps across
`AssistantWelcomeScreen.tsx`, `ChatInputAddMenu.tsx`,
`FrequentAssistantsList.tsx`, `DropdownMenu.tsx`, `EmlPreview.tsx`,
`EratoEmailSuggestion.tsx`, `UserPreferencesDialog.tsx`,
`AssistantHubPage.tsx`, and the six add-in component files — these are
low-risk, mechanical, and the description's affordance-by-affordance
mapping is internally consistent with what was verified. The claimed CSS
bundle size delta was not independently re-measured.

## Release note disposition

Proposed category: Bug fixes. The add-in Tailwind content-glob fix is
worth a specific mention (it fixes a previously-silently-broken spinner
color and unblocks other add-in-only styling), while the general radius
tokenization is minor visual polish likely worth folding into a general
"UI/theming polish" line alongside #843–#847.
