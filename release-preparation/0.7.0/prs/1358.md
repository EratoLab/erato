# PR #1358: Let configured client tools survive a dropped stream through durable operations (ERMAIN-911) (#1358)

- PR: https://github.com/EratoLab/erato/pull/1358
- Status: pending
- Category: Features and enhancements
- Theme: MCP / Durable operations

## Summary

Extends the durable-client-operations foundation (added disabled in an
earlier PR, #1249) so configured client tools — not just native local
evidence — can opt into durable parking. Confirmed via the `config.rs` diff:
a new optional `[client_tools.tools.<id>.durable]` table (`ClientToolDurableConfig`)
lets a tool declare an `attempt_expiry_secs`, `claim_lease_secs`, and an
optional `result_schema`. When a durable-opted-in tool's call has its stream
drop or time out, it now parks instead of simply ending in a timeout; the
same device and host context (a reopened pane, or a second tab) can later
claim and finish it, resuming the turn. The first production opt-in is the
Outlook `fetch_availability` tool (reviewed earlier this session). All other
client tools, native local-evidence durability, and the feature-off path are
unchanged — `durable_operations_enabled` still gates all of it.

Startup validation is strict and specific, confirmed exactly from the code:
`durable` cannot be combined with `submission` on the same tool (panics
otherwise); `attempt_expiry_secs` must be 60–86400 seconds; `claim_lease_secs`
must be 60–900 seconds and no larger than `attempt_expiry_secs`; and
`attempt_expiry_secs` must be large enough to cover the tool's own
`timeout_ms` plus the claim lease, so a park triggered by a timeout can't
immediately expire before anything claims it. An invalid `result_schema` (if
set) is compiled at startup and panics on failure.

Per the PR (not independently re-verified beyond the config surface): the
consent model (the existing #1268 Ask-gate approval card is reused unchanged;
approved calls park as `none`; "Never" settles a waiting call as `withdrawn`
and withdraws an already-parked one at claim time); malformed results
becoming fixed feedback with duplicate/late results fenced; and the frontend
handler registry, hashed-mailbox `X-Erato-Executor` header, Web Lock for
single-execution-per-browser, and refetch-on-status-change behavior.

## Compatibility and configuration

New optional per-tool table, inert unless both
`client_tools.durable_operations_enabled = true` and the tool itself opts
in:

```toml
[client_tools]
durable_operations_enabled = true

[client_tools.tools.outlook_fetch_availability.durable]
attempt_expiry_secs = 300   # 60-86400
claim_lease_secs = 60        # 60-900, and <= attempt_expiry_secs
# result_schema = "..."      # optional JSON Schema, compiled at startup
```

No migration. Cannot be combined with an existing `submission` block on the
same tool — startup panics if both are set. No behavior change for a tool
that doesn't declare `durable`.
