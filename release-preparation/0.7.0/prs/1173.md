# PR #1173: Let a message renderer consume host behaviour instead of copying it

- PR: https://github.com/EratoLab/erato/pull/1173
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Third PR in the ERMAIN-810 series (after #1145, #1161), continuing the
pattern of extracting reusable hooks a `ChatMessageRenderer` override can
consume instead of re-deriving. Motivated by a concrete, disclosed
incident: the openwebui component kit's message renderer had grown to
793 lines by copying host logic to reach the same markup, and the copy
drifted into four real defects (a redundant per-attachment `GET
/files/{id}` refetch, lost `relatedFiles` breaking preview-navigation
siblings, assistant-generated documents never rendering, and dead
@-mention highlighting from a dropped `mentionedAssistants`). Confirmed
the central "extraction plus re-consumption" architecture claim by
direct code inspection:

- **`ChatMessage` genuinely consumes its own extracted hooks — one
  implementation, not two — confirmed exactly**: `useChatMessageRenderer`
  is both *defined* in `ChatMessage.tsx` and *called* by the `ChatMessage`
  component itself (`= useChatMessageRenderer(props)`), and both
  `useChatMessageRenderer` and `useMessageAttachmentFiles` are confirmed
  pinned as explicit named exports on the kit-facing `kit-surface.ts`
  (this session's earlier reviews of #1055/#1138/#1145 established this
  is the deliberate, enforced kit-contract pattern for this codebase).
  This directly substantiates the PR's claim that the host's own
  rendering and a kit's override now run through identical logic, rather
  than the host having one implementation and a kit-consumable "public"
  version drifting from it.
- **`MessageErrorAlert` renders nothing without an error, confirmed
  exactly**: the component's first check is `if (!message.error) { return
  null; }` — matching the PR's claim that it's safe to place
  unconditionally in an override's markup, with no `length`/`hasError`
  guard needed at the call site.
- Per the PR (not independently re-verified given remaining scope): the
  specifics of what `useMessageAttachmentFiles` derives (the assistant-
  side `text_file_pointer` union, the sibling `relatedFiles` list, Teams
  grouping, and files the conversation already holds — stated to close
  the redundant-refetch and lost-siblings defects); what
  `useChatMessageRenderer` derives beyond the confirmed self-consumption
  (`userDisplayNameOverride` precedence, `mentionedAssistants` scoped to
  the user-message branch only — stated to close the dead-@-mention-
  highlighting defect); the prerequisite first commit moving
  markup-free `t()` translation helpers out of `ChatMessage.tsx` into
  their own module (`messageErrorCopy.ts`, 156 lines) with the PR's
  claimed `.po` churn being origin-comment-only (`#:` lines), not actual
  wording changes; and the `459`-line net reduction in `ChatMessage.tsx`
  itself as the host's own code shrinks to use the same extracted pieces.
- **Disclosed verification claim, not independently reproduced**: the PR
  states the full test suite passes with no existing test edited (purely
  additive new test files: `MessageErrorAlert.test.tsx`, 234 lines;
  `messageErrorCopy.test.ts`, 106 lines).

## Compatibility and configuration

None breaking, and no behavior change for the host's own rendering
(confirmed via the direct self-consumption architecture). For
component-kit consumers: a `ChatMessageRenderer` override can now import
`MessageErrorAlert`/`useMessageAttachmentFiles`/`useChatMessageRenderer`
from the kit surface instead of re-deriving the same logic, closing the
specific drift-driven defects this PR's incident report describes. The
companion kit-side change (reducing the openwebui renderer from 793 to
245 lines) lives in a separate repository (`erato-subscription-content`
PR #19), not reviewable here.

## Release note disposition

Proposed category: Bug fixes (component-kit extension-point completeness,
no end-user-visible effect for the standard host). Not release-note-worthy
for the open-source product itself; relevant to component-kit-maintaining

attachment-preview navigation, non-rendering generated documents, dead
@-mention highlighting) in a custom message renderer.
