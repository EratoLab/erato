# PR #1344: Refuse Word selection rewrites that would flatten formatting, and explain bookmarks (ERMAIN-939)

- PR: https://github.com/EratoLab/erato/pull/1344
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: Word selection editing

## Summary

Per the PR description: a follow-up to #1342 (ERMAIN-938, kept items),
addressing several correctness edge cases in the Word Replace feature
built up over this batch. Confirmed directly in `wordSelectionSpan.ts`:
a bookmark other than Word's own `_GoBack` auto-bookmark now sets a
dedicated `hazards.bookmark` flag (previously lumped into the generic
`breakOrSymbol` hazard), giving the refusal card honest, bookmark-specific
copy instead of a generic "special character" message — per the PR, this
followed a probe ("BM0") confirming `getOoxml` reliably lists bookmarks on
Word for PC and the web, but not independently probed on Word for Mac,
where the span checks additionally call `getBookmarks(true, true)` as a
belt-and-suspenders check at both capture and final-check time. Per the
PR's description (not independently verified beyond this): a paragraph
written whole as OOXML to preserve kept items (links, fields, comments,
pictures — from #1342) now also refuses a rewrite that would narrow
inconsistent formatting (color, highlight, font, size, character style)
down to one value, the same rule the plain-text path already applied;
mixed superscript/subscript text (e.g. "m²", "CO₂") becomes context-only
on both paths with a new `mixed_script` reason; and a new
`flattensEmphasis` flag on the capture snapshot surfaces in the card next
to Replace when mixed bold/italic/underline/strikethrough would be
flattened, refusing the write if that emphasis is still present at Send
time, with "Replace selected passage" (from #1338) similarly refusing a
picked copy that has such emphasis when the original request's passage
didn't. An unused `facts.trackedRange` hint and `HINT_CONFLICT` are
removed as dead code per the PR.

## Compatibility and configuration

Bug fix / correctness hardening to the Word Replace feature introduced
earlier in this batch; no config keys, no database migration. Net effect:
some selections that previously silently flattened formatting or gave a
misleading "special character" refusal reason now refuse more honestly or
with clearer copy — a stricter default where the feature already existed,
not a new capability.
