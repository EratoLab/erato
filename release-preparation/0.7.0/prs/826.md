# PR #826: Versioned ERATO_KIT_RUNTIME host surface for component kits

- PR: https://github.com/EratoLab/erato/pull/826
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Third piece of the component-kit de-duplication effort (#822, #825): a new
global, versioned runtime surface, `window.ERATO_KIT_RUNTIME`, exposing
host hooks and UI atoms that kits previously re-implemented as hand-written
stubs. Per the PR, an audit of the Beckhoff kit's ~1100-line stub layer
found several of those stubs silently degraded real functionality
(archive-without-confirm since the stub `DropdownMenu` declared but never
implemented `confirmAction`, message feedback hardcoded off regardless of
config, `useGetFile` never resolving, full page reloads instead of SPA
navigation, empty starter prompts, plus assorted accessibility losses).
Confirmed by reading the new `componentKitHostRuntime.ts` (87 lines) in
full:

- `window.ERATO_KIT_RUNTIME = { version: 1, hooks: {...}, components:
  {...} }` is set with exactly the 6 hooks (`useTraceFeature`,
  `useMessageFeedbackFeature`, `useStarterPromptsData`, `useThemedIcon`,
  `useGetFile`, `useNavigate`) and 10 components (Alert, Avatar, Button,
  ChatHistoryListSkeleton, DropdownMenu, FilePreviewButton,
  FilePreviewLoading, ImageLightbox, InteractiveContainer, ModelSelector)
  the PR description lists.
- Confirmed a subtle, explicitly documented timing constraint: this module
  is imported from `main.tsx` (the app graph), not from the earlier
  `componentKitReactRuntime` pre-app boot entry (deliberately, to avoid
  bundling most of the app into that boot script) — meaning
  `ERATO_KIT_RUNTIME` is populated *after* a kit's own bundle has already
  evaluated, so a kit must read these values lazily inside its
  components/hooks at render/call time, never destructure them at module
  scope (which would capture `undefined`).
- `version: 1` is a literal type, intended to be bumped on breaking shape
  changes so kits can detect a mismatch against what they were built
  against (the PR notes this check is kit-side, not enforced by the host).
- `ChatMessageHostComponents` (from #825) additionally gains
  `LoadingIndicator`, exported alongside the existing `MessageContent`
  entry.
- The pre-existing `ERATO_FEATURES` global from #822 is left completely
  untouched, so already-deployed kit bundles built against it keep
  working unmodified.
- `ComponentKitHostRuntime` is exported from `@erato/frontend/library` as
  a type-only export (erased at compile time, per the PR) so kits get
  compile-time safety against the runtime shape without a runtime
  dependency.

## Compatibility and configuration

None for the base product — purely additive infrastructure for external
component kits. No existing kit is forced to adopt this (per the PR,
`ERATO_FEATURES` remains available unchanged for kits already built
against it); this is opt-in for a kit choosing to replace its own stub
layer with delegation to the host runtime.
