# PR #1033: Add-in: AddinStartView extension point with start/chat view switcher

- PR: https://github.com/EratoLab/erato/pull/1033
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Stacked on #1032. Adds a new component-kit extension point,
`componentRegistry.AddinStartView`: when a kit registers it, the Outlook
task pane opens on that view instead of chat, with a floating toggle to
switch between the two. Confirmed by reading the registry type and the
new switcher component in full:

- **Strict no-op with no registration, confirmed via both
  `componentRegistry.ts` and `OutlookStartViewSwitcher.tsx`**: the new
  `AddinStartView` registry key defaults to `null` (added to
  `emptyComponentRegistry`), and the switcher component's top-level check
  `if (!StartView) { return <>{children}</>; }` renders its children
  completely untouched — no toggle button, no wrapper markup change beyond
  what's needed to host the button — when nothing is registered.
- **Token degradation for hosts without client-side auth, confirmed**:
  `useGraphTokenOptional()` returning falsy (the doc comment states this
  covers hosts like Exchange on-prem behind oauth2-proxy) makes the
  `acquireToken` prop passed to the start view `undefined` via the
  `useMemo` early-return, matching the registry type's own doc comment
  that a start view "MUST render a usable state without it."
- **`skipSessionWarm` always passed, confirmed**: every token acquisition
  routed through the switcher's `acquireToken` wrapper spreads the
  caller's options and unconditionally adds `skipSessionWarm: true` —
  directly building on #1032's new option, consistent with the doc
  comment that start views request custom-audience API tokens the proxy
  cannot use to warm its session.
- **Session-policy hold while the start view is shown, confirmed**: a
  `useEffect` keyed on `startViewActive` (`StartView !== null && view ===
  "start"`) calls `holdSessionPolicy()` and `dismissSessionToasts()` on
  entry and `releaseSessionPolicy()` on cleanup — matching the PR's claim
  that this reuses the same counted gate as the history drawer, so a
  mail-item switch cannot surface a session-ask toast over the start view.
- Per the PR (not independently re-verified given remaining scope): the
  `OutlookStartViewSwitcher` mounts inside `AddinChatProviderCore` at
  `OutlookAddinChatPage`, so chat context, session policy, and any active
  stream survive toggling; the trigger-clearance rows (pin banner,
  delegated-run header, `TopLeftAccessory` wrapper) gain a symmetric
  `pr-10` only while a start view is registered, to avoid the floating
  toggle overlapping their content; and a new shared `ChatBubbleIcon`
  (from iconoir's `ChatBubbleEmpty`) is added and exported to the
  kit-shared surface.

## Compatibility and configuration

None for existing deployments. Purely additive extension point defaulting
to `null`/no-op, confirmed at the two gating points above — an add-in
build with no kit-registered `AddinStartView` opens directly into chat
exactly as before, with byte-identical rendering. No API or database
changes; purely a frontend/add-in-side component-kit contract addition.
