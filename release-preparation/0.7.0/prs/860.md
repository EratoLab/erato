# PR #860: Add desktop-sidecar distribution contract

## Summary

Pure documentation/specification addition — no application code. Adds
`desktop-sidecar-protocol/DISTRIBUTION.md` (323 lines), a normative
(RFC-2119/BCP-14-style "MUST"/"SHOULD") contract defining how the backend
discovers and serves desktop-sidecar installer artifacts from its
filesystem, ahead of implementing that serving logic in a later PR. Key
points documented:
- Exactly one unversioned artifact set is deployed at a time, at a
  configurable root defaulting to `/app/desktop-sidecar-artifacts`, replaced
  wholesale on each deployment (no version directories/channels).
- A single `manifest.json` at the artifact root describes every
  target/platform (`windows-x86_64`, `windows-aarch64`, `macos-x86_64`,
  `macos-aarch64`, `linux-x86_64-gnu`, `linux-aarch64-gnu`) and file within
  it (e.g. `.exe`/`.msi` for Windows, `.app.zip` for macOS,
  binary+`.tar.gz` for Linux).
- Artifact signing/integrity is explicitly out of scope for this contract —
  the responsibility of the build/deployment pipeline, not the manifest.
- New target platforms may be added as new manifest entries without
  changing the overall layout.

Small related edits to `desktop-sidecar-protocol/README.md`,
`SPEC.md`, `TRANSPORT.md`, `package.json`, and
`scripts/package-spec.mjs` (21, 4, 2, 1, 1 lines respectively) cross-link
or reference the new distribution contract.

## Compatibility and configuration

No configuration keys, migrations, or runtime behavior in this PR — it is
specification-only. The documented default artifact root
(`/app/desktop-sidecar-artifacts`) and its configurability are a
forward-looking contract for backend code landing in later PRs
(implementation not present here).
