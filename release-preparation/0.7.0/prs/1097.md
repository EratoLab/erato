# PR #1097: Upgrade to rmcp 3.2.0; Support OAuth2 resource override

- PR: https://github.com/EratoLab/erato/pull/1097
- Status: pending
- Category: Dependency changes
- Theme: MCP controls

## Summary

Upgrades the `rmcp` MCP SDK dependency to the registry release `3.2.0`
(previously presumably an older/patched version). To work around a gap in
that SDK version — its OAuth resource validator requires the resource and
endpoint origins to match, with no public API to override or omit the
`resource` parameter, needed for real-world providers like Entra-protected
APIs where the resource differs from the MCP endpoint's own origin — this
PR adds a new internal crate, `backend/erato_mcp_oauth`, wrapping rmcp's
public `OAuthHttpClient` hook (no vendored/patched SDK code). It exposes
three resource-selection modes via a new config key
`mcp_servers.<server-id>.authentication.oauth2.resource`:
- Unset (default): use the resource identifier advertised by Protected
  Resource Metadata (PRM) discovery; if PRM/its resource field is absent,
  fall back to the MCP endpoint URL with query/fragment stripped
  (preserving existing/prior behavior).
- A non-empty absolute URI: override the PRM-advertised resource with this
  exact value.
- An empty string (`resource = ""`): omit the `resource` parameter
  entirely from authorization/token requests, taking precedence over PRM.

Per the crate's own README, this relaxes only rmcp's endpoint/resource
identity comparison and missing-resource check — it does not change
authorization-server URLs, rewrite issuer metadata, or fetch the resource
URI itself; redirect policy, response-size limits (1 MiB), PKCE, issuer
validation, and credential storage all remain the SDK's responsibility
unchanged. A new `mock-mcp-server/tests/oauth_resource.rs` (502 lines)
regression-tests all three modes across authorization, code exchange, MCP
calls, and refresh, plus metadata fallback and callback issuer validation,
without requiring a live Entra tenant.

## Compatibility and configuration

New optional per-server key, defaulting to unset (preserves prior
PRM/endpoint-fallback behavior — no change for existing MCP OAuth
configurations that don't set it):
```toml
[mcp_servers.<server-id>.authentication.oauth2]
resource = "https://api.example.com"  # or "" to omit, or leave unset
```
No migration; existing encrypted OAuth credential/state formats are
unchanged (still using the SDK's serde representations, per the README).
This specifically unblocks MCP servers behind OAuth providers (e.g. Entra
ID) whose protected-resource identifier legitimately differs from the MCP
transport endpoint's own origin — previously rmcp 3.2.0's stricter
same-origin resource check would have rejected such a configuration.
