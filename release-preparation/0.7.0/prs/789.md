# PR #789: Add option to deselect individual guardrails

- PR: https://github.com/EratoLab/erato/pull/789
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Guardrails and prompt-injection filtering

## Summary

Adds a new `exclude_pattern_ids` list to the prompt-injection guardrail
filter configuration (`PromptInjectionFilterConfig` in
`backend/erato/src/config.rs`). After patterns are selected via
`filter_pattern_ids` and/or `filter_pattern_tags`, any pattern ID also
present in `exclude_pattern_ids` is removed from the applied set
(`backend/erato/src/services/prompt_guardrails.rs`, `selected_patterns`).
This lets an operator apply a broad tag-based rule set (e.g. all patterns
tagged `"input"`) while opting individual patterns back out, e.g. for a
known false positive, without having to enumerate every other pattern ID
individually. Config validation rejects an `exclude_pattern_ids` entry that
does not reference a known pattern in `guardrails.prompt_patterns`.

## Compatibility and configuration

New optional keys, both defaulting to an empty list (no behavior change for
existing configs):
- `chat_providers.all_providers.guardrails.filter_input_prompt_injection.exclude_pattern_ids`
- `chat_providers.providers.<provider-id>.guardrails.filter_input_prompt_injection.exclude_pattern_ids`

No migration required. Documented in `site/content/docs/configuration.mdx`
with an example (`exclude_pattern_ids = ["customer_specific_false_positive"]`).
