# PR #991: Add ability to consume translation authored via admin-panel

- PR: https://github.com/EratoLab/erato/pull/991
- Status: pending
- Category: Features and enhancements
- Theme: None

## Summary

Completes the configuration-hot-reload feature that #913 stubbed out
(that PR's listener previously only logged "reload is not implemented
yet"). This PR adds the ability to serve translation overrides authored
externally (by an "admin panel", per the constant
`ADMIN_PANEL_SOURCE_SERVICE = "erato_admin_panel"`) from the database,
live, without a redeploy:

- New `backend/erato/src/distribution/runtime.rs`: `ReloadableAppState`
  holds a `DistributionBundle` of translation `.po` files loaded from the
  `runtime_configuration` table (filtered to
  `source_service = "erato_admin_panel"` and
  `source_type = "translation_po"`), stored behind an `RwLock` on
  `AppState` (`app_state.reloadable`) so readers always see a complete,
  atomically-swapped bundle. Filenames are validated to the narrow
  `overrides/<locale>.po` pattern (`translation_locale`), rejecting empty,
  nested, or otherwise malformed names (covered by a unit test including
  a path-traversal attempt, `"../overrides/de.po"` → `None`) — a
  deliberate security boundary independent of filesystem path handling.
- `ConfigurationReloadListener` (from #913) now actually calls
  `ReloadableAppState::load` and swaps the in-memory state when a Postgres
  `NOTIFY configuration_changed` arrives, logging and keeping the previous
  state on a reload failure rather than crashing.
- Two new HTTP routes in `backend/erato/src/server/router.rs`:
  `GET /public/common/overrides/index.json` (lists available override
  locales) and `GET /public/common/overrides/{locale}` (compiles and
  serves the matching `.po` override as JSON via the existing
  `TranslationPoCache`, `Cache-Control: no-cache`). `frontend/src/lib/i18n.ts`
  (32-line diff) presumably makes the frontend consult these routes/merge
  the override catalog.

## Compatibility and configuration

No new top-level configuration keys — this activates only when
`runtime_configuration.enabled = true` (existing flag) and the
`erato_admin_panel` source actually writes rows of type `translation_po`
into `runtime_configuration` (an external producer, not part of this
repository). No migration. For deployments without such an admin panel
writing to this table, the new routes simply return an empty locale list
/ 404 for any locale, with no behavior change. This is one of the first
uses of the reload-on-`NOTIFY` mechanism added (as a stub) in #913.
