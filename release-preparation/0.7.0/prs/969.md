# PR #969: Teach and resolve Teams transcript message citations

- PR: https://github.com/EratoLab/erato/pull/969
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Closes the citation loop for attached Teams transcripts: the model can
now cite a specific transcript message by its ordinal (from #956), and
clicking that citation jumps to and highlights the message in the
transcript preview (from #967). Confirmed by reading the full chain:

- `buildTeamsTranscriptFile.ts` appends one fixed teaching line to the
  transcript's prose: `To cite a message above, link its ordinal as
  [n](erato-file://<file_id>#msg=n), where <file_id> is this file's
  erato_file_id.` Confirmed this genuinely names **no real identifier** —
  `<file_id>` is a literal placeholder in the instructional text, and the
  model is expected to substitute the actual `erato_file_id` value the
  backend prepends to every attached file's content as a header (a real,
  pre-existing mechanism, confirmed present at several call sites in
  `file_resolution.rs`/`embedded_images.rs`) — so this preserves #956/#957's
  token-diet work: no message ids, chat ids, or file ids appear anywhere
  in the transcript payload itself, only in this one generic instructional
  line plus the runtime-injected file-id header that already existed for
  other purposes.
- `MessageContent.tsx`'s existing PDF-specific `#page=N` deep-link anchor
  handling is generalized (confirmed via full diff) into a
  `getAnchorParam` helper accepting either `?param=` or `#param=N` forms,
  with the anchor name chosen by file extension: `.pdf` → `page`, `.md` →
  `msg`. A resolved `#msg=N` link now correctly builds a `preview_url`
  carrying that anchor and routes into the file-preview modal, matching
  the existing PDF page-link behavior's code path exactly (the
  `previewFile` construction condition is widened from
  PDF-specific to any resolved anchor value).
- `TeamsTranscriptPreview.tsx` reads the `#msg=` fragment off its own URL
  (confirmed `fetch()` is called against the base URL, ignoring the
  fragment — the same established pattern `PdfPreview` already uses for
  `#page=`) and passes it as a new `focusOrdinal` prop to
  `TeamsConversationView`, which scrolls that message into view on mount
  and keeps it visually highlighted — not independently verified in
  `TeamsConversationView.tsx`'s own 29-line diff, but consistent with the
  rest of the confirmed chain.
- Per the PR, the citation click resolves entirely within the app's own
  preview; the separate per-message "Open in Teams" deep-link button
  (from earlier PRs in this arc) remains the only path to actually leave
  the app and open Teams itself — not re-verified live against the Teams
  client in this review, taken on trust from the PR's own stated live
  verification.
