# PR #1314: Add optional retrieve_file_contents backend tool and read truncated file content

- PR: https://github.com/EratoLab/erato/pull/1314
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: File previews and formats

## Summary

Adds an optional built-in `retrieve_file_contents` tool that lets the model request the full content of files that were initially included as truncated previews due to per-file token budgets (introduced in #1309). This completes the file context budget feature: files are sent as token-efficient previews, and the model can request more detail as needed.

**New `file_retrieval` service** (376 lines). Implements the `retrieve_file_contents` tool with the following behaviour:

- **Input**: A `file_id` parameter identifying which file to retrieve.
- **Output**: The full file content, decoded from the stored blob, along with MIME type and size metadata.
- **Access control**: Only files that were included in the current chat's context (and marked as truncated) can be retrieved. The tool refuses requests for files outside the active context.
- **Token tracking**: When the tool returns file contents, the token usage is accounted against the chat's context budget. Multiple retrievals of the same file within a turn are deduplicated for token accounting.

**Integration with the file context budget system.** The `file_context.rs` service (102 lines changed) marks files that were truncated due to budget limits as "retrievable." The file resolution and token estimation services are updated to track which files have been truncated and to supply the `retrieve_file_contents` tool offer when at least one truncated file exists in the context.

**Configuration.** The tool is off by default and must be enabled:

```toml
[mcp]
builtin_tools = ["retrieve_file_contents"]
```

**MCP file output handling.** The MCP file output path also marks truncated MCP output files as retrievable, so the model can request the full content of files returned by MCP servers that exceeded the preview budget.

**Integration tests.** `mcp_file_outputs.rs` (210 lines added) covers the tool's behaviour: retrieving a full file, attempting retrieval of a non-existent file, and the interaction with MCP file outputs.

## Compatibility and configuration

New opt-in feature. The `retrieve_file_contents` built-in tool is disabled by default. When enabled, the model can use it to request full file contents for files that were truncated due to token budgets.

## Evidence and review

- `file_retrieval.rs` implements the tool with proper input validation and access control.
- Files are marked as retrievable at the point of truncation in `file_context.rs`.
- The tool offer is included in the tool list only when at least one truncated file exists.
- Token accounting is updated after retrieval to reflect the now-visible content.
- Integration tests confirm the tool works end-to-end.

Include in the Features section as a companion to the file context budget feature (#1309). Mention that it requires explicit opt-in via configuration.
