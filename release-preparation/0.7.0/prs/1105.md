# PR #1105: Move the card family onto one Card primitive and themable geometry and skin channels

- PR: https://github.com/EratoLab/erato/pull/1105
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Fifth of nine styling-primitives-consolidation topics (after #1092,
#1096, #1100, #1101). Consolidates two previously non-reusable card
components and roughly 30 hand-rolled framed surfaces (hardcoded
`rounded-lg` Tailwind utility, unreachable by any theme) onto one new
`Container/Card.tsx` primitive with four variants
(`surface`/`interactive`/`selectable`/`expandable`). Given the very large
scope (3097 insertions across 49 files), review focused on the two
concrete, disclosed accessibility fixes and a sample of the disclosed
visible-change table. Confirmed by reading the relevant `EntityRow.tsx`
and page-level Card-adoption diffs:

- **The `EntityRow` collapse/focus-trap accessibility fix, confirmed
  exactly**: `EntityRow` now renders through `Card variant="expandable"`
  with a new `unmountOnCollapse` prop, and a code comment states the bug
  precisely — the previous `Collapse` component hid the expanded details
  by height alone (no `inert`, no `visibility: hidden`), so a collapsed
  row's buttons stayed in the tab order and its content stayed in the
  accessibility tree even while visually hidden. `unmountOnCollapse`
  removes the collapsed body from the DOM entirely rather than merely
  clipping it.
- **The search-result-card focus-tint removal, confirmed exactly via
  `SearchPage.tsx`**: the previous className included
  `focus:bg-theme-bg-hover` (a background-tint-on-keyboard-focus
  utility with no equivalent in the shared `.card-skin` state rules);
  confirmed removed after the `Card` conversion — matching the PR's
  disclosed behavioral delta that the search result card no longer tints
  its background on keyboard focus, since that behavior had no
  translation into the shared skin channel.
- **Category-tile and version-card conversions, confirmed structurally
  via `AssistantsPage.tsx` and `assistantHubUtils.tsx`**: `CategoryTile`'s
  hand-rolled `<button className="rounded-[var(--theme-radius-shell)]
  border ...">` becomes `<Card variant="interactive" as="button"
  data-ui="assistant-category-tile">`; `AssistantHubVersionCard` now
  conditionally renders as `variant={framedAsButton ? "interactive" :
  "surface"}` depending on whether the card itself is the click target or
  merely frames an inner button-plus-actions row — matching the PR's
  stated `interactive`-is-the-frame-that-is-the-click-target design
  distinction exactly.
- Per the PR (not independently re-verified given the very large
  remaining scope): the disclosed accessibility fix giving the hub
  category chips a missing `aria-pressed`/selected-state signal (stated
  as covered by a new 123-line round-trip test, the one part of this
  topic the PR states could not rest on manual review alone) was not
  independently located in the portion of the diff read; the full table
  of ~7 disclosed corner-radius visual deltas (e.g. category
  tile/sidecar-setup tiles/drive card/past-chat card all moving
  0.75rem→0.5rem, hub category chips 0.25rem→0.5rem) and four disclosed
  behavioral deltas beyond the confirmed focus-tint removal (an unchecked
  option card now lifting its border on hover not just its fill; OS
  tiles and the share-enable row gaining a hover border-lift and focus
  ring they previously lacked; `EntityRow`'s details-body padding
  changing from `pt-3` to a uniform 1rem inset); the new
  `ThreadMessageCard.tsx` (155 lines) and the 450-line rewrite of
  `GroupedFileAttachmentsPreview.tsx`; the two deliberately-declined
  conversions (`.card-section` refused on an expandable body, pinned by a
  test, because `Collapse`'s own wrapper breaks `:first-child`/
  `:last-child` corner-rounding logic; and the file-upload drop zone kept
  hand-rolled since `.card-skin`'s final-value border/background would
  outrank plain Tailwind color utilities but not their `hover:`/`dark:`
  variants, which the drop zone's visual language depends on); and the
  theme-facing structural note that `[data-ui="option-card-details"]`
  moved one DOM level deeper, flagged as a check-point for a future kit
  migration phase rather than a current break (both shipped kits and
  customer themes stated as unaffected today).

## Compatibility and configuration

None functionally breaking for the default (non-override) path. Multiple
disclosed, deliberate small corner-radius and hover/focus-affordance
visual changes across roughly a dozen surfaces (assistants page, sidecar
setup, cloud drive picker, share dialog, welcome screen, assistant hub) —
individually minor, collectively the intended and expected consequence of
consolidating onto shared geometry tokens, per the PR's own framing
(echoing #1096's and #1088's similar consolidation-driven deltas earlier
in this same styling-primitives series).

## Release note disposition

Proposed category: Bug fixes. Worth a mention: several card-style
surfaces (assistant category tiles, sidecar setup tiles, the cloud file
picker, the share dialog, expandable settings rows) gain more consistent
theming and, in a few cases, previously-missing keyboard focus/hover
affordances; an accessibility fix ensures a collapsed settings row's
contents (buttons, permission details) are no longer keyboard-reachable
or screen-reader-visible while hidden.
