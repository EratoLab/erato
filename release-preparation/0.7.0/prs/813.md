# PR #813: Add compat flag to make Anthropic + Bifrost + reasoning replay work

- PR: https://github.com/EratoLab/erato/pull/813
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Adds a new `ModelSettings` compatibility flag,
`compat_no_replay_summary` (default `false`), settable per chat provider
(`chat_providers.providers.<id>.model_settings.compat_no_replay_summary`)
or per experimental facet
(`experimental_facets.facets.<facet-id>.model_settings.compat_no_replay_summary`).
Confirmed by reading `build_openai_responses_reasoning_replay_parts` in
`message_streaming.rs`: when `true`, a **plain, summary-only** reasoning
block from a prior turn (no `encrypted_content` backing it) is no longer
replayed as reasoning content on the next request. A reasoning block that
DOES carry `encrypted_content` is still replayed regardless of the flag —
confirmed by the new test
`openai_responses_reasoning_replay_still_replays_encrypted_content_when_summary_disabled`
— since the docs describe the target failure mode precisely: "provider
gateways that require signed or encrypted reasoning replay data and
reject unsigned summary-only reasoning blocks" (i.e. some Anthropic-via-
Bifrost-gateway configurations reject a raw text reasoning summary being
replayed without a cryptographic signature/encryption attached, per the
PR title). Standard `ModelSettings` merge semantics apply
(`merge_model_settings`): once any applicable facet or provider sets it
`true`, it stays `true` (OR-merge, matching the existing
`compat_omit_strict` flag's pattern).

## Compatibility and configuration

New, optional, default-`false` config field — no behavior change for any
existing deployment that doesn't set it:
```toml
[chat_providers.providers.<provider-id>.model_settings]
compat_no_replay_summary = false  # default
```
Also settable per experimental facet. Documented in
`site/content/docs/configuration.mdx` and `erato.template.toml`; the
generated `config_reference.json` schema is updated accordingly (2 new
`erato_toml_config_key` doc anchors for the two settable locations).

## Release note disposition

Proposed category: Bug fixes. Worth a mention for deployments running
Anthropic models through a gateway (e.g. Bifrost) that rejects unsigned
reasoning-summary replay: a new `compat_no_replay_summary` model setting
works around the incompatibility by skipping replay of plain reasoning
summaries while still replaying properly encrypted/signed reasoning
content.
