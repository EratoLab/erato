# PR #1287: Gate Office add-in microphone features on device permission

- PR: https://github.com/EratoLab/erato/pull/1287
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Audio

## Summary

Introduces an optional device-permission boundary for microphone capture in the Office add-in, preventing audio features from attempting capture before the host application has granted consent.

**Problem.** When the Office add-in (embedded in an iframe) attempted to access the microphone via `getUserMedia`, the browser/Office runtime would either silently deny the request or produce an unusable stream on platforms that require explicit user consent before allowing audio capture (notably WebKit/macOS Office).

**Solution.** The PR introduces an `AudioCaptureAccessPolicy` interface that a host (such as the Office add-in) can install to control when microphone capture and device enumeration are permitted:

| Method | Behaviour |
|---|---|
| `beforeCapture()` | Called before every `getUserMedia` call. The host can use this to request device permission from the user or runtime. Throwing cancels the capture. |
| `canEnumerateDevices()` | Returns whether device enumeration is permitted. When `false`, enumeration returns an empty list, preventing the UI from showing a device picker before consent is granted. |

If no policy is installed (the ordinary web app path), the existing browser-default behaviour is unchanged — `getUserMedia` proceeds as normal, relying on the browser's built-in consent.

**New files.**

- `audioCaptureAccess.ts`: Defines the `AudioCaptureAccessPolicy` interface and exports `installAudioCaptureAccessPolicy`, `requestAudioStream`, and `enumerateAudioDevices`.
- Test files: `audioCaptureAccess.test.ts`, `audioSettingsAccess.test.ts`, `useAudioDictationRecorder.test.ts`, `useAudioTranscriptionRecorder.test.ts` — covering the policy enforcement boundary.

**Related.** The PR also includes compose reload state management improvements in `ChatInput.tsx` that preserve the upload state and facet/chat-provider selection when the Office add-in reloads its iframe.

## Compatibility and configuration

No config changes. The audio-capture policy is purely a host-side concept; the web app is unaffected. The Office add-in opts into the policy by calling `installAudioCaptureAccessPolicy` during initialisation.

## Evidence and review

- `requestAudioStream` calls `policy.beforeCapture()` before `getUserMedia`; if the host has been disposed between the call and the policy execution, it throws `AbortError`.
- `enumerateAudioDevices` returns `[]` when `canEnumerateDevices()` returns `false`, preventing a stale device-picker from showing.
- No policy → `hostPolicy` is `undefined` → the `if (policy)` guards skip → ordinary browser behaviour.
- Test coverage validates the boundary in all four new test files.

## Release note disposition

Include in the Audio section of the release notes: microphone features in the Office add-in now request device permission before capture, improving reliability on restricted platforms.
