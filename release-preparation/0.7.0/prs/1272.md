# PR #1272: Calculate timing of trace cluster per cluster

## Summary

No GitHub description beyond a Linear reference (ERMAIN-884); evaluated
directly from the diff, which is small and self-explanatory. Fixes a
trace-timing display bug: when a message's trace is split into multiple
separate clusters by interleaved `text_file_pointer` parts, every
cluster previously showed the *same* duration — the whole message's
`createdAt`-to-`updatedAt` span — rather than its own actual thinking
time. Confirmed exactly:

- **Each cluster now computes its own duration from its own parts,
  confirmed exactly**: `MessageContent.tsx`'s trace rendering changes
  `durationMs={traceDurationMs}` (the single message-level value, shared
  by every cluster) to `durationMs={durationFromTraceParts(cluster.parts)
  ?? (traceClusterCount === 1 ? traceDurationMs : null)}` — each cluster
  now gets a duration computed from its own `cluster.parts` via the
  (pre-existing, newly imported here) `durationFromTraceParts` helper.
- **The message-level fallback is preserved only for the single-cluster
  case, confirmed exactly**: the fallback to `traceDurationMs` (the
  legacy message-timestamp-based value) is gated on `traceClusterCount
  === 1`, computed via a new `useMemo` counting clusters whose `kind ===
  "trace"` — so a message that was never split by a file pointer keeps
  its exact prior behavior, while a split message's clusters never fall
  back to the shared, now-incorrect value.
- **The bug and its fix are directly demonstrated by the new test,
  confirmed exactly**: the new test builds a message with two trace
  clusters separated by two `text_file_pointer` parts — one cluster
  spanning 6 seconds (reasoning + tool use), the other spanning 2
  seconds — and the full message spans 30 seconds
  (`createdAt`="12:00:00" to `updatedAt`="12:00:30"). The test asserts
  both "Thought for 6s" and "Thought for 2s" render, and explicitly
  asserts "Thought for 30s" (the old, shared, whole-message duration)
  does **not** appear anywhere — directly proving the fix closes the
  exact bug described by the PR's title.

## Compatibility and configuration

None. Pure frontend display fix — no backend, config, or wire changes.
Affects only the rendered duration label on a trace cluster for a
message whose trace was split by one or more file-pointer parts; a
message with a single, unsplit trace is unaffected.
