# PR #912: Never let a progress observer break the observed request

- PR: https://github.com/EratoLab/erato/pull/912
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Follow-up fix to #910's `sidecar.progress.v1` polling, closing a gap in
its own documented isolation guarantee ("observation cannot affect the
invoked request"). Confirmed by reading the diff: the caller-supplied
`onProgress` callback was invoked without a try/catch, so an exception
thrown from inside it rejected the internal polling promise chain, which
then surfaced through `invoke()`'s `finally` cleanup — **replacing the
observed request's actual result or error with the observer callback's
own exception**, exactly the failure mode the feature was supposed to be
immune to. Fix: the `onProgress(result)` call is now wrapped in a
try/catch that silently drops any thrown error, so a faulty observer
still receives every progress step it can successfully handle, while the
request being observed always settles with its own genuine outcome
regardless of what the observer does.

## Compatibility and configuration

None for the erato backend/frontend/add-in in this repository — this PR
only changes the standalone `desktop-sidecar-protocol` package (protocol-
only; no product code touched, per the diff stat).
