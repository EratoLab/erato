# PR #1381: Word for Mac: Apply and Revert no longer refuse over Word's own language tagging after opening a document (ERMAIN-974) (#1381)

- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: Word add-in in-place restyle/Revert correctness

## Summary

Per the PR's detailed "Summary"/"How" sections (an unusually precise,
timing-based race-condition fix; treated as reliable but not
independently re-verified line-by-line). On Word for Mac, roughly 10-15
seconds after a document opens (and again after any import), Word
silently tags English paragraphs with `w:lang` on its own background
pass, only afterward writing `w:proofState spelling="clean"` — with no
paragraph event firing to signal it. A document capture taken before
that pass finished (including the one the pane prefetches on load)
lacked these tags, so a later Apply or Revert compared against stale
state and refused with a false mismatch.

- **Fix, as described**: `readWordDocument` (Mac-only) now re-reads
  `/word/settings.xml` every second until that background pass reports
  done, but only keeps waiting if the sole observed change is Word's own
  auto-detected `w:lang` — any other change ends the wait early with the
  read already in hand.
- **Bounded**, per the PR: waits until 20s after pane load or until 20s
  after an import's sync settles, then an additional 3s quiet period,
  never exceeding 25s from the read's start — specifically chosen to stay
  under the add-in's existing 30s send/capture deadline.
- Comparisons themselves are unchanged, so a language the user explicitly
  sets afterward still correctly triggers a refusal (this fix only
  absorbs Word's own automatic, timing-dependent tagging, not genuine
  user edits).
