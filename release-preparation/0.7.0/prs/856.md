# PR #856: Make sm the default button size

- PR: https://github.com/EratoLab/erato/pull/856
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Changes the shared `Button` component's default `size` from `"md"` to
`"sm"`. Per the PR, `sm` was already the dominant size used explicitly
across most areas of the app (settings 100%, assistant 74%, chat 71%,
other 58% — only dialogs skewed toward `md` at 85%), but the *default*
remained `md`, so any call site that simply omitted the `size` prop
produced an outlier rather than the common case — explaining the pattern
of stray `md` buttons appearing beside `sm` siblings noted in #854.
Confirmed by reading the diff: this PR is stacked on #854 (both touch
`Button.tsx`); the default is changed via a single line
(`size = "md"` → `size = "sm"`), and the one call site that had explicitly
set `size="lg"` (the assistant hub "Start chat" CTA, whose #854-driven
growth to 1.125rem text was noted as independently revertible) is changed
to omit the `size` prop entirely, now relying on the new `sm` default. Per
the PR, this makes all 113 production `Button` usages resolve to `sm` (75
explicit, 38 via the new default), with no `md` or `lg` remaining in app
code; `md`/`lg` remain available as options for deliberate emphasis. The
PR states it deliberately chose to change the default rather than sweep
individual call sites, reasoning that a call-site sweep would leave the
old default as a "trap" that future code written without a `size` prop
would fall back into, restarting the same drift.

Per the PR's downstream check, `Button` is exported from the frontend
library, making this a contract change for external consumers that omit
`size`: 2 Outlook add-in buttons (in `UserSettingsTabContent`'s footer)
were found to rely on the old default and will shrink to `sm` as a result
— described as intentional, matching a stated direction the add-in has
already been moving in; 0 component-kit call sites were found affected.

## Compatibility and configuration

None new. Visual-only default change: any `Button` usage across the
frontend or the Outlook add-in that omits the `size` prop now renders at
the smaller `sm` size (0.875rem text, per #854) instead of `md`
(1rem) — confirmed as the intended and, per the PR's own count, now
overwhelmingly common case.

## Evidence and review

Verified via this PR's squash-merge commit against its parent (both
present locally). Full diff read (3 files, 15 insertions/2 deletions) —
confirms the default-size change and the single explicit `lg` call site's
conversion to the new default, exactly as described. The PR's claimed
counts (113 production buttons, 2 add-in call sites affected, 0
component-kit call sites) were not independently re-derived by grepping
every `<Button>` usage across the repo, but the change itself (a
single-line default swap plus one explicit-size removal) is small and
low-risk regardless of the exact counts' precision.
