# PR #892: Add-in: sidecar-backed thread fetcher (ERMAIN-503)

- PR: https://github.com/EratoLab/erato/pull/892
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Wires the desktop sidecar's `outlook.get_conversation.v1` method (added
to the protocol spec in #887) into the Outlook add-in's actual thread
loading, on the on-prem/Exchange-SE path only: conversation loads there
route through the local sidecar instead of `makeEwsRequestAsync`, whose
small size caps degrade large SE threads to body-less placeholder markers
(the problem #887's protocol addition targeted). Confirmed by reading the
new `fetchOutlookMessageSidecar.ts` (219 lines) in full:

- `createSidecarOutlookMessageFetcher` is a **decorator**: it spreads the
  wrapped EWS fetcher's implementation and overrides only
  `fetchConversationMessages`; every other capability (single-message
  fetch, reply/compose, etc.) delegates unchanged to the inner fetcher.
- **Confirmed the fallback-safety guarantee precisely**: the sidecar path
  is only attempted when `client.supports(GET_CONVERSATION)` and both a
  resolvable anchor `internetMessageId` and the user's email address are
  present; if any of those is missing, or if the sidecar call throws for
  any reason (RPC error, no matching local mailbox, an empty result — an
  empty conversation is explicitly treated as a failure, since a
  conversation always contains at least its own anchor message, so an
  empty result signals the anchor wasn't resolvable in the local store,
  not that the thread is genuinely empty), it transparently falls back to
  the wrapped EWS fetcher — **except** when the failure is the caller's own
  `AbortSignal` firing, which is correctly re-thrown rather than
  swallowed into a fallback attempt.
- Sidecar results are mapped into the existing `GraphConversationMessage`
  shape so downstream logic (thread parsing, deduplication, disclosure
  markers, `.eml` synthesis) needs no changes. An attachment whose bytes
  the sidecar couldn't produce (`contentBytes === undefined`) degrades to
  a byte-less marker for just that one attachment and flips the overall
  result to `state: "partial"`, rather than discarding the whole thread —
  confirmed this correctly reuses the `partial`/`ok` distinction from
  #887's protocol shape. Attachment `id`s are built from the sidecar's
  `sha256` (stable across re-fetches, so a per-item dismissal persists)
  plus an index (disambiguating identical-hash siblings and covering
  hash-less unavailable attachments) — confirmed a deliberate, specific
  design choice via the code's own comment, not an incidental detail.
- `useOutlookMessageFetcher.ts` (24-line diff, not read in full) applies
  this decorator only on the on-prem branch when a sidecar client is
  present; the cloud/Graph path is stated as untouched.
- `env.ts` bridges `VITE_DESKTOP_SIDECAR_URL` through to the sidecar
  provider's runtime lookup; without it configured, the provider stays
  inert and the add-in behaves exactly as before this PR.

## Compatibility and configuration

New optional `VITE_DESKTOP_SIDECAR_URL` build-time env var for the
Outlook add-in — without it set, this feature has zero effect (confirmed:
the decorator is gated on sidecar client presence, which depends on this
being configured). Only affects the on-prem/Exchange-SE thread-loading
path; the Exchange Online/Graph path is unaffected. Requires a
sidecar-installed desktop implementing the `outlook.get_conversation.v1`
method from #887 to have any effect at all.

## Release note disposition

Proposed category: Features and enhancements. Not independently
user-visible without a corresponding sidecar deployment and
`VITE_DESKTOP_SIDECAR_URL` configuration; worth mentioning alongside #887
once the full sidecar stack is available: on-prem/Exchange Server Outlook
users with the desktop sidecar installed get full-fidelity thread loading
(bodies and large attachments) instead of degraded, body-less thread
markers, with automatic fallback to the previous behavior if the sidecar
is unavailable or fails.
