# PR #1040: Add wait tool for actions that require it

- PR: https://github.com/EratoLab/erato/pull/1040
- Status: pending
- Category: Features and enhancements
- Theme: MCP controls

## Summary

Adds a synthetic `wait` tool the model can call when an MCP tool reports a
deferred/pollable result (e.g. a long-running action whose result isn't
ready yet). New `backend/erato/src/services/mcp_wait.rs`: `build_wait_tool`
constructs a tool named `wait` taking a required `seconds` integer
(bounded `1..=max_wait_seconds`), with a description instructing the model
to call it after an MCP tool indicates polling is needed, defaulting to a
5-second wait if no timeframe is indicated; `parse_wait_seconds` validates
the model's chosen wait duration server-side (rejecting `0`, values above
the configured maximum, or non-integer input). The tool is exposed
per-MCP-server via a new `wait_tools` wildcard-pattern config
(`mcp_servers.<id>.wait_tools`, matching the `allow_tools`/`exclude_tools`
pattern from #889) and/or a global `mcp_servers_global.enable_wait` flag
(default `false`) — an empty per-server `wait_tools` list disables waiting
for that server unless the global flag is enabled. A new
`mcp_servers_global.max_wait_seconds` (default `60`, validated `> 0` at
startup) caps how long a single wait call can request.
`backend/erato/src/server/api/v1beta/message_streaming.rs` (216-line diff)
integrates the actual pause-and-resume generation-loop behavior when the
model calls `wait`. `backend/mock-mcp-server` gained substantial test
fixtures (237 lines) to simulate deferred/pollable MCP tools for E2E
testing.

## Compatibility and configuration

New configuration, both defaulting to disabled/conservative:
```toml
[mcp_servers_global]
enable_wait = false       # default
max_wait_seconds = 60     # default

[mcp_servers.<server-id>]
wait_tools = []           # default; wildcard patterns of tools that may trigger waiting
```
No migration. No breaking change — the `wait` tool is not exposed to the
model unless a server's `wait_tools` matches a tool name or the global
`enable_wait` is set, so deployments that don't configure this see no new
tool and no behavior change.
