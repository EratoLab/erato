# PR #1036: Add option for configure model preference

- PR: https://github.com/EratoLab/erato/pull/1036
- Status: pending
- Category: Features and enhancements
- Theme: None

## Summary

Lets a user set a persistent default chat model/provider, used to
pre-select their model when starting new chats. New database column
`user_preferences.default_chat_provider` (migration
`0038_add_default_chat_provider_to_user_preferences.sql`, nullable text,
default `NULL`); `UpdateUserPreferencesInput.default_chat_provider` and
`upsert_user_preferences` (`backend/erato/src/models/user_preference.rs`)
wire it through to the existing user-preferences upsert path, alongside
the pre-existing job title/custom instructions/additional information
preferences.

On the frontend, `UserPreferencesDialog.tsx` gains a `ModelSelector`
control (reusing the existing chat model dropdown component) to choose
and save this preference. `useActiveModelSelection.ts`'s `defaultModel`
computation now prefers the model matching
`profile.preference_default_chat_provider` over simply taking the
highest-priority (first) available model, falling back to that prior
behavior when no preference is set or the previously-chosen provider is
no longer available in the current model list. The initial-selection
effect now also waits for the profile to finish loading
(`isProfileLoading`) before applying a default, to avoid a race where the
old default (first available model) briefly flashes before the user's
saved preference loads.

## Compatibility and configuration

No new top-level backend configuration keys — this is a per-user
preference stored in the database, additive column with a `NULL` default
(no backfill needed, no behavior change for existing users until they set
a preference). No migration risk beyond the standard additive-column
pattern. When a user's previously-selected default provider becomes
unavailable (removed from config, access revoked, etc.), the UI falls back
to the normal highest-priority default rather than erroring.
