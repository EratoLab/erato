# PR #1037: Improve error message for prompt injection guardrail

- PR: https://github.com/EratoLab/erato/pull/1037
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: Guardrails and prompt-injection filtering

## Summary

Previously, when Erato's prompt-injection guardrail (from #789 this
cycle) blocked a message, the resulting `content_filter` error was shown
to the user with the same generic message as an actual provider-side
content filter ("Your message was blocked by [provider]'s content
filter..."), with no indication of *why* — no mention of which text
triggered it. `frontend/src/types/chat.ts` distinguishes the two cases at
the type level: `MessageErrorFilterDetails` is now a union of
`ProviderContentFilterDetails` (the existing per-category shape) and a new
`PromptInjectionFilterDetails` (`{ pattern_id: string; matched_text:
string }`), with a type guard `isPromptInjectionFilterDetails`.
`ChatMessage.tsx` now shows a dedicated message for this case: "The
request was blocked because it matched a prompt injection guardrail."
with a call-to-action "Please edit the previous message to remove the
offending text before continuing.", plus the actual `matched_text` shown
in a quoted "Offending text" block — letting the user actually see and
remove the flagged text, rather than being stuck with an opaque generic
content-filter error and no way to know what to change.

## Compatibility and configuration

No configuration keys or migrations. Behavior change is purely in error
presentation on the frontend; the backend's existing prompt-injection
guardrail behavior (from #789) and its error payload shape (which must
already have included `pattern_id`/`matched_text` for this to work,
implying the backend already sends this detail and only the frontend
previously failed to use it) are unaffected.
