# PR #806: Fix shared chat not using profile picture of chat creator

- PR: https://github.com/EratoLab/erato/pull/806
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Fixes the read-only shared-chat view (`SharedChatPage.tsx`) always
rendering the chat owner's messages with the current viewer's own avatar
(or a generic default) instead of the actual chat creator's profile
picture. Confirmed by reading the code:

- `GET .../resolveshare` (`resolve_share_link` in `share_links.rs`) now
  also resolves and returns a new `owner_picture` field on
  `ResolveShareLinkResponse`: the owner's own `picture` when the viewer is
  the owner, otherwise a fresh Microsoft Graph lookup via a new
  `fetch_owner_profile_photo` helper.
- That lookup reuses the existing Entra ID profile-photo machinery
  (`fetch_entra_id_profile_photo_data_url`), generalized via a new
  `ProfilePhotoSubject` enum (`Me` → `/me/photo/$value`, `User(id)` →
  `/users/{id}/photo/$value`, URL-encoded). **Notably, this now fetches
  another user's (the chat owner's) photo using the current viewer's own
  forwarded Entra ID access token** — confirmed in the diff — rather than
  the owner's token (which the server has no access to for another user's
  session). It's gated the same way self-photo lookup already was:
  `integrations.experimental_entra_id.enabled` must be on and the viewer's
  identity must be an Entra ID profile; any Graph error (including a
  403/permission-denied if the tenant's app registration lacks sufficient
  read scope for other users) is caught and logged at `warn`, degrading to
  no picture rather than failing the shared-chat page load — consistent
  with the existing 404-as-"no photo" handling.
- Frontend: `Chat.tsx` gains a new optional `userMessageProfile` prop
  (falling back to the viewer's own `profile` when unset, so no behavior
  change for the normal authenticated-chat view) that overrides the
  profile used for user-authored message avatars; `SharedChatPage.tsx`
  builds a synthetic `UserProfile` from the resolved `owner_picture` (and
  the already-existing `owner_display_name`) and passes it as
  `userMessageProfile`, so shared-chat message bubbles now show the actual
  creator's photo instead of the viewer's.

## Compatibility and configuration

No new configuration keys; behavior-only. Requires the existing
`integrations.experimental_entra_id` Entra ID integration to be enabled
for the picture to resolve at all — deployments without it, or where the
viewer isn't an Entra ID profile, see no change (owner picture stays
absent, matching prior behavior). Fetching another user's Graph photo
depends on the tenant's app registration having sufficient delegated
Graph permission to read other users' photos; if that permission is
missing, the lookup fails silently (logged, not surfaced) and the shared
chat falls back to no owner picture — it does not error the page.
