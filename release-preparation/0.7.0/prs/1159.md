# PR #1159: Add controls for sidecar mailbox activation and priority

- PR: https://github.com/EratoLab/erato/pull/1159
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Desktop Sidecar for local sources

## Summary

Adds an actual frontend UI for controlling which Outlook mailboxes the
desktop sidecar indexes and in what order, building on the mailbox-listing
protocol from #869 and the indexing-status protocol from #1143. New
`SidecarIndexingCard.tsx` (312 lines) — rendered in the desktop sidecar
settings tab from #916 — lets a user enable/disable indexing per mailbox
and set a numeric priority (lower runs first; unconfigured mailboxes
default to `Number.MAX_SAFE_INTEGER`, i.e. lowest priority). New
`frontend/src/lib/desktopSidecar/indexingConfiguration.ts`:
`initializeMailboxConfiguration` auto-populates a first-time user's own
mailbox (matched by their email address) as enabled with priority `0`
once mailboxes are discovered, if no configuration exists yet;
`orderedMailboxes` merges the discovered mailbox list with any
saved overrides and sorts by priority; `mailboxCoverage` reads live
indexing-status statistics (from #1143's `indexing.status.v1`) filtered to
the "active" generation to show per-mailbox indexed/total counts for
emails and files separately. `frontend/src/providers/DesktopSidecarProvider.tsx`
(58-line diff) presumably sends this configuration via the existing
`sidecar.configure.v1` method (from #871) under a new
`indexing_mailboxes` field.

## Compatibility and configuration

No backend configuration keys — this is entirely client-side/protocol
configuration sent to the locally-running sidecar (per-user, stored by the
sidecar itself, not the Erato backend). Depends on the desktop sidecar
settings tab being enabled (`desktop_sidecar.show_settings_tab` from
#916) and a connected sidecar supporting the indexing protocol methods
from #1143. No migration; no effect for deployments not using the
desktop sidecar feature.
