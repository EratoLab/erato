# PR #896: Fix on-prem detection for hybrid mailboxes; record Windows sidecar qualification

## Summary

Two independent items split out of #892 to keep that PR focused, both
surfaced during Outlook-on-Mac testing.

**Bug fix**: `detectExchangeOnPrem()` previously let a cloud
`accountType` value (`"office365"`, `"outlook"`, `"outlookCom"`,
`"gmail"`) veto the on-prem determination outright, falling through to
"not on-prem" before ever checking the mailbox's actual service endpoint
URLs. Confirmed by reading the diff this was wrong for a real case: new
Outlook on Mac reports `accountType: "office365"` for a **hybrid**
account whose mailbox is actually hosted on-prem, because that field
tracks the signed-in Entra identity, not where the mailbox itself lives —
so such hybrid mailboxes were being misrouted to the Graph API path,
which cannot reach an on-prem mailbox at all. The fix removes the
`NON_ON_PREM_ACCOUNT_TYPES` veto set entirely: only the positive
`accountType === "enterprise"` signal is now trusted as conclusive;
otherwise (including when `accountType` is a cloud value, or absent
entirely — it's Mailbox-API 1.6+ and can be missing) the function falls
through to checking whether `ewsUrl`/`restUrl` point at a non-Microsoft
host, which is the more authoritative signal for where the mailbox
actually lives. A new test case is added asserting a non-Microsoft
`ewsUrl` wins over a cloud `accountType`; existing test cases are updated
to use genuinely cloud-hosted endpoints so they still correctly resolve
to "not on-prem" (confirming they weren't relying on the removed veto to
pass).

**Documentation-only**: fills in the Windows classic Outlook row of the
`desktop-sidecar-protocol` `TRANSPORT.md` qualification matrix from live
testing (WebView2 150, no Private-Network-Access preflight or loopback
permission prompt needed) — not independently verified (a factual record
of manual testing); the macOS row remains explicitly pending, tracked
separately under ERMAIN-522 for a required HTTPS profile (WKWebView
blocks plain-HTTP loopback as mixed content).

## Compatibility and configuration

None. Pure bug fix; no configuration or API changes. Behavior change: a
hybrid on-prem/cloud-identity Outlook mailbox (particularly on new
Outlook for Mac) is now correctly routed to the EWS on-prem mail-fetching
path instead of the Graph path, which previously could not reach it at
all.
