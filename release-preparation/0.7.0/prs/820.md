# PR #820: Improve handling and persistence of errors during generation task

- PR: https://github.com/EratoLab/erato/pull/820
- Status: pending (diff reviewed)
- Category: Stability improvements
- Theme: Streaming/generation stability

## Summary

A large reliability refactor of the background chat-generation task in
`backend/erato/src/server/api/v1beta/message_streaming.rs` (801
insertions/498 deletions in this one file). Key changes:

- **New `persist_background_generation_failure`**: when the background
  generation task hits an unrecoverable internal error at one of 4 call
  sites in the generation flow, this now (a) records the error as
  `GenerationErrorType::InternalError` — with the error description built
  from eyre's full `Report` debug representation, preserving the whole
  wrapped cause chain (verified via the new
  `internal_generation_error_keeps_context_and_root_cause` unit test) —
  into the assistant message's `generation_metadata` via
  `update_message_generation_metadata`, and (b) broadcasts a
  `StreamingEvent::Error` to connected clients. Previously such generic
  internal failures could apparently leave a message without a persisted
  error state in the database (message stuck as "generating" with no
  recorded cause) if they weren't already funneled through a more specific
  error path.
- Widespread replacement of silent `.ok()` error-swallowing and
  string-formatted (`String`) errors with structured `Report`/`eyre`
  error propagation and `wrap_err` context throughout the file (e.g.
  `bg_stream_save_user_message` now returns `Result<_, Report>` instead of
  `Result<_, String>`; `fetch_non_streaming_error` now returns a `Result`
  instead of silently discarding provider-selection failures via `.ok()`).
  Malformed/unparseable persisted `generation_metadata` or
  `generation_parameters` (e.g. corrupt JSON) is now logged with
  `tracing::warn!` and skipped, rather than silently ignored via `.ok()`.
  Errors are consistently captured (`capture_report`, presumably to
  Sentry, `log_and_capture_error`/`warn_and_capture_error` helpers) rather
  than only logged in some paths.
- New small helpers factor out repeated patterns: `send_generation_event`,
  `forward_error_report`, `serialize_json_value`,
  `content_parts_json_or_log`, `send_background_event`.
- The generic internal-error SSE message changed from a static string "An
  unexpected error occurred during generation" to
  `format!("Unexpected generation error: {err:?}")`, including the actual
  error's debug output in `parse_streaming_error`.

## Compatibility and configuration

No configuration keys or migrations. Purely internal reliability/error
propagation improvements — no changed request/response schema. User-facing
effect: chats that previously failed silently or ended up stuck without an
error explanation should now more reliably show an error state with a
persisted (and Sentry-captured) diagnostic, and the streamed error message
for unexpected internal failures now includes structured error detail
instead of a generic string.
