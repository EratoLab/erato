# PR #911: Adjust intermediate load balancer network policy

- PR: https://github.com/EratoLab/erato/pull/911
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: Multi-replica / cross-replica generation state

## Summary

Follow-up fix to the "intermediate sticky load balancer" Helm chart
feature added in #901 this same cycle. That feature's `NetworkPolicy`
(`infrastructure/charts/erato/templates/network-policies.yaml`) needed to
allow the Traefik load-balancer pod to reach the Kubernetes API server
(for its Kubernetes CRD/Ingress provider to discover routes), but the
API server's address, once passed through a cluster's internal Service
DNAT, is cluster-specific and can't be hardcoded in the chart. This PR:
- Changes `backend.loadBalancer.networkPolicy.enabled`'s **default from
  `true` to `false`** — i.e. by the time this PR landed, the network
  policy for the load-balancer pods introduced in #901 is now opt-in
  rather than on-by-default, since enabling it without also providing the
  correct CIDR could break the load balancer's ability to reach the API
  server.
- Adds a new `backend.loadBalancer.networkPolicy.apiServerCIDRs` list
  (empty by default), which the network policy template now renders as
  additional `ipBlock` egress rules — required input when an operator
  does enable this network policy, if the Kubernetes API endpoint is
  external to the cluster.
- Adds a `backend.loadBalancer.provider` setting (`kubernetescrd` by
  default, alternative `kubernetesingress`), selecting which Traefik
  provider discovers the load-balancer's route — the CRD-based provider
  supports Traefik's full feature set (needed for the `hrw` strategy),
  the Ingress-based one uses standard Kubernetes `Ingress` resources
  instead.

## Compatibility and configuration

Since this PR lands in the same 0.7.0 release cycle as #901 (which
introduced `backend.loadBalancer.networkPolicy.enabled: true` as its
initial default), the net effect for anyone upgrading straight to 0.7.0 is
that the shipped default is `false`, not `true` — operators enabling the
intermediate load balancer (`backend.loadBalancer.enabled: true`, still
opt-in and default `false`) who also want its dedicated `NetworkPolicy`
must now explicitly set `backend.loadBalancer.networkPolicy.enabled = true`
and, if the Kubernetes API endpoint isn't reachable via the default
in-cluster address, populate `apiServerCIDRs`. No migration. The new
`provider` setting is additive with a backward-compatible default
(`kubernetescrd`, matching the prior implicit behavior).
