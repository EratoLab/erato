# PR #1050: Draw grouped attachment items with the shared tile

- PR: https://github.com/EratoLab/erato/pull/1050

- Category: Bug fixes
- Theme: None

## Summary

Stacked on #1049. Extends the shared `AttachmentTile` to the grouped
preview's `attachment`/`context` file items (used by Outlook/Teams panes),
replacing the separate `FilePreviewButton`/`FilePreviewBase` rendering.
Confirmed by reading both changed files in full:

- **Wrap vs. column, confirmed exactly via `GroupedFileAttachmentsPreview.tsx`**:
  a new `tilesOnly` check — `visibleItems.every(item => item.kind ===
  "attachment" || item.kind === "context")` — switches `itemsClassName`
  from `flex flex-col gap-2` to `flex flex-wrap items-start gap-2` only
  when every visible item in the group is a tile-eligible kind. A code
  comment states groups are homogeneous in practice (staged emails are
  all selectable, compose-mode attachments all plain), so selection rows,
  thread-message groups, loading placeholders, and status notices never
  mix with tiles in the same group.
- **File-size restoration, confirmed exactly via `AttachmentTile.tsx`**:
  a new `getFileSize(file)` call feeds a `metaLabel` computed as
  `` `${typeLabel} · ${fileSize}` `` when a size exists, falling back to
  `typeLabel` alone otherwise — with a code comment stating only
  locally-staged files carry a `size` field, since the server-side API
  type has none. This is consistent with, not contradicting, #1046's
  finding that `showFileSizes` had nothing to show for `FileUploadItem`
  (the server type) specifically — the size restoration here applies to
  the add-in's locally-staged (not-yet-uploaded) email-body/Office.js
  attachments, a different underlying type.
- **`activateLabel` for non-preview activation, confirmed exactly**: the
  tile gains an optional `activateLabel` prop, defaulting to `t\`Preview
  attachment\`` in the `aria-label` construction when absent. Confirmed
  the grouped preview passes `activateLabel={onOpen ? t\`Open\` : undefined}`
  — so an item whose activation opens something other than the file
  itself (the PR's example: the conversation behind a Teams transcript)
  is announced as "Open …" rather than "Preview attachment …".
  `context`-kind items are confirmed to still receive no `onRemove`
  handler (`item.kind === "context" ? undefined : () => onRemoveFile(...)`),
  preserving their read-only contract.

## Compatibility and configuration

None. Pure frontend visual/accessibility change to the grouped attachment
preview used by the Outlook/Teams add-in surfaces; no API or
configuration changes. A component-kit consumer of the grouped preview's
internals is unaffected since this only changes internal rendering, not
its public props (not independently re-verified against the removed
`component-registry.generated.ts` entry, which the diff stat shows losing
one line).
