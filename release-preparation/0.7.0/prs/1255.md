# PR #1255: Add optional tool for retrieval of embedded images

- PR: https://github.com/EratoLab/erato/pull/1255
- Status: pending
- Category: Features and enhancements
- Theme: More configurable assistant discovery and content

## Summary

Adds a synthetic `retrieve_embedded_image` tool letting an image-capable
model fetch images embedded inside a PDF attached to the conversation. New
`backend/erato/src/services/embedded_images.rs` (399 lines) handles
extraction/lookup; per the documentation, PDF text extraction now includes
image markers with an `embeddedId` like `file-embed://<file-id>/0`, and
the model can call the tool with that ID to receive the actual image as a
tool response. Retrieval is scoped to images actually offered in the
current prompt (not an arbitrary file/ID the model might guess) and
re-checks file access permissions at retrieval time, not just when the
PDF was originally attached. Retrieved images remain available in later
turns of the same conversation once fetched.

Gated by a new two-level config: `chat_providers.all_providers.enable_embedded_image_retrieval_tool`
(default `false`) sets the default for all providers, and
`chat_providers.providers.<provider-id>.enable_embedded_image_retrieval_tool`
(`Option<bool>`, unset by default) overrides it per provider — letting an
operator enable the tool broadly while disabling it for a specific
text-only provider, or vice versa (`AppConfig::embedded_image_retrieval_enabled`
implements this per-provider-overrides-global precedence). The docs note
this should be paired with an image-capable model and
`model_capabilities.supports_image_understanding` enabled for that
provider.

## Compatibility and configuration

New optional settings, both defaulting to disabled:
```toml
[chat_providers.all_providers]
enable_embedded_image_retrieval_tool = false  # default

[chat_providers.providers.<provider-id>]
enable_embedded_image_retrieval_tool = true  # optional override
```
No migration. No breaking change — deployments not enabling this see no
new tool offered to the model and no change to existing PDF text
extraction (beyond text extraction now also emitting the `file-embed://`
markers alongside text, per the docs, which happens independent of
whether the retrieval tool itself is enabled — not fully confirmed
whether marker emission is itself gated by this setting or always present
in extracted PDF text).
