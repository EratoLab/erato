## Summary

No GitHub description beyond a Linear reference (ERDSCAR-3); evaluated
directly from the diff. A small, purely additive protocol-schema
extension to the `sources.list.v1` result shape (the same source
descriptor this session reviewed being consumed by PR #1219's
`list_sidecar_mailboxes` tool). Confirmed exactly:

- **Four new optional fields added to the source descriptor, confirmed
  exactly**: `displayName` (human-readable name), `indexingEnabled`
  (the "effective persisted indexing policy... independent of scheduler
  activity or scan health," explicitly distinguished from the
  pre-existing `enabled` flag, which gains a clarifying description:
  "Existing catalog source-enabled flag. It is distinct from effective
  persisted indexing policy in `indexingEnabled`"), `product` (a stable
  family identifier such as `outlook`/`teams`), and `product_variant`
  (a more specific inferred variant such as `outlook_classic`). None of
  the four are added to the schema's `required` array, consistent with
  each field's own description stating "Older sidecars may omit it" —
  confirming genuine backward compatibility for a sidecar that predates
  this extension.
- **Protocol version bumped, confirmed exactly**: `package.json`'s
  version changes `0.1.28` → `0.1.29`.
- Per the PR (not independently re-verified): the generated TypeScript
  types and validator regeneration (`source-descriptor.ts`,
  `sources-list-v1-result.ts`, and the large `validators.mjs` diff); the
  frontend's `desktop-sidecar-protocol.types.ts` consumption (3 lines);
  and the new 20-line addition to
  `desktopSidecarProtocolExtensibility.test.ts` (a test file this
  session also saw touched by PR #1266, suggesting the two PRs are
  closely related in intent — both extending the protocol while
  verifying older-client compatibility).

## Compatibility and configuration

None breaking. All four new fields are optional with explicit
"older sidecars may omit it" framing, and no existing field's semantics
change (the clarified `enabled` description documents existing behavior
rather than altering it). No config keys.
