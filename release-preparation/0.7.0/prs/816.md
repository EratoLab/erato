# PR #816: Persist traces more often to Langfuse during generation including errors

- PR: https://github.com/EratoLab/erato/pull/816
- Status: pending (diff reviewed)
- Category: Observability
- Theme: Observability / Langfuse tracing

## Summary

Substantially reworks when and how much Langfuse (OTEL-transport) tracing
data is persisted during a chat generation turn, in
`backend/erato/src/server/api/v1beta/message_streaming.rs` and
`backend/erato/src/services/genai_langfuse.rs`.

Previously the trace and its generation/tool-call spans were apparently
only fully recorded once a turn completed successfully (`create_trace_from_chat`
was called with the full trace only at that point). Now:
- The parent trace is created immediately at the start of generation
  (`create_trace_from_chat` moved earlier, now also accepts explicit
  `metadata`/`tags` parameters rather than deriving them internally), so a
  trace exists in Langfuse even if the turn later fails before completing.
- A new `create_otel_error_generation_from_chat` persists a "generation"
  observation for a turn that ended in error, including the **partial**
  output produced so far (`output_content: &[ContentPart]`) and a
  structured `GenerationErrorType` (existing error enum, now serialized
  into the observation), marked with Langfuse level `"ERROR"`. Two new
  helpers in `message_streaming.rs`, `persist_otel_generation_error` and
  `persist_otel_tool_call`, wire this into the generation loop's error
  paths and tool-call execution.
- A new `create_otel_tool_call_span` persists a tool-call's input/output
  (or error) as its own OTEL span, linked to its parent observation, so
  individual tool invocations show up in Langfuse even without a
  successful final assistant response.
- Turn/model naming was consolidated into `langfuse_model_name` and
  `langfuse_turn_name` helpers used consistently across turns.

Supporting refactor (not itself tracing-related): `backend/erato/src/services/genai.rs`
introduces a `GenAIClient` trait abstracting chat/streaming/image-generation
calls, and `AppState` gained a `genai_client_override: Option<Arc<dyn
GenAIClient>>` field; `genai_for_*` methods now return `Arc<dyn GenAIClient>`
instead of a concrete `GenaiClient`. This appears to exist to let tests
inject deterministic provider responses/failures to exercise the new
error-tracing paths (`backend/erato/tests/integration_tests/main.rs` gained
a new test module reference).

## Compatibility and configuration

No new configuration keys or migrations. Behavior change is purely about
observability completeness: deployments with Langfuse OTEL tracing enabled
will now see traces/spans for generation turns that failed partway through
(previously such turns may not have produced a trace at all, or produced
an incomplete one), including the partial assistant output and structured
error detail. No change to default-disabled tracing; if Langfuse
tracing/OTEL is not configured, this has no effect.
