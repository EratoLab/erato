# PR #1038: Block chat composer after encountering guardrail

- PR: https://github.com/EratoLab/erato/pull/1038
- Status: pending
- Category: Bug fixes
- Theme: Guardrails and prompt-injection filtering

## Summary

Directly follows #1037 (which added the "Please edit the previous message
to remove the offending text before continuing." call-to-action for a
prompt-injection-blocked message). This PR actually enforces that
instruction in the UI: `Chat.tsx` now computes
`isLastMessageBlockedByPromptInjection` — true when the most recent
message is an assistant message with `error.error_type === "content_filter"`
and `isPromptInjectionFilterDetails(error.filter_details)` (the type guard
from #1037) — and disables the chat composer (`disabled={composerDisabled
|| isLastMessageBlockedByPromptInjection}`) whenever that's the case.
Previously, per the diff, a user could apparently continue typing and
sending new messages even after a prompt-injection block, without first
editing out the offending text as instructed, making the new CTA from
#1037 a suggestion rather than an enforced requirement.

## Compatibility and configuration

None. Purely a frontend UI enforcement change; no configuration keys, API
changes, or migrations. Only affects the specific prompt-injection content
filter case; other error types (e.g. a provider's own content filter, rate
limits) do not disable the composer via this change.
