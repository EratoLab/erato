## Summary

Follow-up to the ERMAIN-459 sign-in fix (#823): bumps the tracked
oauth2-proxy fork image from `v7.15.2-erato.3` to `v7.15.2-erato.4` across
the Helm chart, its generated documentation/tests, and the various local
dev-auth Docker Compose files (confirmed via the version-bump diffs in
`infrastructure/charts/erato/values.yaml`,
`infrastructure/charts/erato/README.md`,
`infrastructure/charts/erato/tests/oauth2-proxy-deployment_test.yaml`, and
three local-auth `docker-compose*.yml` files). Per the PR, this fork
version adds a new opt-in compatibility setting for the case where
Office/NAA keeps returning an expired ID token while its accompanying
access token is still valid — the underlying root cause behind #823's
"force interactive sign-in" fallback fix.

Confirmed the actual new setting,
`insecure_oidc_allow_expired_id_token_on_external_redemption = true`, is
enabled **only in the Outlook add-in's own local-auth oauth2-proxy
config template** (`office-addin/local-auth/oauth2-proxy-entra-id.template.cfg`)
— it is not turned on in the shared production Helm chart's default
`values.yaml`. The setting's own name and the PR's description both scope
it narrowly to "external redemption" (i.e. an ID token presented from an
already-established external session like Office's NAA flow, not a
regular login), with normal access-token validation stated to remain in
place regardless. A production deployment wanting this same compatibility
behavior for its own Office add-in oauth2-proxy instance would need to
set this option in its own config; this PR doesn't flip it on broadly by
default.

## Compatibility and configuration

The oauth2-proxy image version bump applies to any deployment using the
Helm chart's default image tag. The `insecure_oidc_allow_expired_id_token_on_external_redemption`
setting itself is new (available in the bumped fork version) but is only
enabled in the local-dev Office/Entra auth template shipped in this repo
— a production deployment must opt in explicitly to get the same
Office/NAA expired-ID-token tolerance in its own oauth2-proxy
configuration.
