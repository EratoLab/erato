# PR #1069: Resolve dropdown and media borders through the merged theme

- PR: https://github.com/EratoLab/erato/pull/1069
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Follow-up to #1068, fixing one more instance of the same class of bug
(`ThemeProvider` emits every token as a literal value, flattening the
`var()` alias chains `globals.css` declares, so a derived token has to be
explicitly re-derived in `themeUtils.ts`). Confirmed by reading the
complete `themeUtils.ts` diff:

- **The bug and its fix, confirmed exactly**: in
  `withLegacyColorCompatibility`'s border back-fill block, the
  `dropdown` and `media` border assignments previously read from the
  pre-merge `theme` object (`theme.colors.border.divider` /
  `theme.colors.border.primary`) while every sibling assignment in the
  same block (`field`, `chatInput`, `attachment`, etc.) read from
  `nextTheme` — the object already carrying this function's own
  in-progress back-fill. Since `globals.css` declares `dropdown` as an
  alias of `divider` and `media` as an alias of `primary`, and both of
  those in turn follow `border.default` via the same back-fill mechanism,
  reading the pre-merge `theme` meant a theme pack setting only
  `border.default` got every border tinted to its brand color *except*
  dropdown and media, which silently stayed on the built-in `#d1d5db`
  gray. The fix is the minimal one-word change confirmed in the diff:
  both reads switch from `theme.colors.border.*` to
  `nextTheme.colors.border.*`.
- **Precedence preserved, confirmed via the new tests**: a new test
  confirms an explicit `dropdown`/`media` override still wins over the
  alias derivation (unaffected by this change, since the `if
  (!colorsOverride.border.dropdown)` guard is untouched). A second new
  test confirms the more subtle ordering case the PR calls out: when a
  pack explicitly overrides `divider`/`primary` themselves (not just
  `border.default`), `dropdown`/`media` correctly resolve through those
  explicit values rather than bypassing them — verifying the fix reads
  the post-merge, not just post-default-backfill, state.
- **Scope, confirmed by the PR's own stated impact and not independently
  re-verified against those exact theme packs**: affects any pack setting
  only `border.default` (the PR names `novoferm`, `trilux`,
  `trilux-test`, `modern-theme`); packs that already set `dropdown`/
  `media` explicitly (`erato`, `open-webui-like`) are unaffected since the
  back-fill guard already skipped them.
- **Two look-alike non-bugs, documented rather than fixed, per the PR
  (not independently re-verified)**: `--theme-border-subtle: var(--theme-bg-accent)`
  is a deliberate CSS/JS disagreement — making the JS match the CSS would
  tint every subtle border (including the docx/xlsx/pdf preview borders
  #1068 just pointed at this token) with the brand accent color, which is
  undesired; and `--theme-shell-sidebar-hover`/`--theme-message-hover`'s
  `color-mix()` CSS derivations are overridden by the provider's static
  values but are inert in practice, since every current theme pack
  already sets the underlying `background.hover`/`messageItem.hover`
  values the existing back-fill handles — restoring the CSS derivation is
  described as needing a precedence decision, deliberately left
  unresolved here.

## Compatibility and configuration

None breaking. Visual fix only: a theme pack setting only `border.default`
(and not `dropdown`/`media` explicitly) now sees its dropdown-menu and
media borders follow the brand color like every other border, instead of
staying on the built-in gray. A pack that already sets `dropdown`/`media`
explicitly is unaffected.
