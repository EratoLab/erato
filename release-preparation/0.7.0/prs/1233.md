# PR #1233: Extend sidecar protocol for deep linking

- Status: pending (diff reviewed)

## Summary

Pure desktop-sidecar protocol-specification addition (no backend/frontend
application code touched). Adds a `TopLevelParent` shape (`external-ids.schema.json`,
`top-level-parent.schema.json`) referencing "the outermost containing
document, never a folder" for a search result or attachment — e.g. an
email attachment's top-level parent is the email itself. Per its
description, "external IDs belong to that parent, not to the attachment,"
and it carries an optional `documentId` "that can be passed to
`sources.get_document.v1`" (from #1225). This is wired into
`search-query-v1-result.schema.json`,
`sources-get-document-v1-result.schema.json`, and the Outlook-specific
`attachment-reference`/`conversation-message` schemas — letting a client
deep-link from a search hit or attachment back to its containing item
(e.g. to open the original email in Outlook, or fetch the full parent
document) rather than only having the attachment/fragment's own,
potentially less useful, identifiers.

## Compatibility and configuration

No backend/frontend configuration keys or migrations — protocol
specification only; no Erato application code consumes these new fields in
this diff. Additive to existing result schemas (new optional field), not
a breaking change to existing consumers.
