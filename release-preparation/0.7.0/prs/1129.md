# PR #1129: Move the tab family onto one TabRail primitive and themable rail and track channels

- PR: https://github.com/EratoLab/erato/pull/1129
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Seventh (of nine) styling-primitives-consolidation topics, after #1092,
#1096, #1100, #1101, #1105, #1115 — all confirmed by this session to
match their descriptions precisely across extensive spot-checks.
Consolidates four previously hand-rolled tab-shaped surfaces (the two
settings rails, the markdown/preview switch, and `SegmentedControl`)
onto one new `TabRail` primitive. Confirmed by reading the complete
`globals.css` channel additions and the complete `SegmentedControl.tsx`
diff:

- **`SegmentedControl` is now a pure wrapper, confirmed exactly**: its
  own file shrinks from 199 lines of independent implementation (its own
  keyboard handler, its own `nextEnabledIndex` walk, its own JSX) to a
  thin component rendering `<TabRail variant="segmented" ... />` with the
  original prop/type names preserved as aliases
  (`SegmentedControlOption<T> = TabRailOption<T>`,
  `SegmentedControlAttention = TabRailAttention`) — matching the PR's
  claim that `SegmentedControl` "survives as a wrapper... with its name,
  props, memo cast... untouched" at the type/call-site level.
- **The radius-channel `0px`-not-`0` convention, confirmed exactly and
  consistent with this entire series' established pattern**: `.tab-rail-
  geometry` and `.tab-rail-track-geometry` both declare
  `--tab-rail-track-padding`/`--tab-rail-track-border-width` as `0px`
  (unit-qualified), and `.tab-item-geometry`'s `border-radius: max(0px,
  var(--tab-rail-radius, var(--theme-radius-control)) -
  var(--tab-rail-track-padding))` matches the same
  declare-on-the-family/read-on-the-member derivation pattern this
  session already independently confirmed for #1088's dropdown rows,
  #1100's popover rows, and #1105's card children — a code comment
  states the same reason each time: a unitless `0` makes `max()` invalid
  at computed-value time, silently squaring every tab's corners.
  `--tab-rail-radius` itself is confirmed never declared in this file,
  only read with a fallback to `--theme-radius-control` — matching the
  stated "READ, never declared" design so a theme can set it on the hook
  element or any ancestor without being shadowed.
- Per the PR (not independently re-verified given the very large
  remaining scope): the new `TabRail.tsx` primitive itself (370 lines,
  two anatomies `rail`/`segmented`, an explicit `arrowKeys`
  `horizontal`/`vertical`/`both` axis reconciling four previously-
  disagreeing hand-rolled keyboard handlers); six disclosed stock-visual
  deltas (active-tab fill changing from hover-tint to selected-tint in
  both settings dialogs — described as fixing a genuine same-color
  active/hovered-inactive confusion; the markdown/preview tabs growing
  slightly; the assistants-page view switcher losing its bordered-inset-
  track look in favor of bare tabs with a gap, isolated in its own final,
  separately-revertable commit as "the one deliberate re-skin"); the
  disclosed theme-retune acceptance evidence under `open-webui-like`
  (the theme's existing `[data-ui="tab-rail"]` pill-radius rule
  previously reached only 2 of 10 tab sites and now reaches all 10,
  measured via a committed Playwright harness not run in CI); and the
  `ERATO_SHARED_SURFACE_MINOR` version bump from 4 to 5 for the newly
  pinned `TabRail` export.

## Compatibility and configuration

None functionally breaking for the default (non-override) path — the
`SegmentedControl` public API is confirmed unchanged at the type/prop
level. Several disclosed, deliberate small visual deltas (tab sizing,
active-state color, the assistants-page view switcher's look) consistent
with this series' established consolidation-driven-delta pattern from
earlier topics (#1088, #1096, #1105).

## Release note disposition

Proposed category: Bug fixes. Worth a brief mention: the active tab in
Preferences and the add-in Settings dialog is now visually distinct from
a merely-hovered tab (previously both used the same fill color), and the
