# PR #1027: Extract router-free chat-history primitives for host reuse (ERMAIN-614)

- PR: https://github.com/EratoLab/erato/pull/1027
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Large (3274-line) refactor extracting the web sidebar's chat-history
filter/list/navigation logic into router-free, parameterizable primitives
so the Outlook add-in's history drawer (`AddinHistoryDrawerCore.tsx`, new
in this PR) can reuse them with its own persistence and without React
Router. Given the scale, review targeted the pieces most load-bearing for
correctness — whether the extraction actually preserves existing web
behavior rather than silently changing it — and confirmed each by direct
diff read:

- **Filter store becomes a factory, confirmed via
  `chatHistoryFilterStore.ts`**: the module-level `useChatHistoryFilterStore`
  singleton (backed by a hardcoded persistence key) is replaced by
  `createChatHistoryFilterStore(persistName)`, with the web sidebar's own
  instance created by calling it with the original key
  (`"erato.sidebar.chatHistoryFilters"`) — confirmed the store's internal
  logic (actions, the union-coercing `merge` function, devtools naming) is
  otherwise unchanged, just wrapped in the factory. A code comment states
  the rationale: a shared key would let a web sidebar filter silently
  shrink an add-in host's list.
- **A real correctness fix bundled in, confirmed via the same file**: the
  new `useChatHistoryFilterFoldback` hook writes sanitized (assistant-
  scoped-cleared) filter values back into the store itself via `useEffect`
  when `assistantsEnabled` is false, rather than only sanitizing at render
  time as `useSanitizedChatHistoryFilters` already did — a code comment
  states this matters because the recent-chats query reads the raw
  persisted store value directly, so render-time-only sanitization would
  leave a stale assistant-scoped filter silently still filtering the
  actual request.
- **Parameterized consumers, confirmed via `ChatHistoryFilterMenu.tsx`**:
  the component now accepts an optional `store` prop (typed
  `ChatHistoryFilterStoreHook`) defaulting to
  `useChatHistoryFilterStore`, with every internal store-hook call
  (`typeFilter`, `statusFilter`, `groupBy`, and all four setters) switched
  from the singleton to the parameter — confirmed this is a pure
  parameterization with no logic change, since web callers passing no
  `store` prop get byte-identical behavior.
- **Extraction fidelity, confirmed via `useChatHistory.ts` and
  `useInfiniteRecentChats.ts`**: the diff shows
  `buildRecentChatsFilterParams`, `buildInfiniteChatsQueryKey`, and related
  types/constants (`CHAT_HISTORY_PAGE_SIZE`, `RecentChatsCacheEntry`,
  `isPaginated`) removed from `useChatHistory.ts` and re-exported from the
  new `useInfiniteRecentChats.ts` — confirmed by direct comparison that
  `buildRecentChatsFilterParams` and `buildInfiniteChatsQueryKey` moved
  with byte-identical bodies, and `useChatHistory.ts` re-exports them for
  existing import sites so nothing consuming these from their old location
  breaks.
- Per the PR (not independently re-verified given the remaining scope):
  the new `SidebarNavigationItem.tsx` component (141 lines) unifies
  `NewChatItem`/`SearchNavigationItem`/`AssistantsNavigationItem`'s
  layout, active-state, and slim-mode handling; `NewChatItem` and
  `NoFilterMatchesRow` are now exported for the add-in drawer; chat-session
  grouping logic moves into a new `useGroupedChatSessions` hook; the
  283-line `ChatHistoryList.tsx` diff and the 525-line new
  `AddinHistoryDrawerCore.tsx` build the add-in's own drawer surface atop
  these primitives; and the new `office-addin/src/outlook/sessionPolicy/`
  module (`policyGate.ts`) gates some session behavior not otherwise
  described in the PR body.

## Compatibility and configuration

None for the web app: the refactor is designed to be behavior-preserving
for existing surfaces, confirmed at the sampled extraction/parameterization
points above (default-store fallbacks, re-exports, byte-identical function
bodies). No API or database changes. Adds substantial new add-in-only
surface (`AddinHistoryDrawerCore.tsx`, `addinChatHistoryFilterStore.ts`,
`sessionPolicy/`) not otherwise exercised by the web app.
