# PR #846: E2E: harden the queue/streaming spec + cover the mid-stream error path

## Summary

Test-only follow-up to #841's Playwright spec for the message-queue/
streaming-composer feature (#837/#840). Confirmed by the diff stat: only
`queue-and-streaming-composer.many-models.spec.ts` and the shared E2E
helper file `shared.ts` are touched — no product/application code changes
(unlike #841, which despite a similar "E2E" title bundled in a real
production fix). Per the description:

- Hardens existing assertions so a stream ending earlier than expected
  fails loudly instead of silently passing on a different code path
  (e.g. Queue silently becoming Send once the stream ends, previously
  producing a misleading downstream assertion failure rather than a clear
  one) — via a new `expectStreamStillActive` check re-asserted before
  every queue-affecting action, widened timing windows for tests that had
  been running many UI steps inside too-tight a window, and gating
  "nothing was auto-sent" negative assertions behind a terminal-token
  signal plus a grace period so they can actually fail if something does
  send.
- Adds the previously-deferred error-path coverage from #841 (the
  "stream for N seconds, then error" scenario) via two new test helpers,
  `installStreamErrorTap`/`injectStreamError`, which tap the SSE stream
  and inject the exact `event: error` frame the backend emits on a
  provider failure, then end the stream — exercising the drain path where
  a queued draft is returned to the composer rather than sent.
- Redeploys the navigate-away test to first let a turn fully complete
  (rather than navigating away mid-stream) before asserting, since the
  chats sidebar list only refetches on completion, not on a mid-stream
  navigation (a 60-second `staleTime` makes focus-refetches a no-op) — the
  previous test shape is described as flaky for this reason.
- Switches the upload test helper to `setInputFiles` rather than driving
  the file-chooser UI, since the tests exercise upload *routing*, not
  chooser UI which varies by config.
