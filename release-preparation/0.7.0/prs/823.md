# PR #823: Force interactive login on sign-in button

- PR: https://github.com/EratoLab/erato/pull/823
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Fixes an Outlook add-in sign-in dead end (ERMAIN-459): when a silent
"Native Auth Adapter" (NAA) token refresh kept returning the same expired
ID token even after MSAL force-refreshed the accompanying access token,
`oauth2-proxy` would keep rejecting it, and clicking the add-in's "Sign
in" button re-ran the same silent-refresh path — so the user had no way
to escape the loop. Confirmed by reading the code:

- A new `forceInteraction` option is threaded through
  `AuthSource.acquireBootstrapToken` → `createEntraAuthSource`'s
  `acquireMsalResult` → `SessionAuthProvider.refreshSession`. When set, it
  skips `acquireTokenSilent` entirely and goes straight to
  `acquireTokenPopup` (interactive, `prompt: "select_account"`) —
  confirmed this throws `InteractionRequiredError` instead of silently
  proceeding if `allowInteraction` is false, so the flag can't
  accidentally force a popup somewhere interaction isn't allowed.
- The add-in's "Sign in" button handler now calls
  `refreshSession(true, true)` (both `allowInteraction` and the new
  `forceInteraction` set) — confirmed via the added code comment: "This
  button is the user's explicit request to sign in. Go straight to
  interactive NAA instead of first accepting another silent cached ID
  token."
- A new diagnostic: after either a forced silent refresh or a forced
  interactive refresh, the previous bootstrap token (id/access token,
  kept in memory only, never logged) is compared against the newly
  acquired one; if either is byte-identical to before, a
  `console.warn("MSAL bootstrap token refresh returned unchanged token
  values", ...)` fires — surfacing exactly the failure mode this bug
  report described, for future diagnosis, without ever logging actual
  credential values.

## Compatibility and configuration

None. Pure Outlook add-in bug fix; no configuration keys or backend
changes. Behavior change: clicking "Sign in" after a stuck/expired NAA
session now forces an interactive Microsoft account picker instead of
silently retrying (and failing) the same cached token.
