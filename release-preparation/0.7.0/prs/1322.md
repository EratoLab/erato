# PR #1322: Show the indexed time range instead of document counts in indexing settings

- PR: https://github.com/EratoLab/erato/pull/1322
- Status: pending
- Category: Features and enhancements
- Theme: Desktop Sidecar

## Summary

Frontend consumer of the protocol's new "indexed range" (#1316, reviewed
in this batch): replaces the "Settings → Local indexing" per-source
document-count display (e.g. "552 of 554 documents indexed (99%)") with
a time-range statement (e.g. "Indexed Mar 14, 2025 to today"), since
counts don't tell a user which period local search actually covers. Per
the PR's own precise before/after examples and mapping table, confirmed
against the code:

- `indexingConfiguration.ts`'s row summary shape changes from counts
  (`total`/`indexed`/`percentage`/etc., all removed) to
  `{state, range, observedAt, notices}`.
- A full `unavailableReason` → UI-state mapping is implemented exactly as
  described: `not_enumerated` → "Not scanned yet" (confirmed in code at
  the `not_enumerated` branch returning the `notScanned` range);
  `no_searchable_documents`/`index_not_initialized` → "Nothing
  searchable yet"; `source_disabled`/unknown → no range line, pill only.
  When `through` is null the line reads "Indexed {from} to today" or "...
  to {observedAt date}"; when set, "... · newest items still being
  indexed". `olderPending > 0` adds an "Older items are still being
  indexed" details line.
- Legacy sidecars that don't report `indexedRange` get a best-effort
  fallback (oldest `depth.oldestIndexedDocumentAt` to
  `lastSuccessfulScanAt`, only once indexing has settled) rather than
  losing the feature outright; `fullyIndexedSince`/`processedSince` are
  explicitly never read anymore.
- When several discovery entries feed one row (legacy mailbox scope),
  the combined range takes the latest `from`, earliest `through`, and
  earliest `observedAt` across them — a conservative merge.
- The `discoveredTotals` footnote and several now-unused i18n message
  ids (`sidecar.indexing.progress`, `.lastScan`, `.discoveredTotals`,
  etc.) are removed/marked obsolete; a new set of range/notice message
  ids is added with de/es/fr/pl translations filled in (not spot-checked
  per-locale for accuracy).

## Compatibility and configuration

None breaking; purely a settings-UI redesign with a backward-compatible
protocol fallback for sidecars that don't yet report `indexedRange`
(server/protocol package itself is unchanged, per the PR). No config
keys, no migration. The underlying document counts are not lost — the
sidecar and protocol still report them; only this frontend view stops
displaying them.
