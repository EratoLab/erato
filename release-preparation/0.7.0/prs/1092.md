# PR #1092: Move every loading ring onto one themable spinner primitive

- PR: https://github.com/EratoLab/erato/pull/1092
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Consolidates 18 hand-rolled loading rings and 10 spun icons onto one
`SpinnerIcon` primitive with a `.spinner-geometry` CSS class, so a
customer theme can restyle every spinner with one `[data-ui="spinner"]`
rule. Confirmed by reading the complete `SpinnerIcon.tsx` diff and the
relevant `globals.css` addition:

- **The visual bug and its fix, confirmed exactly**: the old
  implementation used `border-e-transparent` — a transparent quadrant cut
  out of the ring, producing a visible 270° arc. The new `.spinner-geometry`
  paints a full solid `border` (all four sides, defaulting to a 25% color
  dilution of the spinner head) and overrides only
  `border-inline-end-color` to the full head color — i.e. a complete,
  centered circular track with one brighter segment, not a cut-out arc. A
  detailed code comment states the underlying geometry problem precisely:
  a ring missing a quadrant carries its visual center of mass off the true
  center by roughly the fraction the PR measures (30% of the radius for a
  three-quarter arc), and that offset travels once per rotation, producing
  a visible wobble — confirmed this is the exact defect the new
  full-track design closes.
- **Literal size-class map, not a template, confirmed exactly**: `SIZE_
  CLASSES` is a plain `Record<size, string>` object literal
  (`sm: "spinner-sm"`, etc.), with a code comment stating why: Tailwind's
  `@layer components` purging drops any class whose name never appears
  literally in a scanned source file, so a `` `spinner-${size}` `` template
  string would compile away every size rule in production.
- **`aria-hidden` opt-out correctly suppresses double-announcement,
  confirmed exactly**: `SpinnerIcon` reads `props["aria-hidden"]` itself
  (via the full `ComponentPropsWithoutRef<"span">` prop spread the old
  component didn't have) to compute `decorative`, which both omits
  `role="status"` and skips rendering the `sr-only` fallback text —
  matching the PR's stated purpose of letting a caller whose surrounding
  element already owns the live region avoid a duplicate announcement.
- **Reduced-motion slows, never freezes, confirmed exactly**: a
  `prefers-reduced-motion: reduce` media query raises
  `animation-duration` to `1.5s` (up from the default `1s`) rather than
  removing the animation, with a code comment stating a frozen spinner
  would be indistinguishable from a hung app, and that the longhand
  property placement deliberately outranks a theme's attempt to override
  the animation-duration shorthand at this rule.
- Per the PR (not independently re-verified given remaining scope): the
  claimed WCAG 1.4.11 contrast improvement (a `--theme-border`-only track
  measuring 1.41:1/2.35:1 light/dark, below the 3:1 non-text floor, versus
  the new painted head measuring 9.86:1/14.33:1) — the code confirms the
  *mechanism* (a distinctly colored head segment against a diluted track)
  that would produce this improvement, but the specific contrast ratios
  were not independently measured; the new `Button.busy` prop (a spinner
  without the disabling `loading` implies, motivated by the audio-mode
  stop button needing to stay clickable while starting); the accessibility
  fix for the Teams picker's decorative chip spinner, whose `aria-hidden`
  previously never reached the DOM and so announced "Loading..." inside
  an already-labelled control; and the claimed reduction of `animate-spin`
  occurrences from 35 to 6 (the survivors being icon-catalogue story
  demos and `FilePreviewLoading`, attributed to separate attachment-related
  work).

## Compatibility and configuration

None breaking for end users. New additive `--spinner-track`/
`--spinner-head`/`--spinner-thickness`/`--spinner-duration` custom
properties for theme customization, scoped under `[data-ui="spinner"]`
and deliberately namespaced apart from `--theme-*` (a code comment notes
`ThemeProvider` emits `--theme-*` tokens as literals on `:root`, which
would otherwise clobber a spinner-specific override). `SpinnerIconProps`
gains new `size` options (`xl`, `fill`) and a `label` prop; existing
`sm`/`md`/`lg` sizes are confirmed unchanged (12/16/24px). Component kits
are explicitly unaffected in this PR — the pinned shared-surface export
is a prerequisite for a kit importing it, not yet exercised.
