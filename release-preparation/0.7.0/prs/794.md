# PR #794: Fix "SSE connection error" on navigation during streaming

- PR: https://github.com/EratoLab/erato/pull/794
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: Streaming/generation stability

## Summary

Fixes a false-positive error surfaced when a user navigates away (or
otherwise aborts a fetch) while a chat response is still streaming via
Server-Sent Events. In `frontend/src/utils/sse/sseClient.ts`, the stream
reader's `catch` block that processes the async generator did not check for
an intentional abort before treating any thrown error as a real stream
error; only the outer `fetch` `catch` block checked `err.name ===
"AbortError"`. A new `isAbortError` helper is added and used in both
places, and the check is broadened to `signal.aborted || isAbortError(err)`
(covering cases where the abort signal fired but the thrown error isn't
literally an `AbortError` instance). When the abort condition is detected,
the code now logs "Stream aborted" and cleanly closes the connection
instead of surfacing an error to the user/UI. A new
`e2e-tests/tests/mock-flows.many-models.spec.ts` test (107 lines) and
updates to `frontend/src/utils/sse/sseClient.test.ts` (44 lines) exercise
this path; `e2e-tests/tests/mcp-resilience.many-models.spec.ts` was also
adjusted.

## Compatibility and configuration

No configuration keys or migrations. Purely a client-side bug fix; no
backend changes. Effect: navigating away from an actively-streaming chat
(or otherwise cancelling the request) no longer surfaces a spurious "SSE
connection error" to the user.
