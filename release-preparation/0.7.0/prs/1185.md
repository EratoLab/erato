# PR #1185: Extend sidebar protocol with generic metadata filter

- PR: https://github.com/EratoLab/erato/pull/1185
- Status: pending (diff reviewed)

- Theme: Desktop Sidecar for local sources

## Summary

Pure desktop-sidecar protocol-specification addition (no backend/frontend
application code touched; the PR title says "sidebar" but this is the
desktop-sidecar protocol, consistent with the rest of this cluster). Adds
a generic, discoverable metadata-filtering capability to
`search.query.v1`: a new `SearchMetadataFilter` shape
(`{field, operator, value}`, all required, `additionalProperties: false`)
that `search-query-v1-params.schema.json` now accepts, and a new
`search.metadata_fields.v1` method that returns the set of filterable
fields a given sidecar/source supports — each entry describing its `field`
name, supported `operators`, value `type`, a human-readable `description`,
and which source kinds (`applicable_kinds`) it applies to. This lets a
client discover valid filter fields/operators dynamically per sidecar
capability set, rather than hardcoding a fixed filter vocabulary.

## Compatibility and configuration

No backend/frontend configuration keys or migrations — protocol
specification only; no Erato application code consumes these new methods
in this diff. No production impact until a real sidecar implementation and
corresponding client integration land.
