# PR #1047: Draw sent-message attachments with the shared tile

- PR: https://github.com/EratoLab/erato/pull/1047
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Stacked on #1046. Extends the shared `AttachmentTile` to sent-message
attachments (previously a separate implementation), rendered read-only at
`size="medium"`. Confirmed by reading the new `MessageAttachments.tsx`,
the `AttachmentTile.tsx` diff, and the relevant `ChatMessage.tsx`
integration:

- **Resolution from `allFilesById`, confirmed exactly via the new
  `MessageAttachments.tsx`**: `missingIds` is computed as
  `fileIds.filter((fileId) => !(fileId in filesById))`, and only those
  missing ids drive `useQueries`/`getFileQuery` fetches (one query per
  missing id, `staleTime: Infinity`) — every id already present in the
  conversation's `filesById` map (confirmed passed in from
  `useChatMessageRenderer`'s output in `ChatMessage.tsx`) is used directly
  with no network request, matching the PR's stated per-attachment
  request elimination. The merge (`{ ...map, ...filesById }`) confirms the
  conversation's own records take precedence over a freshly fetched one.
- **No remove button, confirmed by construction**: `MessageAttachments`
  renders `AttachmentTileList` with only `onActivate` (for preview) wired
  — no `onRemove`/similar prop exists on this call site at all, so
  ERMAIN-691 item 1 (a greyed-out remove button that could never do
  anything) is fixed structurally rather than by disabling it.
- **Accessibility for the caption-less tile, confirmed exactly via
  `AttachmentTile.tsx`**: the image's `alt` becomes `onActivate ? "" :
  filename` (empty when wrapped in a labelled button, to avoid announcing
  the name twice; the filename otherwise, for a standalone/non-interactive
  tile), and the button's `aria-label` becomes
  `` `${t\`Preview attachment\`} ${filename}, ${typeLabel}` `` — confirmed
  matching the PR's example (`"Preview attachment report.pdf, PDF"`)
  exactly. The `title` attribute continues to carry the filename on hover
  in both the button and the non-interactive `<div>` fallback.
- Per the PR (not independently re-verified given remaining scope): the
  separate `max-w-[96px]` caption-truncation rule from the old
  implementation is removed as unnecessary now that captions are off
  entirely (ERMAIN-691 item 4); and the new `RecipeInSentMessage`
  Storybook story exercises the real `ChatMessage` component rather than a
  mock, made possible by the `allFilesById`-based resolution requiring no
  backend for already-known files.

## Compatibility and configuration

None. Pure frontend visual/accessibility change to how sent-message
attachments render; no API or configuration changes. `ChatMessage.tsx`
loses ~139 lines of its own inline attachment-rendering logic in favor of
the new shared `MessageAttachments` component (not independently
re-verified beyond the confirmed integration point above).
