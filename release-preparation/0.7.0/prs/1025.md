# PR #1025: Surface delegated background runs in the add-in pane (ERMAIN-644)

- PR: https://github.com/EratoLab/erato/pull/1025
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Delegation

## Summary

Adds a "host seam" so the Outlook add-in pane — which never mounts the
web app's chat routes — can surface and open delegated background runs
via its own navigation/session logic instead of in-app links. Confirmed
by reading the three core component diffs plus the new provider in full,
two distinct mechanisms are used for two different reach patterns:

- **Prop-based seam for directly-reachable components, confirmed via
  `DelegatedRunsSection.tsx` and `DelegatedRunHeader.tsx`**: both
  components gain an optional callback prop (`onOpenRun`/`onOpenOrigin`).
  Confirmed when supplied, `DelegatedRunRow` renders as an
  `InteractiveContainer` (`useDiv={true}`) with an `onClick` calling
  `onOpen(chat)` and *no* `href` at all, and `DelegatedRunHeader`'s origin
  renders as a `<button onClick={() => onOpenOrigin(originChatId)}>`
  instead of an `<a href>` — confirmed both preserve the exact same visual
  styling/classes as their link counterparts, changing only the
  interaction element. A code comment states the rationale precisely: no
  href means a middle- or cmd-click can't route to a chat URL the host
  doesn't serve. Left unset (the web app's default), both fall back
  unchanged to the pre-existing link-based behavior from #1013/#1021.
- **Context-based seam for the deeply-nested trace affordance, confirmed
  via the new `DelegatedRunOpenProvider.tsx` and the `DelegationStep.tsx`
  diff**: `useDelegatedRunOpener()` returns `null` when no provider is
  mounted (web surfaces render the default new-tab link, confirmed via
  the unchanged fallback `<a href={getChatUrl(...)}>` branch), or the
  host's `onOpen` callback when a `DelegatedRunOpenProvider` wraps the
  tree — confirmed rendering a `<button onClick={() => openRun(chatId)}>`
  in that case. A code comment states this exists specifically because
  the trace's open-run affordance sits deep in the message tree behind
  custom message renderers, where prop-threading `onOpenRun` down from
  the section component would not reach it.
- Per the PR (not independently re-verified given remaining scope): the
  288-line `AddinChatCore.tsx` diff wires both seams into the add-in's own
  pane-navigation/session logic; `useDelegatedRunHeader` forwards the new
  `onOpenOrigin` option through to `DelegatedRunHeader`; the relevant
  props/hooks/provider are exported from `frontend/src/library/index.ts`
  for host consumption; and the `pnpm-lock.yaml` changes are an
  unrelated dependency-version consistency fix (Lingui packages pinned to
  `5.9.4`), not a functional change.

## Compatibility and configuration

None. Purely additive, opt-in props/context on already-shipped delegation
UI (still gated behind the not-yet-enabled `allow_background` flag); web
app behavior is byte-identical when the new props/provider are omitted,
confirmed via the unchanged fallback branches in both components read
above. No API or database changes.
