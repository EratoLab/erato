# PR #1347: Show Word selection replies in the Erato web app (ERMAIN-942)

- PR: https://github.com/EratoLab/erato/pull/1347
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: Word selection editing

## Summary

Per the PR description: a Word selection chat (the Replace feature built
up over this batch), when later opened in the Erato web app or re-rendered
outside the live Word pane, previously showed the assistant's reply as a
raw `erato-word-replace` fenced code block with literal `⟦1⟧…⟦/1⟧` kept-
item markers visible, and the "Selection" quote under the user's message
ran multiple paragraphs together without breaks. Confirmed directly in
`WordHistoryCards.tsx`: a new `WordHistoryReplaceCard` component renders
the fence read-only instead, showing the stored `selected_text` against
the proposal (for a whole-passage rewrite) or the proposal alone with a
short hint otherwise, joining single-paragraph replies' lines the same way
the add-in itself writes them, and labeling markers from the stored
`kept_items` argument the same way the add-in's own card labels them
(falling back to generic `[item n]` labels without that argument); Copy
strips markers, matching the add-in's own context-only fallback
behavior. Per the PR (not independently verified beyond the card
component): a new add-in contract test feeds the add-in's own
`wordKeptItemsArg` output through the web app's marker parser, so a
format mismatch between the two independent implementations fails a test
rather than silently diverging. Separately, `ActionFacetContext` — shared
by the component library's `ChatMessage`, used by both the web app and
the Word/Outlook add-ins — is fixed so the Selection quote keeps paragraph
line breaks and labels markers everywhere, including inside the Word
pane itself once the add-in rebuilds against the updated library, and the
same `whitespace-pre-line` fix preserves line breaks in Outlook's own
selection quotes.

## Compatibility and configuration

Bug fix / rendering improvement; no config keys, no database migration.
Per the PR, Word's own live rendering of the fence (`setWordLiveCards`
and the stamped `hostArtifact` mechanism) is explicitly unchanged — this
PR only affects how the reply renders when viewed outside the live Word
pane (web app, or history), not inside it.
