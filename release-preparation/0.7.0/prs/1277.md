# PR #1277: Fix Teams bot package upload validation

- PR: https://github.com/EratoLab/erato/pull/1277
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Follow-up to the Teams bot cluster (#1253/#1254/#1260/#1275, reviewed
earlier in this session). The Teams admin center rejected the generated
bot package because Teams manifest schema 1.29 requires a top-level
`supportsChannelFeatures` declaration for any app declaring the `team`
scope — which this project's conversational bot does. Confirmed exactly:

- **`supportsChannelFeatures: "tier1"` is set whenever the bot is
  enabled, confirmed exactly**: `apply_bot` (called only when
  `app.bot.enabled`) now sets `document["supportsChannelFeatures"] =
  json!("tier1")`, with a code comment "Manifests v1.25+ with team scope
  must declare channel feature support" — matching "Add the top-level
  `\"supportsChannelFeatures\": \"tier1\"` declaration whenever the
  conversational bot is enabled" exactly.
- **A bot package missing the declaration is rejected at validation,
  confirmed exactly**: `validate_manifest` now asserts
  `document["supportsChannelFeatures"] == "tier1"` whenever
  `app.bot.enabled`, failing with "Teams bot with team scope requires
  supportsChannelFeatures to be tier1" otherwise — matching "reject bot
  packages that omit it" exactly. A new dedicated test
  (`rejects_bot_packages_without_channel_feature_support`) renders a
  valid bot-enabled manifest, strips the field, and asserts packaging
  fails with an error message containing `"supportsChannelFeatures"`.
- **Personal-tab-only (no-bot) packages are genuinely unaffected,
  confirmed exactly**: the existing no-bot test gains an explicit new
  assertion, `assert!(manifest["supportsChannelFeatures"].is_null())` —
  confirming the field is never added when the bot isn't enabled, and
  the existing bot-enabled test gains `assert_eq!(manifest["supportsChannelFeatures"],
  "tier1")` — matching "Personal-tab-only packages remain unchanged"
  precisely, verified on both sides of the condition.
- Per the PR (not independently re-verified): the disclosed validation
  (all four focused Teams distribution tests passing; formatting/diff
  checks; and the disclosed manual confirmation that corrected
  production and staging ZIPs pass Microsoft's published v1.29 JSON
  schema plus the conditional team-scope rule, with IDs and icon bytes
  unchanged).

## Compatibility and configuration

None breaking. Pure bug fix to the existing Teams bot manifest
generation/validation this session already reviewed — no new config
key; the field is derived automatically from the existing
`integrations.ms_office.teams.bot.enabled` setting, confirmed to only
ever appear when that flag is on.
