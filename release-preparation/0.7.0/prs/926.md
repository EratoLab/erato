## Summary

**The recorded merge commit for this PR contains no code changes at
all** — `git diff c10e8d3ba3db59bf9f7483aa82ea1638d8608a26^1
c10e8d3ba3db59bf9f7483aa82ea1638d8608a26` (this PR's squash-merge commit
against its own immediate parent) is empty. Per the PR's own description,
the fix is a one-line addition to `detectExchangeOnPrem()`'s cloud-suffix
allowlist in `office-addin/src/utils/detectExchangeOnPrem.ts`, adding
`.cloud.microsoft` (Microsoft's newer unified domain for Outlook on the
web) so Exchange Online mailboxes served from that domain are no longer
misclassified as on-premises Exchange — which previously (a) triggered an
existing NAA veto for on-prem mailboxes, silently falling back to the
oauth2-proxy auth path instead of mounting `EntraGraphTokenProvider`, and
(b) routed mail access through EWS instead of Graph.

The fix is real and present in the current codebase — `.cloud.microsoft`
is in `detectExchangeOnPrem.ts`'s allowlist and a matching test exists
("treats the unified cloud.microsoft endpoints as Exchange Online" in
`detectExchangeOnPrem.test.ts`) — but `git log -S'".cloud.microsoft"'`
(pickaxe search for when that literal string was introduced) shows it was
actually added by commit `7e6fe5d30771418d873d3aa3f9606ba0fe8e1d24`, whose
message is **"Extract host-neutral add-in core, isolate Outlook
composition (#922)"** — i.e. a *different* PR, #922, not #926. That commit
is exactly this PR's (#926's) immediate parent in `main`'s history. The
most likely explanation: #926's branch was developed in parallel with (or
was rebased onto) #922's branch, #922 incorporated the same fix (perhaps
by rebasing on top of #926, or because both were developed together) and
was merged to `main` first, and by the time #926 was itself squash-merged,
`main` already contained the identical change via #922 — leaving #926's
own squash-merge commit with a net-zero diff.
