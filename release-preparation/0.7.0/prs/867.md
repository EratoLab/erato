# PR #867: Extend MCP file mechanism with metadata marker for filenames

- PR: https://github.com/EratoLab/erato/pull/867
- Status: pending
- Category: Features and enhancements
- Theme: MCP controls

## Summary

Extends Erato's existing MCP file-output mechanism (marking a Base64
string field with the `chat.erato/file_content_field` JSON Schema
annotation, documented and pre-existing before this PR) with a new sibling
annotation, `chat.erato/file_name_field` (alias `x-chat.erato/file_name_field`
also accepted, matching the existing `x-`-prefixed alias support for the
content-field annotation). When an MCP tool's output schema marks one
string field as the file content and another sibling field as
`chat.erato/file_name_field`, Erato now uses that sibling field's value as
the created file upload's display name; if the annotation or value is
absent, a name is still generated as before. At most one sibling field may
be marked as the file name for a given file-content field.

Implementation: `backend/erato/src/server/api/v1beta/message_streaming_file_extraction.rs`
adds a `FileContentPath` struct that tracks, per file-content field
discovered while walking a tool's JSON Schema (including through `$ref`,
`oneOf`/`anyOf`/`allOf`, and array items), the list of sibling
`file_name_field`-marked field names found at that nesting level; a new
`has_schema_annotation` helper checks both the bare and `x-`-prefixed
annotation forms. `ExtractedFileField` gains a `file_name: Option<String>`.
`backend/erato/src/services/mcp_manager.rs` and
`backend/mock-mcp-server/src/lib.rs` received small supporting changes (10
and 3 lines). Documentation in `site/content/docs/features/mcp_servers.mdx`
is substantially expanded (73 new lines) with a full worked example of the
new annotation, and a note that display names from MCP are never used as
storage paths, and that file-output processing currently only supports
image MIME types.

## Compatibility and configuration

No configuration keys or migrations. Purely additive to the MCP tool
schema annotation surface: existing MCP servers using only
`chat.erato/file_content_field` (without the new name annotation) are
unaffected and continue to get generated file names as before. Server
authors can now opt into `chat.erato/file_name_field` for readable
attachment names.
