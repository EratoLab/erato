# PR #1143: Protocol adjustments for sidecar indexing

## Summary

Pure desktop-sidecar protocol-specification addition (no backend or
frontend application code touched — only `desktop-sidecar-protocol/`
files: schemas, generated TypeScript, mock test-server, and conformance
fixtures). Adds two new JSON-RPC methods related to the sidecar's local
search-indexing capability (built on the source-listing/search-query
protocol extensions from earlier this cycle, e.g. #1184/#1186):
- `indexing.status.v1`: takes optional `includeSourceBreakdowns` and
  `includeFileTypeBreakdowns` booleans (both default `true`), returning a
  detailed indexing-statistics result (the largest schema in this diff, at
  1446 lines).
- `indexing.reset.v1`: takes no parameters. Per its own schema
  description, this "fully resets all indexing storage managed by this
  sidecar for the current OS user. No mailbox, generation, or
  filesystem-path selector is supported. This command deletes index data;
  it is not a generation rebuild" — i.e. it's an unconditional, all-or-nothing
  wipe of local index data, not a scoped or reversible operation.

Both are added to `openrpc.json`, with generated TypeScript
types/validators and mock `test-server` support for conformance testing.

## Compatibility and configuration

No backend/frontend configuration keys, migrations, or runtime behavior —
this PR only extends the protocol specification and its reference
client/mock server; no Erato application code consumes these new methods
in this diff. No production impact until a real sidecar implementation and
corresponding Erato client integration land in a later PR.
