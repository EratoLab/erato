# PR #814: Adjust compat_no_replay_summary behaviour

- PR: https://github.com/EratoLab/erato/pull/814
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Changes when persisted reasoning messages are stripped from a chat request
before it is sent to the model provider, in
`backend/erato/src/server/api/v1beta/message_streaming.rs`
(`prepare_chat_request_with_adapters`). Previously, `strip_persisted_reasoning_messages`
was called (a) when the assistant's configured chat provider had changed
since the reasoning was recorded (`did_prior_assistant_chat_provider_change`),
and separately (b) unconditionally whenever the provider kind is
`openai_responses`/`azure_openai_responses`
(`is_openai_responses_provider_kind`). The existing per-model
`compat_no_replay_summary` setting (already used elsewhere to suppress
replaying reasoning summaries specifically for the OpenAI Responses replay
path) did not previously affect whether persisted reasoning messages were
stripped for other provider kinds.

A new helper, `should_strip_persisted_reasoning_messages`, unifies the
three conditions (`did_prior_assistant_chat_provider_change`,
`compat_no_replay_summary`, or an OpenAI Responses provider) into a single
check performed once, earlier in request preparation. The previously
duplicate, unconditional strip call inside the OpenAI-Responses-specific
branch is removed (now redundant, since that branch's condition is already
covered by the unified check). Net effect: setting a model's
`compat_no_replay_summary` to `true` now also strips persisted reasoning
messages from the request for **any** provider kind, not only in the
OpenAI Responses reasoning-replay path.

## Compatibility and configuration

No new configuration keys — `compat_no_replay_summary` is a pre-existing
per-model setting (`ModelSettings.compat_no_replay_summary`, mergeable via
facets in `backend/erato/src/services/prompt_composition/model_settings.rs`).
No migration. Behavior change: deployments that have set
`compat_no_replay_summary = true` on a model using a non-OpenAI-Responses
provider will now also have persisted reasoning messages stripped from
outgoing requests for that model, where they previously were not. This is
a compatibility workaround setting (intended for providers/proxies that
reject replayed reasoning summaries), so this broadens its effect to match
its apparent intent rather than changing default behavior for
unconfigured models.
