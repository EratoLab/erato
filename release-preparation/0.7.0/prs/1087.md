# PR #1087: Reduce and reorganize the new-chat welcome content (ERMAIN-737)

- PR: https://github.com/EratoLab/erato/pull/1087
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Part 2 of the ERMAIN-731 stack, on top of #1086's three-row centered
layout. Splits the generic and assistant welcome screens into
`*Upper`/`*Lower` component pairs that render in the layout's separate
upper/lower rows, and compacts the starter-prompt buttons. Given the
large scope (1561 lines), review focused on the piece most load-bearing
for backward compatibility — whether an existing component-kit override
of `ChatWelcomeScreen`/`AssistantWelcomeScreen` keeps working correctly
— confirmed by reading the complete `ChatEmptyState.tsx` diff:

- **Override-compatibility gate, confirmed exactly**: when
  `componentRegistry.ChatWelcomeScreen` (or `AssistantWelcomeScreen`) is
  set, `ChatEmptyState` renders that override component whole when `part
  !== "lower"` (i.e. the default `"upper"` part) and returns `null` when
  `part === "lower"` — matching the PR's stated design exactly: a
  registered override is treated as a complete, un-split welcome screen
  that renders once in the upper area, with the lower row contributing
  nothing (no default subtitle/description/starter prompts sneaking in
  underneath a kit's custom welcome content).
- **Default (non-override) path, confirmed exactly**: with no override,
  `part === "lower"` renders the new `WelcomeScreenLower`/
  `AssistantWelcomeLower`, otherwise `WelcomeScreenUpper`/
  `AssistantWelcomeUpper` — confirmed the assistant-variant upper call
  passes only `assistant` and `className` (not the full chat-history-
  related prop set), while the lower call spreads the complete
  `assistantProps` object (including `pastChats`, `delegatedRuns`,
  `delegationEnabled`, pin-related props) — consistent with the PR's
  stated content split (upper: avatar/configuration/name/description;
  lower: conversations heading, chats/delegated-runs control, cards).
- Per the PR (not independently re-verified given the remaining scope):
  `WelcomeScreen.tsx`'s 203-line diff implements the actual
  `WelcomeScreenUpper`/`WelcomeScreenLower` split (heading+logo vs.
  subtitle/Markdown-description/starter-prompts, the lower part capped at
  composer width) while `WelcomeScreen` itself stays exported and renders
  both stacked for backward compatibility; `AssistantWelcomeScreen.tsx`'s
  657-line diff does the equivalent split for the assistant variant,
  removing the "Start typing below…" helper text; `StarterPromptsSection.tsx`
  compacts the starter-prompt buttons into a single wrapping row (8px
  radius, 16px icon, ≥36px tall, subtitle moved to the button's `title`
  attribute) while keeping `StarterPromptsRendererProps`, the
  `StarterPrompts` registry override, and existing test ids unchanged;
  two theme tokens (`--theme-starter-prompt-icon-bg`,
  `--theme-starter-prompt-subtitle-fg`) are disclosed as no longer read by
  the default renderer but kept for customer themes that may still
  reference them; and the committed Storybook+Playwright geometry harness
  (now 11 checks, including `CenteredAssistant`/`CenteredLegacyOverride`
  stories) measures pixel-exact positioning, not independently reproduced
  here. The PR also discloses two deviations worth noting: `className` on
  the whole `WelcomeScreen`/`AssistantWelcomeScreen` now lands on the
  stacking wrapper rather than the `*-default` root (stated as unused by
  any in-repo caller), and the e2e-tests ESLint scope gained
  `storybook-welcome-layout/**` coverage.

## Compatibility and configuration

None functionally breaking for the default (non-override) path — the
generic `WelcomeScreen` export still renders the full stacked content for
any consumer that imports it directly. For component-kit consumers using
the `ChatWelcomeScreen`/`AssistantWelcomeScreen` registry override: the
override continues to render its full content, confirmed placed entirely
in the upper row with the lower row suppressed, so no default
subtitle/starter-prompts content leaks in underneath a customized welcome
screen. New additive exports (`WelcomeScreenUpper`/`WelcomeScreenLower`/
`AssistantWelcomeUpper`/`AssistantWelcomeLower`) from the library barrel
and the generated shared registry.
