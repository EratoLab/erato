# PR #916: Add optional settings tab for desktop sidecar

- PR: https://github.com/EratoLab/erato/pull/916
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Desktop Sidecar for local sources

## Summary

Adds an optional "Desktop Sidecar" tab to the user preferences dialog
(`frontend/src/components/ui/Settings/UserPreferencesDialog.tsx`, new
`DesktopSidecarTabContent.tsx`, 133 lines), presumably showing the current
sidecar connection status (using the existing `useDesktopSidecar()`
provider from #857) so a user can see whether their local sidecar is
connected without needing developer tools. Two new backend config flags
(`backend/erato_config/src/config.rs`,
`DesktopSidecarConfig`): `show_settings_tab` (default `false`) controls
whether this tab appears in the web frontend, and
`show_settings_tab_office_addin` (`Option<bool>`, default unset) lets the
Office add-in override that setting independently — when unset, the
add-in inherits the general `show_settings_tab` value. The Office add-in's
own `AddinSettingsDialog.tsx` also gained a corresponding UI section
(28-line diff).

## Compatibility and configuration

New optional config keys, both effectively defaulting to hidden:
```toml
[desktop_sidecar]
show_settings_tab = false                 # default
show_settings_tab_office_addin = false    # optional override; unset inherits show_settings_tab
```
No migration. Purely additive UI surface, hidden by default — no behavior
change unless explicitly enabled. Depends on the underlying desktop
sidecar protocol/provider work from earlier this cycle (#857, #871, #872);
without a configured/connected sidecar, the tab (if shown) would presumably
just display an "unavailable" state.
