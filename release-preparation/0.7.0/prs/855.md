# PR #855: Drop redundant recent-chats refetches on rename

- PR: https://github.com/EratoLab/erato/pull/855
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Fixes redundant network requests on chat rename. `updateChatTitle` already
awaits `invalidateQueries` on the recent-chats query key, which itself
refetches every loaded page of the infinite query — but four call sites
additionally called their own explicit refetch on top of that, so
renaming a chat with N loaded sidebar pages issued 2N GETs to the
`recent_chats` endpoint. Confirmed by reading the diff: the redundant
`refetchHistory()`/`refreshChats()` call after `updateChatTitle` is
removed from `Chat.tsx`, `SearchPageStructure.tsx`, and
`AssistantsPageStructure.tsx`. On `SearchPage.tsx`, the redundant
`refetchHistory()` is dropped from what was previously a
`Promise.all([refetchHistory(), refetchSearchResults()])`, keeping only
`refetchSearchResults()` — confirmed this is a genuinely separate endpoint
the recent-chats invalidation doesn't cover, so that call is correctly
retained. Also cleaned up in `useChatHistory.ts`: a dead
`deepMerge(stableEmptyFetcherOptions, {})` query-key construction ceremony
in both `archiveChat` and `updateChatTitle` is simplified to
`recentChatsQuery({}).queryKey` directly, since (per the new code comment)
request headers never enter the query key at all, making the merge a
no-op; the now-unused `stableEmptyFetcherOptions` memo and its
dependency-array entries are removed alongside it.

## Compatibility and configuration

None. Pure frontend performance/network-efficiency fix; no configuration,
API, or behavior changes — a chat rename still updates the sidebar, search
page, and `document.title` correctly, just without the duplicate fetches.

## Evidence and review

Verified via this PR's squash-merge commit against its parent (both

simplification precisely, including the one call site (`SearchPage`)
