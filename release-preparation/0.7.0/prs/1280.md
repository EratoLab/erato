# PR #1280: Declare accepted MIME types for MCP file inputs and expose metadata

- PR: https://github.com/EratoLab/erato/pull/1280
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: MCP

## Summary

Extends the MCP server tool-description pipeline so that tools handling file inputs can declare which MIME types they accept, and tools producing file outputs can declare what they produce. The declarations are both validated at tool-offer time and appended to the tool's description for the model.

**Backend: MIME discovery and annotation.** The new `discover_file_mime_capabilities` function introspects a tool's JSON Schema for `file`-typed parameters and records their `mime_types` constraint. Two directions are distinguished:

- `FileMimeDirection::Accepted`: MIME types the server advertises as acceptable for an input parameter (the server says "I accept image/png and image/jpeg").
- `FileMimeDirection::Produced`: MIME types the server advertises for an output (the server says "this tool produces application/pdf").

Each discovered capability is recorded as a `FileMimeCapability` with a `path` (JSON pointer to the parameter) and a list of `mime_types`.

When converting MCP tools to genai tools, the discovered capabilities are:

1. **Appended to the tool's description** in a "File capabilities:" block, so the model sees the MIME constraints when deciding which tool to call.
2. **Removed from the JSON Schema** before sending to the model (via `remove_schema_declaration`), so the schema stays compact and the model isn't confused by extension keywords it doesn't understand.

**Validation layer.** At tool-offer time, the MCP manager validates that any file input the model provides matches one of the accepted MIME types. A tool call whose input file has a MIME type outside the server's declared set is rejected before being forwarded, preventing the MCP server from receiving unsupported content.

**Documentation.** The MCP server docs (`site/content/docs/features/mcp_servers.mdx`) are updated to describe how servers can declare accepted MIME types in their tool schemas, and how the backend uses that information.

## Compatibility and configuration

No breaking changes. Servers that do not declare MIME constraints continue to accept all file types (no new validation is imposed). Only servers that opt in by adding `mime_types` to their file-typed schema parameters gain the validation and description annotation.

## Evidence and review

- `discover_file_mime_capabilities` recurses into the schema's `properties` and `items` looking for `{"type": "file", "mime_types": [...]}` objects; absent `mime_types` yields an empty list for that capability.
- `append_input_mime_descriptions` augments the schema with a human-readable enumeration of accepted types.
- `format_file_capability_summary` produces the tool-description appendix.
- Generated docs section explains the new schema extension.

Include in the MCP section of the release notes. Mention that MCP servers can now advertise file-type constraints that the backend enforces at call time.
