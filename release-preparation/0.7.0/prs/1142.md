# PR #1142: Make port, directory, icon, name for sidecar configurable

- PR: https://github.com/EratoLab/erato/pull/1142
- Status: pending
- Category: Features and enhancements
- Theme: Desktop Sidecar for local sources

## Summary

Adds four new white-labeling/deployment options for the desktop sidecar
(`backend/erato_config/src/config.rs`, `DesktopSidecarConfig`), embedded
into personalized downloads via the same immutable bootstrap-document
mechanism established in #917/#1122 (`bootstrap_fields()`):
- `desktop_sidecar.port` (`Option<u16>`, default `23123` when unset) —
  the loopback listener port used both in the embedded bootstrap and in
  the browser-facing endpoint URL (`DesktopSidecarConfig::endpoint()`
  now derives `http(s)://127.0.0.1:<port>/erato/sidecar/rpc`, choosing
  `https` automatically when TLS is configured per #1122). Validated
  `!= 0` at startup.
- `desktop_sidecar.directory_suffix` (`Option<String>`, empty by default)
  — appended to sidecar-owned directories and autorun identities, e.g. to
  let a staging and production sidecar coexist on the same machine.
  Validated as at most 64 ASCII alphanumeric/hyphen/underscore characters.
- `desktop_sidecar.icon` (`Option<String>`, a Base64-encoded PNG, no data
  URL prefix) — a custom tray icon. Validated as decodable, ≤1 MiB
  encoded, and 1–256 pixels in both dimensions (decoded via the `png`
  crate to check actual image dimensions, not just trusting metadata).
- `desktop_sidecar.display_name` (`Option<String>`, default unset) — the
  tray display name. Validated as non-empty (after trimming), ≤128 bytes,
  and free of control characters.

All four are validated eagerly at config-load time
(`AppConfig::try_deserialize`/equivalent paths now call
`desktop_sidecar.bootstrap_fields()` and fail startup on invalid input),
backed by comprehensive unit tests covering both valid configuration and
each rejection case (zero port, path-traversal-like directory suffix,
overlong suffix, blank/control-character display name, invalid icon
Base64).

## Compatibility and configuration

All four fields are optional and unset by default, preserving prior
behavior (default port `23123`, no directory suffix, default icon/name)
for deployments that don't configure them:
```toml
[desktop_sidecar]
port = 23123
directory_suffix = "-staging"
icon = "<base64 PNG, <=256x256, <=1MiB>"
display_name = "Erato Staging"
```
No migration. Misconfiguring any of these now fails backend startup with a
clear validation error rather than producing a broken/unpersonalized
sidecar download at request time.
