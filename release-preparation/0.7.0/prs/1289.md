# PR #1289: Add separate MCP visibility settings for chat dropdown and sidebar

- PR: https://github.com/EratoLab/erato/pull/1289
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: MCP

## Summary

Introduces two new MCP visibility configuration keys that let deployments independently control where MCP servers and their controls appear in the UI, overriding the single `show_frontend_tab` toggle.

**Previous behaviour.** The `[mcp].show_frontend_tab` boolean controlled whether MCP-related UI was shown everywhere: the chat connector dropdown, the assistant editor selector, and the settings sidebar. There was no way to show MCP controls in settings (where users manage server authorisation) without also showing them in the chat composer.

**New configuration.**

| Config key | Overrides | Effect |
|---|---|---|
| `[mcp].show_in_chat_input` | `show_frontend_tab` | Show/hide MCP connector controls in the chat input area (the server/tool selection dropdown). |
| `[mcp].show_in_assistant_editor` | `show_frontend_tab` | Show/hide the MCP server selector in assistant create/edit forms. |

Both new keys default to `None` (inherit the value of `show_frontend_tab`). Setting them to `true` or `false` overrides the general toggle for that specific surface.

**Backend changes.**
- `McpServersGlobalConfig` gains two `Option<bool>` fields: `show_in_chat_input` and `show_in_assistant_editor`.
- `frontend_environment.rs` exposes both new values to the frontend via the environment endpoint.
- Config reference and template updated.
- Unit tests added (`mcp_visibility.rs`) for the resolution logic.

**Frontend changes.**
- The `FeatureConfigProvider` propagates the per-surface visibility values.
- `useBrowsableMcpServers` and `useOpenMcpServersSettings` consult the appropriate config key depending on the context.
- `AssistantForm` and `McpServerSelector` use `show_in_assistant_editor`.
- The chat input uses `show_in_chat_input`.
- Test coverage expanded across the affected components.

## Compatibility and configuration

No breaking changes. Deployments that do not set the new keys inherit the existing `show_frontend_tab` behaviour. To show MCP controls in settings but not in the chat composer:

```toml
[mcp]
show_frontend_tab = true
show_in_chat_input = false
```

## Evidence and review

- Both new fields are `Option<bool>` with `#[serde(default)]`, defaulting to `None`.
- The frontend env includes `show_in_chat_input` and `show_in_assistant_editor`.
- `useBrowsableMcpServers` accepts an optional `surface` parameter; when `"chat_input"`, it checks `show_in_chat_input`; when `"assistant_editor"`, it checks `show_in_assistant_editor`.
- The existing `show_frontend_tab` remains as the fallback for surfaces that don't specify an override.
