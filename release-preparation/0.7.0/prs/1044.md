# PR #1044: Increase the default file limits to 10 files with 50MB each

- PR: https://github.com/EratoLab/erato/pull/1044
- Status: pending
- Category: Features and enhancements
- Theme: None

## Summary

Raises several default file-upload limits and simplifies how the maximum
per-file size is determined:
- Backend `frontend.max_files_per_message` default: `5` → `10`
  (`backend/erato_config/src/config.rs`).
- Backend `assistants.max_files` default: `5` → `10`.
- Frontend fallback body-size limit `DEFAULT_MAX_BODY_LIMIT_BYTES`: 20MB →
  50MB (`frontend/src/app/env.ts`) — used when the backend hasn't
  supplied a `MAX_UPLOAD_SIZE_BYTES` value.
- Frontend fallback constants `DEFAULT_MAX_FILES_PER_MESSAGE` and
  `DEFAULT_MAX_ASSISTANT_FILES` (`frontend/src/utils/fileUploadLimits.ts`):
  `5` → `10`.
- Removes the per-file-type `maxSize` overrides entirely from
  `frontend/src/utils/fileTypes.ts` (previously ranging from 2MB for
  text/code files up to 50MB for archives) and the client-side logic in
  `useFileDropzone.ts` that computed an effective max size as the minimum
  of the backend limit and the accepted file types' individual limits.
  All file types are now subject to a single uniform per-file size limit
  (the backend-configured `maxSizeBytes`), rather than smaller
  type-specific caps.

## Compatibility and configuration

Changed defaults (existing explicit configuration overrides are
unaffected — only the *defaults* change):
```toml
[frontend]
max_files_per_message = 10  # was 5

[assistants]
max_files = 10  # was 5
```
And the effective default max single-file size for all file types is now
governed uniformly by the backend's upload-size-limit configuration
(unchanged mechanism, but the frontend's own fallback default rose to
50MB and per-type caps like the previous 2MB text-file cap are gone). No
migration. Net effect for deployments on defaults: users can now attach
up to 10 files (previously 5) per message/assistant, and individual files
of types that previously had a smaller built-in cap (e.g. plain
text/code files, previously capped at 2MB client-side) can now be as
large as the backend's configured upload limit (up to 50MB by default) —
a meaningful increase in what a chat message/assistant configuration can
carry, worth flagging for capacity/cost planning (larger uploads, more
storage, more tokens if the content is fed to the model).
