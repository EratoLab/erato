# PR #1053: Let images grow in place before the full preview

- PR: https://github.com/EratoLab/erato/pull/1053
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Stacked on #1052. First slice of ERMAIN-658, images only. Adds a middle
tier between the compact tile and the full lightbox preview for images in
sent messages. Confirmed by reading the complete `AttachmentTile.tsx`
diff:

- **Same bounds as assistant images, confirmed exactly**: the expanded
  image's `style` switches to `maxWidth:
  "var(--theme-layout-chat-image-preview-max-width)"` / `maxHeight:
  "var(--theme-layout-chat-image-preview-max-height)"` — the identical
  tokens assistant-generated images already use, matching the PR's claim
  precisely.
- **`object-contain` while expanded, confirmed**: the image's `className`
  switches from `object-cover` (compact/medium, cropped to fill) to
  `w-full object-contain` when `expanded`, with a code comment stating
  cropping is right for a thumbnail standing in for a file but wrong once
  the point is seeing what the image contains.
- **Toggle affordance, confirmed exactly**: a new button positioned
  `absolute -left-1 -top-1` (opposite corner from the existing remove
  button, which sits elsewhere), carrying `aria-expanded={expanded}` and
  an `aria-label` reading `"Expand <filename>"`/`"Collapse <filename>"`.
  Confirmed its visibility classes (`opacity-0` with
  `focus-visible:opacity-100`, `group-hover:opacity-100`,
  `group-focus-within:opacity-100`, and an explicit
  `[@media(hover:none)]:opacity-100` override) match the described
  reveal-on-hover/focus-or-always-visible-without-hover behavior.
- **Clicking the tile still opens the full preview, confirmed
  structurally**: the expand toggle button is rendered as a sibling of
  the `onActivate`-wrapping button/div (not nested inside it), so the two
  click targets are structurally independent — no propagation guard is
  needed because they are separate elements, consistent with the PR's
  claim that the existing tile-click-opens-preview path is unchanged.
- **Off in the composer, confirmed exactly**: the new `expandable` prop
  threads from `AttachmentTileList` (default `false`, with a code comment
  stating explicitly "Off in the composer, where the tile is an inventory
  marker rather than something to read") down to each `AttachmentTile`.
  Confirmed only `MessageAttachments.tsx` (the sent-message surface) passes
  `expandable` (bare, i.e. `true`) on its `AttachmentTileList` — the
  composer's staged-attachment preview passes no such prop and stays at
  its default `false`.
- **Documents out of scope, confirmed by construction**: the expand
  button only renders when `expandable && isMedia`, so a document tile
  never gets the affordance regardless of the `expandable` prop — matching
  the PR's stated reason (expanding a document would require
  lazy-mounting the PDF-preview WASM renderer, deferred to a later pass).

## Compatibility and configuration

None. Pure frontend feature addition; no API or configuration changes.
Purely additive UI affordance on sent-message image attachments, off by
default everywhere else (composer, documents).
