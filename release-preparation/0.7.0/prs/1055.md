# PR #1055: Pin the kit-facing shared surface

- PR: https://github.com/EratoLab/erato/pull/1055
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Fixes a fragility in the `@erato/frontend/shared` surface consumed by
component kits: it was previously a pure byproduct of the import graph —
`component-registry.generated.ts` star-exports every module reachable
from a registry extension point, so a symbol like `Tooltip` was public
only because some other component happened to import it. #1046's rewrite
of `FileAttachmentsPreview` dropped its `Tooltip` import and silently
removed `Tooltip` from the surface, which the PR states would fail an
entire customer kit's module linking (`SyntaxError: does not provide an
export named 'X'`) at load time, since a kit resolves one flat set of
named imports through the browser import map — reverting every override
to its default, with no warning mechanism (`ERATO_SHARED_SURFACE_VERSION`
is imported in the same statement that would fail).

Confirmed via the complete diff: 30 named value exports (plus one type
export, `DropdownMenuItem`) are added explicitly to
`frontend/src/shared/index.ts` — `InteractiveContainer`, `Button`,
`DropdownMenu`, `Alert`, `Avatar`, `CopyErrorButton`, `LoadingIndicator`,
`FilePreviewLoading`, `DefaultMessageControls`, `ImageLightbox`,
`MessageContent`, `MessageTimestamp`, `ModalBase`, `ResolvedIcon`, 15
icon components, `messageStyles`, and `Tooltip` — each re-exported from
its actual source module, placed after the existing `export * from ...`
statements. Since an explicit named export shadows a star export for the
same name in ES modules, this changes nothing about what the generated
surface currently exports (confirmed no lines were removed from the
diff — it is purely additive); it instead makes these specific symbols'
presence a declared, type-checked contract rather than an incidental one.
Per the PR (not independently re-run): renaming `Tooltip`'s own export
was used to verify the mechanism actually works, and now fails the build
at `frontend/src/shared/index.ts` rather than surfacing only in a
customer's browser.

## Compatibility and configuration

None. Purely additive re-exports with no runtime behavior change — the
generated surface and its existing symbols are untouched; this only adds
an explicit, compiler-enforced guarantee that a specific list of
commonly-kit-imported symbols (including the ones the Beckhoff kit is
known to use) will not silently disappear from a future unrelated
refactor.
