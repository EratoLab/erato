# PR #1367: Deactivate Outlook microphone gate permission check (#1367)

## Summary

No GitHub description beyond "Related Linear issue: ERMAIN-963"; evaluated
from the diff. Office.js's `DevicePermissionService` capability check
(used to gate microphone/audio-capture access in the Outlook add-in) does
not reliably indicate actual microphone support, notably in Classic
Outlook — per a new code comment, it could report unsupported when the
microphone was actually usable. This deactivates that gate behind a new
`OFFICE_AUDIO_PERMISSION_GATE_ENABLED = false` constant: `isOfficeAudioCaptureSupported()`
now returns `true` unconditionally (falling back to the browser's own
consent prompt instead) and `createOfficeAudioAccess()` returns a
permissive no-op policy, while the full `DevicePermissionService`-based
implementation is kept in the codebase, dark, for when the Office
permission flow itself is reworked (per the code comment: "retain the
implementation for then").

## Compatibility and configuration

None. No config key; the flag is a hardcoded source constant, not an
`erato.toml` setting. No migration. Confirmed via the complete diff shown
above — a 3-line change plus a new 4-line constant file.

## Evidence and review

Verified via `git diff` between this PR's first parent and merge commits
(both present locally). Read the complete diff for all three changed
provider files, confirming the gate is fully bypassed (not partially) and
the prior `DevicePermissionService`-based logic remains intact but unused.

## Release note disposition

Proposed category: Bug fixes. Worth a brief mention if grouping Outlook
add-in audio fixes: the Outlook add-in no longer incorrectly blocks
microphone access in hosts (notably Classic Outlook) where Office's own
device-permission capability check under-reports support; it now relies on
the browser's own microphone consent prompt instead.
