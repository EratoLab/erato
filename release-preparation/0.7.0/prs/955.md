# PR #955: fix: keep table cells and fenced code intact in html-to-text

- PR: https://github.com/EratoLab/erato/pull/955
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Fixes two data-corruption bugs in `htmlToPlainText` (the shared HTML→text
converter used by email-clipboard copy from #800 and, transitively, by
Teams message-text conversion): adjacent table cells fused together with
no separator (`<td>Price</td><td>40</td>` became `"Price40"`), and
whitespace normalization stripped meaningful indentation and blank lines
*inside* fenced code blocks, silently corrupting pasted Python/YAML/diff
content while the surrounding triple-backtick fence made the result look
intact. Confirmed by reading both changed files in full:

- New shared utility `mapOutsideCodeFences(text, transform)` in
  `codeFences.ts`: applies a transform function to everything *outside*
  fenced code regions (matched via a regex requiring a real closing fence
  of the same backtick/tilde run length) and passes fence contents through
  completely untouched.
- `htmlToPlainText` now emits a sentinel `CELL_BREAK` marker (a literal
  NUL character, chosen specifically because the DOM parser sanitizes any
  NUL appearing in real document content into U+FFFD, so it can never
  collide with genuine text) between adjacent `<td>`/`<th>` cells,
  resolved into `" | "` only after the whole tree walk completes and
  surrounding layout whitespace/newlines have been absorbed — confirmed
  via the code's own comment this two-phase approach is necessary because
  a literal `" | "` pushed during the walk would still get torn apart by
  block-element newlines contributed from within the cell.
- The final whitespace-collapsing pass in `htmlToPlainText` now runs
  through `mapOutsideCodeFences`, so a code fence's internal
  indentation/blank lines survive exactly as authored.
- The Outlook add-in's separate `teamsMessageText.ts` converter gets the
  same `mapOutsideCodeFences` treatment for its own whitespace-collapsing
  pass, plus a related fix: its `<pre>` handling previously called a
  blanket `.trim()` on code content, which would strip the first line's
  indentation whenever an entire code block was itself indented (e.g.
  inside a blockquote or list); it now only strips blank leading lines and
  trailing whitespace, preserving meaningful leading indentation on
  non-blank lines.

## Compatibility and configuration

None. Pure bug fix; no configuration or API changes. Behavior change:
copying an HTML email containing a table now separates cell content with
" | " instead of fusing it together, and copying/attaching content
containing fenced code blocks (Python, YAML, diffs, etc.) preserves the
code's original indentation and blank lines instead of collapsing them.
