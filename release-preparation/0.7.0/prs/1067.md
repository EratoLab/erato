# PR #1067: Pin FilePreviewButton and ChatAttentionStatusDot to the kit-facing shared surface

- PR: https://github.com/EratoLab/erato/pull/1067
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Follow-up in the same vein as #1055/#1060's drift-protection work.
Confirmed by reading the complete (5-line) diff: adds explicit named
exports for `FilePreviewButton` and `ChatAttentionStatusDot` to
`frontend/src/shared/index.ts`, following the same shadow-the-star-export
pattern #1055 established.

- **`FilePreviewButton` claimed already-broken, independently
  corroborated**: the PR states #1050 switched
  `GroupedFileAttachmentsPreview` from `FilePreviewButton` to
  `AttachmentTile`, removing the last registry-reachable importer that
  kept it on the generated surface — this is independently confirmed by
  this session's own earlier review of #1050, which read the exact diff
  hunk replacing `FilePreviewButton`/`FilePreviewBase` usage with
  `AttachmentTile` in that file. The PR's further claims (that
  `FileUpload.tsx`'s own import doesn't help because that file isn't
  registry-reachable, and that a first-party kit currently fails three
  distinct ways as a result: `tsc` failure, bare-import linking failure,
  and an already-built kit breaking against a host built from current
  `main`) were not independently re-verified but are a direct, plausible
  consequence of the star-export mechanism #1055 and #1060 already
  established.
- **`ChatAttentionStatusDot` pinned proactively, confirmed exactly**: the
  code comment on this export states it's pinned "alongside the hook that
  feeds it" (#1066's `useChatHistoryRowPresentation`) since a kit
  rendering its own history rows needs both the status-resolution hook
  and the dot component that renders its result — consistent with #1066's
  own stated design goal that a kit should not reimplement status
  resolution. Per the PR (not independently re-verified): this component
  is currently kept alive by exactly two registry-reachable importers
  (`ChatHistoryList.tsx`, `DelegatedRunsSection.tsx`), so it was not yet
  broken but was one refactor away from the same fate as
  `FilePreviewButton`.
- **No `ERATO_SHARED_SURFACE_VERSION` bump, confirmed consistent**: both
  additions are purely additive named exports of existing components, not
  new API shapes, matching the version-bump policy described in #1055's
  work (scoped to breaking changes only) — not independently re-verified
  against that comment's exact text in this diff, since the version
  constant itself is not touched here.

## Compatibility and configuration

None functionally for the host app. For component-kit consumers: this
*fixes* an already-broken export (`FilePreviewButton`, per the PR
currently failing kit builds/linking three ways) and proactively secures
a second one (`ChatAttentionStatusDot`) against a similar future break.
