## Summary

Fourth PR in the ERMAIN-810 series (after #1145, #1161, #1173), extending
the same extraction pattern to the grouped-attachment-preview extension
point — a kit override of this surface previously duplicated the host's
disclosure/pagination/dispatch/callback logic, which the PR states the
companion OpenWebUI kit change reduces from 667 to 394 lines once
consuming this shared surface. Confirmed the kit-surface pinning and one
concrete behavioral detail by direct code inspection:

- **New hook, types, and helper genuinely pinned on the kit surface,
  confirmed exactly**: `useGroupedFileAttachmentsPreview` (plus its
  `GroupedFileAttachmentsPreviewState`/`.Renderers` types),
  `ThreadMessageCardPresentation`, and `getFileName` are all confirmed
  added both as explicit named exports in `kit-surface.ts` and as string
  entries in the `ERATO_KIT_SURFACE_EXPORTS` array used by the kit-
  manifest-check tooling (#1138) — matching the PR's stated scope
  exactly.
- **`ERATO_SHARED_SURFACE_MINOR` bump matches exactly**: confirmed
  `10 → 11` in `surfaceVersion.ts`, consistent with the established
  additive-growth-only versioning convention this session has repeatedly
  verified across #1055/#1138/#1145/#1168.
- **Group actions correctly tied to disclosure state, confirmed
  exactly**: the extracted hook's per-group state computes `actions:
  isCollapsed ? undefined : groupActions?.[group.id]` — matching the PR's
  stated "caller-supplied group actions stay with the group's content and
  disappear when it collapses" precisely, and confirming this pre-
  existing behavior survived the extraction into the new shared hook
  rather than being lost or altered.
- Per the PR (not independently re-verified given remaining scope): the
  new `ThreadMessageCard` render-prop mechanism preserving the host's
  disclosure state and control semantics while letting a kit customize
  item presentation (chip/image rendering) only; the 437-line
  restructuring of `GroupedFileAttachmentsPreview.tsx` itself splitting
  behavior (the new hook) from the default host renderer, which is
  stated to retain its existing appearance and behavior unchanged; and
  the disclosed validation claims (production build and 19 companion-kit
  tests passing locally, including disclosure persistence across
  rerenders; browser fixture screenshots at two viewport sizes in both
  color schemes matching the prior kit's layout exactly) — none of which
  are independently reproducible in this review, and the PR explicitly
  notes these are component fixtures in the signed-in app, not a full
  Outlook drag/drop integration test.

## Compatibility and configuration

None breaking, and no behavior change for the host's own default
renderer per the PR's own claim (confirmed consistent with the
disclosure-state preservation detail verified above). Additive
`ERATO_SHARED_SURFACE_MINOR` bump only. This PR contains only the host-
side changes; the companion kit reduction (`erato-subscription-content`)
is explicitly stated as a separate, following change not included here.
