# PR #932: fix(office-addin): correct the app icons and give the ribbon its own assets

- PR: https://github.com/EratoLab/erato/pull/932
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Visual/asset fix (ERMAIN-554, stacked on #931): rebuilds the Outlook
add-in's package icons from the brand favicon mark (white tile with the
letter inside the required 120×120 safe area, a spec-valid white-on-
transparent outline icon, and a new `color32x32` slot), and adds nine
dedicated per-size ribbon icon assets (`ribbon-icon-{16,20,24,32,40,48,64,80}.png`)
so the Outlook ribbon button no longer reuses the general-purpose outline
icon at the wrong sizes. Confirmed the backend's default configuration is
updated to match: both `erato.template.toml`'s documented example and
`erato_config`'s actual `default_ms_office_addin_manifest_icon_{16,32,80}_path()`
functions now point at the new `ribbon-icon-{16,32,80}.png` assets instead
of reusing `outline-icon-32x32.png`/`color-icon-192x192.png` at
non-matching sizes. Manifest files (`manifest-local.xml`,
`manifest.json`) are updated to reference the new asset paths
consistently.

## Compatibility and configuration

Changes the *default* values of three existing config fields
(`icon_16_path`, `icon_32_path`, `icon_80_path` under the Office add-in
manifest configuration) to point at newly-shipped asset files. Any
deployment that has explicitly overridden these paths to something
custom is unaffected (overrides win); a deployment relying on the
defaults gets the corrected, properly-sized ribbon icons automatically.
No configuration schema change — same field names, new default file
targets.

Verified via this PR's squash-merge commit against its parent (both
