# PR #957: Index the Teams transcript's identifiers and strip them before the model

- PR: https://github.com/EratoLab/erato/pull/957
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Restores the message ids/deep links/file-to-message joins that #956
removed from the Teams transcript's *prose* to save tokens — but rather
than dropping that information entirely (losing UI capabilities like
deep-linking back to a specific Teams message), it's re-added as one
machine-readable trailing HTML comment
(`<!-- erato:teams-transcript v1 {...json...} -->`) that a permissive
parser can read back for the UI's own use, while the **backend strips
this block before the model ever sees it**, so it costs zero prompt
tokens and never re-introduces the metadata #956 worked to remove.
Confirmed by reading the backend's `strip_transcript_index` in full and
its test suite:

- The stripping function is deliberately defensive against how a
  markdown-round-trip might have mangled the comment: it locates the
  block by its `erato:teams-transcript` marker text (not just the literal
  `<!--` delimiter), then looks backward for the opening `<!--` and
  forward for either a literal `-->` or an escaped `--\>` closing
  delimiter (a markdown renderer can escape comment delimiters as
  `\<!--`/`--\>` rather than passing them through verbatim) — falling
  back to stripping just the containing line if no proper delimiter
  survived, so a mangled block still can't leak its raw content.
- Wired into `XbergProcessor::parse_file` (the shared text-extraction path
  every consumer — prompt composition and token estimation alike — goes
  through), confirmed via the diff to run after the file's other
  extraction steps.
- **Confirmed via two specific backend tests, both read in full**: one
  asserts the extracted text contains no trace of the raw message id,
  chat id, deep link, or the marker string itself, while the actual
  conversation prose (`[1] Ada Lovelace (09:14):` / `Thursday works.`)
  survives; the other is a strong equivalence check — the *same*
  transcript prose extracts to byte-identical output whether or not the
  trailing index block is appended, proving the block truly is invisible
  to the model rather than merely reduced. A third unit test confirms the
  escaped-delimiter fallback handles a comment a markdown renderer has
  mangled.

## Compatibility and configuration

None. Pure bug fix restoring lost UI-facing metadata (deep links,
message-to-file joins) without reintroducing the token cost #956 removed
it to avoid; no configuration or API changes. No behavior change visible
to the model — confirmed by the equivalence test above.
