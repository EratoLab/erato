## Summary

A tiny, purely local-developer-tooling fix (20 lines across two files,
`justfile` and `README.md`). Confirmed the core change exactly: the
`install` recipe now runs `pnpm --dir ../desktop-sidecar-protocol
install --frozen-lockfile` before the frontend's own `pnpm install
--frozen-lockfile` — triggering the protocol package's `prepare` script
(which rebuilds its compiled output) ahead of the frontend installing
its local `file:` dependency on that package — matching "Build the
protocol through its existing `prepare` script before installing
frontend dependencies" exactly. All four authenticated recipes
(`dev`, `dev_keycloak`, `dev_entra_id`, `dev_nginx_jwt`) are confirmed to
now depend on `install` (previously only `dev` depended on
`generate_dex_config`, and the other three had no prerequisite at all),
matching "make the four authenticated `just dev*` recipes depend on this
ordered setup" exactly — fixing the originally-reported `dev_entra_id`
failure along with the other three auth modes that shared the same
unordered-build hazard. Per the PR (not independently re-verified): the
README documentation update explaining the ~43-second startup cost, and
the disclosed validation (reproducing the original TypeScript errors
before the fix, confirming all 206 compiled protocol files match after
rebuilding, `just --dry-run` recipe-ordering checks for all four auth
modes, and the full frontend test/lint/typecheck suite passing).
