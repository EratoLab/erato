# PR #1056: Clamp long code blocks with a reveal control

- PR: https://github.com/EratoLab/erato/pull/1056
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Completes the code half of ERMAIN-658 (independent of the attachment-tile
stack). A long code block now clamps to a themed height with a "Show all
N lines" reveal control, the opposite default to the image-growth feature
in #1053/#1057 (code arrives too tall and shrinks; an image arrives too
small and grows). Confirmed by reading the complete new
`CollapsibleCodeBlock.tsx` and the relevant `MessageContent.tsx`/`theme.ts`
diffs:

- **Not `Collapse`, confirmed structurally**: the component clamps via a
  conditional `max-height`/`overflow-hidden` on a wrapping div rather than
  toggling between fully-hidden and fully-shown — matching the PR's stated
  reasoning that this keeps the first N lines visible at all times rather
  than collapsing to nothing.
- **No gradient fade; footer states the hidden line count, confirmed**:
  there is no fade overlay in the component at all; instead the reveal
  button reads `t\`Show all ${lineCount} lines\`` (collapsed) or `t\`Show
  less\`` (expanded) — matching the PR's stated reasoning that the block's
  background comes from the Prism syntax-highlighting theme, so a fade
  would have to guess at a color it doesn't own.
- **Clamp applies whenever collapsed, not only once overflow is
  confirmed, verified exactly as described**: `const clamped = !expanded
  && !disabled` gates the `max-height`/`overflow-hidden` styling
  unconditionally while collapsed and not disabled — a code comment
  states this directly: measuring the other way round would be circular,
  since an uncapped element can never report that it exceeds the cap. A
  separate `overflows` state (from a `ResizeObserver`-driven
  `scrollHeight > clientHeight` comparison) independently controls
  whether the reveal *button* renders at all — so a block shorter than
  the cap is clamped-but-inert (no visible truncation) and grows no
  toggle, confirmed matching the PR's claim.
- **Suppressed while streaming, confirmed via `MessageContent.tsx`**: the
  new `CollapsibleCodeBlock` wrapping `MarkdownPre`'s `<pre>` passes
  `disabled={isStreaming}` directly — when `disabled` is true,
  `clamped` is false unconditionally, so no cap applies while the block's
  height is still changing chunk-by-chunk.
- **Theme token, confirmed exactly**: `--theme-layout-code-block-collapsed-max-height`
  is added to `theme.ts`/`globals.css` with a default of `24rem`, wired
  through the `ThemeProvider` allowlist (per the PR, not independently
  re-read here, but consistent with the same pattern confirmed for
  #1051's attachment-tile tokens) — matching the PR's stated value and
  wiring approach exactly.

## Compatibility and configuration

None functionally — a code block shorter than 24rem (the default cap)
renders identically to before, confirmed by the `overflows`-gated reveal
button. Adds a new overridable theme token
(`--theme-layout-code-block-collapsed-max-height`); no API or database
changes.
