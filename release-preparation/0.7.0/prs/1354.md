# PR #1354: Let Word turns offer delegated tasks under their action facet's own limits (ERMAIN-954) (#1354)

- PR: https://github.com/EratoLab/erato/pull/1354
- Status: pending
- Category: Features and enhancements
- Theme: Word add-in / Delegation

## Summary

Word turns run under an *action* facet (not a selected/regular facet), so
listing `erato/delegate_task` there already offered the delegated-task tool,
but only under the global `[delegation.tasks]` caps, approval mode, and
child-facet scope — there was no way to give the Word action facet its own
tighter/looser limits. (A hidden regular facet wasn't a workaround either,
since a hidden facet's `erato/*` allowlist pattern switches on MCP filtering
and drops every other MCP tool for that turn.)

Confirmed via the `config.rs` diff: a new optional
`action_facets.facets.<id>.delegation` override block is added, mirroring
the existing per-regular-facet `facets.facets.<id>.delegation` overrides.
When an action facet's `tool_call_allowlist` selects `erato/delegate_task`,
it is now treated as a planning facet too. Merge rules are unchanged and
reused: numeric caps take the minimum, `child_facet_ids`/`run_modes` union,
and approval mode takes the strictest; the action facet's overrides are
merged in *after* the user's own selected-facet overrides, so the user's
selection still determines persona and scheduling. Startup validation is
extended to cover action-facet overrides (warns if `delegation` is set on an
action facet whose allowlist doesn't actually select the tool, and counts
action facets toward the "no allowlist selects this tool" warning).

## Compatibility and configuration

New optional per-action-facet override block, inert unless set:

```toml
[action_facets.facets.<facet-id>.delegation]
max_tasks_per_turn = 3
max_client_tool_calls_per_task = 40
max_server_tool_calls_per_task = 4
child_facet_ids = ["web_search"]

[action_facets.facets.<facet-id>.delegation.approval]
mode = "plan"
```

No migration, no behavior change for any deployment not already using
`[delegation.tasks]` with an action facet selecting `erato/delegate_task`
(this feature builds directly on #1107's `[delegation.tasks]` foundation,
reviewed earlier in this session). MCP filtering/client-tool exclusion for
delegated children is unchanged.
