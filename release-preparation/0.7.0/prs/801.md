# PR #801: Outlook appointment scheduling seam: fetch_availability client tool + outlook_schedule facet

- PR: https://github.com/EratoLab/erato/pull/801
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Outlook scheduling and shared mailboxes

## Summary

Lands the appointment-scheduling integration seam for the Outlook add-in
(ERMAIN-382), built on #798's calendar data layer and #799/#786's
client-tool round-trip. Confirmed by reading the code:

- `outlookScheduleTool.ts` (new, 364 lines) serializes a `NormalizedCalendar`
  into a model-facing result: weekday-labelled local times with a
  per-instant UTC offset (correctly DST-aware — computed via
  `Intl.DateTimeFormat` with `timeZoneName: "longOffset"` at each instant
  rather than a single fixed offset), floating all-day entries (including
  multi-day ranges via `firstDay`/`lastDay`), `durationMinutes` on past
  meetings for duration calibration, and truncation to 300 busy / 150
  history entries (soonest/most-recent kept) with a `notes` field when
  truncated. A fixed `CALENDAR_LEGEND` string is prepended to every result
  stating the correctness rules verbatim (which `busyType`s block time,
  all-day blocks the whole day, degraded legs forbid claiming "free",
  times are already local, subjects/names are untrusted data) — since the
  facet template that would normally carry these rules isn't guaranteed to
  be attached on the turn that actually calls the tool (e.g. a read-mode
  turn reaches the tool via `outlook_reply_from_read`'s allowlist, not the
  schedule facet).
- The executor (`createFetchAvailabilityExecutor`) clamps the model-supplied
  `lookahead_days` to 1–62 (`parseLookaheadDays`), reads the active calendar
  fetcher through a getter (not captured at registration) so an EWS↔Graph
  backend switch mid-session is honored, and returns a clean `{ok: false,
  error}` result on any failure so the backend resumes the turn rather than
  parking until #786's timeout.
- `resolveOutlookActionFacet` (in `outlookActionFacet.ts`) gains two new
  rungs, confirmed by reading the full diff: a **sticky** rung — checked
  immediately after the top-priority active-text-selection check and
  *before* the existing draft-review/reply-from-read checks — that claims
  the facet slot whenever `isSchedulingThreadFresh` says the latest
  assistant message called `fetch_availability` within the last 60 minutes
  (`SCHEDULING_THREAD_MAX_AGE_MS`), so a slot-picking follow-up isn't
  starved by an email facet; and an **ambient** rung at the bottom that
  attaches the schedule facet in neutral contexts (no active
  selection/compose/read item) so "find me a slot" works from a blank
  chat. Both are gated on `scheduleFacetAvailable` (from `GET /me/facets`)
  AND `calendarAvailable` (a calendar fetcher exists for this session) —
  without a fetcher the tool could only ever error.
- `erato.template.toml` documents `[client_tools.tools.<id>]` with the
  `fetch_availability` example and a `CAUTION` note (confirmed verbatim in
  the diff): allowlist patterns select client tools the same way they
  select MCP tools, and a bare `"*"` — global or on any regular facet —
  activates every client tool on every platform, including ones the
  current client can't execute, so namespace-scoped patterns
  (`"outlook/*"`) should be preferred.
- Tool name is deliberately `name = "fetch_availability"` /
  `namespace = "outlook"` — dot-free, since OpenAI/Anthropic reject `.` in
  tool names (`^[a-zA-Z0-9_-]{1,64}$}`) — confirmed as the exact rationale
  in both the PR description and the template comments.

Per the PR description, this ships **read-only**: no
`outlook.create_appointment` confirm action is declared yet (deferred to a
later ticket, ERMAIN-387), and no global `tool_call_allowlist` entry is
added — the tool is gated only through the `outlook_schedule`,
`outlook_reply_from_read`, `compose_email`, and `outlook_review_draft`
facets' own allowlists, so it is never offered on the web app (which has
no executor for it).

## Compatibility and configuration

Additive only; the actual `backend/erato.toml` config for this feature
ships separately (gitignored, per a companion content-repo PR) — this PR
only adds the documented example to `erato.template.toml`. No behavior
change for any deployment that doesn't configure the new
`[client_tools.tools.outlook_fetch_availability]` entry and
`outlook_schedule` action facet. New optional per-tool `timeout_ms`
(defaults to 60000ms, from #786) is mentioned in the template comment.

## Release note disposition

Proposed category: Features and enhancements, "Outlook scheduling and
shared mailboxes". User-visible: in the Outlook add-in, asking the
assistant to find or suggest a meeting time now has it read the user's own
calendar (working hours, busy blocks, recent meetings) and reason over
real availability before answering — read-only in this release; it can't
yet create or confirm an appointment.
