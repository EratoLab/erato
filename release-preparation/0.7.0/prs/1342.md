# PR #1342: Keep fields, links, notes, comments and pictures when Word Replace rewrites a selection (ERMAIN-938)

- PR: https://github.com/EratoLab/erato/pull/1342
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Word selection editing

## Summary

Per the PR description: previously, a selection containing a field, link,
footnote/endnote reference, comment anchor, picture, or line break could
only be treated as read-only context for Replace (introduced earlier in
this batch); this PR lets Replace rewrite the surrounding text while
keeping those embedded items in place. Mechanism, as described: a new
`readWordParagraphItems`/`wordSelectionItems.ts` (713 new lines) locates
each item inside a covered paragraph's OOXML aligned to `paragraph.text`,
and represents them to the model as `⟦n⟧`/`⟦n⟧…⟦/n⟧` markers; a proposal
is only accepted if every paragraph's markers reappear exactly once and in
the same order, otherwise it refuses as `MARKERS_CHANGED` and writes
nothing. A selection that cuts through a field becomes `item_cut`
(presumably also refused); hidden text, tracked changes, and complex
script remain context-only as before. Paragraphs containing items are
rewritten via their own OOXML and `insertOoxml(..., "Replace")` rather
than the plain-text `insertText` path used for item-free paragraphs, each
rewritten piece keeping only the formatting its old runs shared. Track
Changes being on refuses as `TRACKED_ITEMS` (Word would otherwise redline
the whole paragraph); on Word for the web, item-bearing Replace is capped
at 5 paragraphs because `insertOoxml` clears the web's native undo stack
there, so Erato's own per-paragraph Undo must cover the entire write.
Confirmed directly in `wordSelectionArgs.ts`: this whole capability is
gated server-side — markers are only sent when the server advertises a new
`kept_items` capability flag, which per the PR deploys separately
(described as "erato-subscription-content#37" — an external/backend
repo or ticket reference, not further verifiable from this diff alone);
without that flag, these selections fall back to the pre-existing
context-only behavior.

## Compatibility and configuration

Per the PR: gated by the server advertising `kept_items` (not a
deployment-configurable flag in this repo — appears to be a backend
subscription-content capability negotiated outside this codebase). Until
that capability is advertised, behavior for existing users is unchanged
(falls back to context-only treatment of these items, as today). No
config keys in this repo; no database migration.
