# PR #1245: Allow assistant hub assistants to be selected in delegation window

- PR: https://github.com/EratoLab/erato/pull/1245
- Status: pending
- Category: Features and enhancements
- Theme: Assistant Hub and assistant sharing

## Summary

Extends `useMentionableAssistants` (the hook backing the `@`-mention
delegation picker in the chat composer, per the existing CHANGELOG.md
"Delegated assistants" feature) to also include Assistant Hub assistants,
not just the user's own/shared regular assistants. Previously, the
`@`-mention list was built only from `useListAssistants` (the regular
assistants listing, which excludes Hub versions per the code comment: "the
generic listing excludes Hub versions"). This PR adds
`useListAssistantHubAssistants` (fetched only when
`assistant_hub.enabled`, gated behind the same `isGateOpen` lazy-loading
pattern as the other queries, so a deployment without delegation/Hub pays
no extra query cost) and maps each Hub version's `assistant_id` (the
version's underlying assistant ID needed for delegation, not the stable
Hub-listing ID, per the code comment) into the same mentionable-assistant
shape, merged with the regular assistants list before deduplication by
name.

## Compatibility and configuration

None. No configuration keys — reuses the existing `assistant_hub.enabled`
flag and `assistants` delegation feature, both pre-existing. No migration.
Behavior change: users can now `@`-mention Assistant Hub assistants (the
currently published version accessible to them) in the delegation window,
where previously only their own/shared regular assistants were offered.
