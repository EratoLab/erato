# PR #865: Allow users to retract message feedback

- PR: https://github.com/EratoLab/erato/pull/865
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Adds the ability to retract previously-given thumbs up/down feedback on a
message (ERMAIN-488), addressing a customer report that feedback was
one-way. Confirmed by reading the code:

- New `DELETE /api/v1beta/messages/{message_id}/feedback` endpoint
  (`delete_message_feedback`), reusing the same authorization and
  `message_feedback_edit_time_limit_seconds` time-limit guard as the
  existing submit endpoint, and mapping errors identically (`not found` →
  404, `not authorized`/`time limit exceeded` → 403). No database
  migration, confirmed by the diff touching only `message_feedback.rs`
  (model-layer logic, +88 lines, not read in detail) and `mod.rs`
  (endpoint + OpenAPI docs).
- New `LangfuseClient::delete_score`, confirmed via full read: issues a
  direct `DELETE /api/public/scores/{scoreId}` (since Langfuse's score
  deletion isn't part of its batch-ingestion API, unlike score creation).
  Correctly tolerates a `404` (the score was never ingested — e.g. its
  ingestion event was still queued, or the feedback predates score
  forwarding being enabled) as a successful no-op rather than an error,
  and is disabled cleanly (returns `Ok(())` immediately) when the
  Langfuse client itself is disabled.
- Frontend: a new "Remove" button in the feedback-view dialog (reached by
  clicking the currently-active thumb), gated by the same
  `canEdit`/time-limit condition as the existing Edit affordance, with an
  in-dialog error shown on failure.
- **Confirmed a genuine, previously-existing one-way state bug fix**:
  `DefaultMessageControls.tsx`'s feedback-state-sync effect previously only
  ever *set* the filled-thumb UI state when `initialFeedback` was present,
  with no corresponding `else` branch to clear it — so if the feedback
  data disappeared from the cache (e.g. after invalidation, or now, after
  a successful delete), the thumb UI would keep showing as filled/active
  even though the underlying feedback no longer existed. The fix adds the
  missing `else { setFeedbackState(null) }` branch — a minimal, correct
  fix for exactly the symptom this feature would otherwise have exposed.
- Office add-in: `AddinChat.tsx` wires the new dialog props through (3
  lines); the actual dialog implementation is shared via the frontend
  library.

## Compatibility and configuration

None new. Reuses the existing `message_feedback_edit_time_limit_seconds`
config value for the new delete endpoint's time-limit guard — no new
configuration keys. New locale strings added across de/es/fr/pl for the
Remove button and its error state. OpenAPI spec gains the new `DELETE`
endpoint's documentation.
