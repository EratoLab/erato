# PR #1057: Share the growth control between attached and generated images

- PR: https://github.com/EratoLab/erato/pull/1057
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Stacked on #1053. Closes the loose end ERMAIN-690 named: `ImageContentDisplay`
(assistant-generated images) and `AttachmentTile` (attached images) each
hand-rolled their own corner growth control. Confirmed by reading all
three changed files in full:

- **Straight extraction confirmed exactly**: the new `ExpandMediaButton.tsx`
  is byte-identical in markup/classes to the inline button #1053 added to
  `AttachmentTile.tsx` (same `absolute -left-1 -top-1` positioning,
  hover/focus-reveal classes, `aria-expanded`/`aria-label` pattern,
  `CollapseDiagonalIcon`/`ExpandDiagonalIcon` swap). Confirmed
  `AttachmentTile.tsx`'s diff simply replaces its own inline button with
  `<ExpandMediaButton expanded={expanded} onToggle={...}
  label={filename} />`, with no other change to the tile — matching the
  PR's "the tile's behaviour is unchanged; this is a straight extraction"
  claim exactly.
- **Generated images gain the middle tier, confirmed via
  `ImageContentDisplay.tsx`**: a new per-image `expandedIds` Set (toggled
  independently per image id — "growing one says nothing about the
  others," confirmed by the Set-based toggle) drives `frameStyle =
  expanded ? { maxWidth: "100%" } : IMAGE_PREVIEW_CONTAINER_STYLE` —
  confirmed the expanded state grows the image to the full message width
  (`maxWidth: "100%"`) rather than staying capped at the existing chat
  image preview bounds, matching the PR's stated fix for a "generated
  chart at 24rem... too small to read."
- **Static preview stays wholly inert, confirmed exactly**: the
  `!onImageClick` branch (the non-interactive variant, asserted
  non-interactive by an existing test per the PR) renders only the
  `frameStyle`-styled wrapper — no `ExpandMediaButton` at all — while the
  `onImageClick`-present branch renders it. Confirmed by direct
  before/after comparison: the button only appears in the second return
  path.
- **Growing never opens the lightbox, confirmed via two independent
  mechanisms**: `ExpandMediaButton`'s `onClick` calls
  `event.stopPropagation()` before `onToggle()` (a code comment states
  this explicitly guards against also triggering the image's own
  full-preview click), and additionally the button is rendered as a
  sibling of the `InteractiveContainer onClick={() => onImageClick(image)}`
  wrapper (both inside one `<div className="group relative">`), not
  nested inside it — so the click-target separation and the explicit
  `stopPropagation()` both independently prevent the toggle from
  triggering the lightbox.

## Compatibility and configuration

None. Pure frontend feature addition; no API or configuration changes.
Purely additive: attached-image behavior is unchanged (confirmed
byte-identical via the extraction), and generated-image expansion is a
new, opt-in-by-click affordance only on the already-clickable variant.
