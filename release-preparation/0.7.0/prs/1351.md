# PR #1351: Correct the add-in's EWS size-cap comments: a client cap of 1 or 5 MB

- PR: https://github.com/EratoLab/erato/pull/1351
- Status: pending (diff reviewed)
- Category: Chores & Developer experience
- Theme: None

## Summary

Per the PR's own description, this is explicitly a comment-only
correction (plus one test name) in `fetchOutlookMessageEws.ts`: the
existing code comments incorrectly described the EWS request/response
size cap as "5 MB in OWA / 1 MB in classic Outlook" — a simplification
the author says doesn't match Microsoft's documented per-client-version
limits table. The corrected comments explain the cap applies to both
request and response (counted in SOAP-string characters), is 5 MB on
Outlook on the web, new Outlook, classic Windows from version 2303, and
Mac from 16.73 (older builds keep 1 MB), is not an Exchange/tenant-side
limit at all (on-prem OWA's cap is undocumented and inferred at runtime
from error code 9020), and that the direct callback-token path has no
host cap in the first place. Confirmed directly: the diff's only
behavioral touch is the wording of a single `console.warn(...)` call;
every other change is in comments. Scattered prior "1 MB cap" comment
references are corrected to the more accurate "host cap" terminology.
