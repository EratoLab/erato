# PR #986: Assistant space: delegated runs segment, origin hint, attention passthrough (ERMAIN-625)

- PR: https://github.com/EratoLab/erato/pull/986
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Delegation

## Summary

Third and final layer of the delegation frontend stack (built on #982's
listing backend). Gives delegated side-run chats — hidden from every
normal listing by design (#982) — one deliberate place to be found: a
`[Chats | Delegated runs]` segmented view inside the per-assistant space.
Confirmed the two most concrete, individually-verifiable claims by direct
code reading.

- **A genuinely disclosed and confirmed bug fix, unrelated to delegation
  itself**: the optimistic chat-archive cache edit (from #859) previously
  bailed out (`if (!current || !Array.isArray(current.pages)) return
  current;`) on any recent-chats cache entry that wasn't the paginated
  sidebar shape — meaning archiving a chat never actually removed it from
  a *non-paginated* recent-chats cache (e.g., per the PR, this silently
  affected the add-in's own chat list too). Confirmed via the diff: a new
  shared `withoutChat` helper handles both the paginated and single-page
  cache shapes uniformly via a new `isPaginated` type guard, so the fix
  applies everywhere the old code silently skipped.
- **"Never in the sidebar" is enforced by regression test across the full
  filter matrix, confirmed directly**: a new test,
  `"never opts the sidebar into delegated runs"`, asserts
  `buildRecentChatsFilterParams` omits `include_delegated` for **every**
  combination of the existing type filter (`all`/`chat`/`assistant`) and
  status filter (`active`/`all`) from #970 — including specifically the
  `type=assistant` path the PR calls out as the one most likely to
  accidentally opt in. A second test independently confirms the actual
  fetch call's `queryParams` also omit the field for both the main list
  and the pinned-chats list. This directly validates the PR's stated
  approach of re-deriving and testing every recent-chats consumer rather
  than relying on manual inspection.
- Per the PR (not independently re-verified given remaining scope): the
  `/a/:assistantId` assistant space now issues its own
  `include_delegated=true` request rather than reusing the shared sidebar
  query, splitting rows client-side on `provenance_kind === "delegation"`
  — stated to incidentally fix a separate latent bug where the sidebar's
  own Type/Status filters were bleeding into the assistant space's chat
  list, and to replace a previously-hardcoded `isLoadingChats={false}`
  with a real loading state. The segmented control is hidden only when
  there are zero delegated runs *and* delegation is disabled entirely;
  with delegation enabled but no runs yet, an explicit empty state is
  shown instead of hiding the tab (reasoned as less confusing than an
  unexplained absence). Delegated rows show a "from ⟨origin chat⟩" hint
  keyed specifically on `provenance_kind === "delegation"` (not merely the
  active segment), so a hypothetical future `handoff_branch` provenance
  kind sharing the same envelope shape wouldn't incorrectly inherit this
  hint; a dangling `origin_chat_id` (per #982's no-FK design) renders an
  unlinked label rather than a broken link. An "attention passthrough"
  seeds the generation-status store (#868/#918) from the fetched delegated
  rows so a running-or-`awaiting_approval` child surfaces an indicator on
  the "Delegated runs" tab even while hidden from the default view, with
  the indicator exposed as an explicit `SegmentedControlOption` prop
  rather than piggybacking on `icon` (which renders inside an
  `aria-hidden` span and would have been invisible to screen readers).

## Compatibility and configuration

None new beyond the existing delegation config gate (#978). The
non-paginated-cache archive fix is a genuine, independently-valuable bug
fix that applies regardless of whether delegation is enabled at all.
