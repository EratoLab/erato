# PR #1068: Make theming fail loudly instead of silently, and hoist user attachments above the message body

- PR: https://github.com/EratoLab/erato/pull/1068
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Two commits, found and fixed while building a real theme pack end-to-end
against a running instance. Confirmed by reading the three most
load-bearing files in full:

- **Silent theme-fallback logging fix, confirmed exactly via
  `themeConfig.ts`**: `describeRequestedThemes()` builds a list of
  "what was explicitly asked for" descriptors from `themeConfigPath`/
  `themePath`/`themeCustomerName`, each with a `matches(path)` predicate.
  When a theme successfully loads from a path that *doesn't* match any
  requested descriptor, a new `console.warn` fires naming the requested
  theme and the fallback location actually used — confirmed this
  previously logged only `Custom theme loaded: <name> from <path>`
  (success-framed, indistinguishable from the intended theme loading) with
  no signal that a fallback occurred. A second new warning covers the
  case where no candidate path resolves at all, falling through to the
  built-in default. This is logging loudness, not a hard failure — the
  app still boots, but a misconfigured theme request is now visibly
  flagged rather than silently substituted.
- **Font-alias flattening fix, confirmed exactly via `themeUtils.ts`**:
  the new `withTypographyCompatibility` back-fills `fontFamily.heading`
  and `fontFamily.semibold` from `fontFamily.body` when a theme pack sets
  only `typography.fontFamily.body` and leaves the others unset, and
  separately back-fills `headingBold` from the *already-resolved*
  `heading` value (confirmed via a code comment noting `headingBold`
  aliases the resolved heading, which may itself have just inherited from
  body) — precisely matching the described bug where `ThemeProvider`
  emits every CSS custom property explicitly, flattening the
  `--theme-font-heading: var(--theme-font-body)` alias `globals.css`
  otherwise provides, so a brand-face-only override previously left
  headings on the default font silently.
- **Attachment hoisting, confirmed exactly via `ChatMessage.tsx`**: for a
  user message only (`isUser && attachments`), the attachments now render
  in a `<div className="mb-2 empty:hidden" data-ui="message-attachments">`
  positioned as a sibling *before* the message-body row (which itself
  gains `data-ui="message-body"`), rather than nested inside the body as
  before. Confirmed the assistant-message path is untouched — `!isUser &&
  attachments` renders in exactly the same inline position the shared
  `attachments` element previously occupied, unconditionally. The
  `empty:hidden` class is confirmed necessary and deliberate per a code
  comment: the wrapper renders truthy as soon as the message names a file
  id, while `MessageAttachments` itself returns `null` until those ids
  resolve, so without it a themed background would flash as an empty box
  during the fetch.
- Per the PR (not independently re-verified given the remaining scope):
  Tailwind-specificity fixes for `Input.tsx`/`Textarea.tsx` (disabled
  state previously losing to authoring order with no `tailwind-merge` in
  the project) and `GroupedFileAttachmentsPreview`'s error-filename color;
  32 literal colors under `--docx-preview-*`/`--xlsx-preview-*` promoted
  to proper `--theme-*` aliases (matching the pre-existing
  `--pdf-preview-*` pattern); four token renames; and `LoadMoreButton`
  reading `--theme-shell-chat-body`. The PR's disclosed note about
  `.hooks/pre-push`'s `fzf`-based menu hanging in a non-interactive shell
  is process/tooling commentary, not a code change.

## Compatibility and configuration

None breaking. Purely additive logging (louder diagnostics on theme-load
fallback, no behavior change to which theme actually loads), a
compatibility back-fill that only fills in previously-unset typography
keys (an override that explicitly sets `heading`/`semibold`/`headingBold`
is untouched, confirmed by the `if (!fontFamilyOverride.heading)` guards),
and a structural DOM change for user-message attachment positioning (a
customer theme relying on the old nested DOM structure for attachments
within a user message would need to adjust its selectors — not
independently assessed as a real risk given the PR's own stated
`data-ui` hooks are the intended, more stable styling surface going
forward).

## Release note disposition

Proposed category: Bug fixes (theming correctness). Worth a mention:
several theme-customization defects are fixed — a misconfigured custom
theme now logs a visible warning instead of silently loading a fallback,
setting only a brand body font no longer leaves headings on the default
font, and several Tailwind specificity/token-namespace gaps in themed
surfaces are closed. Also worth noting: a sent message's file attachments
now render above the message text instead of below it, to match the
order they were attached in and to give themes a cleaner surface to tint.
