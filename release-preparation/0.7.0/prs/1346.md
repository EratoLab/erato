# PR #1346: Keep bookmarks, such as table-of-contents targets, when Word Replace rewrites a selection (ERMAIN-941)

- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: Word selection editing

## Summary

Per the PR description: stacked on #1344/#1345 (both merged earlier in
this batch; the merge-commit diff includes their commits because this
branch was sequentially rebased on top of them, so most of the listed
commit messages are prior PRs' work, not new in this PR — the genuinely
new commits are the final two, "Keep bookmarks..." and "Refuse bookmarks
that run into another paragraph..."). Extends #1344's bookmark-detection
work (ERMAIN-939) so a heading carrying a table-of-contents bookmark
(`_Toc…`), a cross-reference target (`_Ref…`), or a plain user bookmark
can now be covered by Replace instead of forcing context-only treatment —
bookmarks become kept items with no visible marker sent to the model
(consistent with #1342's kept-items mechanism), written back through the
existing OOXML rewrite path, which per the PR's "BM0" native probe keeps
bookmarks intact; new text inserted where none existed before lands
inside a bookmark only when that bookmark spans the whole rewritten
piece. A bookmark that starts or ends mid-selection (away from another
kept item) now gets a dedicated `bookmark_cut` reason — confirmed
directly in the diff (`WordSelectionCard.tsx`'s reason-text switch and a
matching test using `_Toc938001`/`_Ref938004`/`_Ref938005` bookmark
fixtures) — rather than the generic `bookmark` refusal. Per the PR's
description (not independently verified beyond the one confirmed case):
several narrower bookmark shapes remain refused under the plain
`bookmark` reason — one inside a field, a table-column bookmark, a
Mac-only `getBookmarks`/OOXML discrepancy, and critically a bookmark that
spans across a paragraph boundary, which stays refused "until a native
probe (BM1) shows insertOoxml keeps it" — i.e., the author explicitly
left this case unresolved pending further native testing, rather than
assuming OOXML rewrite handles it safely. The rewrite and its read-back
verification check each bookmark's name and range; a dropped, renamed, or
moved bookmark marks the result unverified.

## Compatibility and configuration

Bug fix / capability extension to the Word Replace feature introduced
earlier in this batch; no config keys, no database migration. Expands
what Replace can cover (bookmarked headings/TOC targets) rather than
removing capability.
