# PR #998: Compose the delegation preamble instead of storing it in the child's message (ERMAIN-630)

- PR: https://github.com/EratoLab/erato/pull/998
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: Delegation

## Summary

Fixes a UX defect in the delegation feature (#978–#994): opening a
delegated child chat showed its first user message with the entire
delegation preamble baked in verbatim — the `<system-reminder>` envelope,
"do not ask clarifying questions / do not address the end user"
boilerplate, and the rendered `Expected output:`/`Constraints:` sections —
so a person reading the delegated run saw machine-directive text meant
for a model, not a clean task brief. Confirmed by reading the code, this
adopts the same solution the existing action-facet directive mechanism
already uses:

- The child's stored user message is now genuinely just the task brief —
  confirmed `dispatch` no longer appends the preamble text to `args.task`
  before persisting it.
- `expected_output`/`constraints` move into the chat's own provenance
  envelope (capped at 4000 chars each) rather than relying solely on the
  parent's copy in its own `ToolUse.input` — since the child chat can't
  read the parent chat's data, and the parent could be deleted
  independently while the child survives.
- The preamble is now **composed fresh on every turn** directly from the
  chat row's provenance, confirmed via the `build_abstract_sequence_with_facet_tool_expansions`
  diff: a new `AbstractChatSequencePart::DelegationPreamble` is pushed
  when `provenance.kind == Delegation && provenance.adopted_at.is_none()`,
  and `resolve_sequence` turns it into a new
  `ContentPart::DelegationPreambleMarker` — a typed marker, not rendered
  text, matching the existing `ActionFacetMarker` pattern exactly (the
  actual template rendering happens later, in `file_resolution.rs`,
  against the configured `erato.template.toml` preamble).
- **Adoption correctly switches the directive off**: confirmed the same
  `provenance.adopted_at.is_none()` gate (from #992's adoption-tracking
  work) that determines composition also feeds a generalized
  `is_prior_turn_directive_message` replay-strip function (renamed from
  `is_prior_turn_action_facet_message`), now stripping *both*
  `ActionFacetMarker` and `DelegationPreambleMarker` content from any
  prior turn's replayed history — so once a human has adopted (written
  into) a delegated run, neither the current turn nor any replayed past
  turn keeps telling the model "do not address the end user," which would
  otherwise be actively wrong advice once the end user is exactly who's
  now writing to it.
- Confirmed the PR's own stated reasoning for why re-deriving every turn
  (rather than the previous first-turn-only behavior riding the persisted
  message) doesn't actually change observable behavior in practice: a
  non-adopted delegated run only ever reaches a second turn by *becoming*
  adopted (since nothing else writes into it), at which point the
  directive is already switched off by the adoption gate — so the
  every-turn/first-turn-only distinction is only ever exercised in the
  degrade-gracefully direction, not a behavior change for any real
  scenario today.
- Runs persisted **before** this change keep their old preamble baked
  into the message row — confirmed the PR explicitly declines to
  pattern-match stored prompt text to retroactively hide it, reasoning
  that doing so would be exactly the kind of fragile text-masking this
  fix exists to avoid in favor of typed markers.

## Compatibility and configuration

None new (reuses existing delegation config from #978, just restructures
how `expected_output`/`constraints` are threaded through). Additive
OpenAPI schema change (new `ContentPart` variant, regenerated types) with
no existing frontend code switching on it, per the PR. Behavior change:
a delegated chat's stored first message is now a clean task brief instead
of a machine-directive-laden prompt; this only affects delegated runs
created after this change ships — pre-existing delegated chats are
unaffected and keep their old inlined format.
