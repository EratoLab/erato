# PR #1013: Delegated background runs of the open chat above the composer (ERMAIN-642)

- PR: https://github.com/EratoLab/erato/pull/1013
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Delegation

## Summary

Adds the surface a background-delegated run's completion (#1008) is
actually meant to be discovered through: a compact, collapsible bar above
the composer listing the current chat's background delegated runs, with
status dots, elapsed time, and an open-run link. Per the PR, this replaces
an originally-sketched sidebar section — landing instead directly above
the composer specifically because it works at small screen sizes, sits
near where the runs were launched from, and stays web-only for free (the
Outlook add-in composes its own surface and never mounts the `Chat.tsx`
component this is added to). Given the 1775-line scale, review targeted
the two claims most load-bearing for correctness.

- **"Only background runs listed," confirmed backend-side**: `RecentChat`
  gains `provenance_run_mode`, extracted from the chat's stored provenance
  JSON the same way `provenance_kind` already is. Confirmed this reuses
  #1005's asymmetric persistence design exactly (only `Background` mode
  is ever written to provenance) — so an *awaited* delegation, whose
  answer already returned inline into the parent turn, naturally has no
  `run_mode` stored and is correctly excluded from this listing by
  filtering on its presence, without needing any new column or a
  separate flag.
- **"Trace and bar can never disagree," confirmed via full read of the
  new `useDelegatedRunLiveStatus.ts`**: the hook that overlays live status
  onto #1012's frozen "Sent to background" trace step calls the *same*
  `resolveDelegatedRunStatus` function the bar's own rows use, reading
  from the same two sources (the generation-status store, and the
  React-Query cache of `recentChats` listings) — confirmed via
  `useSyncExternalStore` subscribing directly to the query cache and a
  shared `findListedRun` lookup, rather than maintaining any separate
  resolution logic for the trace-step context. This is a genuine
  single-source-of-truth design, not just a description of intent: there
  is structurally only one function that decides "is this run running,
  finished, or failed," consumed identically by both surfaces.
- Per the PR (not independently re-verified given the remaining scope):
  the listing query combines `origin_chat_id` (#1007) with
  `include_delegated: true` (since the origin filter alone still excludes
  delegated children per #1007's own composability design) and an
  explicit limit, framed as a recency window rather than a full paginated
  history; the bar seeds the generation-status store from its own fetched
  rows (gating the existing poller, per #868's established store-seeding
  pattern) and `patchTerminalChats` (from #868's `GenerationStatusPoller`)
  is extended to also reach this query's non-paginated cache shape;
  turn-completion cache invalidation is consolidated into one awaited
  invalidation covering both the sidebar's infinite query and this bar's
  variant, replacing a previous refetch-plus-invalidate pair that
  fetched the sidebar's data twice; and several shared helpers
  (`seedGenerationStatusFromListing`, `resolveRecentChatTitle`,
  `BACKGROUND_RUN_MODE`/`isBackgroundRun`) are extracted from what the PR
  describes as previously-triplicated logic.

## Compatibility and configuration

None new beyond the existing delegation/background-mode gates. Additive
`provenance_run_mode` field on `RecentChat` (absent for any non-delegated
or awaited-mode chat, so no behavior change for existing clients). The
new bar only ever renders content once background delegation is both
enabled and actually used — hidden entirely when there are no undismissed
background runs for the open chat.
