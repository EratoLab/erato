# PR #829: Remove outdated image-generation chat mode

- PR: https://github.com/EratoLab/erato/pull/829
- Status: pending (diff reviewed)
- Category: Deprecations and upgrade notes
- Theme: None

## Summary

Removes the `chat_providers.providers.<provider-id>.model_settings.generate_images`
configuration option and its entire implementation. This was a per-model
setting that, when `true`, made a configured chat provider generate an
image (e.g. via OpenAI's DALL-E API) from the user's most recent message
text instead of a normal text response, download the generated image,
store it as a file upload, and add it to the chat as an image attachment.
The `ModelSettings.generate_images` field is deleted from
`backend/erato/src/config.rs`, and the corresponding request-handling
branch is removed from `backend/erato/src/server/api/v1beta/message_streaming.rs`
(243 lines removed) and `backend/erato/src/services/genai.rs` (27-line
diff — image-generation client method likely simplified/removed too, not
fully verified). The dedicated integration test suite
`backend/erato/tests/integration_tests/api/image_generation.rs` (349
lines) is deleted entirely, and its module reference removed from `mod.rs`.
Documentation for `generate_images` and the "Complete Image Generation
Example" section are removed from `site/content/docs/configuration.mdx`,
along with the commented example in `backend/erato.template.toml`.

## Compatibility and configuration

**Breaking configuration change.** Any deployment with
`chat_providers.providers.<provider-id>.model_settings.generate_images = true`
set will have that setting silently ignored after upgrading — confirmed by
checking `ModelSettings` at the current `main` head
(`backend/erato_config/src/config.rs`): it does not carry
`#[serde(deny_unknown_fields)]`, so config parsing will not reject the
startup for an unrecognized `generate_images` key, it will simply be
dropped. The provider will then silently behave as a normal
text-generation model instead of failing fast, which could be surprising
for an operator who doesn't notice the change. No migration script is provided;
operators using this feature must remove the setting and, if they still
need equivalent functionality, find another way to offer image generation
(e.g. via an MCP tool, if available) — this PR provides no replacement.
This should be called out explicitly as a breaking/deprecation-style
change in the release notes, even though the config key is silently
dropped rather than causing a startup error.
