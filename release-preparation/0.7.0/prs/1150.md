# PR #1150: Switch single MCP tools off per chat from the tool browser

- PR: https://github.com/EratoLab/erato/pull/1150
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Stacked on #1149, completing the composer-Connectors MCP-control stack
(#1146–#1150). Adds `chats.disabled_mcp_tools text[]` (migration `0045`)
of `server/tool` patterns, letting a user switch off individual tools
(not just whole servers) for a chat. Confirmed by reading the complete
`filter_mcp_tools_by_disabled_patterns`/`mcp_tool_matches_disabled_patterns`
functions in `message_streaming.rs`:

- **Reuses the existing allowlist pattern grammar exactly, not a
  reimplementation**: `mcp_tool_matches_disabled_patterns` delegates
  directly to `is_qualified_tool_allowed` — the same matcher used
  elsewhere for facet tool allowlists (`*`, bare `server`, `server/*`,
  exact `server/tool`) — confirming the PR's claim that disabled-tool
  patterns "use the facet allowlist grammar" is structural, not merely
  described.
- **The continuation reads the same matcher directly, confirmed exactly
  via its own doc comment**: `mcp_tool_matches_disabled_patterns`'s doc
  comment states "Read directly by a continuation as well, so a parked
  tool stays refused even when its server cannot be reached to
  rediscover it" — matching the PR's stated design that the refusal
  doesn't depend on a live rediscovery of the (possibly now-unreachable)
  server.
- **Reporting drift-tolerance behavior, confirmed structurally via the
  filter ordering**: `filter_mcp_tools_by_disabled_patterns` runs after
  the server-level disable filter (per the PR's stated enforcement order:
  deny → write → disabled-servers → disabled-patterns), so a tool already
  dropped by a server-level disable is no longer present in this
  function's input at all — it cannot be reported a second time under
  the tool-pattern list, naturally producing the PR's stated "a tool
  already gone via the server-level disable is reported under the server
  only" behavior as a structural consequence of the pipeline order,
  confirmed exactly.
- Per the PR (not independently re-verified given the very large
  remaining scope): the migration `0045` itself (additive, no behavior
  change for existing chats); the generalized `dedup_keep_order` helper
  (per the PR, now shared with the server-list dedup from #1149); the
  disclosed review fix where the frontend's tool-disable matcher was
  initially exact-only while the backend honors wildcards — fixed by
  mirroring `is_qualified_tool_allowed` on the frontend
  (`mcpToolPatterns.ts`, 109 lines), so a wildcard-covered tool now
  renders unchecked-and-disabled in the browser modal with a "Switched
  off for this chat by the rule {pattern}" explanation; the new per-tool
  checkbox in the **Browse tools…** modal ("Use {title} in this chat"),
  visually distinct from the Settings approval radios, disabled/locked
  for a server already switched off via #1149; the Connectors server
  row's summary text ("N tools switched off" / "All tools switched off"
  / "Some tools switched off") derived from the stored patterns rather
  than a live roster (since the section builder has no roster available,
  per the disclosed review note); the new shared
  `useChatDisabledMcpList` hook with #1149's hook becoming a thin
  wrapper over it; the new `McpDisabledToolsNotice.tsx` (51 lines)
  surfacing dropped tools on the affected message; and the disclosed,
  accepted edge case that a persisted per-tool disable for a tool the
  server no longer exposes is counted in the row summary but has no
  modal row to clear it (the backend correctly treats the stale pattern
  as a no-op, per the PR, not independently re-verified).

## Compatibility and configuration

New migration `0045` (additive column, default empty array — no behavior
change for existing chats). A user can now switch off individual MCP
tools (not just whole servers) for a specific chat from the composer's
tool browser, completing the granular per-chat MCP control surface built
across #1146–#1150.
