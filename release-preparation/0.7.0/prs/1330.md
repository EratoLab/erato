# PR #1330: Send the Word selection to the model as context (ERMAIN-928, block 1)

- PR: https://github.com/EratoLab/erato/pull/1330
- Status: pending
- Category: Features and enhancements
- Theme: Word selection editing

## Summary

Block 1 of the Word selection-editing effort (building on wave A, #1326,
reviewed earlier in this batch): when a user selects text in Word, the
composer now shows a chip ("Selected passage · N paragraphs"), and
sending the message re-captures the selection and sends it to the model
as context through a `word_selection` action facet — explicitly
**context-only**: nothing is written to the document at this stage.
Per the PR's own precise change list: `wordSelectionCapture.ts` captures
the selection at send time and never reads an `expandTo` range, because
on Word for the web such a read itself mutates the document (a
previously-measured "preflight impact"); offsets are derived from the
selection text, with search hits used to disambiguate a passage that
repeats within its own paragraph, and tracked deletions are excluded
from the captured text. `useWordSelection`/`wordSelectionStore` provide a
single debounced reader on `DocumentSelectionChanged`, with a "disarm"
mechanism so a selection Erato made itself (via Locate/"Show in Word")
is never mistakenly captured and sent as if it were the user's own
selection. A context-only selection never displaces an already-included
document attachment, and a failed capture drops the send attempt and
restores the user's draft rather than sending a degraded context
silently. A new `spanChecked` fact is introduced to keep every
selection context-only until a later "Replace" capability gets its own
span-safety checks.

**Critically, per the PR's own explicit statement**: "Until the server
advertises `word_selection` with `selected_text`, nothing here runs and
sends are unchanged." The facet itself ships through a separate,
externally-maintained deployment config package
(`erato-subscription-content`), not in this repository — confirmed by
grepping this repo's own `erato.template.toml` and `config.rs` for
`word_selection`, which finds no built-in facet definition. So this PR's
UI/capture wiring is inert for any deployment until that external facet
configuration is applied.

## Compatibility and configuration

None breaking; purely additive and, per the PR's own stated server-side
gate, inert without external facet configuration advertising
`word_selection`/`selected_text` (not shipped in this repository). No
config keys in this repo change. No migration.
