# PR #1158: Stabilize all experimental config keys

- PR: https://github.com/EratoLab/erato/pull/1158
- Status: pending (diff reviewed)
- Category: Deprecations and upgrade notes
- Theme: None

## Summary

Promotes three previously-`experimental_`-prefixed configuration sections
to stable, non-prefixed names in `backend/erato_config/src/config.rs`:
- `experimental_facets` → `facets` (`ExperimentalFacetsConfig` renamed to
  `FacetsConfig`)
- `integrations.experimental_sharepoint` → `integrations.sharepoint`
  (`ExperimentalSharepointConfig` → `SharepointConfig`)
- `integrations.experimental_entra_id` → `integrations.entra_id`
  (`ExperimentalEntraIdConfig` → `EntraIdConfig`)

Each field keeps a `#[serde(alias = "experimental_...")]` so an existing
`erato.toml` using the old key names continues to parse and work
unchanged — no functional break for unmigrated configs. A new
`#[facet(erato_config::deprecated_alias(name = "..."))]` attribute (new
`Attr::DeprecatedAlias` variant, `config_facet_attrs.rs`) marks these
aliases so the generated `config_reference.json`/documentation surfaces
each old key as deprecated with a `"Please use \`<new key>\` instead."`
note and `hide_in_docs: true`, while the new canonical key gets normal,
undeprecated documentation. All internal code references, tests, and
example config files (`erato.template.toml`, k3d/e2e scenario TOMLs) were
updated to the new stable names throughout the codebase (859 lines
changed across ~30 files, mostly `experimental_facets.` → `facets.` and
similar renames).

## Compatibility and configuration

**Non-breaking rename with silent backward compatibility**: `erato.toml`
files using `experimental_facets`, `integrations.experimental_sharepoint`,
or `integrations.experimental_entra_id` continue to work unchanged after
upgrading, via the Serde aliases. Important caveat: **there is no runtime
startup warning or log message** when an old key is used — the
deprecation is only reflected in generated documentation
(`config_reference.json`/`configuration.mdx`), not surfaced to an operator
who doesn't consult the docs. Deployments should proactively migrate
`experimental_facets.*` → `facets.*`,
`integrations.experimental_sharepoint.*` → `integrations.sharepoint.*`,
and `integrations.experimental_entra_id.*` → `integrations.entra_id.*` in
their configuration, since the old aliases are documented as deprecated
and could be removed in a future release (no stated removal version found
in this diff). No database migration.
