# PR #1079: Expose complete generated API client in frontend library

- PR: https://github.com/EratoLab/erato/pull/1079
- Status: pending
- Category: Documentation
- Theme: Customer themes and component kits

## Summary

Widens what the `@erato/frontend` library package (built and consumed via
the `frontend/src/library/index.ts` entry point) exports from the
generated `v1beta` API client. Previously only a hand-picked subset of
functions/hooks (`chatMessagesQuery`, `fetchUpdateProfilePreferences`,
`fetchUploadFile`, `profileQuery`, `recentChatsQuery`,
`useArchiveChatEndpoint`, `useFacets`, `useRecentChats`, `useUpdateChat`)
was re-exported. Per the new code comment, "the generated client is part
of the public library surface" — the library now does
`export * from "@/lib/generated/v1betaApi/v1betaApiComponents"` (every
generated fetch function, query builder, and React Query hook), plus all
generated schema types (`export type * from ".../v1betaApiSchemas"`), the
low-level fetcher (`v1betaApiFetch`, `ErrorWrapper`,
`V1betaApiFetcherOptions`), and the React Query context helpers
(`queryKeyFn`, `useV1betaApiContext`, `V1betaApiContext`). Also newly
exported: the `Chat` component from
`@/components/ui/Chat`.

## Compatibility and configuration

No configuration keys, migrations, or backend changes; this only affects
what's importable from the `@erato/frontend` npm package by external
consumers building custom themes/component kits/integrations. This is a
purely additive change to the library's public API surface — existing
named exports are all still present, just alongside many more. External
consumers gain direct access to the full generated API client rather than
being limited to a curated subset, complementing #999 (Git-consumer
support) and #822/#826 (shared frontend distribution) from this cycle.
