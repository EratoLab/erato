# PR #937: Add edit sharing for assistants

- PR: https://github.com/EratoLab/erato/pull/937
- Status: pending
- Category: Features and enhancements
- Theme: Assistant Hub and assistant sharing

## Summary

Adds an "editor" share-grant role for assistants, alongside the
pre-existing "viewer" role (previously the only supported role — share
grants with any other role value were rejected). `create_share_grant` in
`backend/erato/src/models/share_grant.rs` now accepts `role = "editor"`
when `assistants.enable_edit_sharing` is enabled, letting an assistant
owner grant another user or group edit access rather than just view
access. Editor grants are explicitly disallowed for assistants that are
also an Assistant Hub version's source assistant
(`assistant_hub::is_hub_version_assistant`) — a hub-submitted assistant
cannot be shared with edit access, presumably to keep the review/versioning
workflow's ownership model intact. Backend authorization in
`backend/policy/backend/backend.rego` (71-line diff) is extended to grant
edit-level permissions (not just read) to users/groups with an active
"editor" share grant. `frontend/src/components/ui/Sharing/SharingDialog.tsx`
(35-line diff) presumably exposes a role picker (viewer/editor) in the
sharing UI when the feature is enabled.

## Compatibility and configuration

New configuration key, defaulting to enabled:
```toml
[assistants]
enable_edit_sharing = true  # default
```
No migration — this reuses the existing `share_grants` table's `role`
string column with a new accepted value ("editor"), not a schema change.
Deployments that want to restrict sharing to view-only can set
`enable_edit_sharing = false`, which also makes attempting to create an
"editor" grant fail server-side. No breaking change for existing "viewer"
grants.
