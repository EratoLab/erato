# PR #790: Publishing assistant in assistant store also marks as current

- PR: https://github.com/EratoLab/erato/pull/790
- Status: pending
- Category: Bug fixes
- Theme: Assistant Hub and assistant sharing

## Summary

Changes `set_published` in `backend/erato/src/models/assistant_hub.rs` so
that publishing an Assistant Hub assistant version
(`is_published = true`) now also clears `is_current_published_version` on
every other version of that assistant and sets it `true` on the newly
published version, in the same operation. Previously, publishing a version
left `is_current_published_version` unchanged (`false` by default), and a
separate `PUT /assistant-hub/versions/{version_id}/current` call was
required to make the published version visible/current for audience
viewers — per the deleted test assertion "published versions are
intentionally hidden until marked current". Unpublishing continues to clear
`is_current_published_version` to `false`, unchanged.

Before this PR, per `backend/erato/tests/integration_tests/api/assistant_hub.rs`,
publishing alone resulted in `is_current_published_version: false` and the
assistant did not appear in the audience listing until the separate
"mark current" endpoint was also called. After this PR, publishing alone
sets `is_current_published_version: true` and the assistant becomes visible
to the audience immediately upon publish.

## Compatibility and configuration

No configuration keys or migrations. This is a behavior change to the
publish flow: publishing a version now atomically makes it the "current"
one, without requiring a separate "mark as current" call. The
`PUT /assistant-hub/versions/{version_id}/current` endpoint itself is not
removed in this diff, but the two-step publish-then-mark-current workflow
used by (older) frontend or integration code is no longer required — and
if a caller still performs both steps, it remains a no-op/idempotent (the
version is already current after the first call).
