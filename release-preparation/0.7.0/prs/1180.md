# PR #1180: Put a delegated task on disk at the slot it will settle into (ERMAIN-764)

- PR: https://github.com/EratoLab/erato/pull/1180
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Delegation

## Summary

Stack 3 / position 2 of "Dynamic Delegated Tasks (Delegation Level D)"
(stacked on #1166, the reviewed tip of stack 2). Gated by
`delegation.tasks.enabled`. Fixes an awaited task being invisible mid-run
(the assistant row stayed empty until the whole turn ended) by splitting
the task route's dispatch into a launch step (reserves and commits a
placeholder) and an await step (overwrites that same slot on completion).
Confirmed every central mechanism claim by direct code inspection:

- **Launch/await split, confirmed exactly**: `dispatch_task_tool_call` is
  renamed/restructured into `launch_task_tool_call`, which now returns
  `LaunchOutcome` directly instead of resolving the wait internally —
  matching "The task route now splits launching from awaiting" precisely.
  The caller (`stream_generate_chat_completion` in `message_streaming.rs`)
  now matches on `LaunchOutcome::Launched` itself, pushes the placeholder,
  commits it, and only then calls `await_delegation` — confirming the
  await genuinely happens after the commit, not before.
- **Slot reservation and settle-in-place, confirmed exactly**: `slot =
  current_message_content.len()` is captured before dispatch; `reserved:
  Option<usize>` is set to `Some(slot)` only once a placeholder is
  actually pushed (never for a refused call, which returns `Err` before
  reaching that point, and never for the mention route). At settle,
  `let settled_index = reserved.unwrap_or(current_message_content.len())`
  and `match reserved { Some(index) => current_message_content[index] =
  settled, None => current_message_content.push(settled) }` — confirming
  a reserved slot is genuinely overwritten in place rather than appended
  to, exactly matching "the result overwrites that same slot."
- **Settle written before client events, confirmed exactly**: the settle
  commit (`commit_message_content_mid_turn(..., "task settle")`) is
  called immediately after the in-memory overwrite and before
  `send_generation_event(&message, tx.clone())` — with a code comment
  stating the exact reasoning from the PR description: "sending to the
  client can fail the turn and a reserved slot must never be left reading
  'working' for a child that has finished."
- **Both mid-turn writes are best-effort, confirmed exactly**:
  `commit_message_content_mid_turn` only `tracing::warn!`s on a
  persistence error and does not propagate it to the caller — matching "A
  failure is logged, not propagated" for both the launch and settle
  commits, which share this one helper.
- **Placeholder always carries a status, and identity keys are omitted
  rather than null, confirmed exactly**: `task_placeholder_output` always
  sets `"status": "working"` plus `child_run_id`/`delegate_chat_id`, and
  only inserts `assistant_id`/`assistant_name` into the JSON object when
  `Some` — via `if let Some(...) { object.insert(...) }` rather than
  always inserting a possibly-null value — matching "Identity keys are
  omitted rather than sent null."
- **Crash-orphaned placeholder replays untouched, confirmed exactly**: the
  new `a_placeholder_that_never_settled_replays_unchanged` test in
  `transforms.rs` builds a JSON object with exactly the placeholder's
  shape (`status`/`child_run_id`/`delegate_chat_id`, no result field) and
  asserts `strip_ui_only_tool_output` returns it unchanged — directly
  substantiating "a placeholder orphaned by a crash replays untouched... the
  replay framing has to tolerate that rather than fail on the key it does
  not have."
- **The mention route is untouched, confirmed structurally**: the non-task
  branch (`dispatch_delegate_tool_call`) has no diff in this PR, and
  `reserved` stays `None` for it, so its settle falls through to the
  pre-existing append-at-`current_message_content.len()` behavior —
  matching "it reserves nothing and its settle appends exactly where it
  always did."
- **Side effect also fixed: streamed `content_index` now matches the
  settled slot**: both the SSE `update_event.content_index` and the
  Langfuse/tracing streaming event's `content_index` changed from
  `current_message_content.len()` (evaluated *after* the row-mutating
  push, which was already a stale/off-by-one index even before this PR)
  to `settled_index` — a necessary correction for a reserved slot's
  in-place overwrite to report the correct position to the client, not
  separately called out as its own bullet in the PR description but
  directly required by, and consistent with, the reservation mechanism
  described.
- Per the PR (not independently re-verified given remaining scope): the
  "Corrections to the issue as written" claims — that the
  `current_turn_tool_responses` reorder the original issue scoped in is
  unnecessary on the serial path (deferred to ERMAIN-768, where it's
  described as load-bearing against real fan-out-driven out-of-order
  arrival) and that the launch-time commit covers submit/regenerate/edit
  (not just submit) because all three route through the same streaming
  function — both plausible given this session's earlier familiarity
  with this delegation stack, but not independently re-traced here; the
  durability test stalling a child behind a real TCP server (described as
  failing if the launch commit is removed — mutation-verified per the
  PR); and the disclosed verification claims (1111 backend tests, `cargo
  fmt --check`, three CI clippy feature variants with `-D warnings`,
  `gen-openapi --check`/`gen-config-reference --check` clean, no new
  config keys).
