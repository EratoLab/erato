# PR #1278: Scope Word edits, write them in place and make apply errors reportable

- PR: https://github.com/EratoLab/erato/pull/1278
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Word add-in

## Summary

Three connected improvements to the Word document authoring pipeline:

**Scoped edits.** Introduces a `WordReadScope` abstraction that describes which part of the document a proposal targets. Two kinds of scope are defined:

| Scope kind | Target |
|---|---|
| `WordTableCellScope` (existing, extended) | A specific table cell identified by story/section/row/column coordinates |
| `WordObjectScope` (new) | An arbitrary document region identified by `snapshot`, `identity`, `fingerprint`, and a list of `targets` (each with `ref`, `kind`, `text`, and optional `bodyRef`/`storyId`/`sectionId`) |

Scopes are bounded: at most 16 scopes (`MAX_WORD_SCOPES`), each at most 24 KiB (`MAX_WORD_SCOPE_BYTES`). The new `wordPlanMatchesObjectScope` function in `wordReadScope.ts` tests whether a plan fits within a given scope region.

**In-place writing.** Edits are now applied directly inside the document XML rather than by extracting a fragment, modifying it, and re-inserting. The `wordXmlComparison.ts` module is substantially rewritten (146 lines changed) to compute fine-grained XML diffs and apply them as patches to the host document. This preserves document structure (headers, footers, cross-references, revision marks) that the previous extract-edit-replace approach could strip.

**Reportable apply errors.** When an edit application fails (e.g., unexpected document structure, a deleted range that no longer exists, a style reference that cannot be resolved), the error includes enough context for the add-in to display a meaningful message rather than a generic "apply failed." The `wordHistory.ts` module surfaces these errors through the card-based review interface.

**Auxiliary modules.**

- `wordStyleLook.ts` (211 lines new): Resolves the effective rendering of a style by climbing the style hierarchy and deduplicating redundant formatting (`withoutStyleRedundantFormat`). This lets the add-in distinguish between a proposal that genuinely changes formatting and one that merely repeats the built-in default.

- `wordBuiltInStyles.ts` (50 lines new): Catalogues the built-in Word style names and their relationships, used by the plan compiler and scoping logic to avoid treating a style reference as a substantive change.

## Compatibility and configuration

No config changes. The scoped-edit pipeline is internal; existing Word add-in configurations continue to work unchanged. The apply-error surface is new—tool calls that previously returned a generic failure now include a `diagnostics` field on the error receipt.

## Evidence and review

- `wordReadScope.ts` exports `WordScopeTarget`, `WordObjectScope`, and `wordPlanMatchesObjectScope` with documented interfaces; the scope bound constants are enforced at the call sites in `wordDocumentPlan.ts`.
- `wordStyleLook.ts` implements style-resolution by following `style.basedOn` chains, capped at a recursion guard.
- `wordXmlComparison.ts` adds a `fingerprint`-based change-detection path and an `apply_patch` function called by the OOXml host.
- `wordHistory.ts` now records the outcome of each apply step (`success | error`) and the error message when applicable.
- Test coverage expanded in `wordXmlComparison.test.ts` (26 new lines) covering the patch-apply path.

## Release note disposition

Include in the Word add-in section of the release notes. The most user-visible change is that edits now land reliably in the correct document region and that apply failures include actionable diagnostics.
