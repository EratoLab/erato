# PR #1122: Add sidecar TLS bootstrapping

- PR: https://github.com/EratoLab/erato/pull/1122
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Desktop Sidecar for local sources

## Summary

Adds optional TLS support for the desktop sidecar's loopback JSON-RPC
listener, needed per the updated `desktop-sidecar-protocol/TRANSPORT.md`
"HTTPS loopback profile" section because "WKWebView's mixed-content
restriction makes a trusted HTTPS endpoint necessary when the Office
add-in is loaded from HTTPS" (macOS's web view otherwise blocks plain-HTTP
requests to `127.0.0.1` from an HTTPS-loaded page). When configured, the
sidecar serves `https://127.0.0.1:23123/erato/sidecar/rpc` instead of
plain HTTP on the same port (not both simultaneously); the spec explicitly
requires clients not silently downgrade a configured HTTPS endpoint to
HTTP on certificate errors.

New backend config `desktop_sidecar.tls` (`DesktopSidecarTlsConfig`,
`#[serde(deny_unknown_fields)]`) supports two modes: (1) a **fixed
identity** — a single PEM certificate chain plus private key embedded
identically into every personalized download, or (2) an **intermediate
CA** — a signing certificate/key pair used to mint a **fresh leaf
certificate for each personalized download** (with a configurable
validity period, default 365 days, capped at 3650). Per the doc comment,
"the intermediate private key is retained exclusively by the backend"
(never embedded in a distributed artifact). Both this TLS identity and
the existing `allowed_origins` policy (#917) are embedded into the
Windows/macOS bootstrap document using the same immutable, tamper-resistant
mechanism established in #917. New `backend/erato/src/distribution/desktop_sidecar_tls.rs`
(333 lines) and `desktop_sidecar_macos.rs` (207 lines, new macOS-specific
personalization support, since #917 only covered Windows) implement this.

## Compatibility and configuration

New optional config block, all fields unset by default (no TLS, sidecar
serves plain HTTP as before — no behavior change unless explicitly
configured):
```toml
[desktop_sidecar.tls]
# Fixed identity:
certificate_pem = "..."
private_key_pem = "..."
# OR intermediate CA (issues a fresh leaf per download):
intermediate_certificate_pem = "..."
intermediate_private_key_pem = "..."
validity_days = 365  # default
```
No migration. This is required for the Office add-in on macOS (WKWebView)
to reach a local sidecar at all over HTTPS-loaded pages; deployments not
using the desktop sidecar on macOS, or accepting the existing HTTP-only
loopback behavior, need not configure this.
