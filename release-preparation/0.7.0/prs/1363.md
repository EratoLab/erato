# PR #1363: ERMAIN-912: Attach durable client-operation continuations (Part 1) (#1363)

## Summary

Follow-up to the durable-client-operations foundation (#1249, reviewed
earlier) and #1358's durable Outlook `fetch_availability`. Previously, once
a durable client call parked, every *subsequent* call on that executor
treated it as permanently disconnected and parked again too — even if the
same device/tab was still live — so a conversation needing several
sequential Outlook availability reads could never get a live round-trip
after the first park. This adds "attached" SSE continuation: a parked call
can now resume live, in the same turn, over an actively-connected stream
instead of always falling back to the async inbox.

Per the PR description: a logged PostgreSQL row records transport
ownership under the active generation and its captured executor binding.
A matching transport (reconnect or new tab from the same executor) can
acquire a free or expired lease via a 5-second heartbeat / 20-second expiry
lock; a bound observer retries acquisition if a reconnect arrives before
the previous stream has released ownership; closing a stream releases only
its own token (not another transport's). Either backend replica may own
the transport (consistent with the project's multi-replica design).
Durable calls whose owning transport disappears fall back to the existing
async inbox delivery; non-durable calls are entirely unaffected. New DB
migration `0058_add_client_operation_transports` backs this ownership
tracking.

## Compatibility and configuration

None. No new config key — this is purely new backend state-tracking
infrastructure (a DB table + session logic) plus a new DB migration, both
confirmed via the diff stat (`backend/erato_config/src/config.rs` has no
changes in this diff). The feature only activates for calls already using
the durable-operations foundation from #1249/#1358, which itself remains
gated behind `client_tools.durable_operations_enabled` (off by default).
