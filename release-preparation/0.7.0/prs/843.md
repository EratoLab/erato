# PR #843: Separate button geometry from colour variant (theming contract)

- PR: https://github.com/EratoLab/erato/pull/843
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Fixes the shared `Button` component's icon-button geometry (square 36x36
sizing) being reachable only via `variant="icon-only"`, which also forces
a transparent/ghost color look — so a *filled* icon-only button (e.g. the
composer's send/stop/queue/dictation controls) rendered with text-button
geometry (inline padding, a non-square 44x36 box) with no way for a theme
to fix it, since nothing in the DOM distinguished an icon control from a
text one other than a private `btn-geometry-*` class name. Confirmed by
reading the diff:

- New `geometry?: "control" | "icon"` prop, independent of `variant`
  (color). `variant === "icon-only"` still implies icon geometry (backward
  compatible), but a filled/colored button can now opt into square icon
  geometry via `geometry="icon"` without also becoming a transparent ghost
  button.
- Two new stable DOM attributes are emitted on every button:
  `data-geometry` (the *resolved* geometry — `"icon-{size}"`, `"{size}"`,
  `"list-item"`, or `"link"` — not the raw prop, so a theme's CSS can
  target "every icon control at this size" generically) and `data-variant`
  (the raw color variant). Both are placed before the `{...props}` spread,
  so a caller can still override them explicitly if needed.
- `shape="pill"` now resolves `rounded-[var(--theme-radius-pill)]` instead
  of Tailwind's hardcoded `rounded-full` (`9999px`) — the PR notes
  `radius.pill` was previously a dead, unused theme token; a theme that
  sets a different `--theme-radius-pill` value now actually reaches pill
  buttons. Identical rendering under the default/stock theme, where the
  pill token itself is already `9999px`.

## Compatibility and configuration

None new for the base app's own rendering (default theme is visually
unaffected per the PR). This is a theming-contract change for custom
themes: `theme.css` can now target buttons via `[data-geometry="icon-sm"]`
etc. instead of relying on private, unversioned `btn-geometry-*` class
names, and a theme's `--theme-radius-pill` token now actually takes effect
on pill-shaped buttons where it previously had no effect.
