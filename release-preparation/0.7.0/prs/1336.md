# PR #1336: Replace inline, multi-paragraph and table-cell selections (ERMAIN-928, block 3)

- Category: Features and enhancements
- Theme: Word selection editing

## Summary

Per the PR description: block 3 of ERMAIN-928, extending block 2's
whole-paragraph Replace (#1334, same proof-then-write-once-unchanged
mechanism) to also cover a partial single paragraph ("inline"), a 2-40
paragraph span (partial first/last paragraph allowed), and a single
table-cell paragraph. A new `wordSelectionRange.ts` (209 lines) builds the
target sub-range from Word's search-hit results, confirmed directly in the
diff: it only accepts a hit when count, text, order and index all match
the original capture, uses prefix-text/snippet-point matching past 255
characters, and refuses with a new `TARGET_RANGE_UNPROVEN` code
(confirmed present) when it can't build a provably-correct range — on the
web this path never builds an `expandTo` range at all, per the PR, due to
a cited Word-on-the-web read bug. `WORD_SELECTION_REPLACE_SHAPES` gains
`inline`, `multi_paragraph`, and `table_cell` alongside the existing
`paragraph` shape from block 2.

**Explicitly flagged by the PR itself as not fully gated**: its own
"Native gate" section reports 3 wrong-target writes in one no-paragraph-ID
scenario (`twinThenInsertAfter`, a shared text-window resolver issue the
PR says also exists on `main`) and states plainly "Hard gate not met:
stays draft" — i.e. the author's own acceptance testing did not pass
clean, yet this was merged to `main` regardless. No behavior change for
any current user until the matching add-in build ships, since the
`word_selection` facet already offers Replace and these new shapes
activate automatically with that deploy per the PR.

## Compatibility and configuration

Per the PR: no new facet/config key — these shapes activate automatically
wherever `word_selection`'s existing `word.replace_selection` action is
already offered, once the matching add-in build is deployed. No database
migration. The known wrong-target-write risk above is a correctness
concern worth the maintainer's attention before shipping, not a
configuration concern.
