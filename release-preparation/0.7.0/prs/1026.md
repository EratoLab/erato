# PR #1026: Do not clear a still-unlisted chat's placeholder on turn completion (ERMAIN-666)

- PR: https://github.com/EratoLab/erato/pull/1026
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: Delegation

## Summary

Follow-up fix to #1023, which had broken the `sidebar-new-chat.many-models`
e2e suite: #1023's "hygiene backstop" — unconditionally clearing the
pending-chat placeholder in the `assistant_message_completed` handler,
justified as "by completion the chat is listable" — turned out to have a
false premise. Confirmed by reading both diffs in full:

- **The regression and its fix, confirmed via `useChatMessaging.ts`**:
  the single `clearPendingChat(activeStreamKey)` call #1023 added after
  the awaited listing invalidation in the `assistant_message_completed`
  handler is removed, replaced with a comment stating the corrected
  rationale: a chat the refetched list still does not return (filtered
  out, on a later page, or deliberately excluded) has the placeholder as
  its *only* sidebar row, so unconditionally clearing it there deleted
  the open chat's own row the moment its first turn finished. Confirmed
  #1023's actual replay-detection fix (the `chat_created` early-return
  guard) is untouched by this diff — this PR only removes the one
  overreaching backstop clear.
- **Why the backstop is now unnecessary, confirmed by the PR's own
  reasoning (consistent with what #1023's diff showed)**: since replayed
  `chat_created` frames no longer seed placeholders at all (per #1023),
  every remaining placeholder now belongs to a chat this client genuinely
  submitted — meaning the backstop, which was meant to catch delegated
  runs that never become listable, only ever fired on the healthy,
  already-covered path instead. The resume `onError`/`onClose`
  unconditional clears from #1023 are confirmed left in place (not
  touched by this diff), as are the pre-existing clearing paths
  (listed-row swap, starting a New Chat, archiving, stream errors).
- **Test inversion, confirmed via the test diff**: the unit test that had
  asserted `pendingChat` becomes `null` on turn completion is renamed and
  inverted to assert `pendingChat?.id` still equals the chat's id — i.e.
  the test now pins the corrected contract (placeholder survives
  completion while still unlisted) rather than the regressed one.
- Per the PR (not independently re-verified — no CI access in this
  review): the e2e failure was reproduced locally on unfixed main and
  confirmed fixed on both Chromium and Firefox, 3/3 stable on repeat; a
  neighboring, unrelated e2e test at `:168` is noted as a known
  pre-existing flake unaffected by this change.
