# PR #1298: Share MCP approval display metadata across Web and Teams

- PR: https://github.com/EratoLab/erato/pull/1298
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: MCP

## Summary

Unifies the MCP tool approval display metadata so that both the web frontend and the Teams bot render approval requests consistently. Previously, tool approval cards in the Teams bot used a separate rendering path from the web UI, leading to inconsistent information presentation.

**Backend model.** The `message.rs` model is extended with structured approval metadata that captures: which MCP server and tool are being requested, what data access is needed (read scope, write scope, file types), any budget implications, and the current approval state (pending/approved/denied). This metadata is populated by the `tool_call_budget` service and included in the streaming response.

**Teams bot card rendering.** `cards.rs` (228 changes) is refactored to consume the shared metadata format and produce Teams adaptive cards that match the information shown in the web UI. The `render.rs` module formats the metadata for Teams card display.

**Web frontend.** The MCP server listing endpoint (`mcp_servers.rs`) and the message streaming pipeline include the same structured metadata, so the web UI's approval dialog uses a unified data source.

**Streaming.** The streaming pipeline (`message_streaming.rs`) includes the approval metadata in the event stream, so both renderers can show approval state transitions (pending → approved/denied) in real time.

## Compatibility and configuration

No config changes. The refactoring is internal; MCP approval UI appearance is unchanged for existing users.

## Release note disposition

Include in both the MCP and Teams sections of the release notes as an infrastructure unification.
