# PR #884: Restructure assistant hub and assistants pages to share structure

- PR: https://github.com/EratoLab/erato/pull/884
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Assistant Hub and assistant sharing

## Summary

Merges the previously separate `AssistantHubPage.tsx` (489 lines, deleted)
and `AssistantsListPage.tsx` (421 lines, deleted) into a single new
`AssistantsPage.tsx` (942 lines) component parameterized by a `view` prop
(`"shared_with_user" | "owned_by_user" | "hub"`). Routing in
`frontend/src/App.tsx` changes: `/assistants` now renders
`<AssistantsPage view="shared_with_user" />` (previously the combined
list/tabs page), a **new route** `/assistants/created` renders
`<AssistantsPage view="owned_by_user" />`, and `/assistant-hub` (and
`/assistant-hub/category/:categoryId`) render `<AssistantsPage view="hub" />`.

The sidebar navigation is also consolidated:
`AssistantHubNavigationItem` (a separate sidebar link, previously shown
only when both `assistantsEnabled && assistantHubConfig?.enabled`) is
removed entirely; `AssistantsNavigationItem` now takes an `href` and links
to the Hub route when `assistantHubConfig?.enabled`, otherwise to
`/assistants` — so there is now exactly one combined "Assistants" sidebar
entry instead of up to two. Visibility of that single nav item also
changed: it now shows whenever `assistantsEnabled || assistantHubConfig?.enabled`
(previously the Hub link required *both* flags to be true to appear at
all), so a deployment with only the Hub enabled (and "My Assistants"
disabled) now gets a working sidebar entry where it previously may have
had none.

## Compatibility and configuration

No configuration keys added or removed; existing `assistantsEnabled`
(assistants feature) and `assistantHubConfig.enabled` (Assistant Hub
feature) flags continue to gate the same underlying capabilities, just
combined into one page/nav item. Behavior change: deployments with only
the Assistant Hub enabled (not the "My Assistants" list) previously would
not show any assistants-related sidebar link at all (since the old Hub nav
item required both flags); after this PR they get a working link to the
Hub. The URL `/assistants` now specifically means "shared with me" rather
than a general assistants list with internal tabs, with owned assistants
moved to the new `/assistants/created` URL — bookmarks/links to the old
tab-based `/assistants` behavior are unaffected at the URL level (same
path), but the page's internal tab/content structure changed.
