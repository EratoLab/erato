# PR #1353: Read and edit large Word documents section by section instead of refusing every read (ERMAIN-952) (#1353)

- PR: https://github.com/EratoLab/erato/pull/1353
- Status: pending
- Category: Bug fixes
- Theme: Word add-in

## Summary

Follow-up to #1352. A document over the add-in's 192 KiB complete-read limit
(e.g. ~1,600 paragraphs, many in tables) previously set `snapshot.issue =
"too-large"`, which refused every read entirely — including scoped `target`
and `table_cell` reads — even though the chip claimed "first 453 of 1590
paragraphs" was available. This PR splits that single "too-large" refusal
into two tiers:

- The size limit now sets a new `completeReadIssue` instead of the blanket
  `snapshot.issue`. Complete/whole-document reads, plans, and repairs are
  still refused (including in `validateWordDocumentPlan`), but scoped
  `target`, `target.queries`, and `table_cell` reads — and their scoped
  submissions through apply — now work normally.
- Hard issues (genuinely unsupported documents) still block everything, and
  "too-large" no longer incorrectly overwrites an "unsupported" status.
- The read-only review fallback introduced in #1352 now applies only when no
  usable package was captured at all (too large to capture, timed out,
  failed, or unsupported) — a size-only capture stays in the normal
  authoring flow instead of falling back to read-only.
- The chip and model-facing `authoring_status`/`truncation_note` text are
  updated to say that only scoped reads/edits work on a large document
  ("Document included · read in parts"), translated into de/fr/es/pl.
