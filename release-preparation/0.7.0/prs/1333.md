# PR #1333: Report sidecar source capabilities and degrade honestly in chat

- PR: https://github.com/EratoLab/erato/pull/1333
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Sidecar source capabilities (new Outlook for Mac/Windows parity, foundation)

## Summary

Per the PR description: "Foundation 1 of the new Outlook for Mac (Hx) parity
work" (ERDSCAR-41). Extends the desktop-sidecar protocol (bumped to 0.1.36,
catalogue revision 14, additive-only) with a `capabilities` object a sidecar
can attach to a `sources.list.v1` source or an `outlook.list_mailboxes.v1`
mailbox, declaring per-source booleans (`conversations`, `attachments`,
`folders`, `recipients`, `openInOutlook`), a `documentExport` mode
(`complete` vs `cachedOnly`), and the searchable `metadataFields`. An absent
`capabilities` object means unknown, preserving behavior against older
sidecars. New mailbox `source` values (`macOsHxAccount`, `windowsNewOutlook`)
identify the new Outlook clients' local storage formats, and a new
`syncCache` inventory value (alongside existing `localStore`/
`cacheObservations`) describes a sync client's partial local cache. An
optional `error.data.sourceError` open string explains why a source's
content couldn't be produced, without changing the existing closed `kind`
enum or error code. On the frontend, `chatTools.ts` (335-line diff) is
rewired to only offer `readConversation` where a mailbox's capabilities
support it, surfaces typed/actionable errors for unreadable folders instead
of an empty tree, and a new `sourceCapabilities.ts` (189 lines + 440-line
test file) centralizes the capability-gating logic; `LocalSearchCoverageNotice`
and the indexing settings UI gain copy for the new source/inventory states.

## Compatibility and configuration

Additive and backward-compatible per the PR's own framing: an older sidecar
that never sends `capabilities` leaves clients at their previous behavior
(capabilities absent = unknown, not "unsupported"). No config keys; this is
protocol/schema plus frontend consumption only. No database migration.
