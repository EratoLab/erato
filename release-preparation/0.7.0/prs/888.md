# PR #888: Add config option - generation.max_tool_calls_per_message

- PR: https://github.com/EratoLab/erato/pull/888
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Makes the previously hardcoded limit on how many tool calls can be
executed while generating a single assistant message configurable. In
`backend/erato/src/server/api/v1beta/message_streaming.rs`
(`stream_generate_chat_completion`), the constant `max_tool_call_iterations
= 15` is replaced with `app_state.config.generation.max_tool_calls_per_message`,
read from a new `GenerationConfig` struct
(`backend/erato/src/config.rs`). Startup validation
(`GenerationConfig::validate`) rejects a configured value of `0` (panics at
startup with "generation.max_tool_calls_per_message must be greater than
0"). Once a turn reaches this many tool calls, generation is aborted with
an error ("Maximum tool call count per message ... exceeded", renamed from
"Maximum tool-call iteration count ... exceeded").

## Compatibility and configuration

New configuration key `generation.max_tool_calls_per_message`, defaulting
to `15` — identical to the previous hardcoded value, so existing
deployments see no behavior change unless they explicitly configure it.
Must be a positive integer (`u32`, validated `> 0` at startup) or the
backend fails to start. No migration.

```toml
[generation]
max_tool_calls_per_message = 15
```
