# PR #1178: Share attachment tile and composer rendering with component kits

- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Continues the same kit-extraction pattern as the ERMAIN-810 series (#1145,
#1161, #1173, #1174), this time for `AttachmentTile`/`AttachmentTileList`/
`FileAttachmentsPreview` — letting a kit (OpenWebUI, stated to shrink five
kit files from 545 to 172 lines once it lands) supply custom face/preview
rendering while the host retains activation, removal, and selection
state. Confirmed the central render-prop mechanism and helper additions
by direct code inspection:

- **`renderContent` replaces only the visual face, confirmed exactly**:
  `AttachmentTile` gains a `renderContent?: (presentation:
  AttachmentTilePresentation) => React.ReactNode` prop. When supplied,
  `customContent` is substituted for the default icon/filename body *and*
  for the default `<img>` face, but every surrounding control — the
  `RemoveButton` (still wired to the same `onRemove` callback), the
  activatable `<button>`/`<label>` wrapper (still carrying `onActivate`,
  `selection`, `disabled`), and the tile's geometry/selection classes
  (conditionally suppressed only when `renderContent` is present, via
  `renderContent ? undefined : clsx(...)`) — remains host-owned. This
  directly substantiates the PR's claim "retaining host controls and
  state."
- **`AttachmentTilePresentation` carries exactly what a custom face
  needs, confirmed exactly**: the interface is `{ filename: string;
  imageProps: React.ImgHTMLAttributes<HTMLImageElement> | null }`, built
  from the same `src`/`alt`/`onError` object the host's own `<img>` uses
  internally (`imageProps` is `null` when the tile isn't rendering media).
  A code comment states "A custom face uses host metadata and image
  failure handling" — matching the interface shape exactly.
- **`isImage` override and `removeButtonClassName`, confirmed exactly**:
  `isImage ?? fileType === "image"` lets a kit override the host's
  extension-based media detection (a code comment states this is for "an
  API image capability" case), and `removeButtonClassName` replaces only
  the remove button's CSS classes (`className ?? clsx(...)` inside
  `RemoveButton`) while its `onClick`/`onRemove`/`disabled` wiring is
  untouched — matching "Replaces the default remove badge classes; its
  behaviour stays with the host" precisely.
- **New shared helpers, confirmed exactly**: `FilePreviewBase.tsx` gains
  `getFilePreviewUrl` (preview_url, falling back to download_url) and
  `isImageFileResource` (checks the API's `file_capability` metadata —
  `id === "image"` or an `analyze_image` operation — before falling back
  to extension-based `isImageFile`), matching the PR's "Share preview
  URL/image-resource helpers" claim and its stated purpose of identifying
  images by API capability metadata even with opaque filenames.
- **Kit-surface pinning and minor bump, confirmed exactly**:
  `AttachmentTileProps`/`AttachmentTilePresentation`,
  `FileAttachmentsPreview`/`FileAttachmentsPreviewProps`,
  `getFilePreviewUrl`/`isImageFileResource`/`splitFilenameForDisplay`,
  `findCapabilityByExtension`, and `useFileCapabilitiesContext` are all
  confirmed added both as explicit exports in `kit-surface.ts` and as
  string entries in `ERATO_KIT_SURFACE_EXPORTS`. `ERATO_SHARED_SURFACE_MINOR`
  confirmed bumped `11 → 12` in `surfaceVersion.ts`, consistent with the
  established additive-only versioning convention verified repeatedly
  across this session's earlier reviews (#1055/#1138/#1145/#1168/#1174).
- Per the PR (not independently re-verified given remaining scope): the
  `AttachmentTileList.tsx` and `FileAttachmentsPreview.tsx` diffs
  themselves (their own render-prop plumbing feeding into the confirmed
  `AttachmentTile` mechanism), the office-addin mock-contract coverage
  (`eratoLibraryMock.tsx`), and the disclosed validation claims (2,388
  frontend tests passing with 11 skipped — two PDF tests requiring a
  worktree dependency allowlist, 8 office mock tests, kit typecheck/build
  and 25 kit tests, and browser checks at desktop/Outlook widths in both
  color schemes covering keyboard removal, disabled preview, image
  fallback, and 50-file scrolling) — none independently reproduced here.

## Compatibility and configuration

None breaking, and no behavior change for the host's own default
rendering per the PR's own claim (confirmed consistent with the
optional, additive nature of `renderContent`/`isImage`/
`removeButtonClassName` — all undefined by default, preserving the prior
rendering path exactly). Additive `ERATO_SHARED_SURFACE_MINOR` bump only.
This PR contains only the host-side changes; the companion kit reduction
is explicitly stated as prepared locally and to be delivered separately
after this PR merges.
