# PR #1371: Word for the web: Revert of a restyle puts the paragraph style back and never claims it did when it didn't (ERMAIN-967) (#1371)

## Summary

Per the PR's own detailed body (native-gate tested, not independently
re-verified line-by-line but treated as reliable given the gate report
citation): fixes a false-success bug in the Word add-in's in-place Revert
of a paragraph restyle. Word for the web's `Paragraph.getOoxml()` omits
the paragraph's `w:pPr` entirely, so the in-place Revert mechanism — which
both decides whether to act and verifies the result using that same OOXML
signature — saw a restyled paragraph as unchanged and wrote nothing back,
while still reporting "reverted" to the user.

- **Fix, as described**: paragraphs whose style or list the writer sets
  are now also read back through `style`, `styleBuiltIn`, `isListItem` and
  list state; Revert decides/writes/verifies against this richer state,
  and a mismatch now surfaces as `interrupted` (with its own card text)
  rather than a false `reverted`. An Apply whose style doesn't read back
  is now `unverified` rather than silently assumed successful.
- Also fixes a related false-negative: Word for the web writes a
  "Normal" paragraph style under the document's own style ID (e.g. German
  `Standard`); the comparison now recognizes that as equivalent to
  "Normal", so restyles-to-Normal in non-English documents no longer end
  up `unverified` when they actually succeeded.
- `WORD_IN_PLACE_MECHANISMS` is restructured so each in-place mechanism
  names both a forward probe and a Revert probe, and is only considered
  supported when both pass — per the PR, its own native gate (17/17 rows)
  confirms the web `restyle` mechanism passes both directions.
