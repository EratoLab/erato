# PR #1046: Unify staged attachment previews into a shared tile

- PR: https://github.com/EratoLab/erato/pull/1046
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Replaces the composer's staged-attachment full-width list rows with a
shared `AttachmentTile` grid: images render as thumbnails (using the
upload response's already-present `preview_url`), documents as an icon
pill labelled by extension, with media and documents banded separately.
Closes ERMAIN-690 for the composer surface only (the sent-message and
editor previews are explicitly deferred to a stacked follow-up).
Confirmed by reading the two most load-bearing pieces in full:

- **Component-kit override contract preserved, confirmed via
  `FileAttachmentsPreview.tsx`**: the `FileAttachmentsPreviewProps`
  interface itself is untouched by this diff — `showFileTypes`,
  `showFileSizes`, `filenameTruncateLength`, and `surfaceVariant` remain
  declared exactly as before. Confirmed the component body's destructuring
  simply stops reading several of them (`showFileTypes`, `showFileSizes`,
  `filenameTruncateLength`, `surfaceVariant`), with a doc comment stating
  the rationale precisely: the props stay as-is for kit compatibility even
  where the new tile-based rendering no longer needs them —
  `showFileSizes` never had a size to show (the API type carries none) and
  `filenameTruncateLength` is superseded by CSS truncation against the
  fixed tile width. A caller passing these props still compiles and is
  simply now ignored for the ones the tile doesn't use.
- **The `getAudioEnvironment` crash fix, confirmed exactly**: the
  previous guard only checked `typeof navigator !== "undefined"` before
  reading `navigator.userAgent`, which is insufficient in an embedded
  context (Storybook's iframe) where `navigator` exists but
  `navigator.userAgent` itself is `undefined` — that undefined value would
  reach `detectBrowserEngine` as a non-string, violating its documented
  contract. Confirmed the fix changes this to
  `globalThis.navigator?.userAgent ?? ""`, with a code comment explaining
  the deliberate `eslint-disable` (the DOM types declare both as always
  present, so the guard exists against observed runtime reality, not the
  type system).
- Per the PR (not independently re-verified given remaining scope): the
  new `AttachmentTile.tsx` (226 lines) and `AttachmentTileList.tsx` (151
  lines) implement the actual thumbnail/icon-pill tile and its
  media/document banding; the `ChatInput` Storybook stories previously
  rendered blank because the story built a partial provider stack missing
  `ProfileProvider`, fixed by promoting the app's `RootProvider` to a
  global Storybook decorator; and the e2e test diffs across
  `assistants.assistants.spec.ts`, `behaviour.basic.spec.ts`,
  `chat.basic.spec.ts`, and `mock-flows.many-models.spec.ts` update
  selectors/assertions to match the new tile-based DOM structure rather
  than testing new behavior.

## Compatibility and configuration

None functionally breaking for component-kit consumers: the props
interface is unchanged (confirmed above), so an existing kit override
passing the now-unused props continues to compile and simply sees those
specific knobs (file-type/size display, truncate length, surface variant)
no longer have a visible effect on the composer's staged-attachment
preview. No API or database changes.
