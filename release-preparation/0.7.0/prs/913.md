# PR #913: Add configuration change listener

## Summary

Adds a background task, `ConfigurationReloadListener`
(`backend/erato/src/services/configuration_reload_listener.rs`, new file),
that opens a Postgres `LISTEN`/`NOTIFY` connection
(`sqlx::postgres::PgListener`) on a channel named
`configuration_changed`, with exponential-backoff reconnection (starting
at 1s, capped at 60s) if the listener connection drops. Per its own doc
comment, "the listener is deliberately independent from configuration
loading for now. A notification only produces an info log; handling the
reload will be added in a follow-up" — i.e. this PR only logs
("Received configuration reload notification; reload is not implemented
yet") when a `NOTIFY configuration_changed` fires; it does not yet
actually reload or apply any configuration change. It is started in
`backend/erato/src/main.rs` only when `runtime_configuration.enabled` is
true (the same pre-existing flag gating the config-mirroring feature from
#897/#914), using the same database connection URL.

## Compatibility and configuration

No new configuration keys; reuses the existing
`runtime_configuration.enabled` flag to decide whether to start listening.
No migration (assumes some other component, not in this PR, will
eventually `NOTIFY` on the `configuration_changed` channel — not found in
this diff). No functional runtime behavior change yet: since reload
handling isn't implemented, this PR only adds a passive listener and its
log output; it doesn't change how the backend actually behaves in
response to configuration changes.
