# PR #1100: Move the popover family onto a shared panel primitive and themable shape channels

- PR: https://github.com/EratoLab/erato/pull/1100
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Third of nine styling-primitives-consolidation topics (after #1092, #1096).
Consolidates the popover family's geometry (dropdown menus, add menu,
filter menu, assistant-mention popover, delegation-run-mode popover) onto
a new shared `PopoverPanel` primitive and two shape attributes
(`data-popover-width`/`data-popover-position`), replacing inline `style`
objects and per-consumer Tailwind utilities no theme rule could reach.
Confirmed by reading the complete `globals.css` diff and the relevant
`AssistantMentionBackdrop.tsx` diff:

- **Guarded fallback correctly prevents a regression, confirmed exactly**:
  the shared row-radius rule changes from computing
  `max(0px, var(--theme-radius-dropdown) - var(--theme-spacing-dropdown-
  chrome-padding))` inline to reading `var(--dropdown-item-radius,
  max(0px, ...that same expression...))`, with `--dropdown-item-radius`
  declared once on `.anchored-popover-skin` — confirmed the fallback
  repeats the exact original expression verbatim (not a simplified or
  approximated version), matching the stated reason: `.btn-geometry-
  list-item` shares this selector but renders outside any popover, where
  nothing declares `--dropdown-item-radius`, so an unguarded `var()` read
  would silently compute to `0` and square `Button variant="list-item"`'s
  corners.
- **The popover `max-width` calc genuinely preserves the old hardcoded
  value, confirmed exactly**: `.anchored-popover-skin`'s `max-width:
  calc(100vw - 16px)` becomes `calc(100vw - (var(--theme-layout-
  dropdown-viewport-margin) * 2))`, and the token's default is confirmed
  unchanged at `8px` (`8px * 2 = 16px`) — matching the PR's own disclosed
  caveat that this is zero-delta only for themes that either explicitly
  set this key to `8px` or set no `layout.dropdown` block at all (both
  confirmed as the only two possibilities by the PR, not independently
  re-verified against actual theme JSON files).
- **The new shape-attribute rules, confirmed exactly present as
  described**: `[data-popover-width="min"|"content"|"wide"]` and
  `[data-popover-position="fixed"|"absolute"]` are declared inside
  `@layer components` (deliberately below the `.anchored-popover-skin`
  surface rule's layer, so a caller's own `w-*` utility still wins on
  width/position specifically, while the skin's background/border/shadow
  remain unlayered and un-overridable by a utility) — confirmed matching
  the PR's stated two-tier specificity design.
- **The one deliberate visible change, confirmed exactly via
  `AssistantMentionBackdrop.tsx`**: the composer's `@Name` mention pill
  gains `px-1` cancelled by an equal `-mx-1` on the same element — a code
  comment states precisely why padding alone can't be used: the highlight
  is a *mirror* (a div rendering the same text with transparent glyphs
  behind the real textarea), so any padding that widens the span's layout
  box would walk the mirrored glyphs out of alignment with the real ones;
  the padding/negative-margin pair gives the fill extra visual width
  without moving the span's layout advance.
- Per the PR (not independently re-verified given the very large
  remaining scope): the new `Controls/PopoverPanel.tsx` (180 lines)
  exports `PopoverPanel`/`PopoverChrome`/`PopoverSectionHeader`/
  `PopoverSeparator`/`resolvePopoverViewportPadding`, none of which portal
  (positioning/focus/dismissal stay in `AnchoredPopover`, stated as
  behaviorally untouched); five panels' duplicated `panelStyle`/
  `panelClassName`/`viewportPadding` props are removed at their call
  sites; `DropdownMenu`'s `dataUi` prop becomes public (defaulting to
  `"dropdown-panel"`, with the model selector now using
  `"model-selector-menu"`), correcting a documented bug where the
  Beckhoff fork theme's `[data-ui="dropdown-panel"]` rules only ever
  reached one of five popover menus — this PR's own naming of the model
  selector's panel is disclosed as making that existing fork-theme bug
  one menu wider, not introducing a new defect, with the actual fix
  deferred to the fork theme's own sync; and a new `--theme-layout-
  dropdown-wide-width` token (`20rem` default) replaces a hardcoded
  `w-80` at three call sites. The PR's own claimed verification
  methodology (text-diffing the compiled Tailwind stylesheet between this
  branch and `main`, at both the app build and the add-in's shipped
  `dist-library/style.css`, to confirm the change set is exactly five
  rule families and nothing else) was not independently reproduced, but
  the specific rules it claims resulted were each independently
  confirmed present and correctly formed in the `globals.css` diff read
  above.

## Compatibility and configuration

None functionally breaking, and the popover family itself is designed
and (per the PR) measured to ship with zero visual delta at stock, except
for the two caveats disclosed and confirmed above (the viewport-margin
calc's dependency on the `8px` default, and the Beckhoff fork theme's
`dropdown-panel` hook now missing one additional menu). The composer
mention pill's visible width increase (71.7px → 79.7px per the PR's own
measurements, not independently reproduced) is the one deliberate visual
change.
