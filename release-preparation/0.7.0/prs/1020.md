# PR #1020: Render tracked assistant mentions in sent user messages (ERMAIN-661)

- PR: https://github.com/EratoLab/erato/pull/1020
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Fixes a UI regression-shaped gap: the composer highlights `@Name` assistant
mentions while typing, but a sent message rendered the token as plain
prose — no read-side highlighting ever existed. Adds it end to end,
confirmed by reading the load-bearing backend and frontend pieces in
full:

- **Backend resolution, confirmed via `mod.rs`**: a new `MentionedAssistant
  {id, name}` type is added to `ChatMessage` as `mentioned_assistants:
  Vec<...>` with `skip_serializing_if = "Vec::is_empty"` — confirmed this
  makes existing payloads byte-identical for assistant messages and
  mention-less user messages, since the field is simply absent rather than
  an empty array. `resolve_mentioned_assistants_for_messages` batches one
  `get_assistant_names_by_ids` query across an entire page of messages
  (confirmed called once per `assemble_chat_messages_response`, not once
  per message), and confirmed it performs no per-assistant access check —
  a code comment states this mirrors the existing `RecentChat.assistant_name`
  precedent, since the containing chat was already authorized and the
  mentioned ids were validated at submit time. An id that no longer
  resolves (deleted assistant) is silently dropped via the `filter_map`
  over `names.get(&id)`, confirmed leaving its token as plain text on the
  frontend by construction (no pill data to match against).
- **SSE parity, confirmed via `message_streaming.rs`**: both emission
  sites — `bg_stream_save_user_message` (submit) and `edit_message_sse`
  (edit) — call the same new `ChatMessage::with_mentioned_assistants`
  single-message resolver before sending `UserMessageSaved`/
  `MessageSubmitStreamingResponseUserMessageSaved`, confirmed giving a live
  client the same resolved pairs the GET endpoint would serve, without a
  refetch. Confirmed the resolver degrades to no mentions on error
  (logged via `tracing::warn!`) rather than failing the stream.
- **Markdown-pipeline rewrite, confirmed via `MessageContent.tsx`**:
  `linkAssistantMentions` runs `findMentionRanges` — explicitly the same
  matcher the composer and submit path use, not a bare `@word` regex —
  over the raw text and rewrites each matched range into an
  `[text](erato-mention://<id>)` markdown link (escaping `[`/`]` in the
  token first, so a bracketed name can't break out of the link syntax),
  following the existing `autolinkEratoFiles` preprocessing precedent. The
  `a` component override intercepts the `erato-mention://` scheme and
  looks the id up in the message's own `mentionedAssistants` list;
  confirmed a hand-typed `erato-mention://` link for an id the message
  doesn't actually carry falls through to `<>{children}</>` (plain text),
  since only a match renders the pill (`<span>` styled with the composer
  backdrop's own theme tokens, `bg-theme-info-bg`/`--theme-info-border`).
  `urlTransform` is extended to also pass through the new scheme
  unmodified, alongside the pre-existing `erato-file://` exemption.
- **Assistant messages never highlight, confirmed via `ChatMessage.tsx`**:
  `mentionedAssistants={isUser ? message.mentioned_assistants : undefined}`
  — passed only for user messages, with a code comment stating the design
  rationale directly: an assistant echoing "@Name" is quoting, not
  addressing.
- Per the PR (not independently re-verified given remaining scope): the
  optimistic-echo/send-chain wiring (`ChatInput.tsx`, `useChatActions.ts`,
  `useChatMessaging.ts`, `handleUserMessageSaved.ts`) carries the
  composer's already-resolved `{id, name}` pairs into the just-sent
  message immediately and preserves them across the temp→real message-id
  swap, so the highlight is present from the first frame rather than
  waiting for a round trip; and the Outlook add-in's own composer/message
  core (`AddinChatCore.tsx`, `AddinChatInputCore.tsx`,
  `AddinChatInput.tsx`) is wired through the same mechanism.

## Compatibility and configuration

None. Additive, `skip_serializing_if`-guarded API field (confirmed
existing payloads for assistant messages and mention-less user messages
are byte-identical) plus a new OpenAPI schema entry (`MentionedAssistant`).
No configuration change; the composer's mention-tracking mechanism
(`findMentionRanges`, `mentioned_assistant_ids`) already existed and is
reused as-is, not altered.
