# PR #905: Generate serve.json maps; Enforce via E2E tests

- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Adds a new script, `scripts/generate-served-routes.mjs` (272 lines), that
parses the React Router route definitions directly out of
`frontend/src/App.tsx` and `office-addin/src/main.tsx` and generates the
corresponding SPA-fallback rewrite rules into `frontend/serve.edited.json`
and `office-addin/public/serve.json` respectively. This replaces
hand-maintained rewrite-rule files, which could drift out of sync with the
actual router (e.g. a new route added to `App.tsx` but forgotten in the
serve-config rewrites, causing a hard page refresh on that route to 404
instead of correctly falling back to the SPA's `index.html`). CI now runs
`node scripts/generate-served-routes.mjs --check` (new step in
`.github/workflows/docker-build.yml`) to fail the build if the checked-in
`serve.json`/`serve.edited.json` files don't match what the script would
generate from the current routes. A new E2E test file,
`e2e-tests/tests/served-pages.basic.spec.ts`, verifies that requesting a
genuinely missing asset (e.g. `/chat/missing.js`) still correctly returns
`404` (not silently rewritten to the SPA document) and that Office add-in
pages are served correctly when that bundle is enabled.

## Compatibility and configuration

No configuration keys or migrations. There is a genuine backend bug fix
bundled in here, not just tooling: `matches_rewrite_rule` in
`backend/erato/src/frontend_environment.rs` previously could match a
dynamic SPA rewrite rule (e.g. `/chat/:id` → `index.html`) against a
request for a missing static asset with a dot in its last path segment
(e.g. `/chat/missing.js`), rewriting it to serve `index.html` with a `200`
instead of a proper `404`. The fix adds an early return: if the request
path's last segment has a non-empty extension, the rewrite rule never
matches, so such requests fall through to a real `404`. A related helper,
`frontend_relative_path`, was also extracted/hardened to consistently
slash-prefix the mount-relative path (covered by a new unit test). This
matters for correctness of client/crawler/observability tooling that
distinguishes real 404s from page navigations, and is exercised directly
by the new `served-pages.basic.spec.ts` E2E test.
