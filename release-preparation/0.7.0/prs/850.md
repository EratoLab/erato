# PR #850: Cover the message-edit path before the in-place editor lands

- PR: https://github.com/EratoLab/erato/pull/850
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Primarily a test-coverage/cleanup PR (ahead of a planned ERMAIN-471
inline-edit refactor), but the diff includes two small, real bug fixes
not mentioned anywhere in the PR description, both confirmed by reading
the code:

1. **Add-in edit-identity extraction is behavior-preserving**, as the PR
   claims: the logic that anchors an edited exchange's wrong-item guard on
   the *original* exchange's send-time item identity (never the
   currently-open mail item) is extracted verbatim from
   `AddinChat.handleEditSubmit` into a new pure function,
   `resolveEditExchangeItemIdentity` (`exchangeItemIdentity.ts`), with the
   call site now delegating to it — confirmed line-for-line identical
   logic, just relocated so a later UI refactor (moving the edit call
   site) doesn't disturb this correctness rule. Five new unit test cases
   are added, including the load-bearing one the PR calls out: an edit
   must never pick up a *later* exchange's identity.
2. **An undisclosed real bug fix in `ChatInput.tsx`**: a new early-return
   guard (`if (previousModeRef.current !== "compose") return;`) is added
   to the compose-draft-persistence effect. Per the added code comment,
   without this guard, on the render where the composer leaves edit mode,
   `message` still holds the edit draft's text, and this persistence
   effect (which runs before the sibling effect that actually restores the
   compose draft) would write that edit text into the compose draft store
   — which the restore effect then immediately reads back, corrupting the
   chat's saved compose draft with leftover edit text. This fix is not
   mentioned in the PR title, description, or any commit message text
   available in this diff; it was found only by reading the diff directly
   rather than trusting the description's "test coverage" framing.
3. **Dead/flaky E2E test replacement**: the old `edit-message.basic.spec.ts`
   is deleted (483 lines) and replaced with `edit-message.many-models.spec.ts`
   (139 lines). Per the PR, the old spec was pure CI dead weight — all
   four tests carried `test.skip(!!process.env.CI, ...)`, so even the two
   `@ci`-tagged tests CI selects were immediately skipped and *nothing
   actually ran*; it also ran against the `basic` scenario (a real
   `gpt-4o-mini` call, not a mock), whose latency/variability caused the
   original flakiness driving the skip; and its truncation test accepted
   either truncated-or-full-preservation as passing, so it couldn't
   actually catch the ERMAIN-469 regression it was nominally testing. The
   new spec runs against the Mock-LLM `many-models` scenario with no
   skips, and adds one new, deliberate assertion: an edit request must
   **omit `action_facet`**, pinning that the backend's stored-facet
   fallback (#803) is relied on rather than the composer's currently-live
   facet selection leaking into an edit of a different context. The
   truncation test itself is dropped as now covered by #849's
   `edit-regenerate-lineage` spec. Several now-orphaned shared test
   helpers (`waitForMessageIdsToStabilize`, `chatIsReadyToEditMessages`,
   `waitForEditToComplete`, `waitForEditModeToEnd`, `browserCapabilities`)
   are removed from `shared.ts`.

## Compatibility and configuration

None. The add-in extraction is explicitly behavior-preserving. The
`ChatInput.tsx` fix corrects a real (if narrow) draft-corruption bug: no
configuration or API changes either way.

## Release note disposition

Proposed category: Bug fixes. The `ChatInput.tsx` draft-corruption fix is
minor but real and worth a brief mention: canceling or completing a
message edit no longer risks corrupting that chat's saved compose draft
with leftover edit text. The E2E/test cleanup and the add-in extraction
are not independently user-visible.
