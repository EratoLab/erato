# PR #1345: Let the user choose between several Word Replace versions (ERMAIN-940)

- PR: https://github.com/EratoLab/erato/pull/1345
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: Word selection editing

## Summary

Per the PR description: fixes the Word Replace feature (built up over
this batch) when one assistant answer contains several `erato-word-
replace` fenced blocks — previously each block rendered its own review
card with no awareness of the others, so applying one version made
Replace on a sibling version fail with the generic "passage changed"
copy and get permanently stuck, even after undoing the first version.
Confirmed directly: `wordSelectionEdit.ts` gains `countWordReplaceFences`
(detecting more than one `erato-word-replace` block in an answer) and
`wordReviewState.ts` gains a new `refusedForSibling` flag on review state,
with a code comment confirming the intent described in the PR: "The card
stays idle, so it can be replaced once that version is undone." Per the
PR's description (not independently verified beyond the two files above):
while a sibling version from the same answer currently holds the
passage, the other cards now say so and point to that version's Undo (or
Word's Reject under Track Changes), dropping "Ask again" only while that
Undo path still works in Erato — once it's ended, refused, unavailable,
or under Track Changes, the card instead points to Word's native Undo/
Reject and keeps "Ask again" available. A version written onto a
user-picked copy (via #1338's "Replace selected passage") no longer
blocks other versions' own pick flow. With multiple blocks present, no
version auto-applies under an "Always allow" policy and no confirmation
opens unprompted. An undone version can be replaced again. Identical
versions continue sharing one review (one shared key), keeping their
state consistent.

## Compatibility and configuration

Bug fix to the Word Replace feature introduced earlier in this batch; no
config keys, no database migration. Behavior for a single-block answer is
unaffected; the fix only changes how multiple review cards in one answer
interact with each other.
