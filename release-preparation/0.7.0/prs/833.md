# PR #833: Fix chat-history dropdown overflow and double scrollbar (ERMAIN-464)

- PR: https://github.com/EratoLab/erato/pull/833
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Fixes opening the "⋯" context menu on the last chat item in the history
sidebar overflowing the viewport and sometimes producing two scrollbars.
Three root causes, all confirmed fixed by reading the code:

1. `AnchoredPopover` positioned its portaled panel in a post-paint
   `useEffect`, so a bottom-anchored panel briefly painted at its
   unclamped natural height past the viewport bottom before being
   repositioned — adding a document-root scrollbar for one frame. Fixed
   by moving positioning into `useLayoutEffect` (runs before paint) and
   keeping the panel `visibility: hidden` (via a new `isPositioned` state
   flag) until `updatePosition()` has run once, only then revealing it.
2. `maxHeight` was applied to the outer popover panel, but the actual
   scrollable content was a non-flex inner child, so a menu taller than
   its clamped max-height clipped or overflowed instead of scrolling
   internally. Fixed in `DropdownMenu`: the panel is now `flex flex-col`
   (owning `max-height`), and the inner item list is
   `min-h-0 flex-1 overflow-y-auto overscroll-contain` so it scrolls
   within the panel.
3. `ChatHistoryList`'s own wrapper had a redundant `overflow-y-auto` in
   addition to the sidebar's own scroll container, which could
   independently produce a second scrollbar in edge cases; removed,
   leaving the sidebar wrapper as the single scroll owner.

All three fixes land in the shared `AnchoredPopover`/`DropdownMenu`
primitives rather than the chat-history call site specifically, so every
consumer of these shared dropdown components benefits, per the PR.

## Compatibility and configuration

None. Pure frontend visual/layout bug fix; no configuration or API
