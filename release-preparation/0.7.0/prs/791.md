# PR #791: Fix feedback <-> trace correlation in Langfuse OTEL

- PR: https://github.com/EratoLab/erato/pull/791
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: Observability / Langfuse tracing

## Summary

Fixes a bug in `backend/erato/src/services/langfuse.rs` where, when Langfuse
tracing is configured to use OTEL transport
(`langfuse.use_otel = true`), a submitted feedback score's `traceId`
did not match the trace's actual OTEL-derived trace ID. `LangfuseClient::create_score`
previously always sent the raw Langfuse `trace_id` (e.g.
`"trace_58406520a006649127e371903a2de979"`) as-is in the score's `traceId`
field. Traces themselves, when `use_otel` is enabled, are recorded under an
OTEL-format trace ID derived from that Langfuse ID via
`trace_id_from_langfuse_id` (hashed/truncated hex, no `trace_` prefix, e.g.
`"58406520a006649127e371903a2de979"`). Because the score and the trace used
different ID formats, Langfuse could not associate a submitted feedback
score with its originating trace when OTEL mode was active. A new helper,
`score_trace_id_for_transport`, now converts the trace ID through
`trace_id_from_langfuse_id` before attaching it to the score when
`use_otel` is true, and leaves it unchanged (raw Langfuse ID) when
`use_otel` is false. Two unit tests were added/extended
(`sends_score_with_otel_trace_id_when_otel_enabled` and an assertion on the
existing non-OTEL score test) confirming both code paths.

## Compatibility and configuration

No configuration keys added or changed; this only affects internal Langfuse
score submission behavior when `langfuse.use_otel = true` (an existing
config flag, not introduced by this PR). No migration. Deployments that use
Langfuse tracing with `use_otel` enabled and rely on feedback scores being
correlated to their traces in the Langfuse UI would see this correlation
break (before) or work correctly (after) this fix; deployments not using
`use_otel`, or not using Langfuse at all, are unaffected.
