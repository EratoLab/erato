# PR #872: Add desktop-sidecar distribution page

- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Desktop Sidecar for local sources

## Summary

Implements the backend artifact-serving and frontend download UI for the
desktop-sidecar distribution contract specified in #860. New backend
service `backend/erato/src/services/desktop_sidecar_distribution.rs` (410
lines, not read in full) loads and validates the distribution
`manifest.json` and its declared per-platform artifacts (Windows/macOS/
Linux installers) from a configured directory at startup; per the docs,
"invalid or missing manifests and artifacts are logged and the
distribution remains unavailable instead of exposing a partial artifact
set." `backend/erato/src/server/api/v1beta/desktop_sidecar.rs` gains new
endpoints (270-line diff) presumably to list available targets/artifacts
and download them. A new frontend page,
`frontend/src/pages/DesktopSidecarSetupPage.tsx` (408 lines), presents the
download UI, using a new `frontend/src/lib/desktopSidecarPlatform.ts`
helper (with its own test file) to detect the visiting user's OS/platform
and offer the matching installer/target.

## Compatibility and configuration

Two new configuration keys under `desktop_sidecar.distribution`
(`backend/erato/src/config.rs`, `DesktopSidecarDistributionConfig`):
- `desktop_sidecar.distribution.enabled` — defaults to `false`. Must be
  explicitly enabled; when disabled, the download page/artifact API is
  unavailable (no default behavior change for existing deployments).
- `desktop_sidecar.distribution.directory` — defaults to
  `/app/desktop-sidecar-artifacts`, matching the contract documented in
  #860. Must contain exactly one `manifest.json` plus every artifact it
  declares.

No migration. Purely additive and opt-in; deployments that don't set
`desktop_sidecar.distribution.enabled = true` (and don't populate the
artifact directory) see no change. This is the first PR in the Desktop
Sidecar theme that ships an actual user-facing surface (a download page),
though it still depends on an operator having built/placed sidecar
installer artifacts, which is outside the scope of this repository/PR.
