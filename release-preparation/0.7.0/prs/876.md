# PR #876: Layer sendFirstMessage failure diagnosis; widen mcp-auth first-response margin

- Theme: None

## Summary

E2E test-reliability-only change; confirmed by diff stat that only test
spec files and the shared E2E helper module are touched, no product code.
Hardens the shared `sendFirstMessage` helper (used by ~15 first-send
tests) to fail with a specific, diagnosable error instead of a generic
timeout: asserting the submitstream response is `ok()` before pressing
Enter, checking the optimistic user-message bubble actually appears (its
absence indicates the client silently dropped the send), and racing
navigation against a `chat-send-error` event so an explicit send failure
throws with the actual error text rather than surfacing as an opaque 15s
URL-navigation timeout. Separately, widens `mcp-auth`'s first-assistant-
bubble wait margin from the 5s default to the 15s margin its sibling
assertions already use, described as the source of recent
retry-recovered firefox flakes in that spec.
