## Summary

Small, fully verified fix. `OAUTH2_PROXY_SESSION_SCOPES` (the scopes
requested for the Layer-1 bootstrap token redeemed into the oauth2-proxy
session) previously requested only `User.Read`; confirmed the diff adds
`openid`, `profile`, and `email` to the array, matching the PR
description exactly. A code comment notes Entra can still omit the email
claim even when requested, so downstream consumers must continue to
handle its absence.

## Compatibility and configuration

None. Pure Outlook add-in authentication scope change; no API or
configuration changes. Widens the requested OIDC scopes so the ID token
more reliably carries the user's email claim when Entra provides it.
