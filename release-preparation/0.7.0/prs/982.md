# PR #982: Listing surface: hide delegated runs by default, provenance on RecentChat (ERMAIN-623)

- PR: https://github.com/EratoLab/erato/pull/982
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Delegation

## Summary

Fifth and final layer of the delegation stack (on top of #978–#981): the
read side, making delegated child-run chats invisible in normal listings
by default while remaining queryable and reachable where they need to be.
Confirmed by reading the full `models/chat.rs` diff:

- `RecentChatsFilter` gains `include_delegated: bool` (default `false`,
  exposed as a new `include_delegated` query parameter on
  `GET /me/recent_chats`); when `false`, both the listing and count SQL
  queries add a condition excluding any chat whose provenance kind is
  `delegation` (`assistant_configuration #>> '{provenance,kind}' IS
  DISTINCT FROM 'delegation'`), confirmed composed correctly alongside
  the pre-existing `include_archived`/`type`/`q`/`pinned` filter
  conditions in both the page query and its paired count subquery.
- `RecentChat` gains `provenance_kind`, `origin_chat_id`,
  `origin_chat_title`, and `origin_assistant_id`, all optional —
  confirmed the design deliberately exposes the raw provenance kind
  string rather than a boolean "is delegated" flag, so a client derives
  delegation status from the kind rather than a separate, potentially-
  drifting flag.
- **Confirmed the title-leak guard precisely**: origin chat titles are
  resolved via a batch lookup that explicitly filters
  `chats::Column::OwnerUserId.eq(owner_user_id)` — i.e. scoped to chats
  owned by the *same* user making the request. The code's own comment
  states this is forward-looking hardening: today's delegation feature
  guarantees a child chat's owner always equals its origin chat's owner,
  so the filter is currently redundant, but it prevents a *future*
  cross-user provenance kind (e.g. a handoff feature) from accidentally
  turning this lookup into a mechanism for reading another user's chat
  title. A deleted origin chat (no foreign key, per #979's design)
  correctly yields no title rather than an error, since the batch lookup
  simply finds nothing for that id.
- `get_frequent_assistants` is confirmed to exclude delegated runs (not
  independently re-traced in the diff beyond confirming the PR's
  description, but consistent with the general pattern of hiding
  delegated-run noise from ranking/listing surfaces), so a spawned side-run
  chat doesn't skew the assistant-picker's frequency ranking.
- **Confirmed `/me/generating` (`get_generating_chats`) is genuinely
  untouched by this PR** — no diff hunk in `models/chat.rs` modifies that
  function at all, directly confirming the stated design: a delegated
  child that's still running, or parked `awaiting_approval` (from #918),
  remains reachable via `/me/generating` even though it's invisible in
  normal chat listings — since a maintainer/operator or the delegation
  runtime itself may still need to observe or act on it. This is a
  deliberate omission rather than a special-cased inclusion, verified by
  its literal absence from the diff.

## Compatibility and configuration

None new beyond the existing `[assistants.delegation]` gate from #978 —
this layer is purely additive read-side surface. `GET /me/recent_chats`
gains a new optional `include_delegated` query parameter, defaulting to
`false` (matching current behavior for any existing client that doesn't
pass it). `RecentChat`'s new fields are all optional and simply `null`
for any non-delegated chat, so no existing client parsing this response
needs to change.

## Release note disposition

Proposed category: Features and enhancements — completes the delegation
stack (#978–#982). Worth one combined, clear release-note entry covering
the whole feature: the assistant can now delegate part of a task to
another @-mentioned assistant within the same chat (a bounded, awaited
sub-task, one level deep, with its own timeout), and the resulting
delegated-run chats stay out of the normal chat history and
frequently-used-assistants listings by default.
