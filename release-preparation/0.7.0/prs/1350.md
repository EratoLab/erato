# PR #1350: Tell users which Outlook setting limits how far back mail is indexed (ERDSCAR-51)

- PR: https://github.com/EratoLab/erato/pull/1350
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Sidecar source capabilities (new Outlook for Mac/Windows parity, foundation)

## Summary

Per the PR description: the Desktop Sidecar only indexes what Outlook
itself keeps cached on-device, so each store's own "offline window"
setting silently caps how far back indexed search/chat context can
reach — the PR cites a concrete example of 132 of 631 emails being
dropped under new Outlook for Mac's 60-day default. This surfaces that
constraint to the user instead of leaving it invisible: the indexing
settings' per-source detail now names the specific Outlook setting that
controls the window and where to find it, differing by store — "Download
email for the past" (classic Outlook for Windows, OST, via Account
Settings), "Days of email to save" (new Outlook for Windows Settings,
up to 180 days), and "Days of mail to sync" (new Outlook for Mac
Settings, up to 180 days). Confirmed directly in `outlookStores.ts`: a
new `outlookMailWindow()` function maps a store/source kind to one of
three `OutlookMailWindow` variants, explicitly returning `null` (no hint
shown) for a PST or legacy Outlook for Mac — both of which, per a code
comment, already hold all mail locally and have no such limiting
setting. Per the PR (not independently verified beyond the function
above): the exact setting labels/paths were sourced from Microsoft's own
support documentation and from strings found in an installed Outlook for
Mac 16.113, and the de/es/fr/pl translations use Outlook's own localized
label text where it could be confirmed, falling back to a descriptive
(non-quoted) phrasing — specifically for the classic Windows slider —
where it couldn't.

## Compatibility and configuration

Pure UI/copy addition; no config keys, no database migration, no
protocol change. Purely informational — doesn't change what the sidecar
indexes, only explains an existing limitation the user can act on in
Outlook's own settings.

## Evidence and review

Verified via this PR's merge commit against its parent (both present
locally). Confirmed directly: the `outlookMailWindow()` function and its
PST/legacy-Mac `null` exception in `outlookStores.ts`, matching the PR

fact-checked against Microsoft's current UI.
