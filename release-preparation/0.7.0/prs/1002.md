# PR #1002: Make replicaCount for oauth2Proxy configureable in Helm chart

- PR: https://github.com/EratoLab/erato/pull/1002
- Status: pending
- Category: Features and enhancements
- Theme: None

## Summary

Adds a new `oauth2Proxy.replicaCount` Helm value (default `1`, matching
the previous hardcoded value) to
`infrastructure/charts/erato/templates/oauth2-proxy-deployment.yaml`'s
`spec.replicas` (previously hardcoded to `1`). The chart's README is
updated with guidance: all OAuth2 Proxy replicas share the same
chart-managed Redis session store when `oauth2Proxy.redis.enabled` (an
existing setting); that chart-managed Redis is explicitly documented as a
"single-instance session store, not an HA Redis deployment" — operators
needing HA session storage should disable the chart-managed Redis
(`oauth2Proxy.redis.enabled: false`) and point `oauth2Proxy.config` at
their own external Redis. New Helm unit tests cover both the custom
replica count and the external-Redis-configuration-preserved scenario.

## Compatibility and configuration

New value, defaulting to `1` — no behavior change for existing chart
users. To scale oauth2-proxy horizontally:
```yaml
oauth2Proxy:
  replicaCount: 2
```
No migration. Documented caveat worth surfacing to operators: scaling
oauth2-proxy replicas while relying on the chart's own bundled Redis does
not provide session-store high availability (a single Redis instance
remains a single point of failure for sessions even with multiple
oauth2-proxy replicas).
