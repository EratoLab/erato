# PR #1260: Record where chats were created and filter the chat list by source

- PR: https://github.com/EratoLab/erato/pull/1260
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

A follow-up completing the Teams-bot cluster (#1253/#1254): records which
surface created each chat and lets the chat list be filtered by it.
Confirmed the backend column, its check constraint, the historical
backfill logic (including the Teams-bot-vs-tab disambiguation and the
delegation-chain root-inheritance), and the query-filter parsing with
high precision by reading the full migration and the relevant route
code directly:

- **New `created_via` column with the exact enumerated values, default,
  and constraint, confirmed exactly**: migration 0054 adds `created_via
  text NOT NULL DEFAULT 'legacy' CHECK (created_via IN ('legacy', 'web',
  'outlook', 'word', 'office_addin', 'ms_teams_tab', 'ms_teams_bot'))` —
  matching the PR's list verbatim, in the same order.
- **Backfill maps historical platform values correctly, including the
  disclosed early-Outlook-build quirk, confirmed exactly**: the backfill
  CTE reads each chat's earliest assistant message's
  `generation_parameters.request_context.platform` and maps `'web'` →
  `web`; `'outlook'`, `'PC'`, `'Mac'`, `'OfficeOnline'` → `outlook` (with
  an inline SQL comment "Early Outlook add-in builds sent the Office
  runtime platform instead" — directly explaining why three OS/runtime
  literals map to the Outlook surface); `'word'` → `word`;
  `'addin-neutral'`, `'office-addin'` → `office_addin`; and `'teams'`
  splits further (below) — everything else defaults to (stays)
  `'legacy'` via the `ELSE` branch. Matches "Migration `0054` backfills
  existing chats from the platform on their first assistant message" and
  "Everything else stays `legacy`" exactly.
- **Bot-vs-tab Teams disambiguation, confirmed exactly, via the two
  named signals**: a `'teams'`-platform chat is classified `ms_teams_bot`
  only if it's still linked via `ms_teams_conversations.current_chat_id`
  **or** has an attached file named exactly `teams-conversation-context.md`
  — otherwise it falls to `ms_teams_tab`. Matches "Bot chats are
  recognised by their `ms_teams_conversations` link or the
  `teams-conversation-context.md` file. Other Teams chats count as the
  tab" precisely.
- **Delegated runs inherit from the root of their chain, bounded, with
  the disclosed missing-origin fallback, confirmed exactly**: a separate
  recursive CTE walks `origin_chat_id` through up to 64 levels of
  delegation-provenance chats to find the first non-delegation ancestor,
  then copies that ancestor's (already-backfilled, since the first
  UPDATE explicitly excludes delegation chats) `created_via` onto every
  chat in the chain. A chain whose root can't be resolved (gone, or
  exceeding the depth bound) simply never matches the `roots` CTE and
  keeps the column's `'legacy'` default — matching "Delegated runs
  inherit from the root of their delegation chain. A chain whose origin
  chat is gone stays 'legacy'" exactly.
- **Comma-separated filter parsing with unknown values rejected as 400,
  confirmed exactly**: the new `parse_created_via_list` splits on comma,
  trims, skips empty segments, and maps each through
  `ChatCreatedVia::parse`, returning `StatusCode::BAD_REQUEST` the
  instant any segment fails to parse — matching "Takes comma-separated
  `created_via` and `exclude_created_via` filters... Unknown values
  return 400" exactly; both query parameters are documented on
  `/me/recent_chats`'s OpenAPI annotation with the stated "Composes with
  `created_via`" relationship for the exclude variant.
- **`created_via` returned on both the listing and the single-chat read,
  confirmed exactly**: `RecentChat.created_via: ChatCreatedVia` and
  `ChatDetail.created_via: ChatCreatedVia` are both added as required
  (non-optional) fields — matching "Returns `created_via`, as does `GET
  /me/chats/{chat_id}`" exactly, for both named endpoints.
- Per the PR (not independently re-verified given remaining scope): the
  claim that "HTTP chats map `X-Erato-Platform`" and that "`POST
  /me/chats` now reads it too" and "`teams` over HTTP is always the tab"
  (the live, non-backfill creation-time stamping logic, in the 20-line
  `message_streaming.rs` diff and the new `platform_from_headers`
  function now exported, not traced to its call sites); "The Teams bot
  creates its chats as `ms_teams_bot`" (one line in `ms_teams_bot/host.rs`,
  not read); the new frontend `CHAT_CREATED_VIA_SOURCES` environment
  value and its derivation from enabled integrations
  (`frontend_environment.rs`'s 63-line diff); the entire frontend/add-in
  "Source" filter-menu UI (`ChatHistoryFilterMenu.tsx`'s 220-line diff,
  `chatHistoryFilterStore.ts`'s 271-line diff, and the per-surface
  persistence/migration-of-old-stored-filters behavior); the claim that
  silent chat creation (file drops, file sources, recordings) now sends
  `X-Erato-Platform`; and the disclosed follow-up caveat that personal
  bot chats replaced by `/new` before this migration can't be
  distinguished from tab chats and will show under "Teams" alongside
  them, plus the disclosed `frequent_assistants` scope exclusion (it
  still counts chats from every source, unaffected by this filter).

## Compatibility and configuration

Additive database migration (sqitch 0054) with a safe, non-null default
(`'legacy'`) and a one-time backfill — no behavior change for any
existing chat beyond gaining a classification value. New, optional,
comma-separated query parameters on `/me/recent_chats`
(`created_via`/`exclude_created_via`); omitting them preserves existing
behavior. No new index added, per the PR's own disclosed reasoning that
the listing already scans the owner's chats to sort them (not
independently verified against a query plan).

## Release note disposition

Proposed category: Features and enhancements, naturally grouped with
the Teams bot feature (#1253/#1254) but of independent value to any
multi-surface deployment (Outlook, Word, Office add-in, Teams, web).
Worth a release-note mention on its own: the chat history list (web and
add-ins) can now be filtered to show or hide chats by the surface that
created them — including distinguishing Teams tab conversations from
Teams bot conversations — with existing chats classified from their
earliest message where possible and otherwise marked as a generic
pre-existing ("legacy") chat.
