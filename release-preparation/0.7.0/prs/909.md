# PR #909: Add alternative 5 star rating system for assistant hub

- PR: https://github.com/EratoLab/erato/pull/909
- Status: pending
- Category: Features and enhancements
- Theme: Assistant Hub and assistant sharing

## Summary

Adds a new configuration key, `assistant_hub.rating_mode` (string,
`"5_stars"` or `"10_stars"`, validated at startup, defaulting to
`"10_stars"`), controlling how the Assistant Hub review score (added in
#785, always a 1–10 integer) is *displayed and entered* by users. Scores
continue to be persisted and averaged on the underlying 10-point scale
regardless of `rating_mode` — this is purely a display/input
transformation. New helpers in `frontend/src/pages/assistantHubUtils.tsx`:
`getAssistantHubDisplayScore` (divides the stored score by 2 for
`"5_stars"` mode) and `getAssistantHubStoredScore` (multiplies a 5-star
display value by 2 to get the stored 1–10 score), plus
`getAssistantHubRatingScale` (returns `5` or `10`).
`getAssistantHubRatingLabel`, `AssistantHubVersionCard`, and
`AssistantHubVersionOverviewSection` all take a new optional `ratingMode`
prop and render the scaled score (e.g. "4.0 / 5 (3 ratings)" instead of
"8.0 / 10 (3 ratings)"). `frontend/src/pages/AssistantHubDetailPage.tsx`
(167-line diff, not fully reviewed) presumably updates the score-entry
star widget to show 5 stars (each representing 2 points) when in
`"5_stars"` mode.

## Compatibility and configuration

New optional key:
```toml
[assistant_hub]
rating_mode = "10_stars"  # or "5_stars"
```
Defaults to `"10_stars"`, matching the existing (pre-#909) behavior — no
change for deployments that don't set it. Invalid values other than
`"5_stars"`/`"10_stars"` cause a startup validation error. No migration;
no change to how scores are stored (still 1–10 integers in
`assistant_hub_reviews.score`), only how they're presented and how a
user's star-click input is converted back to the stored scale.
