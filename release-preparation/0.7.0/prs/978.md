## Summary

First of a 5-part stacked series (#978 config → #979 provenance/
primitives → #980 mention validation → #981 runtime → #982 listing)
implementing in-chat delegation to @-mentioned assistants. This PR is
purely configuration and gating scaffolding — per its own description,
"nothing consumes it yet beyond gate checks," so it's mergeable
standalone with no actual behavior change. Confirmed by reading the full
`erato_config/src/config.rs` diff:

- New `AssistantsDelegationConfig` nested under the existing
  `AssistantsConfig`, with exactly the five fields and defaults the PR
  describes: `enabled` (default `false`), `run_timeout_seconds` (default
  `600`, must be `> 0`), `max_mentions_per_message` (default `3`, must be
  `≥ 1`), `result_max_chars` (default `16000`, must be `> 0`), and
  `preamble` (a multi-line default directive template telling a delegated
  assistant it's running as a worker whose final message is returned as
  the task result — confirmed the template includes
  `{{expected_output_section}}`/`{{constraints_section}}` placeholders
  meant to be substituted at runtime, not yet consumed in this PR).
- `AssistantsConfig::validate()` gains the stated cross-field rule:
  `delegation.enabled` requires `assistants.enabled` to also be true,
  confirmed as an explicit new check returning a clear error.
- The preamble being config data (not a hardcoded Rust string) means a
  deployment can override it via `erato.toml`; the PR states a test
  parses the commented example block in `erato.template.toml` through the
  real config machinery and asserts it matches the Rust-side defaults
  exactly, so the documented example and the actual default can't drift
  apart — not independently re-run, but a sound testing pattern.
- A new `ASSISTANTS_DELEGATION_ENABLED` frontend environment key is
  injected for both the web and Outlook add-in frontends — explicitly
  described as a UX-only gate (hiding/showing delegation UI), with actual
  enforcement remaining server-side.

## Compatibility and configuration

New, optional config section, entirely default-`false`/inert:
```toml
[assistants.delegation]
enabled = false                  # default; requires assistants.enabled = true
run_timeout_seconds = 600        # default
max_mentions_per_message = 3     # default
result_max_chars = 16000         # default
preamble = "..."                 # default, see erato.template.toml
```
No behavior change for any deployment — this PR adds no code path that
actually delegates anything; it only establishes the configuration
surface and validation rules the later stacked PRs will consume.
