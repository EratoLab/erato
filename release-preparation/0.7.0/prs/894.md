## Summary

Pure internal refactor: moves `backend/erato/src/config.rs` (99%
similarity per the diff, i.e. content essentially unchanged),
`config_facet_attrs.rs`, `config_reference.rs`, and `startup_log.rs` into
a new workspace crate, `backend/erato_config/` (added to
`backend/Cargo.toml`'s workspace members). The main `erato` crate's
`lib.rs` now re-exports these as `pub use erato_config::config`, `pub use
erato_config::config_facet_attrs`, etc., so existing code that references
`crate::config::...` throughout the codebase continues to compile
unchanged. The one substantive relocation: the
`CLIENT_ACTION_TOOL_NAME` constant, previously defined in
`backend/erato/src/services/client_actions.rs` and referenced from
`config.rs` via `crate::services::client_actions::CLIENT_ACTION_TOOL_NAME`,
is now defined directly in `erato_config::config` (since the new crate
cannot depend back on `erato`'s services module) and `client_actions.rs`
now re-exports it (`pub use erato_config::config::CLIENT_ACTION_TOOL_NAME`)
so its own external callers are unaffected.

## Compatibility and configuration

No configuration keys, defaults, or runtime behavior changed — this is a
crate-boundary reorganization intended to reduce compile times or
dependency coupling (not stated in the PR, inferred from the nature of the
change) ahead of further config-related work this cycle (e.g. #897, #914,
#988 "distribution structure"). No migration; purely internal to the Rust
workspace structure.
