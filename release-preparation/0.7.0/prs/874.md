# PR #874: Move profiling image build into manual triggered job

- PR: https://github.com/EratoLab/erato/pull/874
- Status: pending
- Category: Chores & Developer experience
- Theme: None

## Summary

Moves the `build-and-push-profiling-linux` job (which builds and pushes
`erato/backend:*-profiling` and `erato/app:*-profiling` images, built with
`ERATO_FEATURES=profiling`) out of `.github/workflows/docker-build.yml` —
where it previously ran automatically as part of every regular Docker
build (`needs: [build-and-push-amd64]`) — into a new, separate workflow
file `.github/workflows/docker-build-profiling.yml`, triggered only
manually via `workflow_dispatch` with a required `git_sha` input ("the
matching amd64 frontend image must already exist"). Profiling images are
no longer built on every push/release; they must be requested explicitly
for a specific already-built commit SHA.

## Compatibility and configuration

No runtime configuration keys or migrations; this is a CI/build-pipeline
change only. Operationally: profiling-tagged images
(`*-profiling` tags on `erato/backend` and `erato/app`) will no longer be
automatically published for every commit/release going forward — anyone
relying on a profiling image being available for a given tag without
manually triggering the new workflow would need to trigger it explicitly.
