# PR #1242: Extend sidecar protocol with "open data directory" command

- PR: https://github.com/EratoLab/erato/pull/1242
- Status: pending
- Category: Features and enhancements
- Theme: Desktop Sidecar for local sources

## Summary

Adds `sidecar.open_data_directory.v1` to the desktop-sidecar protocol
(no params, returns `{opened: boolean}`) and wires it into the desktop
sidecar settings tab UI (from #916):
`DesktopSidecarTabContent.tsx` now shows an "Open data directory" button
(only when connected and the sidecar advertises support for this method)
that invokes it and shows an inline error ("Could not open the sidecar
data directory.") if the call fails. This lets a user open the sidecar's
local data/index storage location in their OS file browser directly from
the Erato settings dialog, for troubleshooting or inspection, without
needing to know or navigate to the path manually.

## Compatibility and configuration

No backend/frontend configuration keys or migrations. Purely additive:
the button only appears when a connected sidecar reports support for this
specific method (`client?.supports("sidecar.open_data_directory.v1")`),
so older or non-supporting sidecars simply don't show it. No effect for
deployments not using the desktop sidecar feature.
