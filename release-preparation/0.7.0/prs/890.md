# PR #890: Fix outlook addin import map injection

- PR: https://github.com/EratoLab/erato/pull/890
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: Customer themes and component kits

## Summary

Fixes a bug in how the Outlook/Office add-in's **legacy** `/office-addin`
route generated its browser import map (used so component-kit code can
resolve shared bare module specifiers like `react` or `@lingui/core` to
the exact chunk already loaded by the main app bundle, avoiding duplicate
module instances). In `backend/erato/src/frontend_environment.rs`
(`build_frontend_registry`), the legacy route previously called
`load_import_map_json` with the legacy `/office-addin` base path, which
generated import-map entries prefixed with `/office-addin/assets/...`.
However, per the added code comment, the add-in's actual production
module `<script>` tags always reference the canonical
`/public/platform-office-addin` base regardless of which route serves the
HTML document — so the legacy route's import map pointed shared-module
specifiers at URLs that didn't match what the scripts actually requested.
Since ES module identity is based on the resolved URL, this mismatch could
cause the browser to load a second, separate instance of shared modules
like React or Lingui when the add-in was served via the legacy route,
rather than reusing the already-loaded instance — a real risk of duplicate
React instances causing runtime errors (e.g. invalid hook calls) or
inconsistent i18n state.

The fix makes the legacy route's import map identical to the canonical
one (`addin_legacy_import_map_json = addin_import_map_json.clone()`)
instead of regenerating it with a different base path. A new test,
`legacy_office_addin_route_uses_canonical_import_map_urls`, verifies the
legacy route's import map uses `/public/platform-office-addin/assets/...`
URLs and does not contain any `/office-addin/assets/` entries.

## Compatibility and configuration

No configuration keys or migrations. Only affects deployments that have
`integrations.ms_office.addin.serve_bundle_legacy_path = true` (an
existing flag serving the add-in at the legacy `/office-addin` path in
addition to `/public/platform-office-addin`). Fixes a bug rather than
introducing new behavior; users of the legacy route with component kits
that rely on shared React/Lingui instances would see this as a
reliability fix.
