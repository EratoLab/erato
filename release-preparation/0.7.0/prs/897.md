# PR #897: Extend config mirroring to .po translation files

- PR: https://github.com/EratoLab/erato/pull/897
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Extends Erato's existing "runtime configuration mirroring" mechanism
(pre-existing feature, gated by `runtime_configuration.enabled`, which
copies the backend's loaded TOML config source files into a
`runtime_configuration` database table — encrypted and with sensitive
paths redacted — presumably so an admin panel or external tool can inspect
the effective deployed configuration) to also mirror `.po` translation
files. On startup (`backend/erato/src/main.rs`), if
`runtime_configuration.enabled`, a new `discover_translation_po_sources`
(`backend/erato/src/frontend_environment.rs`, +136 lines) finds `.po`
files from the served frontend bundle(s) and passes them to a new
`mirror_erato_backend_sources_with_translation_pos` (replacing the old
`mirror_erato_backend_sources`, which is kept as a thin wrapper calling
the new function with an empty translation-file list, for backward
compatibility with other callers).

Each mirrored row now carries a new `source_type` column
(`backend/sqitch/deploy/0032_add_runtime_configuration_source_type.sql`,
new migration, defaulting existing rows to `'erato_toml'`): TOML config
files are stored as `ERATO_TOML_SOURCE_TYPE` ("erato_toml") and continue to
be redacted (`redact_toml_keys`) and encrypted before storage; `.po`
translation files are stored as `TRANSLATION_PO_SOURCE_TYPE`
("translation_po") and are encrypted but **not** redacted (translation
content isn't secret, unlike config values that may contain credentials).

## Compatibility and configuration

New database migration `0032_add_runtime_configuration_source_type` adds a
`NOT NULL DEFAULT 'erato_toml'` column to `runtime_configuration` — safe
for existing rows, no manual backfill needed. No new top-level
configuration keys; this only activates for deployments that already have
`runtime_configuration.enabled = true`. For such deployments, `.po`
translation files are now also mirrored into the database on every
startup, in addition to the existing TOML config mirroring — increasing
the volume of data stored in that table and its visibility to whatever
consumes it (e.g. an external admin panel, per the "consume translation
authored via admin-panel" related work later this cycle, #991). No
breaking change for deployments with `runtime_configuration` disabled
(default).
