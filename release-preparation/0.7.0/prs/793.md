# PR #793: Fix transient "Error loading file" during generation

- PR: https://github.com/EratoLab/erato/pull/793
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Fixes a transient file-loading error shown for a just-uploaded attachment
on an optimistically-rendered message. `MessageList.tsx`'s `allFilesById`
map (used to resolve `erato-file://` links and attachment previews) was
previously built only from `assistantFiles` and files already attached to
persisted messages (`messages[messageId].files`). When a user sends a
message with a fresh upload, the message renders optimistically before the
server round-trip completes and the message is rehydrated with full file
metadata from the API — during that window, the just-uploaded file wasn't
in `allFilesById` yet, so its preview/link briefly showed as a loading
error. The fix merges in `uploadedFiles` from the existing
`useFileUploadStore` client-side upload-tracking state into the same map,
so a newly uploaded file resolves immediately, before the server response
arrives. Per the PR description, this "only visibly appears in some
custom components" — i.e. the specific rendering path affected depends on
which UI (base app vs. a customer's component kit) is rendering the file
reference.

## Compatibility and configuration
