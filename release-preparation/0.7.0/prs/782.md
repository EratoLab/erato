# PR #782: Switch base image from trixie to chainguard/glibc-dynamic:dev

- PR: https://github.com/EratoLab/erato/pull/782
- Status: pending
- Category: Chores & Developer experience
- Theme: Backend image slimming/hardening

## Summary

Changes the backend runtime container's base image in `backend/Dockerfile`
from `debian:trixie-slim@sha256:5cf544f...` to
`registry.eratolabs.com/erato/chainguard-glibc-dynamic:2026-06-25-dev` (a
custom/private image, presumably built and published by this project from a
Chainguard base — not independently verified since that image's own
Dockerfile/source is outside this PR's diff). The explicit
`apt-get install ca-certificates` step is removed, implying the new base
image already provides CA certificates (or TLS trust is otherwise handled,
e.g. by the rustls switch in #781). `.hadolint.yaml` adds
`registry.eratolabs.com` to `trustedRegistries` so hadolint's Dockerfile
linting accepts the new `FROM` reference.

## Compatibility and configuration

No user-facing configuration change. This affects only how the backend
Docker image is built; behavior should be unaffected as long as the new
base image provides equivalent glibc/runtime library compatibility for the
Rust binary. Self-hosters who build the backend image from source (rather
than pulling the published image) would need access to
`registry.eratolabs.com/erato/chainguard-glibc-dynamic:2026-06-25-dev` — it
is unclear from this diff alone whether that image is publicly pullable;
this should be confirmed by the maintainer before release, since it could
be a build-time breaking change for external contributors building from
source.
