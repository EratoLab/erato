# PR #1341: Document partial Hx attachment exports in the sidecar protocol (ERDSCAR-43)

- PR: https://github.com/EratoLab/erato/pull/1341
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Sidecar source capabilities (new Outlook for Mac/Windows parity, foundation)

## Summary

Per the PR description: protocol part of ERDSCAR-43 ("full Hx item model
for new Outlook for Mac"), bumping the sidecar protocol to 0.1.38 and
directly extending #1335's preview-only-body pattern (0.1.37, ERDSCAR-42)
to attachments. Confirmed directly in the `SPEC.md` diff: for
`macOsHxAccount` sources, a single or thread `.eml` export now includes
whichever attachments are cached on-device (inline images keep their
`Content-ID`); an attachment that isn't cached, can't be read, or exceeds
the size limit is left out of the export instead of failing it, reported
via a new `attachment_unavailable` warning (`sourceError`
`missing_from_local_cache` or another named cause, plus the attachment's
or email's `documentId`). An email whose header claims attachments but
whose attachment list hasn't synced gets one such warning at the email
level; the header flag doesn't count inline images, so an email with only
uncached inline images is exported silently without a warning — a
deliberate, documented gap. Every other source still fails the export
outright on an unreadable/missing attachment, per the existing no-silent-
drop rule. A sidecar older than 0.1.38 still exports new-Outlook-for-Mac
emails without their attachments and without any warning, which `SPEC.md`
now states explicitly as a compatibility note. On the frontend,
`chatTools.ts` forwards `attachment_unavailable` to the model the same way
it already forwards the preview warnings from #1335.

## Compatibility and configuration

Additive protocol change (0.1.37 → 0.1.38); no config keys, no database
migration. Explicitly backward compatible per `SPEC.md`'s own stated
caveat: an older sidecar continues its prior (silent, warning-less)
behavior for new-Outlook-for-Mac attachment exports.
