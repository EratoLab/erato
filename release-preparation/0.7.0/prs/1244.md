# PR #1244: Allow rendering of inline HTML in Markdown; For table line breaks

- PR: https://github.com/EratoLab/erato/pull/1244
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: File previews and formats

## Summary

Enables rendering of raw HTML embedded in Markdown chat messages —
primarily so `<br>` tags work for line breaks inside GFM table cells
(which Markdown's table syntax doesn't otherwise support). Adds two new
rehype plugins to the existing `react-markdown` pipeline
(`frontend/src/components/ui/Message/MessageContent.tsx`): `rehype-raw`
(parses raw HTML in the Markdown source into the render tree) and
`rehype-sanitize` (strips any HTML that isn't in an explicit allowlist)
using a custom schema built on `rehype-sanitize`'s `defaultSchema`,
extended only to permit: the `className` values needed by KaTeX
(`language-*`, `math-inline`, `math-display`, added in #938) and the
`erato-file`/`erato-mention` custom URL schemes (used for internal
file/mention links) as allowed `src`/`href` protocols. Since raw HTML in
an assistant (or, in shared/collaborative contexts, another user's)
message is otherwise a potential XSS vector, enabling `rehype-raw` without
also constraining it via `rehype-sanitize` would have been a real
vulnerability — this PR does both together, and does not appear to widen
the sanitizer's allowlist beyond what KaTeX/internal links need.

The remainder of the diff handles fallout from `rehype-sanitize`'s DOM
"clobbering" protection, which prefixes user-supplied element `id`s with
`user-content-`: footnote reference/definition ID regexes are updated to
strip that prefix even when doubled, footnote anchor hrefs are rewritten
to point at the prefixed IDs, and the footnotes section's own generated
heading ID is updated to match (`footnote-label` → `user-content-footnote-label`).

## Compatibility and configuration

No configuration keys or migrations; the feature is always active, not
gated by a flag, consistent with the other Markdown-rendering
enhancements this cycle (#936, #938). No breaking change for existing
content — plain Markdown without embedded HTML renders identically;
content with (now allowed) `<br>` or other allowlisted HTML renders it,
where previously it may have been shown as literal escaped text or
stripped.
