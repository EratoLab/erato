# PR #780: Split out sqitch migration system into separate Docker image

- PR: https://github.com/EratoLab/erato/pull/780
- Status: pending
- Category: Chores & Developer experience
- Theme: Backend image slimming/hardening

## Summary

Moves the Sqitch database-migration toolchain (`sqitch`, `libdbd-pg-perl`,
`postgresql-client`, and the `/app/sqitch` migration scripts) out of the main
`backend/Dockerfile` into a new, separate `backend/Dockerfile.sqitch-migrator`
image, built from `debian:trixie-slim` and running
`sqitch/deploy_distributed.sh` as its entrypoint. The main backend image no
longer installs Sqitch or its Perl/Postgres-client dependencies, shrinking
it. `.github/workflows/docker-build.yml` adds a new `erato/app-sqitch-migrator`
image, built and pushed for both `amd64`/`arm64` and combined into a
multi-arch manifest alongside the other application images (backend,
frontend, combined app, component-kit-example).

The Helm chart's `run-migrations` init container
(`infrastructure/charts/erato/templates/backend-deployment.yaml`) now pulls
this new migrator image via a new `erato.migrationsImage` helper
(`infrastructure/charts/erato/templates/_helpers.tpl`) instead of reusing
the backend image, and gets its own `imagePullPolicy`.

## Compatibility and configuration

New Helm values under `backend.migrations.image`
(`infrastructure/charts/erato/values.yaml`):
- `backend.migrations.image.repository` — defaults to
  `registry.eratolabs.com/erato/app-sqitch-migrator`.
- `backend.migrations.image.tag` — defaults to empty string, which falls
  back to `backend.image.tag` (via `default .Values.backend.image.tag
  .Values.backend.migrations.image.tag` in `_helpers.tpl`).
- `backend.migrations.image.pullPolicy` — defaults to `IfNotPresent`.

For users of the Helm chart with default values, this is transparent: the
migrator image tag tracks the backend image tag automatically. Deployments
that pin `backend.image.repository` to a private mirror/registry copy of
just the backend image, without also mirroring the new
`app-sqitch-migrator` image, would need to add that image to their mirror
and/or override `backend.migrations.image.repository`. `erato.imagePullSecrets`
now also renders pull secrets for the migrations image.
`infrastructure/scripts/setup-dev` was also updated (not fully inspected) —
likely to build/reference the new Dockerfile for local development.
