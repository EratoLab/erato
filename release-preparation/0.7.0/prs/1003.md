# PR #1003: Improve frontend build layer caching

## Summary

Restructures `frontend/Dockerfile` (and similarly
`component-kit-example/Dockerfile`) to follow the standard Docker
layer-caching pattern: package manifests (`package.json`,
`pnpm-lock.yaml`, `pnpm-workspace.yaml`, `.npmrc`) are now copied and
`pnpm install`ed in their own layer *before* the actual source code is
copied, for each of the `desktop-sidecar-protocol`, `frontend`, and
`office-addin` sub-projects — so an application source-code change no
longer invalidates the (often slow) dependency-install layer, only the
build layers after it. `pnpm install` now also passes `--ignore-scripts`,
presumably to avoid prematurely running the new `prepare` lifecycle script
added in #999 before the full source tree is present; a subsequent
`pnpm rebuild @swc/core esbuild msw protobufjs unrs-resolver` step
explicitly rebuilds the native/binary packages that would otherwise have
run their install scripts. For the Office add-in, the diff preserves the
`pnpm-lock.yaml` produced by the earlier `pnpm update @erato/frontend`
step around the full-source `COPY office-addin /app/office-addin` (copying
it to `/tmp` and restoring it afterward), since that copy would otherwise
overwrite the just-updated lockfile with the pre-update one from the
source tree. `.dockerignore` gained 2 lines, presumably excluding
generated artifacts from being copied unnecessarily.

## Compatibility and configuration

No configuration keys, migrations, or runtime behavior changes — this
only affects Docker build performance/caching for the frontend and
component-kit-example images, not the resulting image contents or
application behavior.
