# PR #988: Refactor to establish clear distribution structure

## Summary

Large internal restructuring of how the backend discovers and describes
the artifacts it serves. Introduces a new `backend/erato/src/distribution/`
module with a top-level `Distribution` struct
(`distribution/mod.rs`) that owns four sub-areas, each moved into its own
file: `frontend_bundles.rs` (313 lines, frontend bundle discovery/rewrites,
moved out of the former monolithic `frontend_environment.rs`),
`component_kits.rs` (271 lines), `translations.rs` (360 lines, the `.po`
discovery/mirroring logic extended by #897/#914 this cycle), and
`desktop_sidecar.rs` (moved/renamed from an existing file per the git
rename). Per the new module's doc comment: "Distribution modules own
filesystem layout, discovery, and validation. Server modules are
deliberately limited to selecting and serving artifacts from these
concrete descriptions." `backend/erato/src/frontend_environment.rs`
shrinks by 866 lines (mostly moved, not deleted logic), and
`backend/erato/src/server/router.rs` is also substantially changed
(93-line diff) to consume the new `Distribution` type via `AppState`
(38-line diff) instead of building things ad hoc at startup.

Spot-checked for behavior preservation: the asset-vs-SPA-rewrite fix from
#905 (`matches_rewrite_rule`'s extension check) is preserved, now as
`rewrites_match_dynamic_routes_but_not_asset_paths` in
`distribution/frontend_bundles.rs`; the JIT-translation ETag fix from #792
and the hashed-component-kit-runtime fix from #824 remain intact (both
their functions and unit tests) in `frontend_environment.rs`.

## Compatibility and configuration

No configuration keys, migrations, or intended runtime behavior change —
this is presented and appears to be a pure internal architectural
refactor consolidating discovery/validation logic that had accumulated
across several PRs this cycle (#792, #824, #872, #897, #905, #914,
#916, #917) into a single coherent module structure.
