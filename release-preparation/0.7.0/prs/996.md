## Summary

Splits the single monolithic `lint` CI job in
`.github/workflows/docker-build.yml` into four parallel jobs:
`lint-frontend` (JS/TS lint/prettier/tests, the desktop-sidecar-protocol
checks, and the served-routes manifest check from #905), `lint-backend`
(Rust `rustfmt` and the sqitch schema-summary check), `lint-infrastructure`
(Dockerfile linting via hadolint and Helm chart linting/unit tests), and
`lint-site-docs` (the config-documentation-coverage check, moved out of
the frontend job). Each job now only installs the toolchains it actually
needs (e.g. `lint-backend` no longer sets up Node/pnpm), and the four jobs
run concurrently instead of sequentially in one job.

## Compatibility and configuration

No configuration keys, migrations, or production runtime changes; this is
purely a CI workflow restructuring intended to reduce total CI wall-clock
time (parallel jobs) and per-job setup overhead (only relevant toolchains
installed). No change to what is actually checked — the same lint/test
steps run, just distributed across separate jobs. CI status checks
required for merging would need to be updated from the single `lint` check
to the four new named checks if branch protection rules reference the job
name directly (not verifiable from this repository diff alone).
