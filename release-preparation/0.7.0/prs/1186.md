# PR #1186: Extend RPC search.query response with external identifiers

- PR: https://github.com/EratoLab/erato/pull/1186
- Status: pending
- Category: Features and enhancements
- Theme: Desktop Sidecar for local sources

## Summary

Pure desktop-sidecar protocol-specification addition (no backend/frontend
application code touched). Adds two optional fields to each result item in
`search.query.v1`'s result schema: `uri` (a retrievable URI identifying
the document, "ideally an externally retrievable URL") and `external_ids`
(an open-ended array of `{key, value}` pairs — per its description,
"identifier keys are open-ended so new identifier kinds do not require a
protocol change"). This lets a search result reference the original
item's external location/identity (e.g. a mailbox item's Graph ID, a
file's path or drive-item ID) without needing a separate protocol version
bump each time a new identifier kind is needed.

## Compatibility and configuration

No backend/frontend configuration keys or migrations — protocol
specification only; no Erato application code consumes these new fields in
this diff. Additive to the result schema (new optional fields), not a
breaking change to existing consumers.
