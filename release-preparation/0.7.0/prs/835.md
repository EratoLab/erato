# PR #835: Make sidebar Assistants section collapsible

- PR: https://github.com/EratoLab/erato/pull/835
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Adds a new config flag,
`assistants.show_recent_items_collapsible` (default `false`), that lets
the sidebar's "recent assistants" section (`FrequentAssistantsList`) be
rendered inside a collapsible section (header + chevron), matching the
existing "Recent chats" section's behavior — previously it always
rendered in a bare, non-collapsible `div`. Confirmed by reading the code:

- Threaded through `AssistantsConfig` (backend, defaults `false`),
  `frontend_environment.rs`, `env.ts`'s `Env` type, and
  `FeatureConfigProvider`'s `AssistantsFeatureConfig` — the same
  four-layer wiring pattern used for the pre-existing
  `assistants.show_recent_items` flag.
- In `ChatHistorySidebar.tsx`: when the new flag is `true`, the assistants
  section renders wrapped in `CollapsibleSection` with expand/collapse
  state persisted to `localStorage` under a new key,
  `erato.sidebar.assistantsSectionExpanded` (defaulting to expanded,
  mirroring the existing `erato.sidebar.recentChatsSectionExpanded`
  pattern for Recent chats). When `false` (the default), the section keeps
  its prior always-visible, non-collapsible rendering — confirmed via the
  ternary branch preserving the original `div` wrapper unchanged.
- The section's title reuses the existing `Assistants` translation string
  rather than introducing a new i18n key, confirmed via `t`Assistants``
  in the `CollapsibleSection`'s `title` prop.
- No change to the pre-existing `assistants.show_recent_items`
  show/hide behavior — confirmed the new flag only gates which of two
  rendering paths is used, not whether the section appears at all.

## Compatibility and configuration

New, optional, default-`false` config field — no behavior change for any
existing deployment that doesn't set it:
```toml
[assistants]
show_recent_items_collapsible = false  # default
```
Documented in `site/content/docs/configuration.mdx` (17 new lines,
not independently read in full) and `erato.template.toml`; generated
`config_reference.json` updated accordingly (1-line diff, mechanical).
