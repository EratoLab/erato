# PR #1312: Keep Outlook selection rewrites on the rewritten passage and out of the body

- PR: https://github.com/EratoLab/erato/pull/1312
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Fixes an Outlook add-in issue where the "Rewrite Selection" action would duplicate content: the rewritten text would both replace the selected passage AND appear appended to the email body.

**Problem.** When a user selected text in an Outlook compose window and requested a rewrite, the `OutlookEratoEmailRenderer` component was inserting the new text as a full body replacement rather than a scoped selection replacement. This resulted in the rewritten text appearing at the cursor position in addition to replacing the selected passage, causing content duplication.

**Fix.** The `OutlookEratoEmailRenderer.tsx` (79 lines changed) is updated to distinguish between scope="selection" (replace only the selected passage) and scope="body" (replace the entire compose body). For selection rewrites, the renderer now constructs the response as a replacement of the selected range only, without affecting the rest of the body. The `outlookClientActions.ts` (28 lines added) sends the correct action type for selection replacements.

**Testing.** `OutlookEratoEmailRenderer.test.tsx` (258 lines added) covers selection and body rewrites in both HTML and plain-text compose modes, including edge cases like empty selections and selections spanning formatting boundaries. `outlookClientActions.test.ts` and `outlookComposeWrite.test.ts` cover the action dispatch.

**Translations.** New locale strings for the "rewrite selection" action across all five locales.

## Compatibility and configuration
