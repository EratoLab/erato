## Summary

No GitHub description beyond "Related Linear issue: ERMAIN-972";
evaluated from the diff and its documentation addition. Adds a new
`{{chat.id}}` Handlebars variable usable in a chat provider's
`additional_request_headers` templates (an existing mechanism alongside
`{{erato_user.id}}` and `{{id_token.claims.<claim>}}`), confirmed exactly
via the `configuration.mdx` documentation diff added by this PR:

- Resolves to the existing Erato conversation UUID, stable across turns,
  retries, tool-call iterations, and resumed generation. Summary/history
  compaction requests use the conversation's own ID; delegated runs use
  their own chat ID (not the parent's).
- When no conversation exists yet (model-availability checks, standalone
  transcription), headers referencing `{{chat.id}}` are omitted entirely
  rather than sending an empty or invented session ID.
- The documented motivating use case is session affinity with a gateway
  like Bifrost (`x-bf-session-id={{chat.id}}`), so repeated calls for the
  same conversation can be routed to the same upstream session.

## Compatibility and configuration

None breaking. Purely additive template variable; existing
`additional_request_headers` templates using only the previously-supported
variables are unaffected. No new top-level config key — this extends the
existing per-provider `additional_request_headers` templating mechanism.
