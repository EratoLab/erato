# PR #1049: Move staged attachments inside the composer shell

- PR: https://github.com/EratoLab/erato/pull/1049
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Stacked on #1047. Moves the default staged-attachments preview from a
position above/outside the composer shell into the shell's existing
in-shell slot (previously used only by a `ChatInputAttachmentPreview`
override), so attachments render as part of the composer rather than a
separate floating card. Confirmed by reading the two most load-bearing
diffs in full:

- **Preview repositioning, confirmed exactly via `ChatInput.tsx`**: the
  old standalone `{!hasAttachmentPreviewOverride && <AttachmentsPreview
  ... />}` block rendered above the shell is removed entirely, and the
  default `AttachmentsPreview` now renders as the `else` branch of
  `{ChatInputAttachmentPreview ? <ChatInputAttachmentPreview ... /> :
  <AttachmentsPreview ... surfaceVariant="message" />}` — i.e. inside the
  same conditional, at the same in-shell position, that previously only
  hosted a component-kit override. A code comment states the rationale
  directly: staged attachments are part of what is about to be sent, not
  a separate card.
- **Footer/Remove-all narrowing, confirmed exactly via
  `AttachmentTileList.tsx`**: the footer's visibility condition changes
  from `showRemoveAll || capHeight` to `showRemoveAll` alone — so the
  count/Remove-all footer no longer appears purely because the list is
  capped/overflowing; it now only rides along with the bulk-remove
  control. A code comment states the design reasoning: a list short
  enough not to need a bulk remove is also, by construction, too short to
  overflow the cap, so there was never a case where `capHeight` alone
  (without `showRemoveAll`) had anything the count needed to warn about.
- Per the PR (not independently re-verified given remaining scope): the
  shell's own gap now spaces the preview, so `FileAttachmentsPreview` no
  longer needs its own bottom margin (a 3-line change in that file, not
  independently read); and a component-kit override of
  `ChatAttachmentsPreview` (distinct from `ChatInputAttachmentPreview`)
  now also renders inside the shell rather than above it — the PR
  explicitly flags this as the one contract change worth scrutiny, since
  the Teams route registers `TeamsAttachmentsPreview` through that slot
  and its grouped preview moves inside too, a change the PR author states
  they could not exercise locally against the actual Teams route.

## Compatibility and configuration

None functionally breaking, but a visible layout change for any
component-kit consumer using `ChatAttachmentsPreview`: its rendered
position moves from above the composer shell to inside it. No API or
database changes. `ChatInput.test.tsx` was updated to assert the new
placement (per the PR, not independently re-verified).
