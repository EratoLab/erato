# PR #815: Make copy error button available for frontend errors

- PR: https://github.com/EratoLab/erato/pull/815
- Status: pending
- Category: Features and enhancements
- Theme: None

## Summary

Adds a "Copy error report" button (`frontend/src/components/ui/Feedback/CopyErrorButton.tsx`)
that renders a Markdown-formatted diagnostic report (environment,
timestamp, chat ID, assistant ID, platform, active facets, and the error
itself, including request/response method/URL/headers/body for network
errors) and copies it to the clipboard via
`navigator.clipboard.writeText`. The rendering logic
(`frontend/src/utils/errorReport.ts`, new file) uses a Handlebars-style
`{{placeholder}}` template, truncates any request/response body over
100,000 characters, pretty-prints JSON bodies, and redacts header values
matching `authorization|cookie|token|api-key|subscription-key|client-secret`
(case-insensitive) as `<redacted>` (`sanitizeHeaders`). The button is wired
into `ChatMessage.tsx` (assistant error display), `ChatInput.tsx`,
`FileUploadStates.tsx`, `ChatErrorBoundary.tsx`, and
`SharingErrorBoundary.tsx`. A new `FrontendRequestError` error class
carries request/response context for API-call failures so it can be
included in the copied report; `useChatMessaging.ts` and `sseClient.ts`
were updated to throw/attach this context.

The `showCopyErrorReport` config flag itself pre-dates this PR (already
present in `FeatureConfigProvider.tsx` defaulting to `true`) but had no
actual button implementation wired to it before now — this PR is what
makes the flag take effect.

## Compatibility and configuration

Two related settings under `frontend.error_report` in
`backend/erato/src/config.rs` (`FrontendErrorReportConfig`):
- `frontend.error_report.show_copy_error_report` — pre-existing, defaults
  to `true`. Now actually shows/hides the new Copy button.
- `frontend.error_report.error_report_template` — new in this PR, defaults
  to the built-in Markdown template shown above (`default_error_report_template`).
  Exposed to the frontend via new `ERROR_REPORT_TEMPLATE` and
  `ERROR_REPORT_ENVIRONMENT` (backend `config.environment`) frontend
  environment variables (`backend/erato/src/frontend_environment.rs`).

No migration. No breaking change; existing deployments get the button
enabled by default (matching the pre-existing default), using the built-in
template. Operators who want to customize the copied report format (e.g.
to point at an internal support/ticketing workflow) can set
`error_report_template`. Sensitive headers are redacted before being
included in the copyable text, reducing (but not eliminating, since
request/response bodies are not redacted) the risk of leaking secrets via
a pasted error report.
