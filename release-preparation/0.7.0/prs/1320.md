# PR #1320: Show and keep the desktop sidecar's effective source priority

- PR: https://github.com/EratoLab/erato/pull/1320
- Status: pending
- Category: Features and enhancements
- Theme: Desktop Sidecar

## Summary

Two related fixes to the Desktop Sidecar indexing-priority UI, per the
PR description ("The sidecar now indexes newest first, and a Teams
account enabled by default runs at priority 0 beside the default
mailbox instead of waiting for every mailbox's backlog"):

- **Protocol addition**: `sources.list.v1`'s per-source descriptor gains
  a new optional `indexingPriority` field (0 to `9007199254740991`,
  mirroring the existing `indexingEnabled` field's pattern) reporting a
  source's *effective* indexing priority — from its policy if set, else
  the sidecar's own default — so a client can show or edit a priority
  for a source that has no explicit policy yet without guessing or
  defaulting it to the maximum value. `SPEC.md` is updated to tell
  clients to start from this reported value rather than assume
  `9007199254740991` for an unlisted source.
- **Frontend fix**: `indexingEntries()` now reads this new
  `source.indexingPriority` as its fallback (before the old hardcoded
  `DEFAULT_MAILBOX_PRIORITY`) when no explicit policy priority exists.
  Separately, a new `rankedWithinProduct()` helper replaces the old
  reorder logic (which assigned a single global, ever-increasing
  priority index across the whole reordered list) — it now assigns
  priorities independently *per product* (e.g. Outlook vs. Teams), so
  reordering no longer forces a newly-enabled Teams account to wait
  behind every Outlook mailbox; each product's first source can run
  alongside the other's.

## Compatibility and configuration

Additive protocol field (`indexingPriority`), backward compatible: an
older sidecar that omits it simply isn't shown an accurate starting
priority, falling back to the previous hardcoded default — no schema
`additionalProperties` tightening, no required-field change. No config
keys. No migration.
