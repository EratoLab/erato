# PR #1225: Extend sidecar protocol for full document retrieval

## Summary

Pure desktop-sidecar protocol-specification addition (no backend/frontend
application code touched). Adds `sources.get_document.v1`: given a
`documentId` (UUID, presumably from a prior `search.query.v1` result per
#1186) and an optional `subject_scope`
(`"subject"` (default) | `"subject_with_thread"` — likely controls whether
just the referenced item or its whole email thread is returned), it
returns the document's full content as `filename`, `mimeType`, and
`contentBase64` (validated against a strict Base64 regex pattern). This
lets a client fetch a full local document (e.g. an indexed email or file)
by ID after finding it via search, rather than only having the search
result's summary/snippet.

## Compatibility and configuration

No backend/frontend configuration keys or migrations — protocol
specification only; no Erato application code consumes this new method in
this diff. No production impact until a real sidecar implementation and
corresponding client integration land (the following PR, #1229, appears to
add that client-tool integration).
