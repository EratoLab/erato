# PR #784: Mac 'pin the add-in' hint for the unpinned/frozen task pane

- PR: https://github.com/EratoLab/erato/pull/784
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: Outlook scheduling and shared mailboxes

## Summary

Adds a dismissible, self-clearing banner nudging the user to "pin" the
Outlook add-in task pane on **new Outlook for Mac desktop**, where an
unpinned pane never receives `ItemChanged` events (a known office-js
platform limitation, #5575) — so the chat silently stays bound to whatever
message was open when the pane first loaded, even as the user navigates to
other mail. Pinning is the only way to make the pane track navigation on
that platform, and there is no programmatic way to pin or reliably detect
pin state, so the fix is a UI nudge rather than an automatic workaround.

New `AddinPinHintBanner.tsx` renders the hint; `OutlookMailItemProvider.tsx`
gains a `hasItemChangedFired` boolean that flips `true` only once the
resolved mail item's identity actually changes to a *different* item — a
real navigation — explicitly ignoring the host's initial same-item
selection-bind event (which would otherwise clear the hint the instant the
first message loads, before the user ever sees it). Item identity
comparison also has to handle unsaved compose drafts specially: a
newly-added `isStableItemIdentity` check rejects identities minted with a
`compose:` prefix (each resolve of the *same* unsaved draft mints a new,
different fallback identity via `Date.now()`/`Math.random()`, so comparing
two of them can never prove a real navigation happened) and
`lastItemIdentityRef` deliberately survives a `null`-item event (a pinned
pane's deselect) so a sequence like item A → deselect → item B still
registers as a genuine navigation.

**The actual gating condition for showing the banner is more precise than
the PR's own description states.** The PR body says the banner "shows only
when `platform === 'Mac' && !hasItemChangedFired && !pinHintDismissed'`,"
but the shipped code in `AddinChat.tsx` is:
```
showPinHint = itemTrackingRequiresPin && !mailItem?.isComposeMode &&
  !hasItemChangedFired && !pinHintDismissed
```
where `itemTrackingRequiresPin` (new field on `OfficeProvider`'s context)
is `platform === "Mac" && !detectExchangeOnPrem()` — i.e. the hint is
*also* suppressed for on-premises Exchange mailboxes (their manifest
declares no pin support at all, so a "pin" instruction would be
misleading there) and for compose-mode panes (pinning doesn't carry across
read/compose mode switches, so showing — and letting the user permanently
dismiss — the hint while composing could burn it for the read-mode case
where it actually matters). Dismissal persists via `usePersistedState` in
`localStorage` under `erato.outlookAddin.pinHintDismissed`, and does *not*
reset the tracking flag itself, so a returning user in a fresh session
sees the hint again briefly until their first real navigation (intentional
— it re-detects if the user has since unpinned).

**The handler-cleanup fix also differs from the PR's own description.**
The PR body says "`removeHandlerAsync` now receives the registered handler
instead of a throwaway `() => {}`." The actual diff does the opposite:
it *removes* the second argument entirely
(`mailbox.removeHandlerAsync(eventType)` instead of
`mailbox.removeHandlerAsync(eventType, () => {})`), with a new code
comment explaining why: "`Mailbox.removeHandlerAsync` removes ALL handlers
for the event type; its optional second arg is a completion callback, not
a handler filter — passing a handler there gets it invoked." I.e. the
previous code accidentally *invoked* a no-op handler as a completion
callback rather than filtering which handler to remove; the fix drops
that misused argument rather than replacing it with "the registered
handler" as described.

No manifest changes ship in this PR (confirmed: neither
`office-addin/manifests/*.xml` nor similar files appear in the diff's
12 changed files).

## Compatibility and configuration

None. Purely a frontend/Office-add-in UX fix scoped to
`office-addin/src/`; no backend configuration keys, migrations, or API
changes. New `localStorage` key `erato.outlookAddin.pinHintDismissed`
(per-browser-profile dismissal state, not synced across devices).
