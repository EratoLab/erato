# PR #915: Add tool call approval interaction

- PR: https://github.com/EratoLab/erato/pull/915
- Status: pending
- Category: Features and enhancements
- Theme: MCP controls

## Summary

Adds an optional approval gate for MCP tool calls: before a matching tool
executes, generation pauses (a durable, message-scoped approval request is
persisted so it survives reconnects — per the frontend component's doc
comment "the continuation is an SSE response; consuming it to completion
... lets the regular message query render the rehydrated transcript") and
the user is shown an `McpToolApprovalCard` in the chat with the tool's
input preview, which they approve or deny before the tool runs.

Gating is controlled by a new `[mcp_servers_global.approval]` config
block (`backend/erato_config/src/config.rs`,
`McpToolApprovalConfig`/`McpToolApprovalPreset`): `enabled` (default
`false`, preserving prior always-execute behavior), `preset`
(`"permissive"` default, or `"restrictive"`), and `allow_always` (default
`false`). Per the documentation added to
`site/content/docs/features/mcp_servers.mdx`: in `"permissive"` mode, a
tool pauses for approval only when its MCP `destructiveHint` is `true` (or
absent, since missing annotations default pessimistically to requiring
approval); in `"restrictive"` mode, a tool proceeds without a prompt only
if it explicitly declares `readOnlyHint = true`, `destructiveHint = false`,
and `openWorldHint = false`. `idempotentHint` is retry metadata only, never
affecting the approval decision. When `allow_always = true`, a user can
choose "Always allow" for a specific tool, persisted per
`(user_id, mcp_server_id, tool_name)` in a new
`user_tool_approval_settings` table, and later revoked via a new
Settings-dialog tab (`McpToolApprovalSettings.tsx`) and its backing API
(`backend/erato/src/server/api/v1beta/user_tool_approval_settings.rs`).

## Compatibility and configuration

New optional config block, disabled by default:
```toml
[mcp_servers_global.approval]
enabled = false        # default; preserves prior always-execute behavior
preset = "permissive"  # or "restrictive"
allow_always = false
```
New database migration `0034_add_user_tool_approval_settings` creates the
`user_tool_approval_settings` table (unique per user/server/tool, with
`active`/`deactivated_at` for soft-revocation) — additive, no backfill
needed. No breaking change: existing deployments see no behavior change
unless `mcp_servers_global.approval.enabled` is explicitly set to `true`.
