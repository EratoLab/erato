## Summary

Pure desktop-sidecar protocol-specification addition (no backend/frontend
application code — only `desktop-sidecar-protocol/` schemas, generated
TypeScript, and conformance tests). Adds three JSON-RPC methods for
running and inspecting indexing performance benchmarks against a specific
mailbox:
- `indexing.benchmark.start.v1`: takes a required `mailboxId` (32-hex or
  standard UUID format) and an optional `mode`
  (`"fiveMinutes"` (default) | `"fullMailbox"`) — starts a timed or
  full-mailbox indexing benchmark run.
- `indexing.benchmark.status.v1`: queries the status/progress of a
  running or completed benchmark.
- `indexing.benchmark.list.v1`: lists prior benchmark runs.

These build on the indexing-status/reset protocol from #1143 and the
mailbox controls from #1159, presumably intended for diagnosing indexing
performance on a real mailbox before rolling out the desktop sidecar
feature more broadly, rather than as an end-user-facing feature.

## Compatibility and configuration

No backend/frontend configuration keys or migrations — protocol
specification only, no Erato application code consumes these methods in
this diff. No production impact until a corresponding sidecar
implementation and UI (if any) land in a later PR.
