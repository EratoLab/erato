# PR #1120: Seat the share button in one chat top bar with the kit accessory

- PR: https://github.com/EratoLab/erato/pull/1120
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Fixes a layout gap left by #1091's in-flow kit-accessory seating: three
share-feature rules still assumed the conversation began at the page top
(a floating share button, a reserved corner on the delegated-run strip,
and 56px of message-list top padding), so under a component kit
supplying `ChatTopLeftAccessory`, that reserved band sat empty above the
accessory while the share button and the "Beginning of conversation"
marker ended up a full row below where the kit's own picker rendered.
Confirmed by reading the complete `Chat.tsx` diff and the relevant
`globals.css` addition:

- **Absolute positioning replaced with one in-flow bar, confirmed
  exactly**: the previous `<div className="absolute right-3 top-3 z-10
  sm:right-4">` wrapper around the share button is removed entirely,
  along with the delegated-run strip's `pr-28 sm:pr-32` corner reservation
  and the message list's `pt-12 sm:pt-14` top padding. A new element
  (`data-ui="chat-top-bar"`) renders both the kit accessory (in a
  `min-w-0 flex-1` slot) and the share button (in a `shrink-0` slot) as
  flex siblings inside one row — confirmed this row renders only when
  `TopLeftAccessory || canShareCurrentChat` is true, matching the PR's
  stated "renders only when an accessory or the share button exists, so
  a stock chat without sharing is unchanged" claim precisely.
- **Toggle-column token, confirmed exactly**: the previous hardcoded
  `pl-12` reserved for the hidden-mode sidebar's floating toggle is
  replaced by `pl-[var(--chat-top-bar-toggle-column)]`, and the new CSS
  custom property is defined as `calc(var(--theme-spacing-control-min-
  height) + 0.5rem)` — matching the PR's stated derivation from the
  control-min-height token rather than a fixed pixel value, so a theme
  sizing its icon buttons differently can correct the reserved column by
  setting this one variable.
- Per the PR (not independently re-verified given remaining scope): the
  disclosed stock-visual delta (with sharing enabled, the share button
  moves from floating over the message list into the new in-flow bar; in
  delegated-run chats it now sits above the run header rather than
  sharing its row); the add-in's pin-hint banner and delegated-run
  header keeping their clearance reservations only while the drawer
  trigger/start-view toggle actually float (the
  `AddinPinHintBanner.tsx` diff, 11 lines, not independently read); and
  the documentation updates in `theming.mdx`/`component_customization.mdx`.

## Compatibility and configuration

None breaking. Real, disclosed visual change only for deployments with
chat sharing enabled: the share button's position moves from a floating
overlay to an in-flow bar at the top of the conversation. No change at
all for a chat with sharing disabled and no kit accessory registered
(confirmed via the conditional-render gate on the new bar). No API or
configuration changes.
