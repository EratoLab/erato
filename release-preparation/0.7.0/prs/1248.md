# PR #1248: Implement standalone distribution for MS Teams

- PR: https://github.com/EratoLab/erato/pull/1248
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Microsoft Teams conversations and bot

## Summary

Adds the ability to distribute Erato as a standalone, installable
Microsoft Teams app (rather than only as an Outlook/Word add-in), building
on the Teams integration work earlier this cycle. New
`backend/erato/src/distribution/teams.rs` (229 lines): `TeamsAppDistribution`
loads a `manifest-teams.json` template from the Office add-in bundle and,
at request time, renders a live Teams app manifest by substituting the
deployment's actual base URL (validated as HTTPS with a real hostname —
explicitly rejecting `localhost`/`*.localhost`, per
`render_manifest`'s checks) and branding config into it, then packages it
with the required icons into an installable Teams app ZIP. Two new
backend routes serve these: `GET /office-addin/teams/manifest.json`
(a rendered manifest preview) and `GET /office-addin/teams/app-package.zip`
(the installable package), gated by a new
`integrations.ms_office.teams.enabled` flag.

The Teams app deliberately reuses the existing Office add-in frontend
bundle and Entra client ID rather than being a separate app — per the
docs, `integrations.ms_office.addin.enabled` and its `msal_client_id` must
also be configured for the Teams app to be enabled. New config:
`integrations.ms_office.teams.app_id` (a distinct, stable GUID identifying
the Teams app, defaulting to a fixed value, must differ from the Outlook
and Word add-in IDs) and `integrations.ms_office.teams.manifest.*`
(branding strings and icon paths — developer name, website/privacy/terms
URLs, short/full name and description, tab name, and three icon paths,
each validated as a safe path relative to the add-in bundle). The package
version tracks the Erato release version automatically, with no separate
override.

## Compatibility and configuration

New configuration block, disabled by default:
```toml
[integrations.ms_office.teams]
enabled = false  # default; requires integrations.ms_office.addin.enabled and msal_client_id
app_id = "c88180bf-f50d-42dc-8b5e-c27280b6035e"  # default; must differ from other add-in IDs

[integrations.ms_office.teams.manifest]
# developer_name, website_url, privacy_url, terms_url, short_name, full_name,
# short_description, full_description, tab_name, color_icon, outline_icon,
# small_color_icon — default to Erato branding and bundled icons.
```
No migration. Purely opt-in — deployments not enabling
`integrations.ms_office.teams.enabled` see no new routes or behavior.
