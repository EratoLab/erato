# PR #1310: Fix MCP file outputs bypassing conversion after approval

- PR: https://github.com/EratoLab/erato/pull/1310
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: MCP

## Summary

Fixes a correctness issue where MCP file outputs from approved tool calls bypassed the standard file conversion pipeline, potentially delivering files to the model in an unexpected format.

**Problem.** When a tool call required user approval and was approved, the file outputs returned by the MCP server were inserted directly into the message content without undergoing the conversion steps that normal file uploads go through (image resizing, format transcoding, MIME type normalization). This could result in the model receiving files in formats it could not process, or in inconsistent sizes.

**Fix.** The message streaming pipeline now ensures that MCP file outputs always pass through the standard file conversion process, regardless of whether the tool call required approval. The conversion step is applied after approval and before the file outputs are added to the conversation content.

**Key changes:**
- `message_streaming.rs`: The approval-handling branch now routes MCP file outputs through the same `process_file_outputs` conversion pipeline used for non-approved calls.
- `mcp_file_outputs.rs` (498 lines new): Integration test module covering all MCP file output paths: non-approved calls, approved calls, calls with no file outputs, calls with mixed file/non-file outputs.
- E2E test configuration updates for the expanded coverage.

## Compatibility and configuration

No config changes. The fix corrects an internal processing gap.
