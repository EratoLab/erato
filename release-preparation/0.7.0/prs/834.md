# PR #834: Dropdown: pointerdown outside-close for touch tap-outside dismiss (ERMAIN-465)

- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Follow-up to #833 (ERMAIN-464): with that fix, the previously-reported
"multiple ⋯ menus open at once" symptom went away as a side effect of
correcting the popover's positioning (an overgrown panel no longer
overlapped neighboring row triggers, so the existing outside-click-close
now reliably fires when another trigger is pressed) — per the PR, no
separate list-level single-open coordination was needed.

One residual gap remained specifically on **touch** surfaces (the Outlook
add-in and the mobile web layout): `AnchoredPopover`'s outside-close
listened on `document.mousedown`, but a touch tap's synthesized
`mousedown` event can be delayed or suppressed by the browser, so tapping
outside an open menu on touch sometimes failed to dismiss it. Confirmed
by reading the diff: the listener is switched from `mousedown` to
`pointerdown` (which fires uniformly across mouse, touch, and pen input),
with the handler's event type changed from `MouseEvent` to `PointerEvent`
(a strict supertype, so the existing target-containment check needed no
changes). The `keydown`/Escape listener alongside it is untouched.

Also included, unrelated cleanup: `.storybook/preview.tsx` had two
type-only exports (`Preview`, `ThemeMode`) imported as values, which broke
`storybook dev` in this checkout — fixed to `import type`.

The PR explicitly scopes out two related but unnecessary changes as
"gold-plating with no user-facing effect": removing the existing 100ms
close timeout, and adding a controlled `isOpen` prop plus list-level
single-open state.
