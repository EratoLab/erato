# PR #847: Take dropdown trigger geometry from the control token

- PR: https://github.com/EratoLab/erato/pull/847
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Fixes the model picker (`ModelSelector`) and audio-input picker
(`AudioInputTabContent`) dropdown triggers hand-rolling their own geometry
(`rounded-[var(--theme-radius-input)] px-3 py-2 shadow-sm`) on top of the
shared `Button`, instead of relying on `Button`'s own control geometry.
Confirmed by reading the diff: both `triggerButtonClassName` props are
reduced to layout-only classes (`min-w-[10rem] justify-between gap-2` /
`w-full justify-between gap-2`), removing the padding (redundant with
`Button`'s own `--theme-spacing-control-padding-x/y`), the drop shadow,
and — most substantively — the `--theme-radius-input` token, which the PR
states is scoped to the composer shell, attachment groups, settings cards,
and the share dialog, so a theme couldn't round these two dropdown
triggers without also reshaping all of those unrelated surfaces. With the
override removed, the triggers now inherit `btn-geometry-sm`'s
`--theme-radius-control`, matching every other button (including the
composer's other controls, moved onto shared geometry by #843/#844),
which the PR notes also makes the triggers reachable by a theme scoping
that token to a specific `data-ui` surface. A new `DropdownMenu` test
pins the trigger to shared geometry and asserts none of the removed
classes leak back in.
