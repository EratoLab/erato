# PR #1364: Ask before replacing the whole document in Word for the web, and edit in place there (ERMAIN-961) (#1364)

- PR: https://github.com/EratoLab/erato/pull/1364
- Status: pending
- Category: Bug fixes
- Theme: Word add-in

## Summary

Every applied Word plan previously went through a whole-document import,
regardless of host. On Word for the web specifically, that import loses
tracked-change authorship (attributing changes to "Unknown"), rewrites
comment dates and resolved flags, can silently drop co-authors' concurrent
edits, and can't be undone via Word's own Undo. This adds a per-host,
per-mechanism apply policy so the web client writes in place where it can
and only falls back to whole-document replacement after the user
explicitly confirms; PC and Mac keep the existing import-based behavior
unchanged (their own in-place mechanism isn't yet signed off).

Confirmed exactly via the `config.rs` diff: a new
`MsOfficeAddinWordApplySettings` config block holds separate `pc`/`mac`/`web`
override tables, each with optional `in_place` (bool), `whole_document_import`
(`allowed` / `confirm` / `off`), and `package_read` (bool) — any unset key
falls back to that host's own hardcoded default. The code's own defaults
make the policy explicit: desktop (PC/Mac) defaults to `in_place: false`,
`whole_document_import: allowed` (import stays the default, unconditionally,
until desktop's in-place probe is approved); web defaults to `in_place:
true`, `whole_document_import: confirm` (write in place when possible, and
only import after a user confirms) — with an inline code comment citing the
exact data-loss reasons (tracked-change authorship, comment metadata,
co-author edits, irreversibility) as the justification for web's stricter
default.

## Compatibility and configuration

New optional per-host override table, with host-specific hardcoded
defaults that already change effective behavior for Word for the web
(no config needed to get the new confirm-before-import behavior there):

```toml
[integrations.ms_office.addin.default_settings.word_apply.web]
in_place = true               # default for web
whole_document_import = "confirm"  # default for web; or "allowed" / "off"
package_read = true

[integrations.ms_office.addin.default_settings.word_apply.pc]
in_place = false               # default for pc/mac (import-only until signed off)
whole_document_import = "allowed"
```

No migration. These settings are explicitly non-user-configurable per the
code comment ("Users cannot change these") — this is an admin/deployment-
level policy, not an end-user preference.

## Release note disposition

Proposed category: Bug fixes (data-loss prevention), grouped with the Word
add-in theme. Worth a specific mention given the data-loss angle: Word for
the web no longer silently replaces the whole document on every applied
edit — it writes in place where possible and now asks for confirmation
before a whole-document replacement, avoiding loss of tracked-change
authorship, comment metadata, and co-authors' concurrent edits. PC and Mac
behavior is unchanged in this release.
