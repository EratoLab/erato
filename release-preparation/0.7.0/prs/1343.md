# PR #1343: Offer Apple Silicon Macs the Apple Silicon sidecar build (ERDSCAR-44)

## Summary

Per the PR description: part 1 of ERDSCAR-44 (Mac platform readiness; the
sidecar-side counterpart is tracked in a separate `erato-desktop-sidecar`
repo, not reviewable from this diff). Fixes the Desktop Sidecar setup
page always recommending the Intel build on Apple Silicon Macs, because
every Mac browser's `navigator.platform`/user-agent reports `MacIntel`
regardless of actual CPU. Confirmed directly in `desktopSidecarPlatform.ts`:
the architecture is now inferred from, in order of preference, Chromium
client hints (`clientHintArchitecture`), the WebGL renderer string
(Firefox reports "Apple M…" for Apple Silicon vs. an Intel/AMD GPU name),
or ASTC texture compression support as a last resort (a code comment notes
Safari masks its renderer as "Apple GPU", but only Apple-family GPUs
decode ASTC, which the PR says was confirmed in WKWebView on an M-series
Mac). When no signal answers, the setup page per the PR lists Apple
Silicon first, marks neither build "Recommended for this device", and
explains how to check in About This Mac rather than guessing — since the
Intel build runs on Apple Silicon via Rosetta but not the reverse, a wrong
guess would be strictly worse in one direction than the other. Per the
PR, the same client-hints path also fixes Windows-on-ARM detection, where
Chrome's user agent reports `x64`. Universal (fat) binaries remain out of
scope deliberately — per the PR, CI already publishes separate macOS
targets and a universal binary would double the download size.

## Compatibility and configuration

Bug fix to client-side platform detection; no config keys, no database
migration, no protocol change. Existing download links/builds are
unaffected; only the setup page's recommendation logic changes.
