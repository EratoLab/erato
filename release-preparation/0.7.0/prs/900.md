# PR #900: Add support for Gateway API in Helm chart

- PR: https://github.com/EratoLab/erato/pull/900
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Adds optional Kubernetes Gateway API support to the `erato` Helm chart, as
an alternative to the existing `Ingress`-based exposure. A new template
`infrastructure/charts/erato/templates/gateway-api.yaml` renders an
`HTTPRoute` (`gateway.networking.k8s.io/v1`) when `gatewayApi.enabled` is
`true`. The template fails fast at render time (via Helm's `fail`) if the
cluster doesn't have the `gateway.networking.k8s.io/v1` API capability
registered, or if `gatewayApi.parentRefs` is empty — both are required for
a valid HTTPRoute. The generated route matches `PathPrefix: /` by default
and routes to the same backend service/port the chart already computes for
its existing ingress (`erato.exposureBackendName`/`erato.exposureBackendPort`
helpers), with support for extra custom rules
(`gatewayApi.extraRules`, `tpl`-rendered) for advanced routing needs.

## Compatibility and configuration

New `gatewayApi.*` values block, disabled by default
(`gatewayApi.enabled: false`) — no behavior change for existing chart
users. To use it:
```yaml
gatewayApi:
  enabled: true
  parentRefs:
    - name: shared-gateway
      namespace: gateway-system
      sectionName: https
  hostnames: []       # optional; omit to match all hostnames on the Gateway
  extraRules: []       # optional advanced HTTPRoute rules
```
Requires the cluster to already have Gateway API CRDs and a compatible
Gateway controller installed; the chart does not install these itself.
This is purely additive — the existing `ingress.*` configuration and
template are unchanged and can be used independently or (presumably) not
simultaneously with Gateway API, though this PR doesn't appear to enforce
mutual exclusivity.
