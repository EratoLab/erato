# PR #1043: Model switch marker: add-in parity and shared transcript notice

- PR: https://github.com/EratoLab/erato/pull/1043
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Follow-up to #1041's model-switch marker, addressing three gaps found on
review. Confirmed by reading the core files in full:

- **Add-in/Teams/Outlook parity, confirmed**: the switch-derivation logic
  previously lived inline in `Chat.tsx` (web-only). It is now extracted
  into a shared `useModelSwitches(messages, messageOrder, availableModels)`
  hook (confirmed byte-identical logic to the code it replaced — building
  the same `modelNames` map and calling the same `getModelSwitches`), and
  confirmed both `Chat.tsx` and `office-addin/src/core/AddinChatCore.tsx`
  now call this hook and thread its result (`modelSwitches`) through to
  their respective message-list renderers — so the marker now renders on
  the add-in/Teams/Outlook surface as well as web, not just web as before.
- **Shared `TranscriptNotice` component, confirmed**: a new
  `TranscriptNotice.tsx` generalizes the "centered, quiet annotation about
  the transcript" shape, and `ModelSwitchMarker.tsx` is confirmed rewritten
  to render through it (passing its icon and text as children) instead of
  duplicating the centered-flex-row markup inline. Per the PR (not
  independently re-verified): `ConversationIndicator` is also migrated to
  the same shared component while keeping its own distinct visual tone
  (`py-2`, `text-theme-fg-secondary`) via its own `className`/`style`
  props — the two notices share structure, not appearance.
- **Theme-token spacing, confirmed exactly**: `ModelSwitchMarker`'s
  previously hard-coded `gap-2` and `mb-4` are replaced — the icon-to-text
  gap now comes from `TranscriptNotice`'s own
  `style={{ gap: "var(--theme-spacing-control-gap)" }}`, and the marker's
  bottom spacing is now `style={{ marginBottom:
  "var(--theme-spacing-message-padding-y)" }}` — confirmed the marker
  additionally drops its own `className`-based spacing entirely in favor
  of these token-driven values, with a code comment noting the value
  intentionally uses the message-padding scale (not a dedicated token) so
  a theme that loosens message spacing loosens this too. The PR notes this
  also incidentally fixes rendering under the Beckhoff kit's right-aligned
  bubble renderer, since `TranscriptNotice`'s centering keeps the marker
  aligned with the column regardless of which side individual bubbles sit
  on (not independently re-verified, no access to that kit's code).
- The PR explicitly flags two known, deliberately unaddressed issues
  rather than silently leaving them: retired models render a raw provider
  id (`modelNames` has no fallback display name for a model no longer in
  `availableModels`); and a pre-existing, now user-visible bug in
  `AssistantChatSpacePage.tsx` passes `initialModelOverride` ungated on
  `chatId`, which can cause the composer to silently reset an existing
  assistant chat to its default model — which this marker will then
  correctly (if confusingly) record as a switch the user never
  deliberately made. Both are called out as belonging in separate PRs, not
  fixed here.

## Compatibility and configuration

None. Pure frontend refactor/parity fix on #1041's presentation-only
feature; no configuration or API changes. Visual effect: the marker's
spacing now responds to theme customization (`--theme-spacing-control-gap`,
`--theme-spacing-message-padding-y`) where it was previously fixed.
