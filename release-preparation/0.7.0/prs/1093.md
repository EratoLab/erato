# PR #1093: Add assistant usage view

- PR: https://github.com/EratoLab/erato/pull/1093
- Status: pending
- Category: Features and enhancements
- Theme: Assistant Hub and assistant sharing

## Summary

Adds a usage-statistics page for assistant owners/editors. New endpoint
`GET /assistants/{assistant_id}/usage`
(`backend/erato/src/server/api/v1beta/assistant_usage.rs`, new file)
returns invocation counts and unique-user counts, bucketed by day over a
selectable window (`weeks` query param: 1, 4, 12, or 52, default 4). Per
its own module doc comment, it is explicitly designed to "aggregate
persisted responses without exposing conversations or user identities" —
the SQL counts persisted assistant-generated messages (`raw_message->>'role'
= 'assistant'` with non-null `generation_metadata`, i.e. actual completed
generations, including regenerations and delegated calls per the docs)
across both the original assistant and any of its Assistant Hub versions,
including archived chats, and reports only counts (total and per-bucket
invocations, and distinct chat-owner counts as "unique users") — no
message content or per-user breakdown is returned. Access requires
`can_subject_edit_assistant` (owner/editor authorization). A new database
migration (`0040_add_assistant_usage_indexes`) adds supporting indexes for
this query. A new frontend page, `AssistantUsagePage.tsx` (279 lines),
presents this as charts/stats, reachable from the assistant edit page and
the assistants list.

## Compatibility and configuration

New configuration key, defaulting to disabled:
```toml
[assistants]
usage_view_enabled = false  # default; requires assistants.enabled
```
New additive database migration (indexes only, no schema/data change,
safe on existing data). No breaking change — the feature and its endpoint
return `404` unless both `assistants.enabled` and
`assistants.usage_view_enabled` are `true`.
