# PR #1132: Clone FrontendRegistry to avoid recompilation

- PR: https://github.com/EratoLab/erato/pull/1132
- Status: pending
- Category: Bug fixes
- Theme: None

## Summary

Fixes two related per-request performance regressions:

1. **`FrontendRegistry` cloned on every request.** `FrontendRegistry` was
   `#[derive(Clone)]` and installed as an Axum `Extension<FrontendRegistry>`
   layer; Axum's `Extension` extractor clones its value out of request
   extensions on every single request, so every static-file/HTML request
   was deep-cloning the entire frontend registry (bundle list, translation
   distribution, etc.). It's now wrapped in `Arc` at startup
   (`Extension<Arc<FrontendRegistry>>` in `main.rs`), so per-request
   "cloning" is just an atomic refcount bump.
2. **Admin-panel translation overrides recompiled on every request.** The
   `GET /public/common/overrides/{locale}` endpoint added in #991
   previously called `TranslationPoCache::default().compile_messages_json_from_contents(...)`
   fresh on every single request for that locale. `DistributionBundle`
   (`backend/erato/src/distribution/runtime.rs`) now compiles each
   admin-panel `.po` override exactly once per reload
   (`DistributionBundle::from_files`, run inside `spawn_blocking` since
   compilation is CPU-bound), caching the compiled JSON as `axum::body::Bytes`
   (cheap to clone/share across concurrent requests) — including caching a
   *failed* compilation's error, so a malformed catalog doesn't get
   re-attempted on every request either. New unit tests verify the cached
   bytes are shared (same pointer) across repeated lookups, that a reload
   replaces stale cached translations, and that one locale's invalid
   catalog doesn't hide other locales' valid ones.

## Compatibility and configuration

No configuration keys or migrations. Pure performance fix — the served
content and API behavior are unchanged; only per-request CPU/allocation
overhead is reduced. Most relevant to deployments with
`runtime_configuration.enabled = true` (the admin-panel translation
mechanism from #897/#991), where the recompilation-per-request bug would
have been most noticeable under load; the `FrontendRegistry` clone-per-request
fix benefits all deployments regardless of that setting.
