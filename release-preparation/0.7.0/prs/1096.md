# PR #1096: Move the capsule dialect, the alert frame and selected state onto themable channels

- PR: https://github.com/EratoLab/erato/pull/1096
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Second of nine styling-primitives-consolidation topics (after #1092's
spinner). Moves capsule/circle geometry, the alert frame, and selected-
state signaling off hardcoded Tailwind utilities and inline `style`
objects onto classes/tokens/attributes a theme can reach. Confirmed by
reading the complete `Alert.tsx` diff, the relevant `globals.css`
additions, and the assistant-hub avatar bug-fix sites in full:

- **Alert frame, confirmed exactly**: `Alert.tsx`'s previous
  `alertFrameStyle` inline-`style` object (border-radius/gap/padding,
  applied only for `geometryVariant === "message"`, and — critically —
  unreachable by any theme CSS rule since inline styles win by
  specificity) is removed entirely, replaced by `.alert-geometry`
  (default variant) or `.message-frame-geometry` (framed variant) classes,
  plus new `data-ui="alert"`/`data-tone={type}` attributes. Confirmed
  `.message-frame-geometry`'s CSS declarations
  (`border-radius: var(--theme-radius-message)`, matching padding/gap) are
  byte-identical in value to the removed inline object, so the framed
  variant is visually unchanged; only its reachability by theme CSS
  changes.
- **Disclosed visible delta, confirmed exactly**: `.alert-geometry`
  declares `border-radius: var(--theme-radius-base)`, replacing the
  previous hardcoded `rounded-md` (0.375rem/6px) Tailwind utility — this
  means any theme that sets `radius.base` to a different value (the PR
  names `open-webui-like` at `0.75rem` and the Beckhoff fork theme at the
  same value) now renders every plain (non-framed) `<Alert>` at that
  theme's radius instead of the previous fixed 6px. This is a real,
  disclosed visual change on live customer themes, not a code defect —
  confirmed as an intentional consequence of moving the frame onto a
  token, with a documented one-line `theme.css` escape hatch
  (`[data-ui="alert"] { border-radius: 0.375rem; }`) for a customer
  wanting to keep the old corner.
- **The capsule/circle split, and the real bug it fixes, confirmed
  exactly via `assistantHubUtils.tsx`**: the two assistant-hub avatar
  spans previously used `rounded-[var(--theme-radius-pill)]` on fixed
  `size-10`/`size-14` boxes — since `--theme-radius-pill` is a themeable
  token (not always `9999px`), a theme setting it to a non-circular value
  (the PR names the Trilux themes resolving it to `0.5rem`) rendered
  these avatars as rounded squares instead of circles. Confirmed the fix
  switches both sites to a new `.avatar-geometry` class, which declares a
  fixed `border-radius: 50%` reading no theme token at all — so these
  avatars are now circles under every theme, not just ones that happen to
  leave the pill token at `9999px`. Confirmed two other true capsule
  sites (`getAssistantHubStatusClassName`, `AssistantHubCurrentPublished
  Indicator`) correctly move to the new `.pill-geometry` class (reading
  `radius.pill`, the intentionally-themeable token) instead, preserving
  the capsule/circle distinction the PR describes.
- Per the PR (not independently re-verified given remaining scope): ten
  more capsule sites move to `.pill-geometry` across badges, status pills,
  trace/tool-call chips, cloud-drive/sharing badges, and the Teams picker
  chip; the modal close button keeps its raw `<button>` (with a stated,
  specific reason `Button`'s unconditional `focus-ring` can't be
  overridden to `focus-ring-tight`, and `ring-offset-2` would draw an
  outside ring on an absolutely-positioned element) and gains
  `.modal-close-geometry`, deliberately *without* a `data-geometry`
  attribute after determining two customer themes' existing rules key on
  that attribute under a documented "reaches only real Button components"
  contract, which a raw button carrying it would have falsified for no
  functional benefit; and the selected-state work makes the contract
  ARIA-first (no parallel `data-` attribute where an element's own ARIA
  role attribute already communicates selection), adding a presence-only
  `data-` attribute on four non-widget wrapper/decorative surfaces and
  `aria-current="page"` on the sidebar navigation's active row (previously
  announced by nothing, since the active branch renders no link) — while
  deliberately excluding the chat-history loading skeleton from the new
  attribute, since it borrows the selected-surface fill class purely as a
  placeholder and marking it selected would paint phantom selected rows
  during every load.

## Compatibility and configuration

**Real, disclosed visual change**: any deployment using a theme that sets
`radius.base` away from the default `0.375rem` (named: `open-webui-like`,
the Beckhoff fork theme, and Trilux via its legacy `borderRadius`
back-fill) now renders plain `<Alert>` components at that theme's base
radius rather than the previous fixed 6px — a one-line `theme.css`
override is documented for any customer wanting to preserve the old
corner. The assistant-hub avatar fix is a pure bug fix with no
configuration surface — avatars render as circles under every theme now,
correcting a defect specifically present under Trilux themes' pill-token
value.
