# PR #1370: Make all branding paths configurable

- PR: https://github.com/EratoLab/erato/pull/1370
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Branding configurability

## Summary

No GitHub description beyond "Related Linear issue: ERMAIN-965"; evaluated
from the diff. Adds deployment-configurable overrides for every
browser-visible branding image path that was previously hardcoded or only
reachable through the fixed `frontend.favicon_path`/theme mechanism:

- **Three new top-level `[frontend]` keys, confirmed exactly**:
  `logo_path`, `logo_dark_path`, `assistant_avatar_path` (all
  `Option<String>`, default `None`) — consumed by
  `ThemeProvider.tsx`/`Logo.tsx` (174 new lines of tests confirm light/dark
  logo and avatar override behavior) and exposed to the frontend via the
  existing `frontend_environment` plumbing (237-line diff in
  `frontend_environment.rs`).
- **Five new per-add-in manifest "source path" overrides, confirmed
  exactly**: `MsOfficeAddinManifestConfig` gains
  `icon_source_path`/`high_resolution_icon_source_path`/`icon_16_source_path`/
  `icon_32_source_path`/`icon_80_source_path`, and
  `MsOfficeTeamsManifestConfig` gains
  `color_icon_source_path`/`outline_icon_source_path`/
  `small_color_icon_source_path` — all `Option<String>`, all documented as
  "local source override; leaves the manifest URL or ZIP entry unchanged",
  i.e. these redirect where the *packaged* icon bytes are read from on disk
  without touching the already-configurable manifest-facing path/filename
  fields that existed before this PR.
- **A new `favicon_path` override on `MsOfficeAddinConfig` itself,
  confirmed exactly**: `Option<String>`, documented as inheriting
  `frontend.favicon_path` when unset — lets the Office add-in's own browser
  tab icon diverge from the main web app's.
- Per the PR (not independently re-verified): the `router.rs` (54-line) and
  `teams.rs`/`translations.rs`/`distribution/mod.rs` diffs that actually
  serve these new source-path overrides at runtime, and the exact
  precedence/fallback chain when a source path is set but the file is
  missing.

## Compatibility and configuration

None breaking. Every new field is an `Option<String>` defaulting to `None`,
preserving prior hardcoded/default behavior for any deployment that
doesn't set them. Purely additive branding configurability.
