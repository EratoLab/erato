# PR #1089: Add a user text-size setting to the Appearance tab (ERMAIN-739)

- PR: https://github.com/EratoLab/erato/pull/1089
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Adds a "Text size" preference (Small/Default/Large/X-Large) to
Preferences → Appearance, scaling the whole interface via a root
font-size percentage, applied across the web app, Outlook add-in, and
Teams. Confirmed by reading the complete `ThemeProvider.tsx` diff and the
relevant `globals.css` diff:

- **Root font-size percentage mapping, confirmed exactly**: `globals.css`
  maps `:root[data-text-size="small"|"large"|"x-large"]` to `font-size:
  87.5%|112.5%|125%` respectively — percentages, not fixed pixel values, with
  a code comment stating this deliberately lets the browser's own
  default-font-size preference still apply underneath. No rule exists for
  `"default"`, consistent with the attribute being absent in that state.
- **No attribute at the default size, confirmed exactly**: `ThemeProvider`'s
  new `useLayoutEffect` calls `document.documentElement
  .removeAttribute("data-text-size")` when `textSize === "default"` and
  sets the attribute otherwise — matching the PR's stated claim that the
  default state leaves existing baselines completely untouched (no CSS
  selector matches an absent attribute, so the 100%-default case adds
  zero new styling).
- **`useLayoutEffect`, not `useEffect`, confirmed exactly**: a code
  comment states this precisely — since the attribute changes the root
  font-size, a passive effect would paint one frame at the old scale
  before applying the new one.
- **Per-device persistence mirroring the existing theme-mode pattern,
  confirmed exactly**: `TEXT_SIZE_LOCAL_STORAGE_KEY = "text-size"`,
  read/written via the same `localStorage`-based `getSavedTextSize`/
  `setTextSize` pattern as `THEME_MODE_LOCAL_STORAGE_KEY`/`toggleTheme`,
  with an `isTextSize` type guard defending against a corrupted/stale
  stored value falling back to `"default"`.
- Per the PR (not independently re-verified given remaining scope): the
  new `TextSizeSetting` component (a `SegmentedControl`, 61 lines) is
  added to both `UserPreferencesDialog` (web) and
  `AddinSettingsDialogCore` (Outlook add-in/Teams) after the existing
  color-mode cards; `useApplySidebarWidth` re-clamps a persisted sidebar
  width when text size changes (presumably because the sidebar's pixel
  width no longer matches its rem-based content at a larger scale);
  `CountBadge` drops a hardcoded pixel font-size so it also scales with
  `rem`; and both the new component and its type are exported additively
  from the library barrel and the generated shared surface with no
  version bump.

## Compatibility and configuration

None breaking. Purely additive user preference, defaulting to no-op
(`"default"` applies no attribute/CSS change). Any element sized in
pixels (borders, scrollbars, modal size caps — per the PR, not
independently verified) does not scale with this setting by design,
consistent with the `rem`-based percentage mechanism only affecting
`rem`-sized content.
