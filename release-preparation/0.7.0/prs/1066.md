# PR #1066: new hook useChatHistoryRowPresentation

## Summary

Small, fully verified extraction PR. Centralizes the chat-history row's
title/status/composed-`aria-label` logic — previously inlined directly
in `ChatHistoryListItem` — into a new exported
`useChatHistoryRowPresentation` hook. Confirmed by reading the complete
`ChatHistoryList.tsx` and `shared/index.ts` diffs:

- **Straight extraction, confirmed by direct comparison**: the new hook
  wraps the pre-existing `useRowTitle`/`useRowStatus` hooks and composes
  `ariaLabel: [title, ...extraLabels, statusLabel].filter(Boolean).join(",
  ")`, which is byte-identical in shape to the array/join logic
  `ChatHistoryListItem` previously built inline
  (`[rowTitle, runOrigin?.label, statusLabel].filter(Boolean).join(", ")`)
  — the `extraLabels` parameter generalizes the single `runOrigin?.label`
  slot the call site previously hardcoded. `ChatHistoryListItem` is
  confirmed rewritten to call the new hook (passing `[runOrigin?.label]`
  as `extraLabels`) and its own inline composition is removed entirely.
- **Kit export, confirmed exactly**: `useChatHistoryRowPresentation` is
  exported from `frontend/src/shared/index.ts` with a code comment
  stating deliberately: "The resolved result, not the stores behind it —
  kits read status, never write it" — matching #1045's
  `resolveSessionRowStatus`/`sessionNeedsAttention` design goal that a kit
  cannot reimplement the status-resolution logic and end up with a row
  dot that disagrees with which list bucket the row sits in.

## Compatibility and configuration

None. Pure frontend refactor with no behavior change for the web
sidebar's existing row rendering (confirmed byte-identical composition
logic above); purely additive new export for component-kit consumers
that want to build a custom chat-history row presentation consistent
with the host's own status resolution.
