## Summary

Follow-up to #1143 (not reviewed in this pass), adding protocol
methods/schemas the PR states were missed: `indexing.start.v1`,
`indexing.stop.v1`, and `search.query.v1` for the desktop sidecar
protocol package (a separate spec/client package, `desktop-sidecar-
protocol/`, used by the Windows desktop sidecar companion for local
email/file indexing and search — primarily relevant to on-prem/Exchange
SE deployments per this session's earlier reviews of related on-prem
work). The PR has minimal narrative beyond a Linear issue reference, so
this review confirms the new `SPEC.md` prose against the actual JSON
schema files it describes, rather than checking authored claims:

- **`indexing.start.v1`'s optional `rebuild` object, confirmed exactly**:
  the new `indexing-start-v1-params.schema.json` defines an optional
  `rebuild` object with BM25-tuning fields (`k1`, `b`, `indexedAvgdl`,
  `maxTextBytes`, each with sensible numeric bounds, e.g. `b` constrained
  to `[0,1]`, `maxTextBytes` capped at 64 MiB) — matching the `SPEC.md`
  prose's description of an optional shadow-rebuild trigger where
  "omitted fields use the implementation's current index settings."
- **`search.query.v1`'s filter set and limit bounds, confirmed exactly**:
  the new `search-query-v1-params.schema.json` defines `limit` (default
  `20`, `minimum: 1`, `maximum: 100`) and a `filters` object with
  `sender`, `mailboxId`, `dateFrom`/`dateTo` (both plain `integer`,
  consistent with the prose's "Unix seconds"), `fileType`, and `kind`
  (an enum) — matching the `SPEC.md` prose's stated defaults and filter
  semantics precisely. Confirmed the schema's `kind` enum additionally
  includes `teams_message` alongside `email`/`file`, a third value not
  called out in the `SPEC.md` prose's "kind selects email/file" sentence
  — a minor documentation gap (the schema is more permissive than the
  prose states) rather than a functional discrepancy, not flagged as a
  concern.
- Per the PR (not independently re-verified given remaining scope): the
  `indexing.stop.v1` semantics (idempotent, drains in-flight work,
  preserves index files, leaves search available, returns state
  `stopped`); the `capability_unavailable` error-reason vocabulary
  (`index_reset_in_progress`, `index_not_initialized`) referenced in the
  spec prose for both methods under contention with an in-progress reset
  or an uninitialized index; the generated TypeScript client/validator
  code (`typescript/src/generated/*.ts`, `validators.mjs`, ~1750 lines
  combined, machine-generated from the schemas per the package's own
  `scripts/generate.mjs`); and the reference mock server's implementation
  in `test-server/src/server.ts` (39 lines), stated by the spec as
  returning synthetic empty results and modeling only lifecycle state,
  not real BM25 scoring or rebuilding.

## Compatibility and configuration

None for the main erato backend/frontend — this PR is entirely scoped to
the separate `desktop-sidecar-protocol` package (spec, schemas, and
generated TypeScript client code), consumed by the desktop sidecar
companion application, not the web/add-in products reviewed elsewhere in
this release-notes pass. Additive protocol methods; no existing method's
schema is changed in a way this review identified as breaking.
