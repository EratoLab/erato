# PR #1091: Give customer themes hooks and tokens for cards, tab rails, attachments, and the add-in header

- PR: https://github.com/EratoLab/erato/pull/1091
- Status: pending (diff reviewed)
- Category: Bug fixes
- Theme: None

## Summary

Host/add-in half of Outlook add-in theming parity work: adds stable
`data-ui` hooks and a new `radius.card` token so customer themes can
style cards, tab rails, and attachment groups without keying on DOM
shape, plus one real behavioral bug fix in the add-in history drawer.
Confirmed by reading the relevant `AddinHistoryDrawerCore.tsx` and
`EntityRow.tsx`/`theme.ts` diffs:

- **Metadata-switch pass-through fix, confirmed exactly**: the add-in
  history drawer's `ChatHistoryList` now receives `showTimestamps=
  {chatHistoryShowMetadata}`, sourced from `useFeatureConfig().sidebar`
  — previously no `showTimestamps` prop was passed at all, so the drawer
  rendered file counts/ages using the component's own default regardless
  of the backend's `sidebar_chat_history_show_metadata` configuration
  switch. This is a genuine fix, not just a hook addition: a deployment
  that disabled this metadata display for the web sidebar previously kept
  seeing it in the add-in drawer regardless.
- **New `radius.card` token, confirmed added to `theme.ts`**: `card:
  "0.5rem"` alongside the existing `radius.dropdown` (from #1088),
  plumbed the same way. `EntityRow.tsx` is confirmed switched from
  `rounded-[var(--theme-radius-control)]` to
  `rounded-[var(--theme-radius-card)]`, and gains `data-ui="entity-row"`.
- **Stock-delta claim not independently confirmed, flagged as a
  discrepancy**: the PR states "entity rows go from 0.75rem to 0.5rem" as
  a visual stock-theme delta from this change. However, the diff read
  shows `--theme-radius-control` (what entity rows read *before* this
  PR) already defaults to `0.5rem` in `theme.ts`, identical to the new
  `--theme-radius-card` default entity rows read *after* this PR — so
  the token swap alone, as diffed, implies no default-theme visual
  change for entity rows, contradicting the PR's stated `0.75rem →
  0.5rem` delta. This may be explained by a `ThemeProvider` override or
  an intermediate class not visible in the hunks read, but it was not
  resolved in this review — worth a maintainer's attention before
  treating the stock-delta table as accurate.
- Per the PR (not independently re-verified given the remaining scope):
  `RadioCard.tsx`'s 27-line diff adds a `.option-card-geometry` class,
  clips hover fill to the rounded border, switches the checked tint to
  `background.selected`, suppresses hover on an already-checked card, and
  adds `data-ui="option-card"`/`data-selected`/`option-card-icon`/
  `option-card-details` hooks (stated stock delta: small-size/icon-tile
  radius 0.375rem→0.5rem, checked tint neutral-200→neutral-300, not
  independently verified); hand-rolled settings tab rails gain
  `data-ui="tab-rail"`; attachment group frames and thread-message cards
  (`GroupedFileAttachmentsPreview.tsx`, 56 lines) move to unlayered
  geometry classes with a frame-radius-minus-inset derivation mirroring
  #1088's dropdown-row pattern, also fixing a hardcoded `rounded-b-md` on
  the expanded sticky frame's item well; and the add-in chat header
  (`AddinChatCore.tsx`, 58 lines) is restructured into one in-flow header
  row (`data-ui="addin-chat-header"`) with the drawer trigger beside a
  kit-supplied top-left accessory when one exists, falling back to the
  previous floating-trigger behavior when no kit accessory is registered
  — with a corresponding web-side reservation of the floating toggle's
  column when the sidebar is collapsed in hidden mode.

## Compatibility and configuration

None breaking. New additive theme tokens (`--theme-radius-card`) and
`data-ui` hooks for customer-theme targeting; documented in
`theming.mdx`. The add-in history-drawer metadata fix is a real,
intentional behavior correction (see above) for any deployment currently
relying on `sidebar_chat_history_show_metadata = false` to hide
timestamps/file-counts, which previously only worked on the web sidebar.
