## Summary

Adds a new local-only, dev/test-only Python tool,
`infrastructure/erato-chaos-creator/` — a small FastAPI service and CLI for
controlled failure injection during local development and E2E testing.
Per its own README, it's "intentionally not a general Redis administration
API": its only supported action is purging an oauth2-proxy session from
Redis (`purge-session` by exact session key, or `purge-cookie`, which
decodes an oauth2-proxy signed cookie to extract the session ticket ID —
"the secret is not used or stored"). It performs one exact Redis `DEL`,
explicitly not scanning/globbing/deleting by prefix. Defaults to
`redis://localhost:6379` (matching the local-auth setup from #832) and
binds to `127.0.0.1:8000`, configurable via `ERATO_CHAOS_REDIS_URL`,
`ERATO_CHAOS_HOST`, `ERATO_CHAOS_PORT`. Presumably used by E2E tests this
cycle exercising session-invalidation/recovery behavior (e.g. related to
the multi-replica/generation-resilience work in #898/#899/#995/#1085).

## Compatibility and configuration

None. This is purely local development/test tooling
(`infrastructure/erato-chaos-creator/`), not part of any production
deployment artifact, backend, or frontend code path. No configuration
keys, migrations, or runtime behavior changes to the shipped product.
