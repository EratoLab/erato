# PR #797: Clean up license information for cargo-deny

- PR: https://github.com/EratoLab/erato/pull/797
- Status: pending (diff reviewed)
- Category: Chores & Developer experience
- Theme: None

## Summary

Reorganizes and tightens `backend/deny.toml`, the config for `cargo-deny`'s
license/dependency auditing. Sets `all-features = true` (was `false`) so
license scanning covers all Cargo features, not just defaults.

The `licenses.allow` (general, applies-to-any-crate) list and
`licenses.exceptions` (per-crate) list swap several entries in opposite
directions, which is easy to misread as a single "expand the allow-list"
change but is actually two separate moves:
- **Promoted to the general allow-list** (now trusted for any crate, not
  just a named one): `0BSD`, `CDDL-1.0`, `MPL-2.0` (previously present
  as a plain `"MPL-2.0"` entry with a `# TODO: Bake sources for libraries
  under MPL-2.0` comment — that TODO is dropped, meaning `MPL-2.0` is now
  accepted outright rather than provisionally), and `Unicode-DFS-2016`.
  Promoting `CDDL-1.0` and `Unicode-DFS-2016` specifically makes two
  previously per-crate exceptions redundant, and both are removed as a
  result: `{ allow = ["CDDL-1.0"], crate = "inferno" }` (a transitive
  `jemalloc_pprof` profiling dependency) and
  `{ allow = ["Unicode-DFS-2016"], crate = "finl_unicode" }` (a transitive
  `kreuzberg`/`comrak` dependency) — both crates confirmed still present
  in `backend/Cargo.lock` at this PR's head, so their license is now
  covered by the general allow-list instead of a dedicated exception.
- **Demoted from the general allow-list to per-crate exceptions**
  (tightened — no longer trusted for any crate, only the ones explicitly
  named, each with a review-justification comment): `CC0-1.0` → now only
  `axum-tracing-opentelemetry`, `tracing-opentelemetry-instrumentation-sdk`,
  and `tiny-keccak` ("No indication for patent usage"); `CDLA-Permissive-2.0`
  → now only `webpki-roots` and `webpki-root-certs` ("Data license — Only
  contains data (root certificates)"). `"OpenSSL"` is dropped from the
  allow-list entirely with no replacement exception (consistent with the
  OpenSSL removal from the dependency tree in the parallel #781 rustls
  switch this cycle — the `openssl` crate itself, whose license needed
  this allowance, is confirmed removed from `backend/Cargo.lock` by #781).

All five newly-exception-scoped crates
(`axum-tracing-opentelemetry`, `tracing-opentelemetry-instrumentation-sdk`,
`tiny-keccak`, `webpki-roots`, `webpki-root-certs`) and both
`[[licenses.clarify]]` crates (`ical`, `synonym`) were confirmed present in
`backend/Cargo.lock` at this PR's head — these are real, exercised
exceptions, not speculative/dead entries for dependencies that don't
actually exist in the tree. The `[[licenses.clarify]]` entries for `ical`
and `synonym` point to specific upstream `LICENSE` file URLs/commit hashes
as evidence for licenses that apparently aren't machine-detectable from
those crates' published metadata. `kreuzberg`'s existing `Elastic-2.0`
exception is untouched by this diff (stays in place, unmoved) but sits
under an updated comment, `# TODO: Update to xberg, which is MIT`,
replacing a prior, differently-scoped comment about MPL-2.0 sourcing —
foreshadowing the separate `kreuzberg` → `xberg` migration completed later
this cycle in #830.

## Compatibility and configuration

No user-facing configuration or runtime behavior change. This only affects
the CI/dev-tooling license-compliance check (`cargo deny check licenses`);
it does not change which crates are compiled into the backend or any
runtime dependency versions.
