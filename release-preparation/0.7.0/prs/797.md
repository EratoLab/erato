# PR #797: Clean up license information for cargo-deny

## Summary

Reorganizes and tightens `backend/deny.toml`, the config for `cargo-deny`'s
license/dependency auditing. Sets `all-features = true` (was `false`) so
license scanning covers all Cargo features, not just defaults. Expands the
`licenses.allow` list with additional OSI-approved licenses (`0BSD`,
`CDDL-1.0`, `MPL-2.0`, `Unicode-DFS-2016`) and adds explanatory comments;
removes the blanket `"CC0-1.0"`, `"CDLA-Permissive-2.0"`, and `"OpenSSL"`
entries from the general allow-list, replacing them with per-crate
`licenses.exceptions` entries (`axum-tracing-opentelemetry`,
`tracing-opentelemetry-instrumentation-sdk`, `tiny-keccak`, `webpki-roots`,
`webpki-root-certs`) with justification comments about patent-compliance
review. Adds `[[licenses.clarify]]` entries for `ical` and `synonym` crates
whose license expression apparently isn't machine-detectable from their
repo, pointing to specific upstream `LICENSE` file URLs/commits as
evidence. The prior blanket `"MPL-2.0"` allow-with-a-TODO is replaced by
moving `kreuzberg`'s `Elastic-2.0` exception to the reviewed-exceptions
section (still present, now with a `# TODO: Update to xberg, which is MIT`
comment — consistent with the separate #830 dependency swap this cycle).

## Compatibility and configuration

No user-facing configuration or runtime behavior change. This only affects
the CI/dev-tooling license-compliance check (`cargo deny check licenses`);
it does not change which crates are compiled into the backend or any
runtime dependency versions.
