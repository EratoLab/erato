# PR #961: Force "whole organization" option to be at top of share grants

- PR: https://github.com/EratoLab/erato/pull/961
- Status: pending
- Category: Features and enhancements
- Theme: Assistant Hub and assistant sharing

## Summary

Two related changes to the "whole organization" sharing target introduced
in #903:

1. **UI ordering fix**: previously in `SubjectSelector.tsx`, the
   whole-organization option was included as one of the `groups` (mixed
   in with organization groups in the "groups" bucket, still generally
   near the top by virtue of being prepended to that array, but as part of
   the groups grouping). It's now rendered as its own dedicated row,
   unconditionally pinned above the search/filtered results (comment:
   "Keep the whole-organization target at the top of the list"),
   independent of the current type filter (user/group/all) or search
   query.
2. **New default-audience config**: `assistant_hub.default_share_with_whole_organization`
   (default `true`) — when submitting a **new** assistant to the
   Assistant Hub, the whole-organization audience option is now
   pre-selected by default (per `AssistantHubSubmitPage.tsx`'s 117-line
   diff, not read in full). Per the documentation, "existing assistant
   versions retain their previous share grants" — i.e. this only affects
   the default selection shown for a fresh submission, not any
   already-submitted/reviewed version's actual grants.

## Compatibility and configuration

New configuration key, defaulting to `true`:
```toml
[assistant_hub]
default_share_with_whole_organization = true  # default
```
No migration. Behavior change for new Assistant Hub submissions: unless an
operator sets this to `false`, a submitter will see "whole organization"
pre-checked as the audience by default (still changeable before
submitting) — deployments that want submitters to explicitly opt into
organization-wide visibility should set this to `false`.
