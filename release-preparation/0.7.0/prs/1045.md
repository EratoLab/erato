# PR #1045: Add a delegated-runs filter and pane attention badge

- PR: https://github.com/EratoLab/erato/pull/1045
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: Delegation

## Summary

Gives both the web sidebar and the add-in pane a way to find a background
delegated run after leaving its launching chat (Scope 1), and gives the
add-in pane a way to learn one finished while the pane wasn't open (Scope
2). Notably, the PR describes a four-way adversarial review of its first
cut that found and fixed four real defects — all four confirmed here by
direct diff read, not just taken on trust:

- **Filter facet, confirmed via `chatHistoryFilterStore.ts` and
  `ChatHistoryList.tsx`**: a new `delegatedFilter`, orthogonal to
  `typeFilter` (composable, since a delegated run is usually also an
  assistant chat), defaults to `"hidden"`. Delegated rows are identified
  purely by `delegatedRunOrigin(session)` returning non-null — confirmed
  this doubles as the row-is-a-run test used to withhold "Remove" (see
  below) and to render the "From &lt;origin&gt;" line.
- **Defect 1 — poller mounted outside `AuthGate`, confirmed via
  `SharedAddinShell.tsx`**: `<GenerationStatusPoller />` previously
  rendered as a sibling of `children` inside `SharedAddinShell`, i.e.
  above/outside `AuthGate`'s own render tree. Confirmed the fix removes it
  from there and adds `<GenerationStatusPoller seedOnMount />` inside
  `AuthGate`'s returned children — a code comment states the prior
  placement fired the seed request before `SessionAuthProvider` existed,
  whose resulting 401 advanced the auth refresh-backoff counter from a
  self-inflicted failure.
- **Defect 2 — badge counted the viewed chat, confirmed via the new
  `useGenerationIndicatorCount.ts`**: the hook builds an `inView` set from
  *two* ids — `currentChatId` (from the generation-status store) and
  `newlyCreatedChatId` (from the messaging store) — confirmed matching the
  PR's stated reason that a first turn streams before its chat id is
  adopted, so counting only the status store's id would leave that turn's
  terminal outcome stuck on the badge. Confirmed `action_required` status
  is added to the count set *before* the `inView` check and skips it
  entirely (via `continue`), so a pending tool approval in the open chat
  still counts, exactly as described as the deliberate exception.
- **Defect 3 — row dot and "Unread" bucket disagreeing, confirmed via
  `chatHistoryGrouping.ts`**: both now route through one function,
  `resolveSessionRowStatus` (dot) and the new `sessionNeedsAttention`
  (bucket), which explicitly calls `resolveSessionRowStatus` internally so
  the bucket cannot compute a different answer than the dot. Confirmed the
  one deliberate narrowing: `sessionNeedsAttention` returns `false` for a
  consumed (`"cleared"`) tombstone even though `resolveSessionRowStatus`
  still reports a status for it — matching the stated design that a
  dismissed run's dot survives (durable, from `delegated_run_outcome`) but
  it no longer sits in "Unread".
- **Defect 4 — Remove withheld from delegated-run rows, confirmed via
  `ChatHistoryList.tsx`**: the row's action-menu array conditionally
  omits the "Remove" entry entirely (`...(runOrigin ? [] : [{ label:
  t\`Remove\`, ... }])`) when `runOrigin` is non-null, with a code comment
  giving the exact stated reasons: `archive_chat` has no in-flight-
  generation check, no cancellation, no unarchive route, and a
  tool-approval-parked run archived this way could never be resumed.
  Share and Rename are confirmed left in the menu (not touched by this
  diff hunk).
- Per the PR (not independently re-verified given remaining scope): the
  persisted `delegatedFilter` folds back to `"hidden"` when either
  `assistantsEnabled` or `delegationEnabled` closes (mirroring the
  existing foldback pattern from #1027); no client-side row filtering is
  added since the list is server-paginated via `include_delegated` on
  `buildRecentChatsFilterParams`; and the attention-count hook is shared
  between the web sidebar's rail badge and the add-in's drawer trigger via
  the same `useGenerationIndicatorCount`.

## Compatibility and configuration

None new. Scope 1 (the filter facet) is gated on the existing
`assistantsEnabled && delegationEnabled` pairing and has no backend
change. Scope 2 (the pane attention badge) only has observable effect
where `ASSISTANTS_DELEGATION_ALLOW_BACKGROUND` is enabled (default
`false`). No API or database changes.

## Release note disposition

Proposed category: Features and enhancements, part of the in-progress
background-delegation stack. Scope 1 (the filter facet) is usable
regardless of background-delegation being enabled, since any delegated
run (awaited or background) can be found this way; Scope 2 is not
independently release-note-worthy until `ASSISTANTS_DELEGATION_ALLOW_BACKGROUND`
is enabled somewhere. Worth a mention alongside the combined delegation
entry: delegated runs can now be found via a dedicated filter in both the
web sidebar and the add-in pane's history drawer.
