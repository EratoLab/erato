# PR #1138: Declare the component-kit surface and the themable host class names

- Category: Bug fixes
- Theme: None

## Summary

Ninth and last of the styling-primitives series (after #1092, #1096,
#1100, #1101, #1105, #1115, #1129, #1133 — every one confirmed by this
session to match its description precisely). Where the previous eight
moved markup onto shared primitives, this one formalizes and enforces
the component-kit-facing export contract itself: splits the hand-pinned
half of `@erato/frontend/shared` into a dedicated `kit-surface.ts`
module, pins six names the PR identifies as currently reachable only as
a byproduct of an unrelated import graph (three of which are declared
dependencies of shipped kits), and adds CI tooling to keep the contract
honest going forward. Confirmed by reading the relevant `shared/index.ts`
and `shared/kit-surface.ts` diffs:

- **The refactor is a pure relocation with zero exports lost, confirmed
  exactly**: `shared/index.ts`'s entire hand-pinned export block
  (matching what this session already confirmed piece-by-piece across
  #1055, #1066, #1067, #1100, #1101, #1105, #1129) is removed and
  replaced with a single `export * from "./kit-surface"` — and the new
  `kit-surface.ts` is confirmed to contain that exact same set of prior
  exports, plus the six new byproduct-dependency names.
- **The six previously-byproduct names are now explicitly pinned,
  confirmed exactly**: `MailIcon`, `PinIcon` (`export { MailIcon, PinIcon
  } from "@/components/ui/icons/index"`), `FileUploadLoading` (with its
  props type), `Card`, `ThreadMessageCard` (with its props/presentation
  types), and `ThemeProvider` (with its props type) are all confirmed
  present as explicit named exports in `kit-surface.ts` — matching the
  PR's table naming these six and identifying three (`MailIcon`,
  `PinIcon`, `FileUploadLoading`) as declared dependencies of the shipped
  `openwebui` and `filesource-grid` kits, per their respective
  `kit.json` files (not independently re-verified against those external
  kit manifests, which are outside this repository).
- **Version bump matches exactly, confirmed by direct diff inspection**:
  `ERATO_SHARED_SURFACE_VERSION` stays `1` (unchanged in this diff) while
  `ERATO_SHARED_SURFACE_MINOR` moves from `5` to `6` — matching the PR's
  stated rationale precisely: both shipped kits compare the major version
  with strict `!==` at startup, so bumping it would make every deployed
  kit log an error until rebuilt, while the minor version exists
  specifically to signal additive-only growth a kit can opt into without
  demanding a rebuild.
- Per the PR (not independently re-verified given the remaining scope):
  the new `component-kit/check-kit-manifest.mjs` (354 lines) failing a
  kit build that imports a *value* (not just a type) from
  `@erato/frontend/library` rather than the pinned `/shared` surface,
  wired into `component-kit-example`'s build and its own CI step; the
  frozen 67-entry `ERATO_GEOMETRY_CLASS` record making CSS class-hook
  names resolvable programmatically rather than copy-pasted as string
  literals a rename could silently break; the shared
  `eslint/themable-geometry.mjs` rule replacing two hand-synchronized
  copies between the frontend and add-in ESLint configs; a disclosed
  fix to the kit-surface-check script itself (`process.argv[1] ===
  fileURLToPath(import.meta.url)` evaluating false through a pnpm
  symlink, which had silently disabled the entire check when invoked
  that way); the new shared `createEratoLibraryMock` stub-set factory
  replacing per-suite hand-rolled add-in barrel mocks, with a companion
  test asserting the stub set covers the full declared surface; and the
  PR's own claimed TypeScript-checker-snapshot verification (`/shared`
  380→404 names, `/library` 1272→1283 names, zero removals on either
  side), not independently reproduced.

## Compatibility and configuration

**No visible delta**, confirmed consistent with the PR's own explicit
claim — this is a pure export-surface reorganization and CI-tooling
addition with no component markup, class value, or token change. The
`ERATO_SHARED_SURFACE_VERSION` major staying at `1` means no deployed
component kit needs an immediate rebuild; the minor bump to `6` is purely
informational for kits that want to gate a feature on a specific host
capability.
