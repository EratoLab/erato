## Summary

Replaces CI's Kubescape (Kubernetes security/compliance scanning of the
Helm chart) invocation, previously via a fork/action
(`EratoLab/kubescape-github-action`, itself a workaround for upstream
Kubescape bugs per the removed comment referencing
`kubescape/kubescape#3056` and `kubescape/github-action#78`), with a
direct CLI install and invocation. `.github/workflows/docker-build.yml`
now downloads a specific pinned Kubescape release
(`4.0.13`, verified via SHA-256 checksum) and runs `kubescape scan
framework <framework> ... --controls-version v2.0.35` for each of the four
existing frameworks (DevOpsBest, MITRE, NSA, SOC2) against
`infrastructure/charts/erato`, keeping the same per-framework fail
thresholds as before (20, 0, 35, 35 respectively) and adding an explicit
`--severity-threshold high`. Per the new comment, both the scanner and
controls versions are pinned and meant to be upgraded together, since
"newer controls may require CEL policies absent from an older binary's
embedded bundle" — the CLI is used directly because the upstream GitHub
Action has no way to pin a specific controls version.

## Compatibility and configuration

No configuration keys, migrations, or production runtime changes; this is
purely a CI security-scanning tooling change. No behavior change to the
application itself — only how/which Kubescape version scans the Helm
chart in CI. The `--severity-threshold high` addition could in principle
change which findings count toward the existing fail thresholds compared
to before (not verified whether this threshold was implicitly applied by
the old action).
