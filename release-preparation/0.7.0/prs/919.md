# PR #919: Merge settings into an entity-first MCP & Apps pane

- PR: https://github.com/EratoLab/erato/pull/919
- Status: pending (diff reviewed)
- Category: Features and enhancements
- Theme: None

## Summary

Large UI restructuring (stacked on #918, 1519 insertions across 30 files)
consolidating the previously-separate MCP servers, Desktop Sidecar, and
(add-in) Outlook actions settings into one shared "MCP & Apps" pane, with
each capability provider (MCP server, Desktop Sidecar, Outlook actions)
rendered as one expandable row rather than as independent list sections.
Given the scale and that this is primarily a settings-UI reorganization
rather than functional/data-layer logic, review focused on confirming the
one concrete backward-compatibility claim made.

- **Confirmed**: `TraceCollapse` (a generic pure-CSS expand/collapse
  primitive, previously living under `Trace/`) is promoted to
  `Controls/Collapse`, and the original `TraceCollapse` export is kept as
  a byte-for-byte compatibility alias (`export const TraceCollapse =
  Collapse`) rather than removed — matching the PR's stated reason
  (a bare re-export would otherwise be dropped by the component-registry
  generator, breaking any component kit still importing the old name).
- Per the PR (not independently verified in detail): on web, the MCP
  servers and Desktop Sidecar settings tabs merge into one tab (shown only
  when either underlying feature flag is on); each MCP server row nests
  that server's own tool-approval decisions inline via a new `serverId`
  embed mode on `McpToolApprovalSettings` (from #918), replacing the
  previous two-independent-lists layout. In the Outlook add-in, MCP
  servers become visible for the first time (status + tool approvals), with
  the OAuth authorize/disconnect flow handed off to the system browser
  (an in-taskpane Office Dialog API flow is explicitly deferred as a
  follow-up); client-action decision rows are extracted out of
  `BehaviorTabContent` into a new `ClientActionsSettings` component and
  injected as a device-local "Outlook actions" entity in the same merged
  pane.
- New primitive: `EntityRow` (131 lines, not read in detail) — described
  as a status-pane-styled expandable row with an `aria-expanded` chevron,
  built on the promoted `Collapse`.
- The `mock-llm-server/src/mocks/mod.rs` 38-line diff and the
  `useChatMessaging.ts`/`generationStatusStore.ts` diffs (21 and 10 lines)
  appear incidental to this settings-UI PR's stated scope and were not
  investigated for unrelated changes, given the review-time budget for a
  primarily cosmetic restructuring.

## Compatibility and configuration

None new. Settings UI reorganization only; no configuration or API
changes. Component-kit-facing: `TraceCollapse` remains exported and
functionally identical (confirmed), so no migration is needed for
existing consumers of that specific export.

## Evidence and review

Verified via this PR's squash-merge commit against its parent (both
present locally). Read in full: the `TraceCollapse.tsx`/`Collapse.tsx`
diff, confirming the compatibility-alias claim precisely. Given the
PR's large scale and that it is primarily a settings-page visual
reorganization (not core data/security logic), the new `EntityRow`,
`ServersToolsPane`, `DesktopSidecarTabContent`, `ClientActionsSettings`
components, and the restructured `UserPreferencesDialog.tsx`/
`AddinSettingsDialog.tsx` (307 and 107 line diffs) were not read in
detail. The `mock-llm-server`, `useChatMessaging.ts`, and
`generationStatusStore.ts` diffs outside the settings-UI scope were noted
but not investigated.

## Release note disposition

Proposed category: Features and enhancements. Worth a mention: MCP
